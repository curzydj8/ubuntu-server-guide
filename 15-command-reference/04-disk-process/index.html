    磁盘与进程命令速查¶

    本章是查表页，不讲原理长文：上半部分覆盖块设备与文件系统查看（lsblk、df、du、findmnt、mount、fdisk -l、LVM 只读三件套），下半部分覆盖进程查看与控制（ps、top、htop、pgrep、pkill、kill、作业控制、nice/renice、uptime）。磁盘爆满的完整排查流程见 磁盘爆满与句柄耗尽，LVM 扩容与分区操作见 LVM 动态卷管理，即时监控工具的界面判读见 命令行即时监控工具。全文示例面向 Ubuntu 22.04 / 24.04，示例用户为 ubuntu。

    磁盘命令¶

    lsblk¶

    • 用途：以树形列出全部块设备、分区与挂载点，是看清「哪块盘、哪个分区、挂在哪」的第一命令。
    • 语法：lsblk [选项] [设备]
    参数 说明
    -f 附带显示文件系统类型、UUID 与可用空间
    -o 列名 自定义输出列，如 NAME,SIZE,FSTYPE,MOUNTPOINT
    -d 只显示磁盘本身，不展开分区
    -p 显示完整设备路径，如 /dev/sda1
    • 示例：
    lsblk -f

    NAME   FSTYPE   SIZE MOUNTPOINT
sda             100G
├─sda1 vfat     512M /boot/efi
└─sda2 ext4    99.5G /

    输出里 sda2 挂在 / 且为 ext4，说明系统盘结构正常；排查新盘时先看这里确认设备名，再做任何后续操作。

    • 常见错误：把分区名看错一位（如 sdb 与 sdb1）就对整盘做操作，后果不可逆。
    • 风险提示：本命令只读无风险，但它输出的设备名是后续危险操作的目标，务必逐字核对。

    df¶

    • 用途：按文件系统查看总容量、已用、可用与挂载点，并可查看 inode 使用率。
    • 语法：df [选项] [路径]
    参数 说明
    -h 以 K/M/G 人类可读单位显示
    -i 显示 inode 总量与使用率（文件数耗尽时用）
    -T 附带文件系统类型
    --total 末尾追加一行汇总
    • 示例：
    df -h /
df -i /

    第二条专查 inode：df -h 显示空间还剩很多、服务却报 No space left on device 时，多半是小文件把 inode 用满，应转到 df -i 确认，并按 磁盘爆满排查 处理。

    • 常见错误：只看 -h 不看 -i，在 inode 耗尽时误判为「空间明明够」而排查方向全错。
    • 风险提示：只读无风险；注意已删除但被进程占用的文件不释放空间，df 与 du 对不上时先查占用进程，不要急着删文件。

    du¶

    • 用途：统计目录或文件实际占用空间，用于定位「哪个目录把磁盘吃满了」。
    • 语法：du [选项] [目录]
    参数 说明
    -s 只输出一个汇总值
    -h 人类可读单位
    --max-depth=N 只统计到第 N 层子目录
    -x 不跨文件系统统计，避免把挂载盘算进来
    • 示例：
    sudo du -h --max-depth=1 /var 2>/dev/null | sort -hr | head -20

    按大小倒序列出 /var 一级子目录，通常日志目录 /var/log 或缓存目录会排在最前，顺着结果再逐层下钻即可锁定大目录。

    • 常见错误：在根目录直接 du -sh /* 扫全盘，既慢又会把 /proc 等伪文件系统算出怪异结果。
    • 风险提示：只读无风险，但全盘扫描会产生大量磁盘 IO，业务高峰期请缩小范围逐层下钻。

    findmnt¶

    • 用途：按树形或条件列出已挂载文件系统及其选项，比直接读 /proc/mounts 清晰。
    • 语法：findmnt [选项] [挂载点|设备]
    参数 说明
    -T 路径 查看指定路径所在文件系统的挂载信息
    -o 列名 自定义列，如 SOURCE,TARGET,FSTYPE,OPTIONS
    -S 设备 按源设备过滤
    -n 不输出表头，方便脚本处理
    • 示例：
    findmnt -T /var/log
findmnt -o SOURCE,TARGET,FSTYPE,OPTIONS /

    第一条确认 /var/log 到底落在哪个文件系统上，磁盘爆满时先分清是根分区满还是独立分区满，再决定清理策略。

    • 常见错误：以为目录在哪个盘就等于挂载点在哪，忽略了子目录可能是单独挂载或软链接跳转。
    • 风险提示：只读无风险。

    mount¶

    • 用途：无参数时列出当前全部挂载；带参数时把设备临时挂载到目录（重启失效，持久化需写 /etc/fstab）。
    • 语法：mount [选项] 设备 挂载点
    参数 说明
    -t 类型 指定文件系统类型，如 ext4、xfs、nfs
    -o 选项 挂载选项，如 ro 只读、noexec 禁执行
    -a 按 /etc/fstab 挂载全部条目
    （无参数） 列出当前挂载，等价于查看 /proc/mounts
    • 示例：
    mount | grep /dev/sda
sudo mkdir -p /mnt/data
sudo mount -t ext4 -o ro /dev/sdb1 /mnt/data

    示例用 ro 只读方式挂载数据盘做检查，确认内容无误后再决定是否改成读写挂载并写入 fstab；fstab 的写法与共享挂载见 挂载与存储共享。

    • 常见错误：挂载点目录非空时挂载会「遮住」原有文件，看起来像文件丢失，卸载后即恢复。
    • 风险提示：挂错设备或写错 fstab 可能导致开机进紧急模式，改 fstab 后先执行 sudo mount -a 验证再重启。

    umount 忙设备：先查占用，不要乱用 -l

    umount 报 target is busy 说明仍有进程在用该文件系统。正确顺序是先查占用再处理进程：

    sudo lsof +D /mnt/data
sudo fuser -vm /mnt/data

    查到占用进程并正常退出后再执行 sudo umount /mnt/data。umount -l（懒卸载）只是把挂载从命名空间摘除，进程仍在写原文件系统，数据状态容易混乱；fuser -k 直接杀占用进程同理，非确认无业务时不要使用。

    fdisk¶

    • 用途：查看或修改 MBR/GPT 分区表；本速查只给只读查看用法。
    • 语法：fdisk [选项] [设备]
    参数 说明
    -l 只读列出指定设备（或全部设备）的分区表
    -x 在 -l 基础上附带更多专家字段
    -s 分区 输出分区大小（以块为单位）
    • 示例：
    sudo fdisk -l /dev/sda

    Disk /dev/sda: 100 GiB, 107374182400 bytes, 209715200 sectors
Disklabel type: gpt
Device     Start       End   Sectors  Size Type
/dev/sda1   2048   1050623   1048576  512M EFI System
/dev/sda2 1050624 209713151 208662528 99.5G Linux filesystem

    从输出确认分区表类型（gpt/mbr）、分区起止与大小，是扩容或救援前核对磁盘布局的标准动作。

    • 常见错误：把交互模式里的 w 当成查看键——w 是写入保存，按错即改盘。
    • 风险提示：只读查看用 -l 即可，不要在生产盘上「顺手」进入交互模式试按键。

    分区修改不在本页执行

    新建、删除、调整分区等一切写操作（交互模式的 n/d/w、脚本化改分区表）都会改写分区表，选错设备或偏移即全盘数据丢失。本页不给写操作示例；确需改分区时，先备份、确认设备名，并严格按 LVM 动态卷管理 与存储章节的步骤操作，改完先用 fdisk -l 复核再重启。

    pvs / vgs / lvs¶

    • 用途：LVM 三层只读巡检：物理卷（PV）、卷组（VG）、逻辑卷（LV）的容量与剩余空间。
    • 语法：pvs|vgs|lvs [选项] [名称]
    参数 说明
    pvs 列物理卷：所属 VG、大小与可用空间（PFree）
    vgs 列卷组：总大小与可分配空间（VFree），扩容前先看它
    lvs 列逻辑卷：大小、挂载所对应的 LV 路径
    -o 列名 自定义列，如 lv_name,lv_size,data_percent
    • 示例：
    sudo pvs
sudo vgs
sudo lvs

    判读顺序是自下而上：lvs 看哪个 LV 满了，vgs 看 VG 的 VFree 是否还有余量可扩，pvs 看物理盘是否已全部纳入，具体扩容步骤见 LVM 动态卷管理。

    • 常见错误：LV 满了直接找新盘，却没先看 vgs 的 VFree——VG 里有余量时一条扩容命令即可解决。
    • 风险提示：三条均为只读无风险；缩减 LV、删除 VG 等写操作不在本页范围内，务必走存储章流程并提前备份。

    进程命令¶

    ps¶

    • 用途：静态快照查看进程列表，是脚本里取 PID、命令行与资源占用的主力。
    • 语法：ps [选项]
    参数 说明
    aux BSD 风格：全部用户进程 + 用户、CPU、内存列
    -ef SysV 风格：全部进程 + PPID 父进程列，查父子关系用它
    --sort=-%mem 按内存占用倒序（-%cpu 同理）
    -o 列名 自定义列，如 pid,ppid,%cpu,%mem,cmd
    -p PID 只看指定进程
    • 示例：
    ps aux --sort=-%mem | head -10
ps -ef | grep -v grep | grep nginx

    aux 与 -ef 的核心区别：aux 多了 %CPU/%MEM/RSS 等资源列适合看占用，-ef 多了 PPID 适合追父进程；两条示例分别用于找内存大户与确认 nginx 的主/工作进程关系。

    • 常见错误：ps | grep xxx 把 grep 自身也匹配进来，计数或取 PID 时多出一行，应加 grep -v grep 或用 pgrep。
    • 风险提示：只读无风险。

    top¶

    • 用途：动态刷新查看负载、CPU/内存汇总与进程排行，不装任何工具时的默认现场工具。
    • 语法：top [选项]
    参数 说明
    -u 用户 只看指定用户的进程
    -p PID 只监控指定进程，可逗号分隔多个
    -n 次数 刷新指定次数后退出，适合脚本采样
    -b 批处理模式输出，配合 -n 留存记录
    • 示例：
    top
top -b -n 1 | head -20

    交互界面常用键：q 退出、M 按内存排序、P 按 CPU 排序、1 展开每个 CPU 核心；第二条把一次快照存进日志，适合在故障时先留证再处理。

    • 常见错误：看到内存 used 高就断定内存不足——Linux 闲置内存用作缓存属于正常，应结合 buff/cache 与可用量判读（见本章 free 相关说明与第 06 章）。
    • 风险提示：只读查看无风险；界面内按 k 可直接杀进程，操作前务必确认光标所在 PID。

    htop¶

    • 用途：top 的增强版：彩色界面、鼠标可点、进程树与筛选更顺手。
    • 语法：htop [选项]
    参数 说明
    -u 用户 只显示指定用户的进程
    -p PID 只显示指定进程
    -d 秒数 刷新间隔（单位为 0.1 秒的数值写法见 --delay）
    --tree 启动即树状视图
    • 示例：
    htop
sudo apt install -y htop

    若提示命令不存在，执行第二条安装即可；界面内按 F5 切换进程树、按 M/P 排序、按 / 搜索进程名，判读方法见 命令行即时监控工具。

    • 常见错误：把顶部内存条的缓存段当成已用内存而误判内存告警。
    • 风险提示：查看无风险；界面内 F9 是发送信号结束进程，选中系统关键进程误按会直接影响服务。

    pgrep¶

    • 用途：按名称或条件查找进程 PID，是脚本中取 PID 的标准做法。
    • 语法：pgrep [选项] 模式
    参数 说明
    -a 连同完整命令行一起显示
    -u 用户 限定进程所属用户
    -f 匹配完整命令行而非仅进程名
    -x 进程名精确匹配
    • 示例：
    pgrep -a nginx
pgrep -u ubuntu -f 'python3 app.py'

    第一条列出 nginx 全部进程及启动参数；动任何进程之前，先用 pgrep -a 预览将要命中的对象，这是本章后续 pkill 的前置动作。

    • 常见错误：默认只匹配进程名且最长 15 个字符，长名字的 Java/Python 进程查不到，需加 -f 匹配命令行。
    • 风险提示：只读无风险。

    pkill¶

    • 用途：按名称或条件批量发送信号结束进程，适合清理一组同名进程。
    • 语法：pkill [选项] 模式
    参数 说明
    -f 按完整命令行匹配
    -u 用户 限定用户，避免波及他人进程
    -signal 信号 指定信号，如 -TERM（默认）、-KILL
    -x 精确匹配进程名
    • 示例：
    pgrep -a -f 'python3 worker.py'
pkill -TERM -u ubuntu -f 'python3 worker.py'

    先用完全相同的匹配条件跑一遍 pgrep -a 预览，确认列表里全是目标进程后，再把命令换成 pkill 执行。

    • 常见错误：用过短的模式如 pkill java，把同机其他 Java 服务一并杀掉。
    • 风险提示：批量结束不可批量撤销，匹配条件越宽误伤面越大。

    pkill 按名匹配最易误杀

    pkill 只要名字对上就发信号，不区分实例用途。生产机上执行前必须：①用 pgrep -a 同条件预览；②尽量叠加 -u 用户 与 -f 完整命令行缩小范围；③默认用 TERM 让进程自行清理，确认不退再考虑强杀。切勿用 pkill -9 -f 开局。

    kill¶

    • 用途：向指定 PID 发送信号，默认 TERM(15) 请求进程正常退出。
    • 语法：kill [选项] PID
    参数 说明
    -l 列出全部信号名与编号
    -15 / -TERM 正常终止（默认）：进程可捕获并做清理后退出
    -1 / -HUP 挂断信号：不少守护进程用它重读配置
    -9 / -KILL 强制终止：进程不可捕获、不可清理，仅作最后手段
    -0 PID 不发信号，只检测进程是否存在
    • 示例：
    kill 12345
sleep 3
kill -0 12345 2>/dev/null && echo '仍在运行' || echo '已退出'

    先发默认的 TERM 并等待数秒，再用 -0 探测是否已退出；多数服务在收到 TERM 后需要一点时间写完日志与释放端口，不要连按强杀。

    • 常见错误：进程刚发 TERM 没立刻消失就断定「杀不掉」，其实它正在做退出清理。
    • 风险提示：对 PID 1、数据库、存储类进程发信号影响面极大，动手前先用 ps -p PID -o pid,user,cmd 确认身份。

    kill -9 是最后手段

    KILL(9) 直接由内核终止进程，不给它写日志、刷盘、释放锁与删除临时文件的机会，数据库与存储服务被强杀可能留下损坏或不一致状态。标准顺序：先 kill PID（TERM）→ 等待数秒 → 仍不退再查原因（是否僵尸、是否卡在不可中断睡眠 D 状态）→ 确认无其他办法后才用 kill -9。对僵尸进程发任何信号都无效，应处理其父进程。

    jobs / bg / fg¶

    • 用途：管理当前 Shell 会话里的前后台作业：查看、继续后台运行、调回前台。
    • 语法：jobs [选项] / bg %作业号 / fg %作业号
    参数 说明
    jobs -l 列出作业号同时显示 PID
    Ctrl+Z 挂起当前前台作业（不是退出）
    bg %n 让编号 n 的挂起作业在后台继续
    fg %n 把编号 n 的作业调回前台
    • 示例：
    tar -czf /tmp/home-backup.tar.gz /home/ubuntu
# 按 Ctrl+Z 挂起后：
jobs -l
bg %1
fg %1

    长任务被误挂起时不要关终端：用 jobs 确认它还活着，bg 让它在后台跑完即可；需要长期脱离终端运行的任务应改用 nohup、tmux 或 systemd 服务，不要依赖作业控制。

    • 常见错误：挂起后直接关终端，作业随会话结束被终止，前功尽弃。
    • 风险提示：作业只属于当前 Shell 会话，SSH 断线即消失；重要长任务请勿用这种方式托管。

    nice / renice¶

    • 用途：调整进程的调度优先级（nice 值 -20 最高、19 最低，默认 0），让批处理任务给在线服务让路。
    • 语法：nice [选项] 命令 / renice [-n] 值 PID
    参数 说明
    nice -n 增量 以默认 0 为基准加增量启动命令
    renice -n 值 调整已运行进程的 nice 值
    -u 用户 renice 时批量调整某用户全部进程
    -g 组 按进程组批量调整
    • 示例：
    nice -n 10 tar -czf /tmp/home-backup.tar.gz /home/ubuntu
renice -n 10 -p 12345

    备份、打包这类批处理以 nice -n 10 低优先级启动，能明显减少它对在线服务的 CPU 抢占；注意普通用户只能调高 nice 值（降优先级），调低需要 sudo。

    • 常见错误：以为 nice 能限制内存或磁盘 IO——它只影响 CPU 调度优先级，IO 限制需另用 ionice。
    • 风险提示：给关键服务进程随意调高优先级（负 nice）可能饿死系统进程，非明确场景不要对系统进程使用负值。

    uptime¶

    • 用途：一行看清运行时长与过去 1/5/15 分钟的系统平均负载。
    • 语法：uptime [选项]
    参数 说明
    -p 以易读形式显示已运行时长
    -s 显示系统启动的日期时间
    （负载三数） 分别为 1、5、15 分钟平均负载，判读见下
    • 示例：
    uptime
nproc

    16:20:01 up 12 days,  3:04,  2 users,  load average: 0.85, 1.20, 2.40

    负载要结合 nproc 的核心数判读：4 核机器上负载 0.85 属轻载；三数由近及远递减（如 2.40→1.20→0.85 的反向读法）说明高峰正在回落，持续高于核心数才表示 CPU 长期排队。

    • 常见错误：脱离核心数谈负载——8 核机器负载 4 是半载，1 核机器负载 4 已是严重过载。
    • 风险提示：只读无风险。

    本章排坑与安全总则¶

    • 先只读、后写操作：看盘一律 lsblk -f → df -h/-i → du 逐层下钻 → fdisk -l 复核，分区与 LVM 的写操作一律回存储章按流程执行。
    • 设备名逐字核对：sdb 与 sdb1、nvme0n1 与 nvme0n1p1 差一个字符就是整盘与分区之别，所有危险命令执行前再读一遍目标。
    • 结束进程的标准顺序：pgrep -a 预览 → kill 发 TERM → 等待并用 kill -0 确认 → 查清不退原因 → 最后才考虑 -9；pkill 必须叠加用户与完整命令行缩小范围。
    • df 与 du 对不上，多半是文件已删但被进程占用，先用 lsof 查占用并重启对应服务释放，不要反复删文件。
    • 负载与内存先判读再下结论：负载对照核心数看，内存结合缓存看，避免把 Linux 的正常缓存行为误报为故障。
    • 一切临时挂载都不持久：写进 /etc/fstab 前先 sudo mount -a 验证，验证不过绝不重启。
