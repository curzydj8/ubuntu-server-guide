## 术语表

[术语表](glossary.md)收录正文里反复出现、但很少在首次出现处展开解释的概念：从 LTS、ESM、Ubuntu Pro 这类版本与订阅概念，到 DNSSEC、SPF / DKIM / DMARC 这类邮件与域名安全概念，再到 IOMMU、VFIO、SR-IOV 这类虚拟化概念与 RPO / RTO、脑裂这类高可用与容灾概念。每个词条只给一句话解释和一条「详见」链接——足够你在读正文时不中断，读不懂细节时再跳到对应章节深挖。适用场景：读教程时遇到不认识的缩写；写运维文档或与同行沟通时需要确认一个词的标准含义；新人入职培训时按表逐条过一遍本站的「行话」。

## 命令索引

[命令索引](command-index.md)把第 15 部分《Linux 命令速查手册》的全部条目按字母序汇成一张总表，每行给出命令、用途、风险等级、适用版本和直达速查条目的链接。它和速查手册的分工是：速查手册按「文件与权限、网络诊断、磁盘与进程」等场景分章，适合你已经知道要解决哪类问题时按分类翻；命令索引按字母序排列，适合你只记得命令名、想确认它危险不危险、参数在哪一页时直接定位。适用场景：敲命令前先扫一眼风险等级；评审同事的脚本或命令清单时逐条核对；不记得某个命令收在哪一章时按字母找。

## 端口与协议目录

[端口与协议目录](ports.md)汇总运维中会实际遇到的服务端口：默认端口、TCP / UDP、一句话用途，以及最关键的一列——是否应暴露公网，给出「可暴露 / 仅内网 / 经隧道或反代后暴露」的明确建议和理由。适用场景：开新服务前确认默认端口有没有记错；做防火墙规则或云安全组评审时逐条核对哪些端口不该出现在公网；排查「外网连不上」时先确认端口与协议（尤其是 TCP / UDP 写反）是否对得上。它与[端口开放「三重门」](../10-game-servers/01-port-opening.md)分工：三重门讲开放端口的操作流程与验证方法，本目录只负责「查表定性」，不重复操作步骤。

## 配置文件索引

[配置文件索引](config-files.md)按路径汇总服务器上最常改的一批配置文件：所属软件、用途、修改风险等级、改前备份与改坏后的恢复方法、对应正文章节。它与正文章节的分工是：正文讲某个服务时只讲与该服务有关的配置片段，本索引按「路径」这个维度横切全部服务，适合你面对一个陌生路径先定性——这文件归谁、能不能直接改、改之前要先跑什么校验命令。适用场景：接手一台别人维护的服务器做配置巡检；改配置前查恢复方法（如 sshd 的 `sshd -t`、Nginx 的 `nginx -t`）；新人熟悉「/etc 下面到底哪些文件是人改的、哪些是程序自动生成的」。

## 内容贡献规范

[内容贡献规范](contributing.md)面向想给本站纠错、补章节或提改进的读者与贡献者：本站结构、六段式文章模板、命令测试要求、代码与配置格式、风险标注与过期内容标记规范、审查流程，以及通过 GitHub Issues / PR 参与的方式。适用场景：第一次提 PR 之前通读一遍，避免因格式或验证标注问题被打回；发现正文命令过期或错误时，按规范里的反馈路径提交，让维护者能直接复核。

## 与正文、速查的关系

- **正文（第 01–14 部分）**是唯一的操作依据：完整步骤、前置条件、验证方法与排坑都在正文，索引只做定位与定性，不替代正文流程。尤其是改防火墙、分区、权限这类高风险操作，不要只看索引表就动手。
- **[第 15 部分命令速查](../15-command-reference/index.md)**给单条命令的参数、示例与风险提示；本部分的命令索引只指路，不复制参数表。
- **[版本兼容与验证状态](../compatibility.md)**是全站验证状态的唯一基准：索引里写的「适用版本」从简标注，具体到某一章在某个 Ubuntu 版本上是已实测、文档核对还是待核验，以兼容页为准。
- 索引与正文冲突时以正文和兼容页为准，并欢迎按[内容贡献规范](contributing.md)的反馈路径提 Issue 指出，本页会随正文增补同步更新。
