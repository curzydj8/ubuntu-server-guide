# 端口与协议目录

本目录汇总运维中会实际遇到的服务默认端口，按场景分组。最需要认真看的是最后一列——**是否应暴露公网**：端口开错方向（该对内的开到了公网）是服务器被入侵最常见的入口之一，评审防火墙与云安全组规则时请逐行核对本表。

!!! danger "数据库与缓存端口默认不向公网开放"
    MySQL 3306、PostgreSQL 5432、Redis 6379、MongoDB 27017 这类端口**默认一律不对公网开放**，只允许本机、内网或明确的应用服务器来源访问。历史上大量数据泄露与勒索事件都是数据库端口裸奔公网导致的；确需跨机访问时走内网、VPN、SSH 隧道或云厂商的内网组网，并同时开启账号强口令与访问白名单，不要只靠「改个冷门端口」代替隔离。

说明：「可暴露」指该端口设计上就是对外提供服务的，但仍须配合表内备注的前提（如密钥登录、强认证）；「仅内网」指只应监听内网或本机，外网访问一律经 VPN、SSH 隧道或跳板机；「经隧道或反代后暴露」指服务本身不直接对公网监听，由反向代理或隧道承接外部流量。

## 系统与远程管理

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| SSH | 22 | TCP | 远程登录与管理、SFTP / SCP 文件传输 | 可暴露——前提是密钥登录、禁用口令与 root 直登，最好再限源 IP 或改走跳板机，见 [SSH 安全加固](../02-security/01-ssh-hardening.md) |
| DNS | 53 | UDP + TCP | 域名解析（大响应与区域传送走 TCP） | 分情况——权威解析服务可暴露；递归解析仅内网，对公网开放递归会被滥用为攻击反射源，见 [DNS 服务器搭建](../04-network/01-dns.md) |
| RDP | 3389 | TCP + UDP | Windows 远程桌面（Ubuntu 服务器一般不装，仅作对比：远程图形管理不要学它裸奔） | 仅内网——确需外网访问先套 VPN 或网关，它是暴力破解与漏洞利用的长期重灾区 |
| VNC | 5900 | TCP | 图形桌面远程控制（5900 起按显示编号递增） | 仅内网——协议加密弱，经 SSH 隧道或 VPN 访问，见 [SSH 隧道与跳板机](../14-ssh/05-tunnels-jump.md) |
| 宝塔面板 | 安装后随机生成、以面板显示为准 | TCP | 宝塔 / aaPanel 的 Web 管理入口 | 仅内网——随机端口不是安全措施，还须改面板入口路径、开访问限制并限源 IP，外网管理经隧道，见 [宝塔面板安装与安全加固](../09-web-hosting/02-baota-panel.md) |

## Web 与证书

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| HTTP | 80 | TCP | 网站明文入口，一般只做跳转 HTTPS 与证书签发校验 | 可暴露——但业务内容必须 301 跳转到 443，不要在 80 上承载登录与业务，见 [HTTPS 自动化证书](../09-web-hosting/05-https-certificates.md) |
| HTTPS | 443 | TCP | 网站加密入口，反向代理与站点对外服务的主端口 | 可暴露——这是 Web 服务的标准对外端口，确保 TLS 配置与证书续期正常，见 [Web 服务器与反向代理](../04-network/02-web-proxy.md) |

## 邮件

邮件全套端口与记录配置见 [邮件服务器](../09-web-hosting/06-mail-server.md)；先说清一个前提：自建邮件要正常收发，除下表端口外还须配好 PTR 反向解析与 SPF、DKIM、DMARC 记录（见[术语表](glossary.md)），缺任意一项都容易进垃圾箱或被拒收。

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| SMTP | 25 | TCP | 服务器之间投递邮件（收信入口） | 可暴露——不开放就收不到外部邮件，但须做好防开放中继与发信信誉维护 |
| Submission | 587 | TCP | 客户端提交发信（带认证与 STARTTLS） | 可暴露——这是给自有用户提交邮件的标准端口，必须启用认证与加密 |
| SMTPS | 465 | TCP | 隐式 TLS 的客户端提交发信 | 可暴露——与 587 二选一或并存，同样必须启用认证 |
| IMAP | 143 | TCP | 客户端同步收取邮件（明文，可 STARTTLS 升级） | 仅内网——公网收信请用 IMAPS 993，不要让明文凭据在公网上传输 |
| IMAPS | 993 | TCP | 加密版 IMAP | 可暴露——对外提供邮箱同步的标准做法 |
| POP3 | 110 | TCP | 客户端下载式收信（明文） | 仅内网——公网收信请用 POP3S 995，能不用 POP3 就不用 |
| POP3S | 995 | TCP | 加密版 POP3 | 可暴露——仅在确有客户端依赖 POP3 时开放 |

## 数据库与缓存

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| MySQL / MariaDB | 3306 | TCP | 关系型数据库连接 | 仅内网——只放行应用服务器来源，远程管理走隧道，见 [MySQL 用户、权限与远程访问](../11-databases/02-mysql-users-remote.md) |
| PostgreSQL | 5432 | TCP | 关系型数据库连接 | 仅内网——同上，并配合 pg_hba.conf 的来源限制，见 [PostgreSQL 安装与认证](../11-databases/05-postgresql-install-auth.md) |
| Redis | 6379 | TCP | 缓存与会话存储连接 | 仅内网——历史上未授权访问事件频发，至少绑定内网地址、设密码并改默认配置，见 [Redis 与 Sentinel 高可用](../11-databases/07-redis.md) |
| MongoDB | 27017 | TCP | 文档数据库连接 | 仅内网——必须开启认证并限定来源，见 [MongoDB 安装与调优](../11-databases/08-mongodb.md) |

## 文件共享与存储

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| Samba（SMB） | 445（139 为旧 NetBIOS） | TCP | Windows 兼容的文件与打印共享 | 仅内网——SMB 裸奔公网是勒索病毒的主要入口之一，跨网访问走 VPN，见 [挂载与存储共享](../03-storage/03-mount-sharing.md) |
| NFS | 2049 | TCP + UDP | Linux 之间网络文件系统共享 | 仅内网——权限模型基本只认 IP 与 UID，只在可信内网使用并配 /etc/exports 白名单 |
| iSCSI | 3260 | TCP | 把远程块设备经网络挂成本地磁盘 | 仅内网——只走存储专网或隔离 VLAN，并启用 CHAP 认证，不要与业务网混用 |

## 监控

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| Prometheus | 9090 | TCP | 指标采集与 PromQL 查询界面 | 经隧道或反代后暴露——自带界面无登录认证，外网查看时套反向代理加认证或只走内网，见 [Prometheus + Grafana 监控栈](../06-monitoring/02-prometheus-grafana.md) |
| Grafana | 3000 | TCP | 监控仪表盘 Web 界面 | 经隧道或反代后暴露——启用账号登录后可经反向代理对外，不要用默认口令直接开放 |
| Node Exporter | 9100 | TCP | 向 Prometheus 暴露主机指标的采集端点 | 仅内网——它没有任何认证，只应允许 Prometheus 服务器来抓取 |

## 游戏与组网

游戏服端口的开放流程（本机防火墙、云安全组、路由器映射三重门）见[端口开放「三重门」](../10-game-servers/01-port-opening.md)，具体游戏搭建见[游戏服务端实战](../10-game-servers/02-game-server-setup.md)。

| 服务 | 默认端口 | TCP / UDP | 用途 | 是否应暴露公网 |
| --- | --- | --- | --- | --- |
| Minecraft（Java 版） | 25565 | TCP | 游戏客户端连接入口 | 可暴露——联机游戏必须对外，但请开白名单与正版验证，离线模式服务器是冒名顶替的重灾区 |
| Palworld（幻兽帕鲁） | 8211（游戏）、27015（Steam 查询） | UDP | 游戏连接与服务器列表查询 | 可暴露——联机必需，建议设服务器密码并只把实际用到的端口做映射 |
| WireGuard | 51820 | UDP | 现代 VPN 组网监听端口 | 可暴露——协议对未认证数据包不作回应，暴露面小，是组网工具里少数可安心对外的端口，见 [网络隧道与 VPN](../04-network/03-vpn-tunnel.md) |
| OpenVPN | 1194 | UDP（也可 TCP） | 传统 VPN 组网监听端口 | 可暴露——同 WireGuard 属设计上对外监听的 VPN 入口，保持软件更新即可 |
| v2ray 类代理 | 无统一默认、按自有配置，1080 / 10808 SOCKS、7890 混合端口为常见客户端惯例 | TCP（按配置） | 本地代理客户端的入站监听 | 仅内网——这类端口的设计用途是给本机或内网程序做代理，只监听 127.0.0.1，不要改成对公网监听 |

## 查完端口之后

确认「该不该开」之后再动手开：本机侧用 [UFW 防火墙](../02-security/03-firewall.md)放行，云服务器还要同步改安全组，家庭宽带还要做路由器端口映射，三处缺一不可；开完从外网真实拨测验证，不要只在服务器本机自测。拿不准某个端口现在到底有没有在监听，用 `ss -tulnp` 先查现状（见[命令索引](command-index.md)中的 `ss` 条目）。
