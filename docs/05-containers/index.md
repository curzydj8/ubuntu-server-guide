# 第 05 部分：容器化与云原生

欢迎来到容器化与云原生部分。前面几部分已经把 Ubuntu Server 的系统管理、网络、存储与安全基础打牢，本部分解决下一个问题：怎样让应用摆脱对单台机器环境的强绑定，做到可复制、可迁移、可批量管理。容器把应用和依赖打包在一起，编排工具再把多个容器组织成可对外提供服务的系统，这正是现代运维的主流做法。

## 本部分地图

本部分共三章，由单机到集群、由主流到补充，逻辑层层递进：

| 章节 | 文件 | 定位 |
| --- | --- | --- |
| 第 1 章 | 01-docker.md | 单机容器主力方案，生态最广，新手和生产环境都适用 |
| 第 2 章 | 02-podman.md | 无守护进程、无根运行的安全型方案，与 Docker 命令高度兼容 |
| 第 3 章 | 03-kubernetes-light.md | 轻量 Kubernetes，把单机容器经验扩展到多节点集群 |

## 每章一句话

- **Docker 基础与进阶**：一次讲透 Engine 安装、镜像与容器命令、Compose 编排和镜像优化，学完即可独立交付一个多容器应用。
- **Podman 无根容器**：不依赖常驻守护进程、普通用户即可运行容器，重点讲清 rootless 原理、与 Docker 的对照关系以及和 systemd 的集成方式。
- **Kubernetes 轻量集群**：对比 k3s 与 microk8s 两种轻量发行版，完成从单节点体验到多节点搭建、发布示例应用的完整入门路径。

## 推荐学习顺序

建议严格按 01、02、03 的顺序学习。先在 Docker 上建立镜像、分层、网络、数据卷这套核心概念，后面看 Podman 时只需关注差异点，看 Kubernetes 时也能把 Pod、Service、Ingress 与之前的端口映射、服务发现对应起来。如果你的目标只是单机部署几个内部服务，学完第 1 章就可以投入使用；如果对安全隔离要求高，再补第 2 章；只有当服务需要多节点高可用或弹性伸缩时，才继续进入第 3 章，不要为了追新而过早上集群。

!!! tip "学习方法建议"

    每章都配有可直接复制执行的命令和完整的验证步骤。建议准备一台 Ubuntu 22.04 或 24.04 的测试机或虚拟机，边读边敲，命令执行完立刻对照验证部分的期望输出检查结果，效果远好于只看不练。

## 学完本部分你能做到什么

完成本部分后，你应当能够：独立安装和加固 Docker、使用 Compose 管理多容器应用、写出体积小且构建快的镜像；理解 rootless 容器的安全价值并用 Podman 替代部分 Docker 场景；根据资源条件在 k3s 与 microk8s 之间做选型，并独立搭建一个可用的轻量集群、发布和访问示例应用。这些能力也是后续学习自动化运维部分的前置基础。
