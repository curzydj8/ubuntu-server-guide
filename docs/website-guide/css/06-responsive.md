## 6. 技术原理

### 响应式是什么

响应式设计（Responsive Web Design）的意思是：**同一套 HTML、同一套 CSS，根据屏幕宽度（以及方向、是否支持悬停等条件）自动调整布局**，手机上 1 列、平板上 2 列、桌面上 3 列，但内容是同一份，不用给手机、平板、桌面各做一套页面、维护三份代码。

它和“自适应（Adaptive）”的区别要分清：自适应是提前做好几套固定宽度的页面，浏览器按宽度挑一套；响应式是同一套页面连续变化，中间宽度也能正常显示。本篇讲的是响应式，不是自适应。

实现响应式的三件套，缺一不可：

1. **流式布局**：宽度用百分比、`fr`、`rem`、`vw` 这种相对单位，不用处处写死 `px`，容器才能随屏幕伸缩；
2. **弹性媒体**：图片、视频最大宽度不超过容器（`max-width: 100%`），不会把页面撑出横向滚动条；
3. **媒体查询**：`@media` 按宽度、方向等条件，在某个宽度区间换一套布局（比如列数从 1 列变 2 列、导航从纵向变横向）。

### 媒体查询是怎么工作的

`@media` 的基本写法是“条件 + 一组规则”：条件成立时，大括号里的规则生效；条件不成立时，大括号里的规则等于不存在。

```css
@media (min-width: 600px) {
  .card-list {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

上面这段的意思是：视口宽度大于等于 600px 时，卡片列表变成 2 列；小于 600px 时，这条规则不生效，卡片列表保持基础样式（本篇实战里基础样式是 1 列）。

### 移动优先是怎么回事

移动优先（Mobile First）是写响应式样式的顺序，不是“只做手机版”：

1. **先写手机版**：不写任何 `@media` 的基础样式，就是手机版——单列、纵向导航、大号可点按的按钮；
2. **再往上加**：用 `@media (min-width: ...)` 逐步加平板版、桌面版，每加一个断点，只写“和手机版不一样的那部分”，不重复写全部样式。

为什么推荐移动优先，有三个实在的理由：

- 手机是约束最多的设备（屏幕窄、触屏、流量有限），先把手机版做对，往上加内容是做加法；反过来先做桌面版再往下删，是做减法，容易漏删、容易在手机上留下桌面版的包袱；
- 移动优先的 `@media` 都是 `min-width`，条件之间不互相打架，读起来是“宽度到了多少，就加什么”，比一堆 `max-width` 交错好维护；
- 搜索引擎和用户都先看手机版，手机版先行，收录和首屏体验都不吃亏。

桌面优先（先写桌面版，再用 `max-width` 往下改）不是错的，老项目里很常见，但新项目推荐移动优先，本篇实战就按移动优先写。

### 断点是怎么选的

断点（Breakpoint）就是“布局要变的那几个宽度”。选断点的正确方法是**按内容选，不是按手机型号硬抄**：

- 把浏览器窗口从宽往窄拖，拖到某个宽度时，某一行文字挤得难受、某张卡片窄得没法看、导航开始重叠——那个宽度附近就是一个断点；
- 断点是“内容撑不住时才加”，不是越多越好。断点越多，维护成本越高，中间宽度反而容易出没人测过的怪布局。本篇实战只用了两个断点（600px、900px），就覆盖了手机、平板、桌面三档，够用了。

常用断点区间示例（只是示例，不是标准，照抄之前先按自己内容拖一遍窗口验证）：

| 档位 | 宽度区间示例 | 本篇实战里的布局 |
|---|---|---|
| 手机 | 小于 600px | 卡片 1 列，导航纵向 |
| 平板 | 600px～899px | 卡片 2 列，导航横向 |
| 桌面 | 大于等于 900px | 卡片 3 列，导航横向 |

注意：600px、900px 是本篇示例的数字，不是“所有网站都必须用这两个数”。你的内容在 700px 才撑不住，那你的断点就该是 700px，不要为了凑常用数字硬套。

### 流式字号：`clamp()` 是干什么的

只用断点调字号，字号会在断点处“跳”一下：599px 是 18px，600px 突然变成 24px。`clamp()` 是让字号随宽度平滑变化的办法，写法是 `clamp(最小值, 首选值, 最大值)`：

```css
h1 {
  font-size: clamp(24px, 5vw, 40px);
}
```

意思是：首选值是 `5vw`（视口宽度的 5%），但不能小于 24px，也不能大于 40px。窗口很窄时，`5vw` 算出来小于 24px，就用 24px；窗口很宽时，`5vw` 算出来大于 40px，就用 40px；中间宽度就跟着 `5vw` 平滑变化。这就是“流式字号”：不断点、不跳变，始终在可读范围内。

`rem` 和 `vw` 在响应式里是分工的：`rem` 管“全站统一基准”（改根字号全站按比例变，CSS-02 讲过），`vw` 管“跟随视口变化”，`clamp()` 是把两者结合起来——最小值、最大值常用 `px` 或 `rem` 定死，首选值用 `vw` 做流式变化。

## 7. 架构说明

本篇完整示例的页面结构，仍然是 WEB-01、CSS-01 的骨架，只在 `main` 里加了三节，每节演示一组响应式做法：

```text
header（标题：字号用 clamp() 做流式字号）
nav（导航：手机纵向，桌面横向；汉堡按钮只做结构思路，不接 JS）
main
├── section#hero（主视觉：picture/source 按宽度换图，图片自适应）
├── section#cards（卡片列表：手机 1 列，平板 2 列，桌面 3 列，移动优先）
└── section#media（视频自适应：max-width: 100%，高度自动）
footer（页脚）
```

三节之间没有依赖关系，可以单独拿出来用：只要卡片列数，就复制卡片那一节；只要图片自适应，就复制主视觉那一节。每一节内部也是独立的，删掉一节不影响另外两节。

导航的汉堡菜单思路（本篇只讲结构，不写 JS）：

```text
手机版：只显示一个汉堡按钮（☰），菜单列表默认隐藏
桌面版：汉堡按钮隐藏，菜单列表横向显示
交互（JS 阶段做）：点汉堡按钮时，给菜单加一个 .nav-open 类，CSS 里 .nav-open 时菜单显示；再点一次，去掉这个类，菜单隐藏
```

本篇示例里的导航为了“一个文件就能跑通、无 JS 也能用”，做的是更稳妥的做法：手机版导航纵向排列（不用点开也能看到全部链接），桌面版横向排列。汉堡菜单的完整交互（点按钮展开/收起）留到 JS 阶段，那时再给这个导航接上 JS，不要在本篇硬写一个没有 JS 的“假汉堡按钮”——点不动的按钮比纵向导航更糟。

## 9. 逐步操作

1. 在练习文件夹里新建文件 `responsive.html`；
2. 把第 10 节的完整代码从头到尾复制进去；
3. 保存，UTF-8，双击用浏览器打开；
4. 先看手机宽度：把窗口拖到最窄（或者开发者工具里选一款手机宽度），看卡片是不是 1 列、导航是不是纵向、标题字号是不是最小档（24px 附近）；
5. 再把窗口慢慢拖宽：拖过 600px 时，卡片是不是变成 2 列、导航是不是变成横向；拖过 900px 时，卡片是不是变成 3 列、标题字号是不是变大了但没有超过 40px；
6. 再看主视觉图：窗口从窄拖到宽，图片是不是始终没有撑破容器、没有变形（图片文件本身是占位路径时，显示的是 `alt` 文字和图注，重点看容器没有被撑出横向滚动条）；
7. 再看视频区：视频是不是始终在容器内，宽度跟着容器变，高度按比例变，没有变形；
8. 把 `viewport` 那行 `meta` 删掉，保存刷新，再把窗口拖到手机宽度，看页面是不是突然变得很小、要双指放大才能看——这一步是让你亲眼看到 `viewport` 漏写的后果；看完把那行加回去。

## 10. 完整代码

## 12. 每个关键属性/语法的解释

| 写法 | 作用 | 容易错的地方 |
|---|---|---|
| `@media (min-width: 600px)` | 视口宽度大于等于 600px 时，大括号里的规则生效 | 移动优先用 `min-width` 往上加，不要和桌面优先的 `max-width` 在同一个项目里混着写，混写后条件交错，排查时很难算清哪条生效 |
| `@media (max-width: 700px)` | 视口宽度小于等于 700px 时，大括号里的规则生效 | `max-width` 的边界是“小于等于”，`min-width` 的边界是“大于等于”，600px 这个点上，`min-width: 600px` 和 `max-width: 600px` 会同时成立，写断点时要留心这个重叠点，不要在重叠点上写互相矛盾的规则 |
| `@media (orientation: landscape)` | 设备横屏时生效，竖屏时不生效 | `orientation` 是按视口宽高比判断的，宽大于高就是横屏；手机横过来时宽度变了，列数规则和方向规则可能同时生效，两条规则写了互相矛盾的样式时，按优先级和顺序算，不要指望方向规则自动盖过宽度规则 |
| `@media (orientation: landscape) and (max-width: 700px)` | 两个条件同时成立时才生效 | `and` 前后都要有空格，条件都要用括号括起来，`@media (orientation: landscape)and(max-width: 700px)` 这种没空格的写法是无效的 |
| `@media (hover: hover)` | 只有能精确悬停的设备（鼠标、触控板）上才生效，触屏手机上不生效 | 触屏上 `hover` 样式点一下会“粘”住不消失，看起来像按钮卡住了；悬停才有的效果（比如悬停变背景色）要包在 `(hover: hover)` 里，只在能悬停的设备上给 |
| `clamp(最小值, 首选值, 最大值)` | 首选值随视口变化，但不小于最小值、不大于最大值 | 三个值的顺序不能错，`clamp(40px, 5vw, 24px)` 这种最小值比最大值大的写法是无效的，整条声明会被丢弃；首选值常用 `vw`，最小值、最大值常用 `px` 或 `rem` |
| `rem` | 根元素字号，全页统一基准（CSS-02 讲过） | 响应式里 `rem` 的作用是“改根字号全站按比例变”，比如小屏时把根字号调小一档，全站 `rem` 间距跟着变；不要把 `rem` 和 `vw` 的作用混了，`rem` 不跟视口走 |
| `vw` / `vh` | 视口宽 / 高的百分比（CSS-02 讲过） | `100vw` 包含滚动条宽度时，页面可能多出横向滚动条，全宽区块慎用 `100vw`，用 `width: 100%` 更稳 |
| `100dvh` | 动态视口高度，手机浏览器地址栏收起展开时跟着变 | 老浏览器不支持 `dvh`，要写两行回退：先写 `min-height: 100vh;`，再写 `min-height: 100dvh;`，老浏览器读不懂第二行就用第一行，新浏览器用第二行盖掉第一行，顺序不能反 |
| `max-width: 100%`（图片、视频） | 媒体最大宽度不超过容器，容器窄了它跟着缩 | 只写 `max-width: 100%` 不写 `height: auto`，图片高度不会按比例变，会变形；两个要一起写 |
| `height: auto`（图片、视频） | 高度按原比例自动算 | 图片同时写了固定高度和 `max-width: 100%` 时，高度固定了就不会按比例变，宽高比就乱了 |
| `picture` / `source` / `srcset` | 按条件换图：`source` 的 `media` 条件成立时用它的 `srcset`，都不成立时用 `img` 的 `src` | `source` 的顺序是从上往下匹配，先写大宽度条件、后写小宽度条件（本篇示例就是 900px 在前、600px 在后），顺序反了，大图条件永远匹配不到；最后一定要有 `img` 做兜底，没有 `img`，`picture` 里就什么都不显示 |
| `object-fit: cover` | 图片在固定尺寸的框里铺满，多余部分裁掉 | 只在图片有固定宽高（比如横屏小屏时限高 240px）时才有意义，没有固定尺寸时写它没效果；和 `background-size: cover` 是一个意思，一个是给 `img` 用的，一个是给背景图用的 |

## 13. 执行结果示例

下面是三种宽度下，你应该看到的样子，验证方法就是改浏览器窗口宽度，不用换设备：

- **手机宽度（小于 600px，比如 390px）**：标题字号最小档（24px 附近）；导航纵向排列，三个链接上下排；卡片 1 列，从上到下排成一列；主视觉图用小图（占位路径时显示 `alt` 文字），图片没有撑破容器，没有横向滚动条；视频在容器内，宽度跟着容器变。
- **平板宽度（600px～899px，比如 768px）**：标题字号比手机时大了一点（`5vw` 算出来在 24px～40px 之间）；导航变成横向排列；卡片变成 2 列，六张卡片排成 3 行；主视觉图换成中图（占位路径时还是 `alt` 文字，重点看容器没有被撑破）；视频仍然在容器内。
- **桌面宽度（大于等于 900px，比如 1200px）**：标题字号最大档（40px，不会再随窗口变大）；导航横向；卡片变成 3 列，六张卡片排成 2 行；主视觉图换成大图；视频仍然在容器内。
- **横屏小屏（横屏且宽度小于等于 700px，比如手机横过来）**：主视觉图高度被限制在 240px 以内，多余部分按 `cover` 裁掉，不会把页面撑得很高；卡片列数仍按宽度规则走（横屏手机宽度如果过了 600px，就是 2 列）。

如果你在手机宽度下看到页面整体很小、要双指放大才能看，先查 `viewport` 那行 `meta` 是不是漏写了（见第 9 节第 8 步）；如果你在桌面宽度下卡片还是 1 列，先查 `@media (min-width: 900px)` 的大括号是不是漏写了、列数规则是不是写在了 `@media` 外面。

## 14. 成功验证

按顺序做，全部通过才算本篇完成：

1. **文件验证**：`responsive.html` 在练习文件夹里，双击能打开，不是 `.txt`；
2. **手机验证**：窗口拖到最窄（小于 600px），卡片 1 列，导航纵向，标题字号最小档；
3. **平板验证**：窗口拖到 600px～899px（比如 768px），卡片变成 2 列，导航变成横向；
4. **桌面验证**：窗口拖到大于等于 900px（比如 1200px），卡片变成 3 列，标题字号最大档且不再随窗口变大；
5. **图片验证**：窗口从窄拖到宽，图片始终没有撑破容器、没有变形，也没有出现横向滚动条（占位路径时看容器和 `alt` 文字，不看图片本身）；
6. **视频验证**：视频始终在容器内，宽度跟着容器变，高度按比例变，没有变形；
7. **横屏验证（可选）**：把窗口拖成横屏小屏（宽大于高、且宽度小于等于 700px），主视觉图高度被限制在 240px 以内；
8. **viewport 验证**：删掉 `viewport` 那行 `meta`，手机宽度下页面变小、要放大才能看；加回去，恢复正常——这一步做完要把那行加回去，不要留着删掉的状态。

## 15. 常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 漏写 `viewport` 的 `meta` | 手机上页面整体很小，要双指放大才能看 | `head` 里加上 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`，这是响应式的第一行代码 |
| 全站都用固定 `px` 宽度 | 窄屏下内容撑破容器，出现横向滚动条 | 容器宽度用 `%`、`fr`、`rem` 等相对单位，图片、视频用 `max-width: 100%` |
| 断点按手机型号硬抄 | 换个型号的手机，布局在某个宽度又乱了 | 按内容选断点：拖动窗口，拖到内容撑不住的那个宽度附近再加断点 |
| 断点太多 | 维护成本高，中间宽度出现没人测过的怪布局 | 断点是内容撑不住时才加，本篇实战两个断点就够三档，够用就不要再加 |
| `min-width` 和 `max-width` 混写打架 | 某个宽度下两条互相矛盾的规则同时生效，效果不可预测 | 新项目统一移动优先、只用 `min-width` 往上加；老项目维持桌面优先时，也不要在同一个文件里两种混写 |
| `clamp()` 三个值顺序错 | 整条字号声明失效，字号回到默认值 | 顺序是最小值、首选值、最大值，最小值不能大于最大值 |
| 图片只写 `max-width: 100%` 不写 `height: auto` | 图片变形 | 两个一起写，高度按比例自动算 |
| `picture` 的 `source` 顺序反了 | 大图条件永远匹配不到，一直用小图 | 先写大宽度条件、后写小宽度条件，最后一定有 `img` 做兜底 |
| `100vh` 在手机上抖动 | 地址栏收起展开时，页面高度跟着跳，底部按钮一上一下 | 写两行回退：先 `100vh`，再 `100dvh`，顺序不能反 |
| 触屏上 `hover` 样式粘住 | 点一下按钮，悬停样式不消失，看起来像卡住了 | 悬停才有的效果包在 `@media (hover: hover)` 里，触屏上不给悬停样式 |
| 固定元素在手机上遮挡内容 | 固定导航、固定按钮盖住了正文、表单按钮点不到 | 固定元素要给正文留出对应的内边距，或者小屏下改成不固定，遮挡是最常见的手机端可用性问题 |
| 汉堡按钮没有 JS 却假装能点 | 点按钮没反应，用户以为页面坏了 | 没有 JS 时，手机导航就用纵向排列，不要做点不动的假按钮；汉堡交互留到 JS 阶段再接 |

## 16. 故障排查

- **手机宽度下页面整体很小**：先查 `viewport` 的 `meta` 是不是漏写了，再查是不是某个容器写了固定 `px` 宽度把页面撑宽了。
- **拖到断点宽度列数没变**：先查 `@media` 的大括号是不是漏写了、列数规则是不是写在了 `@media` 外面，再查断点数字是不是写错了（比如把 600 写成了 6000），再查是不是有更高优先级的规则盖住了列数规则（CSS-01 的优先级算法）。
- **图片撑破容器**：先查 `max-width: 100%` 是不是写在了图片本身上（写在父级上没用），再查 `height: auto` 是不是漏了，再查图片是不是被固定宽度、固定高度钉死了。
- **横屏时布局乱了**：先查是不是方向规则和宽度规则同时生效且互相矛盾，再查是不是 `100vh` 在横屏时算出来的高度和预想的不一样。
- **标题字号不变或跳变**：先查 `clamp()` 三个值的顺序和数值，再查是不是被更高优先级的字号规则盖住了，再查是不是把 `clamp()` 写在了不支持它的老浏览器里（现代浏览器都支持，基本不用怀疑这一点）。
- **改了 CSS 刷新没变**：确认保存了，再按 Ctrl+F5 强制刷新，排除浏览器缓存；改断点、改列数时尤其要强制刷新一次，因为浏览器缓存的旧样式表会让你以为断点没生效。

## 17. 安全注意事项

- 响应式本身没有直接的安全风险，但 `picture`、`video`、`img` 引用的外部图片、视频地址要确认来源可信，不要引用来路不明的外部媒体，外部媒体一旦换内容，你的页面上显示的就是对方的内容。
- 不要把真实用户的隐私信息写进示例代码里，占位图片路径、占位文字就够了。
- 固定元素、弹窗、汉堡菜单不要盖住页面上必须能点的按钮（比如“取消”“关闭”“提交”），盖住重要按钮是可用性问题，也是防误操作的问题，CSS-03 第 17 节讲过这个原则。

## 18. 回滚和恢复

本篇和 CSS-01～CSS-03、WEB 系列一样，没有服务器、没有数据库、没有配置改动，回滚就是：

- 改错了：编辑器里 Ctrl+Z 撤销，或把第 10 节的完整代码重新复制覆盖一次；
- 断点改乱了：把 `@media` 里的规则删掉，页面就回到手机版单列，再一步一步加断点；
