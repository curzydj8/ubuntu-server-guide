# UX-01：网站设计与用户体验完整教程

> 任务编号：UX-01（网站建设与部署实战指南 · 网站设计与用户体验）
> 上一篇：[UI-01 UI 组件库](../frontend/07-ui-libraries.md)；下一篇：[NET-01 互联网、HTTP/HTTPS、浏览器、DNS、域名、IP、端口](../basics/01-internet.md)。
> 本篇只讲网站设计与用户体验：布局、色彩、字体、交互、移动端、无障碍的引用。不讲具体某个 UI 组件库的用法（那是 UI-01），不讲后端与性能优化。

## 1. 本章目标

读完并动手做完本篇，你能：

1. 给一个普通内容页定出清晰的视觉层级：第一眼先看到什么、第二眼看到什么、最后看到什么；
2. 定一套能直接用的色彩方案：主色、辅助色、文字色、背景色，并说清每种颜色用在哪里；
3. 定一套字体层级：标题、正文、辅助文字的字号与行高，保证长文读得下去；
4. 写出带反馈的交互：按钮、链接、表单在悬停、聚焦、点击、出错时各是什么样子；
5. 让页面在手机上也能用：单列布局、足够大的触摸目标、单手能点到主要操作；
6. 做一遍基础无障碍自查：键盘能走通、焦点看得见、信息不只靠颜色传达。

本篇适合已经学完 HTML 基础（WEB-01 至 WEB-03）和 CSS 基础（CSS-01 至 CSS-03、CSS-06、CSS-07）的读者，正在做自己的第一个网站，想把页面从“能打开”做到“看着顺、用着顺”。不需要设计专业背景，不需要会用专业设计软件，不需要先学某个框架。

## 6. 技术原理

设计不是“凭感觉调好看”，背后是几条可以说得清的规律。先理解它们，再动手才不会东改西改。

**视觉层级：先分轻重，再谈美观。** 人打开一个页面，第一眼只会抓住一到两个最突出的东西：最大的标题、最亮的按钮、最靠上的横幅。做法是给信息排优先级：最重要的只给一个主标题和一个主操作，次要的用小一号的字、浅一点的颜色、靠后的位置。页面上如果有三个一样大、一样亮的东西，用户就不知道先看哪一个，等于没有层级。

**接近性与相似性：挨得近的是一组，长得像的是一类。** 导航里的几个链接挨在一起，用户就知道它们是一组；三张卡片用同样的标题字号、同样的内边距、同样的按钮样式，用户就知道它们是同一类内容。反过来，标题和它自己的正文离得太远，正文和下一节的标题离得太近，读者就会把归属读错。所以间距不是装饰，是分组的手段。

**阅读顺序：先上后下、先左后右，标题带路。** 中文页面默认从上往下、从左往右读，标题就是路标：主标题讲整页讲什么，二级标题讲每一段讲什么，正文只负责展开。不要用加粗的正文代替标题，也不要用大字号的正文冒充标题，屏幕阅读器和搜索引擎都是靠标题结构理解页面的，这一点在 WEB-03 里已经讲过。

**对比与留白：对比用来区分，留白用来呼吸。** 对比包括字号对比、颜色对比、粗细对比、留白对比；留白不是“空着浪费”，而是让眼睛有地方停。段落之间、卡片之间、标题与正文之间都要留白，挤在一起的页面读起来累，不是信息多，是呼吸的地方被占了。

**反馈与可预见：每一次操作都要有回音。** 点按钮要有按下去的样子，提交表单出错要告诉用户错在哪、怎么改，加载要告诉用户正在进行。用户最怕的不是慢，而是点了之后什么都没发生，不知道刚才那一下到底生效没有。反馈要及时、要具体，不能只靠颜色变化（色弱用户可能看不出来），还要有文字或形状的变化。

**触摸与单手：手指比鼠标粗，拇指够不到顶部。** 桌面上鼠标可以点很小的链接，手机上手指点不准小目标，所以移动端的主要按钮和链接要做大、间距要留够；页面最重要的操作尽量放在拇指容易够到的中下部，而不是只放在顶栏最远的角落。

## 7. 架构说明

一个普通内容页的结构只有四层，设计工作就是给这四层定规矩，而不是每页重新发明：

| 层 | 内容 | 设计上要定的事 |
| --- | --- | --- |
| 顶栏 | 站名、导航链接 | 站名最醒目，导航链接字号一致、间距一致、当前页有区分 |
| 英雄区 | 主标题、一句话介绍、一个主操作 | 主标题最大，一句话只讲一件事，主操作全页只有一个 |
| 内容区 | 卡片列表或文章段落 | 卡片样式统一，标题、正文、链接的层级在所有卡片里一致 |
| 页脚 | 次要链接、版权说明 | 字号最小、颜色最浅，不抢正文的风头 |

在这四层之上，还有一套所有页面共用的规矩，叫设计令牌，放在第 11 节的 `design-tokens.css` 里：颜色、字号、间距、圆角、阴影、焦点样式各只定义一次，各页面只引用令牌、不各自写死数值。这样改主色时改一个地方，全站一起变；不这样做的话，改一次颜色要翻遍所有页面，还容易漏改一处，导致同一个按钮在不同页面长得不一样。

设计流程的顺序也固定：先定目标和用户（这个页面是给谁看、看完要做什么），再定层级（先看什么、后看什么），再定色彩和字体，再定间距和组件样式，最后才写代码。顺序反过来——先挑一个好看的组件、再往里面塞内容——最容易做出“每个局部都好看、整页不知道讲什么”的页面。

## 8. 操作前检查

动手前按下面清单逐项打勾，缺哪项补哪项：

1. 浏览器能打开本地 `.html` 文件，开发者工具能打开并切换到手机模式；
2. 编辑器能保存纯文本文件，文件名后缀是 `.html`，不是 `.txt`；
3. 已经想好练习页的主题和一句话介绍，写在纸上或记事本里，不要边写代码边想文案；
4. 已经决定主色和辅助色各一个，颜色数量先定死，不要写着写着又加第三、第四种主色；
5. 已经确认正文与背景的对比度目标是 4.5:1，准备用浏览器工具核对，而不是凭感觉；
6. 已经准备好第 14 节的三遍验证时间：桌面宽度一遍、窄窗口一遍、只用键盘一遍。

## 9. 逐步操作

按下面八步做，每一步做完再做下一步，不要跳步：

1. **定目标和用户。** 用一句话写下来：这个页面是给谁看的、看完要他做什么。例如“给第一次来的人介绍本站的三个栏目，看完点进任意一篇去读”。目标超过一个的，先砍到一个。
2. **定层级。** 在纸上画四层：顶栏、英雄区、内容区、页脚；英雄区只留一个主标题、一句话、一个主操作；内容区先定卡片数量，再定每张卡片里标题、正文、链接的顺序。
3. **定色彩。** 主色一个、辅助色一个、文字色两个（正文深色、辅助浅色）、背景色一个、边框色一个，写进令牌文件。主色只用在主操作和少量强调上，不要满页铺主色。
4. **定字体。** 主标题、正文、辅助文字各定一个字号和行高，正文行高不小于 1.6，段落之间用间距分开，不用首行缩进混排。
5. **定间距。** 用一套间距刻度，例如 8px、16px、24px、32px、48px，卡片内边距、卡片之间、区块之间都从这套刻度里选，不要每个地方各写一个随手数字。
6. **写页面。** 按第 10 节的完整示例结构写，先写 HTML 语义结构（header、nav、main、section、article、footer），再写样式；样式先写令牌变量，再写各层样式，最后写移动端媒体查询。
7. **做反馈和焦点。** 给链接和按钮加悬停样式，给所有可聚焦元素加 `:focus-visible` 样式（键盘 Tab 到哪里、哪里就有明显的框），表单出错时除了变色还要有文字说明。
8. **三遍验证。** 按第 14 节做桌面、窄窗口、键盘三遍，改完一处再走一遍，不要只改不验。

## 11. 完整配置文件

第 10 节的示例为了“复制一个文件就能打开”，把样式写在了页面内部。真正做多页面网站时，不要每个页面各抄一份样式，要把共用的规矩抽出来存成一个令牌文件，各页面引用它。下面就是完整的令牌文件，存放在 `design-tokens.css`，与练习页放在同一个文件夹里，页面里用 `<link rel="stylesheet" href="design-tokens.css">` 引入后，第 10 节样式里的变量名可以直接沿用。

```css
:root {
  --color-primary: #9a3412;
  --color-text: #111827;
  --color-muted: #475569;
  --color-bg: #ffffff;
  --color-card: #f8fafc;
  --color-border: #e2e8f0;
  --color-link: #1d4ed8;
  --space-1: 8px;
  --space-2: 16px;
  --space-3: 24px;
  --space-4: 32px;
  --space-5: 48px;
  --font-body: system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
  --font-size-h1: 32px;
  --font-size-h2: 20px;
  --font-size-body: 16px;
  --font-size-small: 14px;
  --line-height-heading: 1.4;
  --line-height-body: 1.7;
  --radius-card: 8px;
  --radius-button: 6px;
  --focus-width: 3px;
  --touch-min: 44px;
}
```

注意：令牌文件里只有变量定义，没有任何页面结构样式；页面结构样式（顶栏怎么排、卡片怎么摆）仍然写在各页面自己的样式里。这样改颜色、改字号、改间距刻度时只改这一个文件，改布局时改对应页面，两边不会互相牵连。

## 12. 每个关键配置项的解释

| 配置项 | 值 | 用在哪里 | 为什么这样定 |
| --- | --- | --- | --- |
| `--color-primary` | `#9a3412` | 主操作按钮、焦点框、少量强调 | 全页只用在一个主操作上，深橙色在白色背景上醒目，且与白色文字的对比要过 4.5:1 的目标，见第 14 节核对方法 |
| `--color-text` | `#111827` | 正文、标题 | 接近黑色的深灰，比纯黑柔和，在白色背景上对比充足 |
| `--color-muted` | `#475569` | 辅助说明、卡片正文、页脚 | 比正文浅一级，表示“次要信息”，但仍然是深色，不用浅灰，避免对比不够 |
| `--color-bg` / `--color-card` | `#ffffff` / `#f8fafc` | 页面背景 / 卡片背景 | 卡片比页面背景略深一点，卡片边界不用加粗边框也能看出来是一组 |
| `--color-border` | `#e2e8f0` | 卡片边框、顶栏与页脚分隔线 | 浅灰只做分隔，不抢内容 |
| `--color-link` | `#1d4ed8` | 正文里的链接 | 蓝色是用户最熟悉的“可点”信号，且在白色背景上对比充足；链接还要有下划线或悬停变化，不能只靠颜色区分 |
| `--space-1` 至 `--space-5` | 8px、16px、24px、32px、48px | 全部间距 | 固定刻度，不随手写数字；小间距管组内，大间距管区块之间 |
| `--font-size-h1` / `--font-size-h2` / `--font-size-body` | 32px / 20px / 16px | 主标题 / 卡片标题 / 正文 | 三级之间差距明显，扫一眼就知道谁是标题、谁是正文 |
| `--line-height-body` | 1.7 | 正文行高 | 长文行高不小于 1.6，行与行不打架，读长段不累 |
| `--radius-card` / `--radius-button` | 8px / 6px | 卡片圆角 / 按钮圆角 | 全站只用这两个圆角值，不出现每个组件各一个圆角的情况 |
| `--focus-width` | 3px | 键盘焦点框宽度 | 键盘 Tab 到哪里，哪里就有一圈够粗的框，1px 的框在屏幕上很容易看漏 |
| `--touch-min` | 44px | 导航链接、按钮的最小高度 | 手指点按的目标不能太小，44px 是移动端常用的下限，低于它就容易点错 |

## 13. 执行结果示例

按第 10 节复制出来的页面，在桌面宽度下应该长这样：顶栏左边是站名、右边是三个导航链接；英雄区一个大标题、一句话介绍、一个深橙色主按钮；下面三张卡片并排，每张卡片都是标题在上、正文在中、蓝色链接在下；页脚一行小字、颜色最浅。

窗口缩窄到 700px 以下时，三张卡片变成单列上下排，顶栏改纵向，站名在上、导航在下，主标题字号从 32px 变成 26px，但内容顺序不变：还是先标题、后介绍、后按钮、后卡片、最后页脚，没有任何内容因为变窄而消失或被盖住。

只用键盘操作时，按 Tab 的顺序应该是：跳过链接、导航三个链接、主按钮、三张卡片的链接、页脚；每停到一个可点元素上，都有一圈深橙色焦点框；按到跳过链接时它会出现在左上角，按回车直接跳到正文，不用再按一长串 Tab 才能越过导航。

如果上面三条里任何一条对不上，先看第 16 节的排查表，不要直接改颜色或字号——大多数“看着不对”其实是结构或顺序错了，不是颜色选错了。

## 14. 成功验证

按下面五步验证，每一步都要亲手做一遍，不要只看代码觉得对：

1. **桌面宽度打开。** 用浏览器打开第 10 节的页面，确认主标题最大、主操作只有一个、三张卡片样式一致、页脚最浅；如果发现两个一样醒目的按钮，先砍掉一个。
2. **缩窄窗口。** 把窗口拖到手机宽度，或用开发者工具切到手机模式，确认卡片变单列、顶栏纵向、没有横向滚动条、文字没有被裁掉。
3. **键盘走一遍。** 从地址栏开始按 Tab，确认顺序是跳过链接、导航、主按钮、卡片链接、页脚，每个停留点都有明显焦点框；按 Shift+Tab 能原路返回。
4. **对比度核对。** 用浏览器开发者工具的对比度检查，逐项核对正文、辅助文字、按钮文字、链接与背景的对比度，正文目标是 4.5:1；哪一项不达标就调深文字色或调浅背景色，不要调到“看起来差不多”就停。
5. **手机模式点一遍。** 在手机模式下点导航链接和主按钮，确认手指点得准、没有点到旁边的链接；主按钮离屏幕边缘留有间距，不会被手指挡住文字。

五步全部通过才算本篇做完；任何一步不通过，回到第 9 节对应的步骤改，改完重新走五步，不要只重做不通过的那一步——改颜色可能影响对比度，改布局可能影响键盘顺序。

## 15. 常见错误

| 错误 | 现象 | 为什么错 |
| --- | --- | --- |
| 满页都是重点 | 标题、按钮、横幅全都又大又亮 | 没有排优先级，用户不知道先看哪一个，等于没有层级 |
| 颜色越加越多 | 主色三个、辅助色四个，越写越乱 | 颜色一多就失去“主色只强调一件事”的作用，改起来也处处漏改 |
| 浅灰正文 | 正文用很浅的灰色，看着“高级” | 对比度不够，阳光下、老花眼、普通屏幕上都读不清，4.5:1 的目标就是防这个 |
| 只靠颜色传信息 | 出错只变红、成功只变绿，没有文字 | 色弱用户分不出来，必须同时有文字或形状变化 |
| 焦点框被去掉 | 为了“好看”把 `outline` 设成 `none`，又没补别的焦点样式 | 键盘用户彻底不知道自己停在哪一处，等于把键盘路堵死了 |
| 悬停才给信息 | 重要说明只在鼠标悬停时出现 | 触屏没有悬停，键盘用户也够不着，信息等于不存在 |
| 触摸目标太小 | 链接挤在一起，手指一点就点错 | 桌面鼠标点得准不代表手指点得准，移动端目标至少 44px 高 |
| 标题当装饰用 | 为了字号大而用标题标签包正文，或跳级用标题 | 标题结构是给屏幕阅读器和搜索引擎读的路标，乱用等于路标指错路 |
| 段落挤成一团 | 行高太小、段间距为零，长文读两行就累 | 留白是分组和呼吸的手段，不是浪费 |
| 移动端直接缩小桌面版 | 手机上整页缩成一小条，要双指放大才能读 | 移动端要改布局（单列、纵向顶栏），不是把桌面版等比缩小 |

## 16. 故障排查

| 现象 | 可能原因 | 排查与修复 |
| --- | --- | --- |
| 卡片在窄窗口下还是三列，出现横向滚动条 | 媒体查询没生效，或断点写错，或 `viewport` 元标签漏写 | 先查 `<meta name="viewport">` 是否在 `<head>` 里，再查媒体查询的宽度条件是否写成了 `min-width`，最后在开发者工具里看 `.cards` 的实际列数 |
| 键盘 Tab 看不到焦点 | 样式里把 `outline` 设成了 `none`，又没写 `:focus-visible` | 恢复焦点样式：给 `a`、`button` 写 `:focus-visible` 的 `outline`，不要只写 `:focus` 去掉它 |
| 按钮在手机上点不准 | 按钮高度小于 44px，或两个可点元素挨得太近 | 把按钮和导航链接的最小高度设到 44px，可点元素之间留出间距 |
| 页脚比正文还醒目 | 页脚字号或颜色与正文相同甚至更深 | 页脚字号改小一级、颜色改成辅助色，页脚只是收尾，不是第二主角 |
| 主标题和卡片标题分不清 | 两级标题字号差距太小，或粗细相同 | 拉开字号差距，主标题 32px、卡片标题 20px，差距要一眼看出来 |
| 链接和正文分不清 | 链接只比正文颜色略深，没有下划线也没有悬停变化 | 链接加下划线或悬停下划线，不要只靠颜色区分 |
| 改了主色，全站没一起变 | 各页面各自写死了颜色值，没有走令牌文件 | 把颜色值全部改成引用 `design-tokens.css` 里的变量，改色只改令牌文件 |
| 跳过链接按 Tab 不出现 | 跳过链接的初始位置写错，或 `:focus` 样式没写 | 检查 `.skip-link` 平时在视野外、聚焦时回到左上角，且 `href` 指向正文容器的 `id` |

## 17. 安全注意事项

设计里的“安全”不是指服务器安全，而是指不要用设计手段误导或伤害用户，清单如下：

1. **不要做诱导式设计。** 不要把“取消”按钮做得灰小难找、把“同意”按钮做得又大又亮来诱使用户点同意；不要用默认勾选让用户在没注意时订阅或付费；不要用倒计时、假库存制造不必要的紧迫感。这些做法即使一时提高了点击，也是在消耗信任，出了问题很难挽回。
2. **不要只靠颜色传达关键信息。** 出错、成功、警告、必填，除了颜色还要有文字或图标；色弱用户、黑白打印、阳光下的屏幕都会让“只看颜色”失效。
3. **不要在页面里藏重要信息。** 价格、退订方法、隐私说明不要只放在悬停提示、折叠角落或很浅的小字里；用户要找的东西，应该在正常阅读顺序里就能找到。
4. **表单只问必要的信息。** 练习页或内容页的表单不要多问电话、地址等与当前目标无关的个人信息；问得越少，用户越愿意填，出问题的影响面也越小。
5. **不要自动播放声音或视频。** 自动播放会吓到用户、消耗流量，在公共场合尤其不合适；需要播放的一律由用户点播放才开始。
6. **外链要让人看得出是外链。** 跳到别的网站的链接，文字或附近说明要讲清，不要让用户以为还在本站内；这一点在内容页里尤其重要。

## 18. 回滚和恢复

设计改坏了不要硬改，要能一键回到改之前的样子，做法如下：

1. **改之前先备份。** 把原来的 `.html` 文件复制一份，名字后加 `-bak`，例如 `ux.html` 改之前先存一份 `ux-bak.html`；令牌文件同样先存一份 `design-tokens-bak.css`。
2. **一次只改一类。** 改颜色只改令牌文件，改布局只改页面样式，不要颜色、字号、布局一起改；改完立刻按第 14 节验证，验证不过就知道是哪一类改坏了。
3. **回滚步骤。** 把备份文件改回原名覆盖当前文件，刷新浏览器确认回到改前样子；如果已经把令牌文件引入了多个页面，先把各页面的 `<link>` 指回备份的令牌文件，再逐页验证。
4. **恢复后复查。** 回滚不是结束，要再走一遍第 14 节的桌面、窄窗口、键盘三遍，确认回滚本身没有引入新的错位或丢失；确认无误后再决定要不要重新改，重新改时换一种更小步的做法。
