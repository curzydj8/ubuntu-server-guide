## 1. 本章目标

读完并动手做完本篇，你能：

1. 写出一个标题、描述、规范链接、社交分享卡片都齐全的页面 `head`；

## 6. 技术原理

### 搜索引擎是怎么读页面的

搜索引擎派爬虫（比如 Baiduspider、Googlebot、Bingbot）来抓你的页面，流程是三步：

1. **抓取**：爬虫按链接爬到你的页面，下载 HTML——它下载的是 HTML 源代码，不是浏览器渲染后的截图，所以 `head` 里的标题、描述、规范链接，它第一时间就能看到；
2. **理解**：它按标签理解结构：`h1` 是主题，`h2` 是节，`article` 是一篇文章，`alt` 是图片内容，`a` 的文字是链接目标的描述；
3. **索引和排名**：理解后存进索引库，用户搜索时按相关性、质量、权重排序展示。

所以 SEO 的 HTML 部分，本质就是“把你想让搜索引擎理解的东西，用它能理解的标签写清楚”：标题写清楚、描述写清楚、结构写清楚、图片写清楚、链接文字写清楚。堆关键词、藏白字、复制别人文章，这些不是“优化”，是作弊，查出来会被降权甚至移出索引。

### 无障碍是怎么回事

无障碍（Accessibility，常缩写成 a11y，a 和 y 之间有 11 个字母）不是“给少数人做的额外功能”，而是“让所有人都能用页面”：

- 视障用户用屏幕阅读器“听”页面：它按标签顺序读，`h1`、`nav`、`main`、`alt`、`label` 都是它理解页面的依据；
- 运动障碍用户用键盘操作页面：Tab 键要能走到每一个可操作的元素（链接、按钮、输入框），焦点要看得见，顺序要合理；
- 色弱用户、低视力用户、手机强光下看屏幕的用户，都需要足够的颜色对比度和可放大的字号。

一个常见的误解是“无障碍 = 加一堆 ARIA”。恰恰相反：**先用正确的原生标签，再考虑 ARIA**。原生 `<button>` 自带键盘操作和读屏语义，`<div onclick>` 再加 ARIA 也补不齐；原生 `<label>` 自带关联，`aria-label` 只是备用。ARIA 是“原生标签不够用时的补充”，不是“不用原生标签的借口”。

## 7. 架构说明

本篇完整示例的页面结构，仍然是 WEB-01 的骨架，只在两个地方做了 SEO 和无障碍的补齐：

```text
head（本篇重点之一）
├── title（搜索结果标题）
├── meta description（搜索结果摘要）
├── link canonical（规范链接：告诉搜索引擎“这个页面以哪个地址为准”）
├── meta robots（告诉爬虫“能不能索引、能不能跟随链接”）
├── Open Graph（og:title、og:description、og:image：分享到社交平台时显示的标题、摘要、配图）
├── Twitter Card（twitter:card 等：分享到 X/Twitter 时的卡片样式）
└── script JSON-LD（结构化数据：告诉搜索引擎“这是一篇文章”）

body（本篇重点之二）
├── a.skip-link（跳过导航，直接跳到正文：键盘用户和读屏用户的第一站）
├── header / nav（和 WEB-01 相同）
├── main#main-content（正文，skip-link 跳到的目标）
│   └── article（文章，带发布时间、作者信息）
├── aside（补充内容）
└── footer（页脚）
```

`head` 里这些东西用户在页面上看不到，但搜索引擎和社交平台全靠它们；`body` 里那个跳过链接平时也不显眼，键盘用户按 Tab 时才会出现——“看不到”不等于“没用”，这两处正是本篇的价值所在。

## 9. 逐步操作

1. 在练习文件夹里新建文件 `seo-a11y.html`；
2. 把第 10 节的完整代码从头到尾复制进去；
3. 保存，UTF-8，双击用浏览器打开；
4. 先按 Tab 键：第一个焦点应该落在“跳到正文内容”这个链接上，按回车，页面应该跳到正文那一节——这是键盘无障碍的第一道检查；
5. 再看页面本身：标题、导航、正文、文章、侧栏、页脚是不是和 WEB-01 的骨架一样齐全；
6. 再看源代码（右键 → 查看源代码）：`head` 里是不是有 `title`、`description`、`canonical`、`og:`、`twitter:` 和 JSON-LD，缺一个就对照第 12 节补上；
7. 把 `title` 里的文字改成你自己的站名，保存刷新，看浏览器标签页是不是跟着变了；
8. 把图片的 `alt` 删掉再刷新，看图片位置是不是变成一片空白、读屏软件也读不出任何信息——再把 `alt` 加回去，这一步是让你亲眼看到 `alt` 不是可有可无的。

## 10. 完整代码

下面是本篇的完整示例，没有省略号，复制下来就是一个能打开的页面。存放位置：练习文件夹里的 `seo-a11y.html`。注意：示例里的网址 `https://example.com/`、`https://example.com/images/cover.jpg` 是占位地址，正式上线时要改成你自己的真实域名和真实图片地址；`canonical`、`og:url`、`og:image` 写错地址比不写更糟，搜索引擎会按你写的错误地址去索引。

## 11. 完整配置文件

本篇不需要服务器配置文件，也不需要构建工具。唯一的文件就是第 10 节的 `seo-a11y.html`，放在练习文件夹根目录。

和本篇相关的两个服务器端文件，本篇只讲“页面里要配合什么”，不讲“怎么生成和部署它们”，那是 OPS-01 阶段的事，这里先记下结论，避免以后混淆：

- `sitemap.xml`：告诉搜索引擎“站里有哪些页面”，放在网站根目录，搜索引擎按它去抓；
- `robots.txt`：告诉爬虫“哪些能抓、哪些别抓”，也放在网站根目录，`meta robots` 是针对单个页面的，`robots.txt` 是针对全站的，两者不要写反。

## 12. 每个关键标签和属性的解释

### SEO：head 里那些用户看不到、搜索引擎全靠它们的东西

| 标签 / 属性 | 作用 | 容易错的地方 |
|---|---|---|
| `<title>` | 搜索结果里显示的标题，也是浏览器标签页的文字 | 每个页面都要不一样，不要全站都叫“首页”；长度控制在一句话内，太长搜索结果会截断；不要堆关键词，堆了反而降权 |
| `<meta name="description">` | 搜索结果里显示的摘要 | 摘要要一句话说清这页是讲什么的，吸引人点进来；不写它，搜索引擎会自己从正文里截一段，截出来的不一定是你想让别人看到的那段 |
| `<link rel="canonical">` | 规范链接：告诉搜索引擎“这个页面以哪个地址为准” | 同一篇文章能用 `https://example.com/a` 和 `https://example.com/a?from=home` 两个地址打开时，必须写 `canonical`，否则搜索引擎会当成两篇重复文章，分散权重；`canonical` 的地址必须是真实能打开的地址，写错比不写更糟 |
| `<meta name="robots" content="index, follow">` | 告诉爬虫“能不能索引这页、能不能跟随这页的链接” | `noindex` 是“不要收录这页”，`nofollow` 是“不要跟随这页的链接”，只在确实不想被收录的页面（比如登录后的页面、重复的筛选页）上用，正常文章页不要写 `noindex`，写了就等于主动放弃收录 |
| Open Graph（`og:title`、`og:description`、`og:image`、`og:url`、`og:type`） | 分享到微信、微博、Facebook 等平台时显示的标题、摘要、配图、链接 | `og:image` 的图片要是真实存在的、尺寸够大的图，写错地址分享出去就是一张裂图；`og:title` 和 `<title>` 可以不一样，分享标题可以写得更口语一点，但不要标题党 |
| Twitter Card（`twitter:card` 等） | 分享到 X/Twitter 时的卡片样式，`summary_large_image` 是大图卡片 | 只写 `og:` 不写 `twitter:`，X 上也能显示，但样式不一定是你想要的大图卡片；两个都写最稳 |
| JSON-LD 结构化数据 | 用 JSON 告诉搜索引擎“这是什么类型的内容”：文章、产品、问答、活动等 | JSON 必须是合法的 JSON，少一个逗号、多一个括号，整段都会失效；类型要和页面内容一致，文章页写 `Article`，不要把产品页也写成 `Article`；`datePublished`、`author`、`image` 这些字段能写就写，写得越全，搜索引擎理解得越准 |
| `<time datetime="2026-11-03">` | 给机器读的时间，`datetime` 是标准格式，标签里的文字是给人读的 | 只写“昨天”“上周”这种相对时间，搜索引擎和读屏软件都不知道具体是哪天 |

### 无障碍：让键盘和屏幕阅读器能用的东西

| 标签 / 属性 | 作用 | 容易错的地方 |
|---|---|---|
| 跳过链接（`<a href="#main-content">跳到正文内容</a>`） | 键盘用户按 Tab 时第一个落到的链接，按回车直接跳过导航，到正文 | 跳过链接的目标 `id`（这里是 `main-content`）必须存在，且目标元素要能获得焦点或本身就是 `main`；跳过链接不要用 `display: none` 藏起来，藏起来键盘用户也看不到、按不到了，正确做法是平时视觉上弱化、获得焦点时显示（样式在 CSS 阶段讲，本篇先保证链接存在且能跳） |
| `aria-label="主导航"` | 给没有可见文字说明的区域一个名字，读屏软件会读出“主导航” | 一个页面有多个 `nav` 时，每个都要有不同的 `aria-label`（主导航、页脚导航），否则读屏用户分不清哪个是哪个；只有一个 `nav` 时写不写都可以，写了更清楚 |
| `aria-describedby="email-error"` | 把输入框和错误提示绑在一起，读屏软件读到输入框时，会顺带读出错误提示 | `aria-describedby` 的值要等于错误提示元素的 `id`，对不上就绑不上；错误提示不要只用红色区分，色弱用户看不出红绿区别，文字本身就要说清楚错在哪 |
| `aria-live` | 告诉读屏软件“这块内容会动态变化，变了要读出来”，比如表单提交后的提示、搜索结果数 | 只在确实会动态变化的区域用，不要全页都加，加多了读屏软件会不停打断用户 |
| `role` | 给没有原生语义的元素一个角色，比如 `role="dialog"` | 能用原生标签（`button`、`nav`、`main`、`dialog`）就不要用 `div` + `role` 冒充，原生标签自带键盘和读屏行为，`role` 补不齐 |
| 键盘操作 | 所有可操作的元素（链接、按钮、输入框）都要能用 Tab 走到、用回车或空格操作 | 用 `div onclick` 做按钮是最常见的无障碍错误：鼠标能点，键盘按不到，读屏软件也不知道这是个按钮；改成 `<button>` 就全解决了 |
| `tabindex` | 控制 Tab 顺序：`tabindex="0"` 是“按自然顺序能走到”，`tabindex="-1"` 是“Tab 走不到，但程序可以让它获得焦点”（比如跳过链接的目标） | 不要用正数 `tabindex="1"`、`tabindex="2"` 手动排顺序，页面一改顺序就全乱了，还会让读屏顺序和视觉顺序不一致；绝大多数情况下根本不需要写 `tabindex`，自然顺序就是对的 |
| 颜色对比度 | 文字和背景的对比度要够，正常文字至少 4.5:1，大字至少 3:1 | 只用颜色区分状态（比如“红色是错、绿色是对”）是不够的，色弱用户分不出来，状态必须同时用文字说明 |
| 图片 `alt`（WEB-02 已讲，本篇再强调一次） | 图片的替代文字，读屏软件读的就是它 | 有信息的图片 `alt` 要说清楚图里是什么；装饰性图片 `alt=""`，表示可以跳过；`alt` 写成“图片”“image”等于没写 |
| 链接文字 | 链接的文字要说明点过去是什么 | 不要全写“点击这里”“更多”“了解更多”，读屏用户单独听链接列表时，十个“点击这里”分不清哪个是哪个；写成“查看 HTML 表单教程”这种能独立理解的文字 |
| 视频字幕（`<track kind="captions">`） | 给视频加字幕，听障用户、静音环境下看视频的用户都需要 | 有对白的视频没有字幕，就是不完整的无障碍；字幕文件是 WebVTT 格式（`.vtt`），本篇只讲概念，字幕制作和部署在媒体阶段以后再细讲 |

双击打开后，你应该看到：

- 浏览器标签页显示“如何写出结构清晰的网页 | 我的学习笔记站”；
- 按 Tab 键，第一个焦点落在“跳到正文内容”上，按回车，页面跳到正文那一节；

- 右键 → 查看源代码，`head` 里能找到 `title`、`description`、`canonical`、`og:title`、`og:image`、`twitter:card` 和那段 JSON-LD，一项都不少；
- 图片位置显示 `alt` 文字或你的封面图，下面有图注。

如果你在源代码里找不到 JSON-LD，检查两点：是不是把 `<script type="application/ld+json">` 写进了 `body` 而不是 `head`（写进 `body` 也能工作，但按本篇的规范放在 `head` 里）；JSON 里是不是少了逗号或括号，少了整段都会失效。

## 14. 成功验证

按顺序做，全部通过才算本篇完成：

1. **标题验证**：浏览器标签页和查看源代码里的 `<title>` 一致，且每个页面（如果你做了多个练习页）的标题都不一样；
2. **描述验证**：源代码里有 `meta description`，一句话说清这页是讲什么的，不是关键词堆砌；
3. **键盘验证**：从页面顶部开始按 Tab，能依次走到跳过链接、导航链接、正文链接、表单按钮（如果有），没有哪一步“按 Tab 没反应、焦点丢了”；
4. **跳过验证**：在跳过链接上按回车，页面跳到正文，接下来按 Tab 应该继续在正文里走，而不是回到导航开头；
5. **读屏要点验证**（不用真的装读屏软件，用检查代替）：图片都有 `alt`、表单输入框都有 `label`、表格有 `caption` 和 `scope`、链接文字都能独立理解——这四项在 WEB-01、WEB-02 里已经做过，本篇再通查一遍；
6. **可选的分享预览验证**：把练习页部署到一个能公开访问的地址后，分享到社交平台，看标题、摘要、配图是不是你写的那套；本地文件分享出去是看不到卡片的，这一步要等部署阶段，不影响本篇。

## 15. 常见错误

| 错误 | 现象 | 改法 |
|---|---|---|
| 全站标题都一样 | 搜索结果里十个页面标题都叫“首页”，用户分不清该点哪个 | 每个页面写自己的标题，格式建议“文章标题 \| 站名” |
| 描述堆关键词 | 摘要读起来像关键词清单，用户不想点，搜索引擎也可能不采用 | 摘要写一句话，说清这页是讲什么的、适合谁看 |
| `canonical` 写错地址 | 搜索引擎按错误地址索引，正确地址反而没权重 | `canonical` 必须是真实能打开的、你希望被索引的那个地址 |
| 正常文章页写了 `noindex` | 文章怎么都搜不到 | 删掉 `noindex`，只在确实不想被收录的页面上用 |
| JSON-LD 写错 JSON | 结构化数据整段失效，搜索引擎认不出文章类型 | 用 JSON 校验工具先校验一次，再贴进页面；注意逗号和括号 |
| 图片 `alt` 空着或写“图片” | 读屏用户听不到图片信息，图片加载失败时一片空白 | 有信息的图片写清楚图里是什么，装饰图写 `alt=""` |
| 链接文字全是“点击这里” | 读屏用户听链接列表时分不清哪个是哪个 | 链接文字写成能独立理解的描述，比如“查看 HTML 表单教程” |
| 用 `div onclick` 做按钮 | 鼠标能点，键盘按不到，读屏软件不知道这是按钮 | 改成 `<button>`，原生按钮自带键盘和读屏行为 |
| 只用颜色区分对错 | 色弱用户分不出红绿，不知道哪项错了 | 状态同时用文字说明，错误提示写清楚错在哪、怎么改 |
| 正数 `tabindex` 手动排序 | 页面一改顺序就全乱，读屏顺序和视觉顺序不一致 | 删掉正数 `tabindex`，用自然顺序，特殊情况只用 `0` 和 `-1` |
| 跳过链接用 `display: none` 藏起来 | 键盘用户按 Tab 也找不到它，等于没有 | 跳过链接要能被 Tab 走到，平时视觉弱化、获得焦点时显示即可（样式在 CSS 阶段讲） |
| 堆关键词、藏文字、复制别人文章 | 短期内可能有点排名，查出来降权甚至移出索引 | 不要碰作弊手段，标题、描述、结构写清楚就是正道 |

## 16. 故障排查

- **搜索结果标题不是你写的标题**：搜索引擎有权按正文重写标题，常见原因是你的 `title` 太长、太堆砌、和正文不符；先把 `title` 改成一句话、和正文主题一致，再等爬虫重新抓取（不是改完立刻生效）。
- **分享出去没有配图**：先查 `og:image` 的地址能不能直接在浏览器里打开，再查图片尺寸是不是太小、格式是不是不常见（JPG、PNG 最稳），再查是不是写成了相对路径——分享卡片要求绝对地址（`https://` 开头）。
- **按 Tab 焦点丢了**：检查是不是用了 `div onclick` 做按钮、是不是给某个元素写了 `tabindex="-1"` 又指望 Tab 能走到它、是不是把跳过链接藏起来了。
- **读屏软件读不出表单错误**：检查 `aria-describedby` 的值和错误提示的 `id` 是不是一模一样，差一个字母就绑不上。
- **JSON-LD 不生效**：先校验 JSON 格式，再检查 `type` 是不是 `application/ld+json`，再检查是不是把 JSON 写进了 HTML 注释里。
- **改了 `title` 刷新没变**：确认保存了，再按 Ctrl+F5 强制刷新，排除浏览器缓存；搜索结果里的标题更新要等爬虫重新抓取，不是浏览器刷新的事。

## 17. 安全注意事项

- 结构化数据里不要写真实用户的隐私信息（真实姓名、电话、地址、邮箱），示例用占位数据就够了；作者信息写站名或笔名即可。
- `canonical`、`og:url`、`og:image` 必须写你自己的域名，不要复制别人的地址，否则流量和权重会导向别人的站。
- 不要为了 SEO 在页面里藏文字（白字、白底、移出屏幕外的大段关键词），这是作弊，查出来会被处罚；无障碍需要的“视觉弱化、焦点时显示”不是藏文字，两者要分清：前者是骗搜索引擎，后者是给键盘用户用的正常做法。
- 第三方分享、统计、广告代码（以后 OPS 阶段会讲）要确认来源可信，不要贴来路不明的脚本，脚本一旦贴进页面，就等于给了对方在你的页面上运行代码的权限。

## 18. 回滚和恢复

本篇和 WEB-01、WEB-02 一样，没有服务器、没有数据库、没有配置改动，回滚就是：

- 改错了：编辑器里 Ctrl+Z 撤销，或把第 10 节的完整代码重新复制覆盖一次；
- 文件删错了：重新新建 `seo-a11y.html`，把第 10 节代码再贴一遍；
- `title`、`description`、`canonical` 写错了：改回正确的文字和地址，保存即可，搜索引擎那边要等下次抓取才更新，不是立刻生效；
- 没有任何线上内容会被影响，因为本篇文件只在你的练习文件夹里，还没有部署到 crozz.me。
