## 6. 技术原理

### 6.1 域名解析：从输入域名到拿到 IP

访客输入域名后，解析链是：浏览器缓存 → 系统缓存 → 递归 DNS（如运营商或公共 DNS）→ 域名授权 DNS（你域名所在的解析服务）→ 返回记录。关键概念：

- **A 记录**：域名指向 IPv4 地址；**AAAA 记录**：域名指向 IPv6 地址；**CNAME 记录**：域名指向另一个域名（常用于指向 CDN 提供的加速域名）。
- **TTL**：解析结果在各级缓存里能存活的秒数。TTL 越长，改解析后全球生效越慢；TTL 越短，查询越频繁。上线前提前把 TTL 调小，是上线流程里最重要的一步准备工作。
- **生效不是瞬时的**：你刚在控制台改完记录，访客那边可能还拿着旧缓存，这是正常现象，不是“解析没配好”。判断方法见第 14 节，不要一改完就反复改。

### 6.2 HTTPS：证书证明“你连对了服务器”

HTTPS 做两件事：加密浏览器和服务器之间的流量，让中间网络偷看不到、改不动内容；用证书证明访客连到的确实是你的服务器（证书里的域名必须与访问的域名一致，否则浏览器会报不安全）。握手成功后，浏览器地址栏出现锁形标志才算 HTTPS 可用。

证书签发与自动续期的具体操作见 09-web-hosting/05，本文不再重复。本篇只讲：证书在上线流程里要在 DNS 生效之后申请（ACME 验证需要通过域名找到你的服务器），以及上线后怎么验证证书（第 14 节）。

### 6.3 CDN：把静态内容放到离访客近的节点

CDN 的原理是：访客先访问离他近的边缘节点，节点有缓存就直接返回（命中，响应头里常能看到 `HIT` 字样），没有缓存才回源站取一次（回源），取回来后按缓存规则存一份，下次再有人要就直接给。关键概念：

- **回源**：边缘节点向你的源站请求内容；回源地址、回源协议（HTTP 还是 HTTPS）、回源 Host 都要在 CDN 里配对，否则会出现 502。
- **缓存规则**：哪些文件缓存、缓存多久，按路径或文件类型配。HTML 一般缓存时间短（内容常变），图片、CSS、JS、字体可以缓存久一点。
- **刷新与预热**：内容更新后要让旧缓存失效叫刷新（也叫 purge）；提前把热点内容推到边缘节点叫预热。刷新不是瞬时生效的，也要等一会儿再验证。

### 6.4 HSTS：一旦开启，浏览器会记住“只用 HTTPS”

HSTS（HTTP Strict Transport Security）是服务器通过响应头告诉浏览器“这个域名以后只用 HTTPS 访问”。浏览器记住后，即使访客手动输入 `http://` 也会自动跳到 `https://`。好处是防降级劫持；风险是：一旦开启，短时间内无法反悔（见第 17、18 节），所以上线时要先用短时间，再逐步加长。

## 7. 架构说明

上线后有两种常见形态，本文以第二种为主线讲全流程（第一种是第二种去掉 CDN 的简化版）：

| 形态 | 请求路径 | 适用场景 |
| --- | --- | --- |
| 无 CDN 直连源站 | 访客 → DNS → 源站 Nginx → 应用 | 访客集中、流量小、刚上线验证阶段 |
| CDN 在前、源站在后 | 访客 → DNS（CNAME 到 CDN）→ CDN 边缘节点 → 回源 → 源站 Nginx → 应用 | 访客分散、静态资源多、想省源站带宽 |

各层负责什么、不负责什么：

- DNS 只负责“域名指向哪”，不负责内容对不对、快不快。
- CDN 只负责“静态内容加速与缓存”，不负责你的应用逻辑对不对；动态接口一般不缓存，直接回源。
- 源站 Nginx 只负责“收到请求后按配置返回或转发”，证书、跳转、安全头都在这一层落到实处。
- 证书只负责“加密与身份”，不负责解析、不负责缓存。

## 9. 逐步操作

### 9.1 备份现有配置

在服务器上执行（普通用户加 `sudo`，家目录）：

```bash
sudo cp -a /etc/nginx /etc/nginx.bak.$(date +%F)
ls -ld /etc/nginx.bak.*
```

备份做完再改配置，这是回滚的底气。

### 9.2 确认源站可用

在服务器本机执行：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/
```

应看到 `200`（或你站点首页的正常状态码）。源站本机都不通时，不要先去改解析——解析改了也只会把错误暴露给所有人。

### 9.3 备案：只在满足条件时才做

结论直接引用 NET-02，不重新编一套说法：

- 只有域名解析指向中国内地服务器、并开通 Web 服务时，才需要在服务器所在的接入商处做 ICP 备案。
- 解析指向中国香港、中国澳门、中国台湾或境外其他国家和地区服务器的，不需要做中国大陆 ICP 备案。
- 只买域名、不解析到大陆服务器、不对外提供服务，就不触发备案；备案不是域名的属性，而是“域名 + 大陆服务器 + 对外提供互联网信息服务”三件事凑齐之后才触发的一道手续。
- 备案的具体流程以主管部门与接入商当场公布的要求为准，本文不写死某家接入商的页面步骤。

### 9.4 加解析记录

在域名解析控制台加记录（字段名以你所用厂商为准，含义通用）：

| 主机记录 | 记录类型 | 记录值 | TTL（秒） | 说明 |
| --- | --- | --- | --- | --- |
| @ | A | 203.0.113.10 | 300 | 主域名指向源站 IPv4，示例地址须换成你的真实 IP |
| www | A | 203.0.113.10 | 300 | www 子域名同样指向源站 |
| www | CNAME | example.com | 300 | www 用 CNAME 指回主域名时，二选一，不要与上面的 www 的 A 记录同时存在 |

注意三条铁律：同一条主机记录、同一类型不要同时配两个互相冲突的值；CNAME 的记录值末尾按厂商要求决定是否加圆点（有的厂商自动补，有的要求手动加，保存后以解析结果为准）；示例里的 `203.0.113.10` 是文档示例保留地址，不是真实服务器地址。

如果要走 CDN：先在 CDN 控制台添加加速域名并拿到 CDN 分配的加速域名（例如 `example.com.cdn.example.net`，以厂商实际分配的为准），再把解析改成 CNAME 指向它，而不是直接指向源站 IP。CDN 的回源地址填源站 IP 或源站域名，回源协议与回源 Host 按第 12 节的解释配对。

### 9.5 等解析生效并验证

改完解析不要马上断言成功。先查权威解析，再查公共解析（命令与判断方法见第 14 节），确认新记录在多个解析器上都出现后，再往下走。

### 9.6 申请证书并开启 HTTPS

解析生效后，按 09-web-hosting/05 的方法申请证书并配好自动续期。证书申请里的域名验证需要通过域名找到你的服务器，所以这一步必须放在解析生效之后，不能颠倒顺序。

### 9.7 配好 80 跳转与安全头

把第 10.3 节的 Nginx 配置放到服务器上（存放路径见第 11 节），检查语法、重载，让所有 HTTP 请求跳转到 HTTPS，并按第 17 节的取舍先给 HSTS 一个短时间。

### 9.8 接入 CDN 并验证缓存

CDN 接入后做两件事验证：连续请求两次同一静态文件，第一次可能是 `MISS`（回源），第二次应为 `HIT`（命中缓存）；改一次静态文件后做一次缓存刷新，再请求确认拿到的是新内容。验证方法见第 14 节。

### 9.9 上线后监控

上线不是改完解析就结束：接下来 24 小时内留意证书到期提醒、CDN 回源错误率、源站负载三项，任何一项异常都按第 16 节分层定位，不要凭感觉改配置。

### 10.1 上线检查清单（按顺序、可打勾，每一项都有验证方法）

| 序号 | 检查项 | 验证方法（不要只写“检查一下”） |
| --- | --- | --- |
| 1 | 源站本机 HTTP 可用 | 服务器上执行 `curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/`，应为 `200` 或你站点正常的首页状态码 |
| 2 | 域名实名已通过 | 解析控制台里实名状态为通过；未通过时解析会被暂停，先办实名再上线 |
| 3 | 80 与 443 端口已放行 | 安全组与服务器防火墙两处都确认放行；从外网执行 `curl -s -o /dev/null -w "%{http_code}\n" http://example.com/` 能通才算数 |
| 4 | 旧配置已备份 | `/etc/nginx.bak.日期` 目录存在且能列出文件（见第 9.1 节） |
| 5 | TTL 已提前调小并过期 | 解析记录的 TTL 显示为 300 秒左右，且距离上次改 TTL 已超过旧 TTL 的时长 |
| 6 | 备案判断已做 | 按第 9.3 节确认：大陆服务器 + 对外服务才需要备案，境外服务器不需要大陆 ICP 备案 |
| 7 | 解析记录已加对 | `dig example.com A` 与 `dig www.example.com A`（或 CNAME）返回的值与控制台填写的一致 |
| 8 | 解析在多个解析器上生效 | 换两个公共 DNS 再查一次，结果一致才算生效，只查一个解析器不算 |
| 9 | 证书已申请且域名匹配 | 浏览器打开 `https://example.com/` 出现锁形标志；`curl -v https://example.com/` 的证书域名与访问域名一致 |
| 10 | HTTP 已强制跳转 HTTPS | `curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://example.com/` 应为 `301 https://example.com/` |
| 11 | HSTS 已按短时间开启 | 响应头里有 `strict-transport-security`，且 `max-age` 先用短时间（见第 12、17 节），不要一上来就写一年 |
| 12 | CDN 缓存已命中 | 同一静态文件连续请求两次，第二次响应头显示缓存命中（厂商字段名不同，含义是“命中”） |
| 13 | 缓存刷新已验证 | 改一次静态文件并刷新缓存后，再请求拿到的是新内容，不是旧缓存 |
| 14 | www 与主域名行为一致 | `https://www.example.com/` 与 `https://example.com/` 都能打开，且跳转关系符合你的设计（统一到一处，不要两处各说各话） |
| 15 | 动态接口未被错误缓存 | 登录、下单、提交类接口每次请求都回源，不会把 A 用户的数据缓存给 B 用户看 |
| 16 | 证书自动续期已配好 | 按 09-web-hosting/05 的续期方法确认定时任务存在且上次演练成功 |
| 17 | 监控已就位 | 证书到期提醒、CDN 回源错误、源站负载三项至少有一处能收到告警 |

### 10.2 反面例子（只写在表格与行内代码里，不要照抄）

| 错误做法 | 为什么错 |
| --- | --- |
| 解析记录里同时给 `www` 配 A 记录又配 CNAME | 同一条记录两种指向互相冲突，解析结果不可预测 |
| 证书还没申请就先在 CDN 里开强制 HTTPS | 回源与边缘都拿不到合法证书，访客看到的是证书错误而不是你的网站 |
| 上线当天才把 TTL 从 86400 改成 300 就立即切换 | 旧 TTL 还没过期，各地缓存仍按旧 TTL 存着旧记录，切换要等旧 TTL 过期才真正生效 |
| HSTS 一上来就写 `max-age=31536000; includeSubDomains; preload` | 一旦有子域名还没准备好 HTTPS，或以后想暂时关 HTTPS，浏览器在一年内都会强制 HTTPS，无法立即撤销 |
| 把动态接口也配成缓存一小时 | 登录态、购物车、订单数据会被缓存串给别人看，属于安全事故，不是性能优化 |

### 10.3 Nginx HTTPS 完整配置

下面是一份完整的 Nginx 配置，适用场景：主域名 `example.com` 与 `www.example.com` 统一提供 HTTPS 服务，静态文件由 Nginx 直接返回，`/api/` 转发到本机后端。存放路径见第 11 节，证书路径、域名、后端端口须换成你自己的真实值。

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name example.com www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    root /var/www/example.com;
    index index.html;

    add_header Strict-Transport-Security "max-age=86400" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    location / {
        try_files $uri $uri/ =404;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location ~* \.(css|js|png|jpg|jpeg|gif|svg|woff|woff2)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

检查与重载（普通用户加 `sudo`）：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

`nginx -t` 通过后再重载；通不过时不要重载，先按报错行号改配置——重载一个语法错误的配置会让 Nginx 拒绝加载新配置，旧配置虽然还在跑，但你的改动等于没生效，容易误以为“已经上线了”。

## 11. 完整配置文件（注明存放路径）

| 文件 | 存放路径 | 说明 |
| --- | --- | --- |
| Nginx 站点配置 | `/etc/nginx/sites-available/example.com.conf` | 全文就是第 10.3 节的那份配置；启用方法是软链接到 `/etc/nginx/sites-enabled/`，Ubuntu/Debian 系适用 |
| Nginx 配置备份 | `/etc/nginx.bak.日期/` | 第 9.1 节备份的整个配置目录，回滚时从这里恢复 |
| 证书文件 | `/etc/letsencrypt/live/example.com/` | ACME 自动签发后生成，`fullchain.pem` 与 `privkey.pem` 的路径须与第 10.3 节一致；私钥文件权限只给 root 读 |
| 上线检查脚本 | `/usr/local/bin/launch-check.sh` | 下面的完整脚本，跑一次就能把第 10.1 节里能用命令验证的项过一遍 |

上线检查脚本全文（存放路径 `/usr/local/bin/launch-check.sh`，`chmod +x` 后执行，域名须换成你自己的真实域名）：

```bash
#!/bin/bash
DOMAIN="example.com"
echo "== HTTP 跳转 =="
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" "http://${DOMAIN}/"
echo "== HTTPS 状态 =="
curl -s -o /dev/null -w "%{http_code}\n" "https://${DOMAIN}/"
echo "== 证书到期 =="
echo | openssl s_client -servername "${DOMAIN}" -connect "${DOMAIN}:443" 2>/dev/null | openssl x509 -noout -enddate
echo "== 解析 =="
dig +short "${DOMAIN}" A
dig +short "www.${DOMAIN}" A
echo "== 静态缓存（请求两次，对比缓存命中字段）=="
curl -s -I "https://${DOMAIN}/styles.css" | grep -i -E "cache|hit|miss" || echo "未返回缓存相关响应头，请按厂商字段名确认"
curl -s -I "https://${DOMAIN}/styles.css" | grep -i -E "cache|hit|miss" || echo "未返回缓存相关响应头，请按厂商字段名确认"
```

脚本说明：脚本只做检查，不改任何配置；`styles.css` 只是示例静态文件路径，换成你站点真实存在的静态文件；CDN 各厂商的缓存命中响应头字段名不同（有的叫 `X-Cache`，有的叫 `cf-cache-status` 之类），脚本用 `grep` 宽泛匹配，拿到响应头后以厂商文档的字段含义为准。

## 12. 每个关键配置项的解释

### 12.1 Nginx 配置项

| 配置项 | 含义 | 写错的后果 |
| --- | --- | --- |
| `listen 80;` 与 `return 301 https://$host$request_uri;` | 80 端口的请求全部 301 跳转到同域名的 HTTPS 地址，`$host` 保留访客访问的域名，`$request_uri` 保留路径与查询串 | 写成固定域名会把 `www` 也跳到主域名（如果你本意是保留 www，这就是错）；漏写 `$request_uri` 会把带路径的访问都跳到首页 |
| `listen 443 ssl;` | 443 端口启用 TLS | 漏写 `ssl` 时 Nginx 会把 TLS 握手当成明文 HTTP 处理，浏览器报协议错误 |
| `ssl_certificate` 与 `ssl_certificate_key` | 证书链文件与私钥文件的路径 | 路径写错时 `nginx -t` 直接报错；私钥权限放得太开时有泄露风险，只给 root 读 |
| `ssl_protocols TLSv1.2 TLSv1.3;` | 只允许 TLS 1.2 与 1.3，关掉老旧的不安全版本 | 加上 TLS 1.0/1.1 会让老旧的不安全协议重新可用，不符合安全要求 |
| `ssl_prefer_server_ciphers off;` | TLS 1.3 下由客户端选密码套件，服务端不强制 | 在 TLS 1.2 为主的环境里含义不同，照抄前要确认你的 TLS 版本组合 |
| `add_header Strict-Transport-Security "max-age=86400" always;` | HSTS，告诉浏览器 86400 秒（一天）内只用 HTTPS 访问本域名；`always` 表示错误响应也带这个头 | 上线初期 `max-age` 写一年是常见错误（见第 10.2 节），先短后长；`includeSubDomains` 与 `preload` 见第 17 节的取舍 |
| `add_header X-Content-Type-Options "nosniff" always;` | 禁止浏览器猜测文件类型，防止把文本文件当脚本执行 | 不写时某些老浏览器会按内容猜测类型，有被利用的风险 |
| `add_header X-Frame-Options "SAMEORIGIN" always;` | 只允许同源页面用 iframe 嵌套本页，防点击劫持 | 写成 `DENY` 时连你自己的同源嵌套也会被禁，按需二选一 |
| `try_files $uri $uri/ =404;` | 先找文件、再找目录、都没有就返回 404 | 漏写 `=404` 时 Nginx 会把不存在的路径继续往下走，可能返回错误的默认页 |
| `proxy_pass http://127.0.0.1:8080;` | `/api/` 的请求转发到本机 8080 端口的后端 | 后端端口写错时访客看到 502，排查先看后端在不在 8080 上监听 |
| `proxy_set_header X-Forwarded-Proto $scheme;` | 告诉后端原始请求是 HTTP 还是 HTTPS | 漏写时后端可能以为请求是 HTTP，于是自己又跳一次 HTTP，造成跳转循环 |
| `expires 7d;` 与 `add_header Cache-Control "public";` | 静态文件让浏览器与 CDN 缓存 7 天 | 把 HTML 也配成 7 天时，文章更新后访客一周都看不到新内容；HTML 的缓存时间要单独配短 |

### 12.2 DNS 与 CDN 术语

| 术语 | 含义 | 容易踩的坑 |
| --- | --- | --- |
| TTL | 解析结果在各级缓存里的存活秒数 | 上线当天才调小等于没调，要提前 24–48 小时调 |
| 回源 | CDN 边缘节点向源站取内容 | 回源地址、回源协议、回源 Host 三者有一个配错就是 502 |
| 回源 Host | 回源时 CDN 向源站发送的 Host 头 | 源站按域名区分站点时，回源 Host 必须是你源站认识的域名，不能写成 CDN 的加速域名 |
| 缓存键 | 决定“两次请求是不是同一份缓存”的标识，一般含域名、路径、查询串 | 查询串参与缓存键时，带随机参数的请求永远命中不了缓存；不参与时，带参数的动态内容可能被错误共用 |
| 刷新（purge） | 让边缘节点的旧缓存失效 | 刷新不是瞬时生效，刷新完马上验证可能仍看到旧内容，等一会儿再查 |
| 预热 | 提前把热点内容推到边缘节点 | 预热只对可缓存的静态内容有效，动态接口不要预热 |

301 https://example.com/

HTTP/2 200

要点：状态码 200、HSTS 头存在且 `max-age` 是你配的短时间，说明 HTTPS 与安全头都已生效。

## 14. 成功验证

按顺序做完下面每一项，才算上线成功；只做其中一两项不算：

1. **解析验证**：`dig example.com A` 与 `dig www.example.com A`（或 CNAME）返回的值与控制台一致；再换两个公共 DNS 查一次，结果一致才算生效。
2. **跳转验证**：`curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://example.com/` 应为 `301 https://example.com/`，且带路径的访问（例如 `http://example.com/about/`）跳转后路径没有丢。
3. **证书验证**：浏览器打开 `https://example.com/` 出现锁形标志，点开证书确认域名是你自己的域名、到期日在未来；`curl -v https://example.com/` 的 TLS 握手没有报错。
4. **内容验证**：首页、文章页、登录页各打开一次，确认没有混合内容警告（HTTPS 页面里混了 HTTP 的图片、脚本、样式时浏览器会报，表现是锁形标志变灰或直接告警）。
5. **CDN 验证**：同一静态文件连续请求两次，第二次缓存命中；改一次静态文件并刷新缓存后，再请求拿到的是新内容。
6. **www 与主域名验证**：`https://www.example.com/` 与 `https://example.com/` 都能打开，且跳转关系符合你的设计。
7. **动态接口验证**：登录、提交类接口每次请求都回源，不会把 A 用户的数据缓存给 B 用户看（用两个账号各请求一次，对比返回内容是否串了）。
8. **续期验证**：按 09-web-hosting/05 的方法确认自动续期定时任务存在，且演练成功过一次。
9. **监控验证**：证书到期提醒、CDN 回源错误、源站负载三项至少有一处能收到告警，而不是等访客来报。

## 15. 常见错误

| 现象 | 最可能的原因 | 先查哪一项 |
| --- | --- | --- |
| 域名打不开，解析查不到 | 实名未通过导致解析被暂停，或记录根本没保存成功 | 解析控制台的实名状态与记录列表 |
| 有的地方能打开，有的地方打不开 | TTL 还没过期，各地缓存仍拿着旧记录 | 等旧 TTL 过期后再查，不要反复改记录 |
| 浏览器报证书域名不匹配 | 证书里的域名与访问的域名不一致（例如证书只有 `example.com`，却用 `www.example.com` 访问） | 证书的域名列表里有没有你访问的那个域名 |
| 浏览器报证书不受信任 | 证书链不完整（只配了证书没配中间证书），或证书已过期 | `ssl_certificate` 配的是不是 `fullchain`，到期日是不是已过 |
| HTTPS 页面里部分图片、样式加载不出来 | 混合内容：HTTPS 页面引用了 HTTP 地址的资源 | 浏览器开发者工具的控制台，看哪条资源走了 HTTP |
| HTTP 跳转死循环 | 后端以为请求是 HTTP，自己又跳一次（`X-Forwarded-Proto` 没传对），或 CDN 与源站互相跳转 | 先看 `proxy_set_header X-Forwarded-Proto` 与 CDN 的回源协议是否配对 |
| CDN 一直 502 | 回源地址、回源协议、回源 Host 三者有配错的，或源站 443/80 没放行 | 先绕过 CDN 直接访问源站，源站通、CDN 不通就是回源配置问题 |
| 改了静态文件，访客仍看到旧的 | 缓存没刷新，或刷新了但还没生效，或浏览器本地缓存 | 先刷新 CDN 缓存、等一会儿，再清浏览器缓存复查 |
| 换了新服务器，旧解析迟迟不换 | 上线前没提前调小 TTL，旧 TTL 还没过期 | 下次上线提前 24–48 小时调 TTL；这次只能等 |

## 16. 故障排查

排查按分层顺序来，不要一上来就改配置：

1. **先定层**：`dig` 查解析（DNS 层）、`curl -v` 看 TLS 握手（证书层）、绕过 CDN 直接访问源站（CDN 层还是源站层）、看 Nginx 与应用日志（源站层）。四层里先找到哪一层开始出错，再在那一层里找原因。
2. **DNS 层**：`dig example.com A` 与换公共 DNS 再查的结果不一致时，是缓存未过期，等，不要改；权威解析本身返回错值时，才是控制台记录填错了，改控制台。
3. **证书层**：`curl -v https://example.com/` 的握手报错先看证书域名与到期日；握手通但浏览器仍告警时，看混合内容与证书链完整性。
4. **CDN 层**：源站直接访问通、经 CDN 不通时，查回源地址、回源协议、回源 Host；CDN 缓存行为异常时，查缓存规则与缓存键（查询串是否参与缓存键）。
5. **源站层**：Nginx 报错先跑 `nginx -t` 看行号；502 先看后端进程在不在监听端口上；应用报错看应用日志，不要只看 Nginx 日志。
6. **绕过 CDN 测源站的方法**：在你自己电脑的 hosts 文件里把域名临时指向源站 IP（只改你自己电脑，不改公共解析），测完立即删掉这行。hosts 改了不删时，你以后看到的永远是源站，CDN 的问题永远测不出来。

## 17. 安全注意事项

- **HSTS 的取舍**：上线初期 `max-age` 先用一天（86400），稳定运行一段时间后再逐步加长；`includeSubDomains` 会让所有子域名也被强制 HTTPS，子域名还没准备好 HTTPS 时不要加；`preload` 一旦提交到浏览器预加载列表，撤销要走浏览器厂商的流程、耗时以月计，没有十足把握不要提交。
- **私钥保护**：证书私钥文件只给 root 读，不要提交到代码仓库、不要贴到聊天记录与工单里；私钥一旦泄露，吊销旧证书、重新签发、换私钥三步都要做，只换证书不换私钥等于没换。
- **TLS 版本**：只开 TLS 1.2 与 1.3，不要为了兼容老设备把 TLS 1.0/1.1 加回来；老设备打不开时，升级设备或浏览器才是正解。
- **不要把动态接口缓存**：登录态、购物车、订单、个人数据一律不缓存；缓存规则按路径写白名单（只缓存明确的静态路径），不要写“全部缓存、动态除外”这种容易漏的反向规则。
- **源站不要裸奔**：CDN 在前时，源站最好只接受 CDN 回源与你自己的管理 IP，至少不要把源站 IP 公开写在页面里；源站 IP 一旦公开，访客绕过 CDN 直接打源站，CDN 的防护与加速都等于没有。
- **备案合规**：大陆服务器对外服务时备案是前置手续，不要先上线、后补备案；境外服务器不需要大陆 ICP 备案，但仍要遵守服务器所在地的法律（结论引用 NET-02，流程以主管部门与接入商当场公布的要求为准）。

## 18. 回滚和恢复

上线出问题时，按下面顺序回滚，不要慌着删配置：

1. **解析回滚**：把解析记录改回旧值（旧 IP 或旧 CNAME），TTL 保持 300 秒，等缓存过期；改解析本身不删记录，只改值，删记录会让域名直接解析不到。
2. **CDN 回滚**：CDN 出问题时先把解析改回直连源站（A 记录指向源站 IP），确认源站直连可用后，再慢慢查 CDN 的回源配置；不要在 CDN 配置里反复试错，访客看到的全是试错结果。
3. **Nginx 回滚**：用第 9.1 节的备份恢复配置，`cp -a /etc/nginx.bak.日期/. /etc/nginx/` 后跑 `nginx -t`、重载；恢复前先确认备份目录的日期就是上线前的那一份。
4. **HSTS 回滚的特殊性**：HSTS 一旦被浏览器记住，服务端改配置不能立即让访客的浏览器忘掉，只能把 `max-age` 改成 0 再等访客访问一次、或等原来的 `max-age` 自然过期。这就是第 17 节要求上线初期先用短时间的原因。
5. **证书回滚**：证书出问题时先确认是证书本身错（域名、过期、链不完整）还是配置错（路径、权限）；配置错改配置，证书错重新签发，不要把旧的过期证书又贴回去。
6. **回滚后验证**：回滚完按第 14 节重做一遍验证，确认回到上线前的可用状态后，再复盘问题根因，不要回滚完就直接再次上线。
