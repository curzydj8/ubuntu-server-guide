# 第 11 部分：数据库安装、管理与高可用

应用宕机可以重启，数据丢了往往没有第二次机会。本部分在 Ubuntu Server 22.04 / 24.04 LTS 上，把 MySQL / MariaDB、PostgreSQL、Redis、MongoDB 从「装得上」做到「管得住、扛得住、恢复得回来」，最后补齐高可用与容器化。先学 MySQL 的方法论，后面三类数据库会顺很多。

## DBA 生产四原则

!!! danger "一、安全防线"
    禁空密码，禁用 `root` 跑应用，3306 等数据库端口绝不直接对公网全开。分层防御：`bind-address` 只听内网或本机，安全组与 UFW 只放行明确来源，强密码与最小权限兜底。任何一层偷懒，都会被逐个击穿。

!!! warning "二、参数有据"
    每个关键数值都要能说出计算过程，例如缓冲池按物理内存 50%～70% 扣除系统开销估算，连接数对上应用连接池总和。本部分只给带公式的示例值，不写「按需调整」。

!!! tip "三、备份含还原演练"
    导出成功只证明文件写出来了，不证明能恢复。合格流程必须含文件校验、恢复到临时实例验证，以及至少一次「全量恢复 + binlog 重放」演练。

!!! note "四、最小权限"
    备份账号只读、应用账号只碰业务库、管理账号单独用并限来源。宁可分开授权，也不要一次给 `ALL PRIVILEGES ON *.*`——权限收不回来时，往往数据已经出事。
