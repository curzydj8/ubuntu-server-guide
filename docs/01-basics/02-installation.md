# 系统安装

## 一、概述与使用场景

本章完成 Ubuntu Server 从镜像到可登录系统的全过程，包括校验镜像、制作启动盘、使用 Subiquity 安装器逐屏安装、以及磁盘分区与 LVM 配置。安装是唯一一次能低成本决定磁盘布局、文件系统和卷管理方式的机会，系统一旦投入运行，再改分区和卷结构往往需要停机、迁移数据甚至重装，因此本章把每一步的判断依据都写清楚，而不是只给点击顺序。

为什么要认真对待安装环节，有三个现实原因。第一，镜像完整性决定系统可信度，下载中断或镜像被篡改时装出的系统可能随机报错或自带风险，校验哈希只需要一分钟，却能排除一整类难以定位的故障。第二，分区方案决定未来的扩容能力，根分区太小会被日志和软件撑满，数据和系统混在一块磁盘上会让备份和迁移互相牵制，而 LVM 能把这些问题变成在线可调整的配置。第三，安装选项决定初始安全面，例如是否安装 OpenSSH、是否创建具备 sudo 权限的管理员、是否开启磁盘加密，这些选择在安装后逐个补改的成本明显更高。

不认真安装的典型后果包括：跳过校验导致安装中途失败并浪费数小时排查硬件；分区时把整块大盘只分出一小部分给根卷，装完才发现可用空间远小于磁盘容量；没有勾选 OpenSSH 导致装完无法远程登录，只能再次回到机房接显示器；UEFI 与传统启动模式混用导致引导失败。以上问题在本章都有对应的预防动作和验证命令。

本章适用于物理服务器、家用主机和虚拟机三种场景。虚拟机安装可以跳过制作启动盘，直接挂载镜像文件启动，其余 Subiquity 步骤与物理机完全一致。示例中的磁盘容量以 500 GB 单盘为例讲解，读者按自己磁盘的实际容量等比例调整即可。

## 二、环境准备与前置条件

版本基线：使用 Ubuntu Server 22.04 LTS 或 24.04 LTS 的 amd64 镜像，文件名形如 ubuntu-22.04-live-server-amd64.iso 和 ubuntu-24.04-live-server-amd64.iso，从 Ubuntu 官方发布页或官方认证镜像站获取，并同时获取同目录下的 SHA256SUMS 文件用于校验。ARM 机器改用 arm64 镜像，安装步骤相同。

硬件最低配置：2 核 CPU、4 GB 内存、25 GB 可用磁盘。生产建议 4 核以上、8 GB 以上内存、80 GB 以上磁盘，并确认机器支持 UEFI 启动。制作启动盘需要一个 8 GB 以上 U 盘，制作过程会清空 U 盘全部数据，提前把其中文件复制到别处保存。

权限与外设条件：物理机需要能进入固件设置修改启动顺序的权限，需要显示器和键盘完成首次安装，虚拟机需要虚拟化平台的控制台权限。网络条件：安装阶段建议接通有线网络并能通过 DHCP 获得地址，安装器会用它同步时间和下载少量更新，没有网络也能离线安装，但装完后必须先联网完成更新。

需要提前定好的四项规划，请在开机安装前写在纸上或文档里：主机名、管理员用户名、磁盘方案、是否使用 LVM。管理员示例用户名使用 opsadmin，主机名示例使用 server01。密码不在文档中记录明文，应在安装时输入强密码并保存到团队密码库。

!!! warning "版本之间的安装器差异"

    20.04 使用的 Subiquity 早期版本界面选项顺序与现在稍有不同，且默认文件系统和内核更旧，本章不再覆盖 20.04 的安装画面。22.04 与 24.04 的 Subiquity 操作逻辑一致，主要差别是 24.04 的安装器响应更快、存储页面默认布局稍有调整，按本章步骤在两个版本上都能完成安装。

## 三、手把手操作步骤

### 步骤一：校验镜像完整性

在下载镜像的电脑上执行校验。Linux 终端中进入镜像所在目录后执行第一条命令，把输出的哈希值与 SHA256SUMS 文件中同名文件那一行逐字对比；也可以执行第二条命令自动比对，输出末尾显示 OK 才算通过。

```bash
sha256sum ubuntu-24.04-live-server-amd64.iso
sha256sum --check --ignore-missing SHA256SUMS
```

第二条命令的期望输出如下。

```text
ubuntu-24.04-live-server-amd64.iso: OK
```

若显示 FAILED，说明文件不完整或与官方发布不一致，删除后重新下载，不要尝试用它安装。Windows 上可用 PowerShell 的 Get-FileHash 命令得到同样的哈希值再人工比对。

### 步骤二：制作启动盘

Linux 下推荐用 dd 制作。先插入 U 盘并执行 `lsblk` 确认设备名，下例中 U 盘为整个设备 sdb，务必按容量核对，不要把系统盘写成目标。执行写入前不需要备份配置，但必须再次核对设备名，因为 dd 会直接覆盖目标设备全部内容，没有确认提示。

```bash
lsblk -o NAME,SIZE,MODEL,TRAN
sudo umount /dev/sdb1
sudo dd if=ubuntu-24.04-live-server-amd64.iso of=/dev/sdb bs=4M status=progress oflag=sync
sync
```

参数逐项讲解：`if` 是输入文件即镜像路径；`of` 是输出设备，必须写整盘设备名 sdb，不能写分区名 sdb1；`bs=4M` 表示每次读写 4 MB，兼顾速度和稳定性；`status=progress` 显示实时进度；`oflag=sync` 要求数据真正落盘后才返回，避免拔盘时数据未写完。Windows 用户可用 Rufus 制作，在 Rufus 中选择 U 盘设备、选择镜像文件、分区类型选 GPT、目标系统选 UEFI，其余保持默认后开始写入。macOS 和 Windows 通用的图形工具 balenaEtcher 也可以完成同样工作，操作为选镜像、选 U 盘、开始烧录三步。

### 步骤三：从 U 盘启动并进入安装器

把启动盘插入目标机器，开机时按固件启动菜单键进入启动设备列表，常见按键为 F11、F12 或 Esc，以机器开机画面提示为准。在列表中选择带有 UEFI 字样的 U 盘条目启动，进入 GRUB 菜单后选择 Try or Install Ubuntu Server 并回车，等待 Subiquity 安装器加载完成。安装器全程用键盘操作，方向键移动光标，Tab 在字段间切换，空格切换勾选，回车确认。

### 步骤四：Subiquity 逐屏配置

第一屏语言选择 English，服务器保持英文语言环境有利于日志检索和排障，键盘布局保持 English US 不变。第二屏安装类型选择 Ubuntu Server，不要选 Minimized，精简版会缺少大量常用工具，后期补装反而更费时。第三屏网络连接保持 DHCP 自动获取，记下画面显示的网卡名和临时地址，静态地址留到下一章用 Netplan 统一配置，在安装器里手填静态地址填错一项就要反复返工。第四屏代理地址留空，镜像地址保持默认，装完后再按第四章的方法替换为就近镜像。

第五屏存储配置是核心，详细方案见步骤五和步骤六，先在此选择 Use an entire disk 或 Custom storage layout。第六屏确认磁盘变更摘要，核对设备名和容量无误后确认，此后磁盘原有数据会被清除。第七屏填写个人资料，字段逐项如下表。

| 字段 | 示例值 | 填写要求 |
|------|--------|----------|
| Your name | Ops Admin | 管理员显示名，可用英文 |
| Your server name | server01 | 主机名，只用小写字母数字和连字符 |
| Pick a username | opsadmin | 登录用户名，创建后默认加入 sudo 组 |
| Choose a password | 安装时现场输入 | 强密码，长度至少 12 位并混合字符类型 |
| Confirm your password | 与上一行一致 | 两次输入必须完全相同 |

第八屏 SSH 设置必须勾选 Install OpenSSH server，不勾选则装完没有远程登录服务。导入密钥选项可以从 GitHub 或本地文件导入公钥，新手可先跳过并在后续章节补学密钥登录。第九屏 Featured Server Snaps 全部不勾选，保持系统干净，需要的服务在系统装好后按需安装，版本更可控。确认后安装器开始复制文件，完成后选择 Reboot Now，出现提示拔出 U 盘的画面时先拔盘再回车。

!!! tip "安装中途断电或卡住的处理"

    安装复制文件阶段若进度长时间不动，先看磁盘指示灯和安装器右上角的日志入口，不要直接断电。只有确认安装器报错退出后才重新启动并重走安装流程，因为磁盘此时尚未完成分区和引导写入，重装不会叠加出双重系统。

### 步骤五：磁盘分区方案设计

UEFI 模式下必须有 EFI 系统分区。推荐的单盘手动方案如下表，适用于 500 GB 磁盘并使用普通分区加 ext4 的简单结构。

| 挂载点 | 大小 | 文件系统 | 用途说明 |
|--------|------|----------|----------|
| /boot/efi | 1 GB | FAT32 | 存放 UEFI 引导文件，必须标记为 EFI System Partition |
| /boot | 2 GB | ext4 | 存放内核和引导菜单，多内核并存时不紧张 |
| / | 100 GB | ext4 | 系统、软件和配置的根分区 |
| /data | 剩余全部空间 | ext4 | 业务数据独立分区，与系统互不撑满 |
| swap | 4 GB | swap 或交换文件 | 内存不足时的缓冲，服务器不依赖休眠时 4 GB 足够 |

在 Custom storage layout 页面中依次选中空闲空间并创建上表分区，每个分区创建时都要选对挂载点和文件系统。根分区不要小于 50 GB，日志、容器镜像和软件缓存的增长速度通常超出新手预期。不单独分出 /home 是服务器的常见做法，因为服务器上用户主目录不是主要数据来源，把空间留给根分区和数据分区更实用。

### 步骤六：LVM 配置方法与空间分配

打算长期运行并可能扩容的机器推荐使用 LVM。在存储页勾选 Set up this disk as an LVM group 后，安装器会创建卷组 ubuntu-vg 和根逻辑卷 ubuntu-lv。LVM 的三层概念为物理卷 PV、卷组 VG、逻辑卷 LV，理解为磁盘先交卷组统一管理，再从卷组中切出逻辑卷给文件系统使用，扩容时只需给卷组加盘并扩大逻辑卷，不必改分区表。

必须注意一个默认行为：安装器使用 LVM 时可能只把卷组的一部分分给根逻辑卷，剩余空间留在卷组中待分配。这不是丢盘，而是预留。安装完成后按第四节的方法检查并按需扩大。若在安装器里走自定义 LVM，可直接把根逻辑卷设为计划大小，例如 100 GB，并保留部分卷组空间给未来的数据卷和快照。启用 LVM 加密的选项会要求每次开机输入解密口令，无人值守自动重启的服务器不要开启，否则重启后会停在解密界面等待人工输入。

安装前最后确认三件事：启动模式是 UEFI、目标磁盘选对、SSH 已勾选。三项无误后再确认安装。

## 四、效果验证与测试

重启进入新系统后，用安装时创建的 opsadmin 用户在控制台登录，依次执行以下命令验证安装成果。

```bash
lsb_release -a
hostnamectl
ip address show
df -h
free -h
lsblk -f
sudo vgdisplay
sudo lvdisplay
systemctl status ssh --no-pager
```

期望输出关键点：版本显示为 22.04 或 24.04 且带有 LTS 字样；`df -h` 中根分区的总容量与规划接近，若使用 LVM 且根卷明显小于磁盘容量，说明卷组还有未分配空间，按下方命令把全部剩余空间扩给根卷并在线扩大文件系统，执行前先用 vgdisplay 确认卷组确有空闲空间。

```bash
sudo lvextend --extents +100%FREE /dev/ubuntu-vg/ubuntu-lv
sudo resize2fs /dev/ubuntu-vg/ubuntu-lv
df -h /
```

`ip address show` 应能看到网卡已获得 DHCP 地址。在另一台电脑上执行远程登录测试，把地址换成服务器实际获得的地址。

```bash
ssh opsadmin@192.0.2.10
```

能输入密码并进入命令行提示符，说明系统、网络和 SSH 三者同时正常。最后执行 `sudo apt update` 确认软件源可达，本章验证即全部通过。

## 五、常见错误与排坑指南

### 错误一：安装完成重启后又进入安装界面

现象：重启后屏幕再次出现安装器语言选择画面，看起来像没有装成功。原因：U 盘还插在机器上且启动顺序中 U 盘优先，固件再次从 U 盘启动。修复方法：关机后拔出 U 盘再开机，系统会从硬盘的 EFI 分区正常引导。若拔盘后提示无可启动设备，说明安装时可能以传统模式启动或引导未写入，需要重新用带 UEFI 字样的 U 盘条目启动并重装。

### 错误二：LVM 安装后根分区只有磁盘一半大小

报错与现象原文片段如下，用户在 500 GB 磁盘上只看到约 100 GB 的根分区。

```text
/dev/mapper/ubuntu--vg-ubuntu--lv  98G   12G   82G  13% /
```

原因：安装器默认只给根逻辑卷分配部分卷组空间，其余空间保留在卷组中，并非磁盘损坏或识别错误。修复命令见第四节的 lvextend 与 resize2fs 两条，执行后再用 `df -h` 复查根分区容量应接近预期。若 vgdisplay 显示卷组也没有剩余空间，则是当初自定义分区时把空间分给了其他卷，按规划决定是否回收，不要直接删除在用的逻辑卷。

### 错误三：dd 写盘后 U 盘容量显示异常或无法启动

现象原文片段如下，写入过程被中断或目标选错分区时常见。

```text
dd: error writing '/dev/sdb': No space left on device
```

原因有三类：U 盘实际容量小于镜像体积、写入时把 of 写成了分区导致空间不足、或者 U 盘本身有坏块。修复方法：先用 `lsblk` 重新核对整盘设备名和容量，换用容量充足的 U 盘，按第三节命令对整盘重新写入，写入完成后执行 `sync` 再拔盘。写盘后的 U 盘在 Windows 下显示容量变小是镜像分区结构造成的正常现象，不要在安装前对它执行格式化。

## 六、生产环境最佳实践与安全建议

第一，安装介质只从官方渠道获取并逐台校验哈希值，把镜像文件名、哈希校验结果和安装日期登记入台账。任何来源不明的镜像都不要用于生产，哪怕它声称集成了驱动和优化。

第二，分区方案在装机前评审而不是装机时即兴决定。系统与数据分离、根分区留足余量、需要弹性扩容时使用 LVM，这三条原则能挡住绝大多数后期磁盘事故。对承载重要数据的机器，优先采用独立数据盘加独立备份盘的布局，不要把备份和源数据放在同一块物理盘上。

第三，初始账号安全在安装当天落实：管理员使用强密码并保存进密码库，确认 root 账户保持默认锁定状态，不为了方便而给 root 设置可登录密码。SSH 在安装时装好后，后续章节会继续完成密钥登录和关闭密码登录等加固，安装当天不要对外网直接开放 22 端口，先置于受控网络内完成初始化。

第四，保留安装证据。每台机器留存一份记录，内容包括系统版本、主机名、管理员用户名、磁盘布局输出和 LVM 布局输出，命令 `lsblk -f` 与 `sudo lvdisplay` 的结果直接存入运维文档。日后扩容、迁移和故障恢复时，这份记录能省去大量现场猜测。

第五，装完立刻更新并重启验证一次。首次登录后执行完整的系统更新，在提示需要重启时择时重启，并确认重启后 SSH 和业务前置服务都能正常起来。一台没有经历过一次完整重启验证的服务器，不要直接交付为生产节点。
