# 第 07 部分：自动化运维与脚本

走到这一部分，单台服务器的日常操作你已经基本掌握，接下来要解决的是规模和重复的问题：同样的巡检、备份、配置变更，一台机器上手工做要十分钟，十台机器就是一整个下午，还特别容易漏、容易错。自动化运维的核心思想只有一句：把做过一次且还会再做的操作，沉淀成可重复执行、可检查结果的脚本和配置，让机器去干重复劳动，人只负责定规则和看异常。

## 本部分地图

本部分共三章，从单机脚本到定时调度，再到多机批量管理，是一条完整的进阶路线：

| 章节 | 文件 | 定位 |
| --- | --- | --- |
| 第 1 章 | 01-shell-scripting.md | 一切自动化的基本功，单机脚本的写法规范和现成范例 |
| 第 2 章 | 02-systemd-timers.md | 让脚本可靠地跑起来，服务托管和定时调度统一交给 systemd |
| 第 3 章 | 03-ansible.md | 从一台到多台，用声明式配置批量管理整个机群 |

## 每章一句话

- **Shell 自动化运维脚本**：讲透严格模式、日志、防重复运行和参数处理，并给出巡检、备份、证书检查三个拿来就能用的完整脚本。
- **Systemd 服务与定时任务**：逐行拆解 unit 文件写法和服务加固选项，再用 Timer 替代老旧的 Cron，定时任务从此可查日志、可补跑、可控随机延迟。
- **Ansible 自动化配置管理**：无代理架构、装完即用，完成清单管理、临时命令、批量初始化 Playbook 和 Role 结构入门，批量运维不再靠逐台登录。

## 推荐学习顺序

请按 01、02、03 顺序学习，不要跳章。脚本写不规范，放到定时任务里只会定时制造故障；定时调度没学好，直接上 Ansible 批量执行，错误也会被批量放大。正确的节奏是：先在第 1 章把单个脚本写对、测好，再在第 2 章让它稳定地定时运行，最后在第 3 章把验证过的操作推广到多台机器。每推广一层，执行前都要先小范围试跑，确认结果无误再扩大范围。

!!! tip "本部分的使用方式"

    本部分的脚本和 Playbook 都是完整可运行的版本，建议原样保存到你的测试机上先跑通一遍，再按注释理解每一行的作用，最后替换成你自己的路径、域名和主机清单。不要在没有读懂的情况下直接把脚本放到生产机器上执行。

## 学完本部分你能做到什么

学完后，你能写出经得起生产检验的运维脚本，能用 systemd 托管自研服务并接管全部定时任务，能用 Ansible 一条命令完成多台新机器的统一初始化。更重要的是，你会养成自动化运维的基本习惯：执行前先备份、变更前先预演、结果必须可验证、失败必须有日志可查。
