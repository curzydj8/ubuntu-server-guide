# 文本与归档命令速查

本章分两组：文本组覆盖日常处理日志与配置最高频的工具（`grep`、`sed`、`awk`、`sort`、`uniq`、`head`/`tail`、`wc`、`cut`、`jq`），归档组覆盖打包压缩（`tar`、`gzip`/`gunzip`、`xz`、`zip`/`unzip`）。文本处理与日志分析的体系化内容见 [集中式日志收集](../06-monitoring/03-logging-stack.md) 与 [时间同步与系统日志](../04-network/04-time-logging.md)，备份策略层面的取舍见 [磁盘健康与备份](../03-storage/04-backup.md)。全文示例面向 Ubuntu 22.04 / 24.04，示例用户为 `ubuntu`、示例地址为文档段 `192.0.2.x`。

## 文本命令

### `grep`

- **用途**：按模式在文件或管道中搜索匹配行，是日志排查的第一工具。
- **语法**：`grep [选项] '模式' 文件`

| 参数 | 说明 |
| --- | --- |
| `-i` | 忽略大小写 |
| `-n` | 显示行号 |
| `-r` | 递归搜索目录 |
| `-v` | 反选：输出不匹配的行 |
| `-E` | 扩展正则，如 `error\|fail` 可写成 `(error\|fail)` 之外支持 `+ ? \|` |
| `--include='*.log'` | 递归时只搜指定文件类型 |

- **示例**：

```bash
grep -inE 'error|fail|denied' /var/log/auth.log | head -30
grep -rn --include='*.conf' '192.0.2.10' /etc/nginx/
```

第一条在认证日志里带行号地找错误类关键词，配合 [日志栈](../06-monitoring/03-logging-stack.md) 做登录失败分析；第二条只在 nginx 的 `.conf` 文件里定位某个旧地址出现的所有配置行。

- **常见错误**：模式里含 `$`、`*` 等字符却不加引号，被 Shell 先展开或报错；养成模式一律单引号包裹的习惯。
- **风险提示**：只读无风险；对超大日志递归搜索前先限定目录与 `--include`，避免全盘扫描拖慢 IO。

### `sed`

- **用途**：流式文本编辑：替换、删除、打印指定行，常用于批量改配置与日志切片。
- **语法**：`sed [选项] '脚本' 文件`

| 参数 | 说明 |
| --- | --- |
| `s/旧/新/` | 替换本行首次匹配，行尾加 `g` 替换全部 |
| `-n '10,20p'` | 只打印第 10–20 行（地址范围） |
| `/模式/d` | 删除匹配行 |
| `-E` | 使用扩展正则 |
| `-i.bak` | 原地修改并保留 `.bak` 备份 |

- **示例**：

```bash
sed 's/192.0.2.10/192.0.2.20/g' /etc/app/app.conf
sed -i.bak 's/192.0.2.10/192.0.2.20/g' /etc/app/app.conf
```

第一条只把结果打印到屏幕预览，不动原文件；确认替换无误后才执行第二条真正落盘，并留下 `app.conf.bak` 可回滚。

- **常见错误**：替换内容包含 `/`（如路径）时不换分隔符导致语法错误，此时改用 `s|旧|新|` 写法。
- **风险提示**：`-i` 直接改原文件且不可自动撤销，务必先不带 `-i` 预览、再用 `-i.bak` 落盘留备份。

### `awk`

- **用途**：按列处理文本：取字段、按条件过滤、做简单汇总统计，管道统计的终点站。
- **语法**：`awk [选项] '条件{动作}' 文件`

| 参数 | 说明 |
| --- | --- |
| `{print $1}` | 打印第 1 列，`$0` 为整行、`$NF` 为最后一列 |
| `-F':'` | 指定分隔符，如处理 `/etc/passwd` 用冒号 |
| `NR` | 当前行号内置变量，常用于跳过表头 |
| `END{...}` | 全部读完后执行的收尾动作，常用于输出汇总 |

- **示例**：

```bash
awk -F: '$3 >= 1000 {print $1, $3}' /etc/passwd
df -h / | awk 'NR==2 {print $5}'
awk '{sum += $1} END {print sum}' /tmp/sizes.txt
```

三例分别是：列出 UID 不小于 1000 的普通用户、取根分区使用率那一列、对一个数字文件逐行求和；awk 的价值在于一条命令同时完成过滤、取列与计算。

- **常见错误**：脚本外层用了双引号，导致 `$1` 被 Shell 先替换成空值；awk 脚本一律用单引号包裹。
- **风险提示**：只读处理无风险；注意 awk 的除法与浮点输出格式，金额类统计不要用它做最终对账。

### `sort`

- **用途**：对行排序，是聚合统计（sort | uniq）与找极值的前置步骤。
- **语法**：`sort [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-n` | 按数值大小排序（不加会把 100 排在 20 前面） |
| `-r` | 逆序，从大到小 |
| `-h` | 按人类可读单位排序，识别 K/M/G |
| `-k N` | 按第 N 列排序，可写 `-k2,2` 限定单列 |
| `-u` | 排序同时去重 |

- **示例**：

```bash
du -h /var/log/* 2>/dev/null | sort -hr | head -5
sort -t: -k3 -n /etc/passwd | tail -5
```

第一条按体积倒序找最大的日志文件；第二条按 `/etc/passwd` 第三列（UID）数值排序看末尾的大 UID 账号，两条都是先 `sort` 把顺序立起来，后续处理才有意义。

- **常见错误**：对数字列不加 `-n`，按字典序得到「10 < 100 < 20」的错误结果。
- **风险提示**：只读无风险；对数 GB 大文件排序会大量占用内存与临时空间，先用 `head` 抽样验证参数。

### `uniq`

- **用途**：去除或统计相邻重复行，与 `sort` 搭配做频次排行。
- **语法**：`uniq [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-c` | 在每行前给出重复次数 |
| `-d` | 只输出重复过的行 |
| `-u` | 只输出未重复的行 |
| `-f N` | 比较时跳过前 N 列 |

- **示例**：

```bash
grep -oE '192\.0\.2\.[0-9]+' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -10
```

这条管道统计访问日志里出现最多的来源 IP：先 `grep` 提取、再 `sort` 让相同 IP 相邻、`uniq -c` 计数、最后数值倒序取前十，缺了中间的 `sort` 结果必然是错的。

- **常见错误**：不 `sort` 直接 `uniq`——它只合并相邻重复行，分散的重复项不会被统计到一起。
- **风险提示**：只读无风险。

### `head` / `tail`

- **用途**：查看文件头尾若干行；`tail -f` 实时跟踪日志新增内容。
- **语法**：`head|tail [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-n N` | 取前/后 N 行，`tail -n +N` 表示从第 N 行开始 |
| `-c N` | 按字节数取 |
| `tail -f` | 跟踪同一文件描述符，文件被截断/重建后可能停更 |
| `tail -F` | 按文件名跟踪，日志轮转（rotate）后自动跟上新文件 |

- **示例**：

```bash
head -n 5 /etc/passwd
tail -n 50 /var/log/syslog
tail -F /var/log/nginx/error.log
```

跟日志排障统一用 `tail -F`：日志被 logrotate 切走生成新文件时，`-f` 会盯着旧文件再无输出，看起来像「服务不写日志了」，实为跟踪失效。

- **常见错误**：用 `tail -f` 跟踪会被轮转的日志而误判服务异常，这正是 `-F` 存在的原因。
- **风险提示**：只读无风险；`tail -f` 会长期占住终端，排障结束记得 `Ctrl+C` 退出。

### `wc`

- **用途**：统计行数、单词数与字节数，快速摸清文件规模。
- **语法**：`wc [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-l` | 只统计行数，最常用 |
| `-w` | 统计单词数 |
| `-c` | 统计字节数 |
| `-L` | 输出最长一行的长度 |

- **示例**：

```bash
wc -l /var/log/auth.log
grep -c 'Failed password' /var/log/auth.log
```

第一条看日志总行数估算体量；第二条是常见变体，用 `grep -c` 直接数匹配行数，比先筛再 `wc -l` 更简洁。

- **常见错误**：用 `wc -l` 数「条目」时漏掉最后一行没有换行符的记录，行数会少 1。
- **风险提示**：只读无风险。

### `cut`

- **用途**：按分隔符或固定列切取字段，做轻量提取时比 awk 更直白。
- **语法**：`cut [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-d':'` | 指定分隔符 |
| `-f N` | 取第 N 列，可写 `-f1,3` 或 `-f2-` |
| `-c N` | 按字符位置切取，如 `-c1-10` |
| `--complement` | 取所选之外的其余列 |

- **示例**：

```bash
cut -d: -f1 /etc/passwd
cut -d' ' -f1,7 /var/log/nginx/access.log | head -5
```

第一条取出全部用户名；`cut` 只认单个字符分隔符，列内结构复杂（多空格、对齐列）时应改用 awk。

- **常见错误**：拿 `cut` 切以空格对齐的命令输出，分隔符不统一导致列错位。
- **风险提示**：只读无风险。

### `jq`

- **用途**：解析与提取 JSON：取字段、遍历数组、格式化输出，处理 API 与程序配置必备。
- **语法**：`jq [选项] '过滤表达式' 文件`

| 参数 | 说明 |
| --- | --- |
| `.key` | 提取字段，如 `.version`；嵌套写 `.a.b` |
| `-r` | 原始输出：字符串不带引号，可直接给脚本用 |
| `.[]` | 遍历数组每个元素 |
| `-e` | 按查询结果设置退出码，方便脚本判断 |

- **示例**：

```bash
jq -r '.database.host, .database.port' /etc/app/config.json
jq -r '.users[] | "\(.name) \(.role)"' /tmp/users.json
sudo apt install -y jq
```

第一条逐行取出嵌套字段的纯值，可直接赋给 Shell 变量；第二条遍历 `users` 数组拼出姓名与角色。若提示命令不存在，执行第三条安装。

- **常见错误**：不用 `-r` 时取出的字符串带双引号，赋给变量后拼路径或作参数会莫名失败。
- **风险提示**：只读查询无风险；用 jq 回写 JSON（如赋值改配置）会重排格式丢注释，改配置仍建议用编辑器或 sed 并留备份。

## 归档命令

### `tar`

- **用途**：打包/解包归档文件，可叠加 gzip、xz 等压缩，是 Linux 备份与分发的标准格式。
- **语法**：`tar [选项] -f 归档文件 [文件...]`

| 参数 | 说明 |
| --- | --- |
| `-c` | 创建归档（打包） |
| `-x` | 解开归档（解包） |
| `-t` | 只查看归档内清单，不解压 |
| `-z` | 叠加 gzip 压缩（`.tar.gz`） |
| `-J` | 叠加 xz 压缩（`.tar.xz`），压得更小但更慢 |
| `-C 目录` | 解包/打包前切换到指定目录 |
| `-f` | 指定归档文件名，必须紧跟文件名，通常放参数串末尾 |

- **示例**：

```bash
tar -czf /tmp/etc-backup.tar.gz -C / etc/nginx etc/app
tar -tzf /tmp/etc-backup.tar.gz | head -20
tar -xzf /tmp/etc-backup.tar.gz -C /tmp/restore-check
```

流程要点：打包时用 `-C /` 加相对路径避免把绝对路径写进归档；解任何来历的包之前先 `-t` 看清单，再用 `-C` 解到专用目录核查，确认无误才动正式目录。与 restic 等专用备份工具的取舍见 [磁盘健康与备份](../03-storage/04-backup.md)。

- **常见错误**：参数里 `-f` 后面漏写文件名或顺序错位，把下一个参数当成归档名，轻则报错重则覆盖同名文件。
- **风险提示**：解包默认写到当前目录并同名覆盖，先看清单、指定 `-C` 目录再操作。

!!! danger "解压前必须先 -t 查看，警惕覆盖与绝对路径成员"
    来历不明的 tar 包可能包含绝对路径成员（如 `/etc/cron.d/xxx`）或 `../../` 上跳成员，解包时会被写到预期之外的系统位置；即便是正常包，同名文件也会被无提示覆盖。铁律：任何包先执行 `tar -tf 归档文件` 通读清单（发现绝对路径或上跳成员直接弃用），再 `tar -xf 归档文件 -C /tmp/专用空目录` 解开核查，确认内容与落点都正确后才合并到正式目录。

### `gzip` / `gunzip`

- **用途**：单文件压缩与解压（不打包，多文件先用 tar），日志压缩最常见。
- **语法**：`gzip [选项] 文件` / `gunzip [选项] 文件.gz`

| 参数 | 说明 |
| --- | --- |
| `-k` | 保留源文件（默认压缩后删除源文件） |
| `-d` | 解压，等同 gunzip |
| `-l` | 查看 `.gz` 的压缩前后大小信息 |
| `-1` / `-9` | 压缩速度/比率档位，`-1` 最快、`-9` 最小 |
| `-t` | 测试压缩文件完整性 |

- **示例**：

```bash
gzip -k /var/log/app/app.log.1
gunzip -k /var/log/app/app.log.1.gz
gzip -t /tmp/etc-backup.tar.gz && echo OK
```

查老日志时用 `gunzip -k` 解一份副本来查、或直接用 `zgrep` 搜压缩包，避免破坏归档原文件；下载大文件后先用 `-t` 验完整再解压。

- **常见错误**：不知道默认删除源文件，`gzip data.csv` 后找不到 `data.csv` 而以为数据丢了——文件只是变成了 `data.csv.gz`。
- **风险提示**：对正在被程序写入的文件做 gzip 压缩/解压可能得到不一致副本，先停写或复制一份再处理。

### `xz`

- **用途**：高压缩比的单文件压缩，适合长期归档与镜像分发（常以 `.tar.xz` 形式出现）。
- **语法**：`xz [选项] 文件`

| 参数 | 说明 |
| --- | --- |
| `-k` | 保留源文件 |
| `-d` | 解压，等同 `unxz` |
| `-l` | 查看压缩信息 |
| `-T 0` | 使用全部 CPU 核心并行压缩（大文件才划算） |
| `-9 -e` | 极限压缩档位，耗时与内存明显增加 |

- **示例**：

```bash
tar -cJf /tmp/rootfs-backup.tar.xz -C /srv rootfs
unxz -k /tmp/rootfs-backup.tar.xz
```

xz 的比率优于 gzip，但压缩慢数倍：日常备份用 gzip，只有长期冷归档或带宽极贵的分发场景才值得换 xz。

- **常见错误**：对几十 GB 文件不开 `-T 0` 单线程压到天荒地老；另外 `-9` 档位内存占用很高，小内存机器可能被 OOM 终止。
- **风险提示**：同 gzip，默认删除源文件，需保留时加 `-k`。

### `zip` / `unzip`

- **用途**：与 Windows 互通的 ZIP 格式打包解包，跨平台交接文件时使用。
- **语法**：`zip [选项] 包名.zip 文件...` / `unzip [选项] 包名.zip`

| 参数 | 说明 |
| --- | --- |
| `zip -r` | 递归打包整个目录 |
| `unzip -l` | 只列清单，不解压 |
| `unzip -d 目录` | 解压到指定目录 |
| `unzip -o` | 不询问直接覆盖同名文件 |
| `zip -x 模式` | 打包时排除，如 `-x '*.log'` |

- **示例**：

```bash
zip -r /tmp/site-handover.zip /var/www/html -x '*.log'
unzip -l /tmp/site-handover.zip
unzip /tmp/site-handover.zip -d /tmp/handover-check
```

交付给 Windows 用户时用 zip 最省事；收到 zip 包同样遵循先 `-l` 看清单、再 `-d` 解到专用目录的老规矩，不要在原地直接解压。

- **常见错误**：`zip -r` 时把正在生成的 zip 包本身也扫进目录，或漏加 `-r` 只打包了目录空壳。
- **风险提示**：同 tar，解压会覆盖同名文件且 zip 同样可能含上跳路径成员，先看清单再指定目录解压。

## 本章排坑与安全总则

- sed 落盘三步：先不带 `-i` 预览输出、再 `-i.bak` 落盘留备份、最后 `diff` 核对差异，生产配置从不一步到位。
- 解压铁律：无论 tar 还是 zip，先列清单（`-t`/`-l`）、再解到专用空目录核查、最后才合并，绝不在当前工作目录对来历不明的包直接解压。
- 管道顺序不能乱：`sort | uniq -c` 是频次统计的固定搭配；grep 取出的值要进脚本变量时记得格式处理（jq 用 `-r`，文本注意尾随空格）。
- 压缩默认删源文件：`gzip`、`xz` 不加 `-k` 都会删源文件，处理唯一的日志或数据副本时先确认还有备份。
- 大文件先抽样：对数 GB 的日志做 sort、全量 sed 或 xz 前，先用 `head`/`tail` 小样本验证命令与参数，避免跑数十分钟才发现参数写错。
- 优先只读工具：能用 `zgrep`、查看清单、管道预览解决的，就不要先解压或落盘改文件，减少不可逆动作。
