# 文件与权限命令速查

本章覆盖服务器日常最高频的一组命令：查看与定位文件（`ls`、`pwd`/`cd`、`find`、`file`、`stat`）、复制移动与删除（`cp`、`mv`、`rm`、`mkdir`、`touch`、`rsync`、`ln`），以及权限管理（`chmod`、`chown`、`sudo`、`umask`）。原理与体系讲解见第 02 部分的用户与权限教程，本章只给参数、示例与坑点。示例用户为 `ubuntu`，路径以 `/home/ubuntu` 与 `/srv` 为主。

## `ls`

- **用途**：列出目录内容与文件属性，是确认目标存在、看清权限属主的第一步。
- **语法**：`ls [选项] [路径]`

| 参数 | 说明 |
|------|------|
| `-l` | 长格式：权限、属主、大小、修改时间 |
| `-a` | 显示隐藏文件（以 `.` 开头） |
| `-h` | 大小以 KB/MB/GB 易读格式显示，常与 `-l` 合用为 `-lh` |
| `-t` | 按修改时间排序，最新在前 |
| `-R` | 递归列出子目录（目录深时慎用，输出很长） |

- **示例**：

```bash
ls -lh /srv/
ls -lt /var/log/ | head
```

```text
total 8.0K
drwxr-xr-x 2 ubuntu ubuntu 4.0K Oct 21 10:00 app
-rw-r--r-- 1 ubuntu ubuntu  120 Oct 21 09:30 README.txt
```

解读：第一列是权限，第二列属主与属组，先看这两项再决定要不要改权限。

- **常见错误**：只看文件名不看 `-l` 的权限与属主列，服务读不到文件时还在怀疑程序本身。
- **风险提示**：`ls` 本身只读无风险；养成「改、删之前先 `ls` 确认目标」的习惯，能挡住多数误删。

## `pwd` / `cd`

- **用途**：`pwd` 显示当前所在目录，`cd` 切换目录；脚本与批量操作前先确认位置。
- **语法**：`pwd`；`cd [目录]`

| 参数 | 说明 |
|------|------|
| `cd /绝对路径` | 从根目录写全路径，不依赖当前位置 |
| `cd 相对路径` | 相对当前目录，如 `cd logs`、`cd ../conf` |
| `cd ~` 或 `cd` | 回到当前用户家目录 |
| `cd -` | 回到上一次所在目录 |
| `pwd -P` | 显示解析符号链接后的真实路径 |

- **示例**：

```bash
pwd
cd /etc/nginx
pwd
cd -
```

```text
/home/ubuntu
/etc/nginx
/home/ubuntu
```

解读：`cd -` 在两个目录之间来回切换时最省事，输出会打印切换后的目录。

- **常见错误**：在相对路径下执行删除或覆盖，又忘了自己当前在哪个目录；路径含空格时不加引号会被拆成两个参数。
- **风险提示**：在不确定的目录里执行写操作前先 `pwd` + `ls` 双确认，尤其在 `sudo` 会话中。

## `cp`

- **用途**：复制文件或目录，改配置前备份、部署文件副本都用它。
- **语法**：`cp [选项] 源 目标`

| 参数 | 说明 |
|------|------|
| `-r` | 递归复制目录（目录必须带此参数） |
| `-a` | 归档复制：保留权限、属主、时间与链接，备份目录首选 |
| `-i` | 覆盖前逐个询问 |
| `-v` | 显示复制过程 |
| `-p` | 保留权限与时间戳（不含属主，普通用户够用） |

- **示例**：

```bash
sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak-20261021
cp -a /srv/app /srv/app-backup
cp -iv *.conf /srv/app/conf/
```

解读：改系统配置前先按第一行的方式留一份带日期的备份，出问题一条 `cp` 即可还原。

- **常见错误**：复制目录忘了 `-r` 直接报错；用普通 `cp` 备份后权限与时间全变，还原后服务仍异常。
- **风险提示**：目标写错会静默覆盖同名文件，覆盖系统配置前先备份原文件。

## `mv`

- **用途**：移动文件或重命名，两者是同一操作。
- **语法**：`mv [选项] 源 目标`

| 参数 | 说明 |
|------|------|
| `-i` | 目标已存在时覆盖前询问 |
| `-n` | 目标已存在时不覆盖 |
| `-v` | 显示移动过程 |
| `-u` | 仅当源比目标新时才移动 |

- **示例**：

```bash
mv app.log app.log.20261021
mv -i /tmp/upload.tar.gz /srv/app/
```

解读：同分区内 `mv` 只是改目录项，瞬间完成；跨分区才是真正的复制再删除，大文件会耗时。

- **常见错误**：把目录移动到已存在的同名目录下，结果变成嵌进一层（如 `mv app /srv/` 而 `/srv/app` 已存在，得到 `/srv/app/app`）。
- **风险提示**：目标同名文件会被直接覆盖且无回收站，重要文件移动时加 `-i`。

## `rm`

- **用途**：删除文件或目录，删除即不可恢复，默认没有回收站。
- **语法**：`rm [选项] 文件...`

| 参数 | 说明 |
|------|------|
| `-r` | 递归删除目录及其内容 |
| `-f` | 强制删除，不提示、不因不存在报错 |
| `-i` | 每个文件删除前询问 |
| `-v` | 显示删除过程 |
| `--` | 结束选项解析，后面以 `-` 开头的文件名按文件名处理 |

- **示例**：

```bash
ls -lh /srv/app/tmp/
rm -i /srv/app/tmp/old-cache.tmp
rm -rf /srv/app/tmp/build-cache/
```

解读：安全顺序是先 `ls` 看清目标、单个文件用 `-i` 确认、确认无误的缓存目录才用 `-rf` 一次清掉。

- **常见错误**：变量为空时执行 `rm -rf $DIR/` 会变成删根目录下的内容；把 `rm -rf / srv/app` 中间多打一个空格，目标就变成了 `/`。
- **风险提示**：见下方单独警示。

!!! danger "rm：-rf 与根目录/家目录误删"

    `rm -rf /`、`rm -rf ~`、`rm -rf /*` 会递归删掉系统或全部个人数据，且多数文件系统下不可恢复。安全替代：①执行前先用 `ls` 列一遍将删的路径；②批量删除加 `-i` 或先不带 `-f` 试跑看报错；③重要数据先 `mv` 到临时目录观察几天再删，桌面环境可用回收站思路（先移走、后清空），服务器上同理；④路径来自变量时先 `echo` 打印变量值再执行。

## `mkdir`

- **用途**：创建目录。
- **语法**：`mkdir [选项] 目录...`

| 参数 | 说明 |
|------|------|
| `-p` | 父目录不存在时一并创建，已存在不报错 |
| `-m 权限` | 创建时直接指定权限，如 `-m 750` |
| `-v` | 显示创建过程 |

- **示例**：

```bash
mkdir -p /srv/app/{conf,logs,data}
ls -ld /srv/app/logs
```

解读：`-p` 配合大括号展开一次建好整棵目录树，脚本里也应默认带 `-p` 保证可重复执行。

- **常见错误**：不带 `-p` 创建多级目录时因父目录不存在报错；目录名含空格不加引号被拆开。
- **风险提示**：只读风险低；注意默认权限受 `umask` 影响，需要严格权限时用 `-m` 显式指定。

## `touch`

- **用途**：更新文件时间戳；文件不存在时创建一个空文件。
- **语法**：`touch [选项] 文件...`

| 参数 | 说明 |
|------|------|
| `-c` | 文件不存在时不创建，只更新已有文件时间 |
| `-d "时间"` | 指定时间，如 `-d "2026-10-01 08:00"` |
| `-r 参考文件` | 以另一个文件的时间为准 |
| `-a` / `-m` | 只改访问时间 / 只改修改时间 |

- **示例**：

```bash
touch /srv/app/logs/app.log
touch -c -d "2026-10-21 00:00" /srv/app/data/marker
```

解读：常用于创建占位或标记文件、触发按时间判断的脚本逻辑，而不是写内容。

- **常见错误**：以为 `touch` 能写内容——它只建空文件或改时间，写内容用编辑器或重定向。
- **风险提示**：对已有文件执行会改掉它的修改时间，按 `mtime` 做清理或增量备份的流程可能因此误判。

## `find`

- **用途**：按名称、类型、大小、时间等条件递归查找文件，可批量执行后续动作。
- **语法**：`find [路径] [条件] [动作]`

| 参数 | 说明 |
|------|------|
| `-name "模式"` | 按文件名匹配（大小写敏感），`-iname` 不敏感 |
| `-type f/d/l` | 只找文件 / 目录 / 符号链接 |
| `-size +100M` | 大于 100MB，`-` 为小于，单位 `k/M/G` |
| `-mtime -7` | 最近 7 天内修改过，`+7` 为 7 天前 |
| `-exec 命令 {} \;` | 对每个结果执行命令，`{}` 是占位符 |
| `-print` / `-ls` | 打印路径 / 以长格式打印（默认只打印路径） |

- **示例**：

```bash
find /var/log -name "*.log" -mtime +30
find /srv -type f -size +500M
find /srv/app/tmp -type f -mtime +7 -print
```

解读：先只加 `-print` 看清命中清单，确认无误后再把动作换成删除或移动。

- **常见错误**：`-name` 的模式不加引号会被 shell 先展开；`-exec rm` 前不预览就批量执行，条件写错即批量误删。
- **风险提示**：`find ... -delete` 与 `-exec rm` 没有回收站，永远先用 `-print`  dry-run 一遍再执行动作。

## `rsync`

- **用途**：高效增量同步文件与目录，支持本地与远程、断点续传与保留属性，是备份与部署的主力。
- **语法**：`rsync [选项] 源 目标`

| 参数 | 说明 |
|------|------|
| `-a` | 归档模式：递归并保留权限、属主、时间、链接 |
| `-v` | 显示同步过程，`-z` 传输时压缩（慢速网络用） |
| `--dry-run` | 只模拟不真正执行，先预览必带 |
| `--delete` | 删除目标端源端已不存在的文件（高危，见警示） |
| `-e ssh` | 指定远程通道，远程同步默认走 SSH |
| `--exclude="模式"` | 排除文件，如 `--exclude="*.log"` |

- **示例**：

```bash
rsync -av --dry-run /srv/app/ ubuntu@192.0.2.20:/srv/app/
rsync -av /srv/app/ ubuntu@192.0.2.20:/srv/app/
```

解读：源路径末尾的 `/` 表示同步目录内容本身；不带 `/` 会把目录再套一层。先 `--dry-run` 看清单再实跑。完整的远程传输与参数讲解见 [文件传输与远程执行](../14-ssh/04-transfer-remote-exec.md)。

- **常见错误**：源末尾斜杠有无搞反导致目录多套一层；在错的主机或错的方向上执行同步。
- **风险提示**：`--delete` 会让目标端与源端完全一致，源端误删会同步成目标端也删；备份场景先不加 `--delete`，确认策略后再启用。

## `ln`

- **用途**：创建链接：符号链接（软链接）像快捷方式，硬链接是同一文件的另一个名字。
- **语法**：`ln [选项] 目标 链接名`

| 参数 | 说明 |
|------|------|
| `-s` | 创建符号链接（不带此参数为硬链接） |
| `-f` | 链接名已存在时强制覆盖 |
| `-n` | 链接名是指向目录的符号链接时按文件处理，常与 `-f` 合用 |
| `-v` | 显示创建过程 |

- **示例**：

```bash
ln -s /srv/app/releases/v2 /srv/app/current
ln /srv/data/report.csv /srv/backup/report-link.csv
ls -l /srv/app/current
```

解读：`ls -l` 中符号链接显示为 `l` 开头并带 `-> 目标`；配置里指向 `current`，发版时只切换链接即可回滚。

- **常见错误**：建符号链接时目标写相对路径，链接换个目录就失效；对目录建硬链接会被系统拒绝（默认不允许）。
- **风险提示**：删掉源文件后符号链接会悬空失效；硬链接删其一不影响其余，两者不要混淆。

## `file`

- **用途**：判断文件的真实类型（看内容不看扩展名），排查「文件打不开/格式不对」时先用它确认。
- **语法**：`file [选项] 文件...`

| 参数 | 说明 |
|------|------|
| `-b` | 简洁输出，只给类型不带文件名 |
| `-i` | 输出 MIME 类型 |
| `-L` | 跟随符号链接，看目标本体类型 |
| `-z` | 尝试看压缩包内部内容类型 |

- **示例**：

```bash
file /srv/app/upload.tar.gz /usr/bin/ls
```

```text
/srv/app/upload.tar.gz: gzip compressed data, was "upload.tar"
/usr/bin/ls: ELF 64-bit LSB pie executable, x86-64
```

解读：扩展名是 `.tar.gz` 但 `file` 若显示为其他类型，说明文件已损坏或根本不是该格式，不要硬解压。

- **常见错误**：只信扩展名——Linux 下扩展名可以任意改，类型以 `file` 的判断为准。
- **风险提示**：只读命令，无风险。

## `stat`

- **用途**：显示文件或文件系统的完整元数据：大小、权限八进制、属主、三个时间戳、inode。
- **语法**：`stat [选项] 文件...`

| 参数 | 说明 |
|------|------|
| `-c "格式"` | 自定义输出，如 `-c "%a %U %n"` 输出权限、属主、文件名 |
| `-f` | 显示文件系统信息而非文件信息 |
| `--printf` | 同 `-c` 但不自动加换行，脚本拼输出用 |

- **示例**：

```bash
stat /etc/nginx/nginx.conf
stat -c "%a %U:%G %n" /srv/app /srv/app/conf
```

```text
755 ubuntu:ubuntu /srv/app
750 ubuntu:ubuntu /srv/app/conf
```

解读：排障时用 `stat -c` 一次看齐权限数字与属主，比 `ls -l` 更适合写进脚本与记录。

- **常见错误**：把访问时间 `atime` 当成修改时间 `mtime` 判断「文件被改过」；挂载了 `noatime` 时 `atime` 本来就不更新。
- **风险提示**：只读命令，无风险。

## `chmod`

- **用途**：修改文件或目录的读、写、执行权限，权限模型为属主 / 属组 / 其他人三组 `rwx`。
- **语法**：`chmod [选项] 权限 文件...`

| 参数 | 说明 |
|------|------|
| 数字法如 `755` | 三位八进制，每位为 r(4)+w(2)+x(1) 之和 |
| 符号法如 `u+x` | `u/g/o/a` 指对象，`+/-=` 指增/减/设定，`rwx` 指权限 |
| `-R` | 递归修改目录下全部内容（见下方警示） |
| `--reference=文件` | 参照另一个文件的权限来设置 |
| `-v` | 显示修改过程 |

数字法与符号法对照：

| 数字 | 二进制 | 权限 | 典型用途 |
|------|--------|------|----------|
| `755` | 111 101 101 | `rwxr-xr-x` | 目录、可执行脚本 |
| `644` | 110 100 100 | `rw-r--r--` | 普通文件、网页文件 |
| `750` | 111 101 000 | `rwxr-x---` | 仅属主与属组可进的目录 |
| `700` | 111 000 000 | `rwx------` | 私有目录，如 `~/.ssh` |
| `600` | 110 000 000 | `rw-------` | 私钥、含密配置 |

- **示例**：

```bash
chmod 644 /srv/app/conf/app.conf
chmod u+x /srv/app/bin/run.sh
chmod -R 750 /srv/app/data
```

解读：目录必须有 `x` 才能进入，只给 `r` 会出现「能看到文件名却打不开」的经典现象。

- **常见错误**：给私钥或 `.ssh` 目录设成 `644/755`，SSH 会因权限过宽直接拒绝使用密钥；对目录漏给 `x` 导致无法进入。
- **风险提示**：见下方单独警示。

!!! danger "chmod -R：递归改权限"

    `chmod -R 777 /`、`chmod -R` 作用在 `/etc`、`/var`、`/home` 等系统目录上，会把全站权限一次性打乱：服务读不到或人人可写、SSH 与 sudo 因权限校验失败直接罢工，修复成本极高。原则：`-R` 只用于明确的业务目录，先在小子目录验证效果；永远不要给系统目录设 `777`，排障时先查属主与单文件权限，而不是一把 `-R 777` 放行。

## `chown`

- **用途**：修改文件的属主与属组，解决「文件在、权限对，但用户不对」的访问问题。
- **语法**：`chown [选项] 属主[:属组] 文件...`

| 参数 | 说明 |
|------|------|
| `ubuntu` | 只改属主，属组不变 |
| `ubuntu:ubuntu` | 同时改属主与属组 |
| `:ubuntu` | 只改属组 |
| `-R` | 递归修改（见下方警示） |
| `--reference=文件` | 参照另一个文件的属主属组 |
| `-v` | 显示修改过程 |

- **示例**：

```bash
sudo chown ubuntu:ubuntu /srv/app/data/upload.db
sudo chown -R www-data:www-data /srv/www
```

解读：以 root 身份解压或复制过来的文件属主常是 `root`，服务账号读不了，先 `ls -l` 确认再 `chown` 给运行账号。

- **常见错误**：属主属组语法写成 `ubuntu.ubuntu`（旧写法易误读），统一用冒号；改完只看命令无报错，不回头用服务账号实测读写。
- **风险提示**：见下方单独警示。

!!! danger "chown -R：递归改属主"

    `chown -R` 作用错目录会把系统文件的属主整片改掉，例如把 `/etc` 改给普通用户后，sudo、SSH、定时任务会因所有权校验失败而异常，且很难逐个还原。原则：`-R` 只对业务数据目录使用；系统目录只改单个明确文件；执行前先 `ls -l` 核对现任属主，执行后立即用目标账号验证。

## `sudo`

- **用途**：以 root 或指定用户身份执行单条命令，或切换到管理员会话；权限来自 `/etc/sudoers` 授权。
- **语法**：`sudo [选项] 命令`

| 参数 | 说明 |
|------|------|
| `-i` | 以 root 身份启动登录 shell（环境与家目录都切到 root） |
| `-u 用户` | 以指定用户身份执行，如 `sudo -u www-data id` |
| `-l` | 列出当前用户被授权的 sudo 权限 |
| `-k` | 立即让已缓存的认证失效，下次需重新输密码 |
| `-e 文件` | 安全编辑文件（sudoedit，走授权校验的编辑方式） |

- **示例**：

```bash
sudo -l
sudo systemctl restart nginx
sudo -u www-data touch /srv/www/test-write
```

解读：第三行以服务账号实际写一次文件，是验证目录属主与权限是否真的对服务可用的最可靠方法。

- **常见错误**：整段会话都开着 root shell 做日常操作，一次手误即系统级事故；给不需要提权的查询命令也习惯性加 `sudo`，掩盖了真实的权限问题。
- **风险提示**：`sudo` 执行的命令等同 root 操作，粘贴网上命令前逐字看清；授权他人时按最小权限给具体命令，不要轻易给 `ALL=(ALL) ALL`。

## `umask`

- **用途**：查看或设置新建文件/目录的默认权限掩码，决定新文件的起始权限宽严。
- **语法**：`umask [值]`

| 参数 | 说明 |
|------|------|
| 无参数 | 以八进制显示当前掩码，如 `0002` |
| `-S` | 以符号形式显示，如 `u=rwx,g=rwx,o=rx` |
| `umask 027` | 在当前 shell 会话内设置新掩码 |
| `umask 022` | 恢复常见默认掩码 |

- **示例**：

```bash
umask
umask -S
umask 027
touch newfile && mkdir newdir && ls -ld newfile newdir
```

```text
-rw-r----- 1 ubuntu ubuntu 0 Oct 21 10:00 newfile
drwxr-x--- 1 ubuntu ubuntu 0 Oct 21 10:00 newdir
```

解读：默认权限的算法是文件从 `666`、目录从 `777` 中减去掩码位。`027` 的效果：新文件 `640`（属主读写、属组只读、其他人无权），新目录 `750`，适合多人共用服务器收紧默认暴露面。

- **常见错误**：以为改 `umask` 会修改已有文件权限——它只影响之后新建的文件；把掩码当成权限本身直接相减，掩码是「去掉的位」不是结果值。
- **风险提示**：在当前会话临时改大掩码后忘了恢复，新建的日志或备份可能过严导致服务账号读不到；持久修改应改 shell 配置并知会同机用户。

## 本章排坑与安全总则

1. **先看后动**：任何改、删、移之前先 `ls -l` / `stat` 看清目标、权限与属主，路径来自变量时先 `echo` 打印再执行。
2. **删除默认不可恢复**：`rm`、`find -delete`、带 `--delete` 的 `rsync` 都没有回收站；先 dry-run 或 `-print` 预览，重要数据先移走观察、再真删。
3. **`-R` 只给业务目录**：`chmod -R`、`chown -R`、`rm -rf` 的递归操作永远不指向 `/`、`/etc`、`/var`、`/home` 等系统位置，范围先小后大、先验证再扩大。
4. **权限问题先查属主**：服务读不到文件时，顺序是属主 → 权限位 → 目录 `x`，而不是直接 `777` 放行；`777` 出现在生产目录上本身就是待整改项。
5. **备份先行且可还原**：改系统配置前 `cp` 一份带日期的备份；用 `-a` 保留属性；还原后必须重启或重载服务实测，不能只看文件回来了。
6. **提权最小化**：`sudo` 只加在真正需要的那一条命令上，改完用服务账号身份（如 `sudo -u www-data`）实测一次读写闭环。
