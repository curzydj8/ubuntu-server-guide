# 网络诊断命令速查

本章覆盖网络排查的速查工具箱：看地址与路由（`ip`）、看监听与连接（`ss`）、测连通（`ping`、`nc`、`traceroute`）、测应用层（`curl`）、查解析（`dig`、`nslookup`）、抓包定界（`tcpdump`）与远程操作（`ssh`、`scp`）。分层排查的完整案例与判读流程见教程章 [网络故障排查流程](../08-troubleshooting/02-network-diagnosis.md)，DNS 原理与搭建见 [DNS 服务器搭建](../04-network/01-dns.md)。本章只给参数、示例与坑点。示例统一使用文档段：服务器 `192.0.2.10`、网关 `192.0.2.1`、DNS `192.0.2.53`，网卡示例名 `enp3s0`，执行前先用 `ip -br link` 核对本机真实网卡名。

## `ip`

- **用途**：查看与临时修改网卡地址、链路状态与路由表，是网络排查的第一个命令。
- **语法**：`ip [addr|route|link] [动作] [对象]`

| 参数 | 说明 |
|------|------|
| `addr`（简写 `a`） | 查看/增删 IP 地址，如 `ip -br addr` 简洁列表 |
| `route`（简写 `r`） | 查看路由表，`ip route get 目标` 看实际选路 |
| `link` | 查看/启停网卡，如 `ip link set enp3s0 up` |
| `-br` | 简洁输出，一行一个对象，先看概览用 |
| `-4` / `-6` | 只看 IPv4 / IPv6 |

- **示例**：

```bash
ip -br addr
ip route
ip route get 198.51.100.20
ip -br link
```

```text
enp3s0           UP             192.0.2.10/24
default via 192.0.2.1 dev enp3s0 proto static
192.0.2.0/24 dev enp3s0 proto kernel scope link src 192.0.2.10
```

解读：先确认业务网卡有规划内地址且状态 `UP`，再确认有 `default via 网关` 一行；两项缺一就先别往上层查。

- **常见错误**：用 `ip` 命令改的地址与路由是临时的，重启即失；验证有效后必须写回 Netplan 等配置文件持久化。
- **风险提示**：在 SSH 会话中改地址、路由或停用网卡会立即断开连接，远程操作先留带外通道。

## `ss`

- **用途**：查看监听端口与网络连接，比老命令 `netstat` 更快，是「端口通不通」排查的第一站。
- **语法**：`ss [选项] [过滤条件]`

| 参数 | 说明 |
|------|------|
| `-tuln` | 常用组合：TCP+UDP、监听中、数字端口不解析 |
| `-lntp` | 监听中的 TCP 并显示进程（看清谁在监听需 sudo） |
| `-s` | 连接统计汇总 |
| `-p` | 显示占用连接的进程 |
| `sport = :80` | 按端口过滤，如 `ss -tn sport = :443` |

- **示例**：

```bash
sudo ss -tuln
sudo ss -lntp | grep -E ":80|:443"
ss -s
```

```text
LISTEN 0  4096  0.0.0.0:22   0.0.0.0:*  users:(("sshd",pid=1234,fd=3))
LISTEN 0  511   127.0.0.1:3306 0.0.0.0:* users:(("mysqld",pid=2345,fd=21))
```

解读：看监听地址列——`0.0.0.0` 表示对外可达，只写 `127.0.0.1` 时外部永远连不上，先查这一列再查防火墙。

- **常见错误**：不加 `sudo` 看不到进程名，便误判端口无人监听；把 `TIME-WAIT` 等正常连接状态当成异常。
- **风险提示**：只读命令，无风险。

## `ping`

- **用途**：测目标的 ICMP 连通、时延与丢包，按「网关 → 外网 IP → 域名」顺序分层定位。
- **语法**：`ping [选项] 目标`

| 参数 | 说明 |
|------|------|
| `-c 次数` | 发指定次数后停止，排查时必带，避免无限刷屏 |
| `-i 间隔` | 发包间隔秒数，如 `-i 0.2` 快速采样 |
| `-W 超时` | 等待单次回复的超时秒数 |
| `-6` | 强制走 IPv6（也可直接用 `ping -6 目标`） |
| `-M do -s 大小` | 禁止分片并指定载荷，用于 MTU 验证 |

- **示例**：

```bash
ping -c 4 192.0.2.1
ping -c 20 198.51.100.20
ping -6 -c 4 2606:4700:4700::1111
```

```text
20 packets transmitted, 20 received, 0% packet loss, time 19023ms
rtt min/avg/max/mdev = 18.204/19.631/24.908/1.112 ms
```

解读：判读只看汇总行——`packet loss` 定丢包，`avg/max` 定时延与抖动；单次超时不下结论。

- **常见错误**：只 `ping` 域名就断定网络不通——先 ping IP 再 ping 域名，才能分清是链路问题还是纯 DNS 问题；目标禁 ICMP 时 ping 不通不等于服务不通，要用 `nc`/`curl` 复核端口。
- **风险提示**：只读探测无风险；不要对他人网络做高频大包 ping，正常排查控制次数与间隔。

## `curl`

- **用途**：测 HTTP/HTTPS 应用层：看状态码、响应头、证书阶段与耗时，是「网站打不开」的定界工具。
- **语法**：`curl [选项] URL`

| 参数 | 说明 |
|------|------|
| `-I` | 只看响应头（HEAD 请求），确认状态码与跳转 |
| `-v` | 详细过程：连接、TLS 握手、请求与响应全程，排障必备 |
| `-o 文件` | 把响应体下载保存到文件 |
| `-X 方法` / `--data "内容"` | 指定请求方法 / 发送 POST 数据 |
| `-w "格式"` | 请求结束后按格式输出变量，如 `%{http_code}` 状态码、`%{time_total}` 总耗时 |
| `--connect-timeout 秒` | 连接超时上限，避免长时间挂起 |

- **示例**：

```bash
curl -I https://example.com/
curl -v --connect-timeout 5 https://example.com/ 2>&1 | head -n 30
curl -o /dev/null -s -w "%{http_code} %{time_total}\n" https://example.com/
curl -X POST --data "name=test" http://192.0.2.10:8080/api/check
```

```text
200 0.183
```

解读：`-v` 按阶段判读——卡连接是路由或防火墙、立即被拒绝是无人监听、连上后 502/504 是后端问题、证书阶段报错是 TLS 问题，四类根因完全不同。

- **常见错误**：只看「打不开」不分阶段，把证书过期当网络故障查半天；用 `-k` 跳过证书校验测通了就宣布恢复，实际上用户侧仍会报错。
- **风险提示**：`--data` 与请求头里不要放真实口令等敏感信息做随手测试，命令会留在 shell 历史与日志中。

## `dig`

- **用途**：查 DNS 解析的完整细节：状态、答案、实际询问的 DNS 服务器，是域名问题的权威工具。
- **语法**：`dig [选项] [@DNS服务器] 域名 [记录类型]`

| 参数 | 说明 |
|------|------|
| `+short` | 只输出解析结果，脚本与快速确认用 |
| `@192.0.2.53` | 指定要询问的 DNS 服务器，对照排查用 |
| `A` / `AAAA` / `MX` / `TXT` | 指定记录类型，不写默认查 A |
| `+trace` | 从根开始逐级追踪解析链 |
| `-x IP` | 反向解析 IP 对应的域名 |

- **示例**：

```bash
dig example.com
dig +short example.com
dig @192.0.2.53 example.com
dig example.com MX
```

```text
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 12345
;; ANSWER SECTION:
example.com.        300     IN      A       93.184.216.34
```

解读：`status: NOERROR` 且 ANSWER 区有记录为正常；`SERVFAIL` 是上游或 DNSSEC 问题，`NXDOMAIN` 是域名或记录不存在；末尾 `SERVER` 一行确认实际问的是哪台 DNS。

- **常见错误**：未安装时提示命令不存在——`dig` 在 `dnsutils` 包里，先 `sudo apt install -y dnsutils`；只看默认 `dig` 不通就改本机配置，应先用 `@` 指定已知 DNS 对照，分清是本机配置问题还是上游问题。
- **风险提示**：只读查询，无风险。

## `nslookup`

- **用途**：简易域名解析查询，输出比 `dig` 直白；老系统与跨平台场景常见，深度排查仍以 `dig` 为准。
- **语法**：`nslookup [域名] [DNS服务器]`

| 参数 | 说明 |
|------|------|
| `nslookup 域名` | 用系统默认 DNS 查询 |
| `nslookup 域名 192.0.2.53` | 指定 DNS 服务器查询 |
| `-type=MX` | 指定记录类型，如 MX、TXT |
| `-debug` | 显示查询调试细节 |

- **示例**：

```bash
nslookup example.com
nslookup example.com 192.0.2.53
```

解读：两个结果不一致时，问题在本机默认 DNS 的配置或缓存，而不是域名本身。

- **常见错误**：看到输出里的 `Non-authoritative answer` 以为是报错——它只是表示答案来自缓存或非权威服务器，属于正常信息。
- **风险提示**：只读查询，无风险。

## `nc`

- **用途**：测 TCP/UDP 端口连通性（不依赖业务协议），区分「端口不通」与「服务内容不对」。
- **语法**：`nc [选项] 主机 端口`

| 参数 | 说明 |
|------|------|
| `-v` | 显示连接过程与结果 |
| `-z` | 只扫描连通性，不发送数据，最常用组合是 `-vz` |
| `-w 秒` | 连接超时，如 `-w 3` |
| `-u` | 测 UDP（无连接，结果判读比 TCP 弱） |

- **示例**：

```bash
nc -vz -w 3 192.0.2.10 22
nc -vz -w 3 192.0.2.10 443
```

```text
Connection to 192.0.2.10 22 port [tcp/ssh] succeeded!
```

解读：`succeeded` 说明三次握手能完成，故障在应用层；超时多为防火墙丢弃，立即 `refused` 多为目标无监听或主动拒绝。

- **常见错误**：未安装时先 `sudo apt install -y netcat-openbsd`；用 UDP 测试得到「成功」便下结论——UDP 无握手，`nc -u` 的结果只能作参考。
- **风险提示**：只对自己管理或已获授权的主机与端口做连通测试，不要对他人网络批量扫端口。

## `tcpdump`

- **用途**：抓包取证，回答「请求到底到没到这台机器、出去了没有回来」这一分界问题，需要 root 权限。
- **语法**：`sudo tcpdump [选项] [过滤表达式]`

| 参数 | 说明 |
|------|------|
| `-i 接口` | 指定网卡，如 `-i enp3s0`，`any` 为全部接口 |
| `-n` | 不解析主机名与端口名（`-nn` 连端口名也不解析），避免解析干扰 |
| `host 192.0.2.10` | 只抓与该主机相关的包 |
| `port 443` | 只抓该端口，可与 host 用 `and` 组合 |
| `-c 次数` | 抓满指定包数自动停止，避免无限抓 |
| `-w 文件` | 写入 pcap 文件供离线分析（配合过滤条件缩小范围） |

- **示例**：

```bash
sudo tcpdump -i enp3s0 -nn host 198.51.100.20 and port 443 -c 20
sudo tcpdump -i enp3s0 -nn port 80 -c 50
```

解读：外部访问时完全看不到 SYN，是请求没到本机（查安全组、NAT 与上游）；有 SYN 无 SYN-ACK，是本机防火墙或监听问题；握手完整则转应用层查内容。

- **常见错误**：不加任何过滤在繁忙网卡上抓包，瞬间刷屏且文件巨大，还混入大量无关流量；忘了 `sudo` 报无权限打开网卡。
- **风险提示**：见下方单独警示。

!!! danger "tcpdump：抓包内容敏感，生产慎用并先授权"

    抓包会记录经过网卡的真实业务内容，可能包含账号、口令、业务数据等敏感信息。生产环境抓包前先取得授权，只抓定位所需的最小范围（限定主机、端口与包数），抓包文件加密保存、限定访问人员，问题关闭后及时销毁；不要在无过滤条件下长时间全量抓包。

## `traceroute`

- **用途**：显示到目标逐跳经过的路径与每跳时延，定位丢包与高时延出现在哪一段。
- **语法**：`traceroute [选项] 目标`

| 参数 | 说明 |
|------|------|
| `-n` | 不解析主机名，只显示 IP，速度快且不被 DNS 干扰 |
| `-m 跳数` | 最大跳数，默认 30 |
| `-w 秒` | 每跳等待回复的秒数 |
| `-T` | 用 TCP 探测（部分网络对 UDP/ICMP 探测限速时用） |

- **示例**：

```bash
traceroute -n 198.51.100.20
```

```text
 1  192.0.2.1      0.512 ms  0.430 ms  0.389 ms
 2  198.51.100.1   8.214 ms  8.103 ms  8.052 ms
 3  * * *
```

解读：某一跳起后续都丢包，故障点在该跳之后；只有中间某跳丢包而终点正常，多为该设备限制探测报文速率，不是真实故障，结论以最后一跳为准。

- **常见错误**：未安装时提示命令不存在，先 `sudo apt install -y traceroute`，或改用系统自带的 `tracepath` 查路径、用 `mtr` 看持续统计。
- **风险提示**：只读探测无风险；不要凭中间跳的单点数据就向运营商报障，先用持续 `ping` 与终点数据交叉验证。

## `ssh`

- **用途**：加密远程登录与远程执行命令，是服务器管理的主通道；本条只给速查参数，密钥、配置与加固的完整教程见 [SSH 连接与客户端配置](../14-ssh/02-connect-config.md)。
- **语法**：`ssh [选项] [用户@]主机 [远程命令]`

| 参数 | 说明 |
|------|------|
| `-p 端口` | 指定端口，如 `-p 2222` |
| `-i 私钥文件` | 指定登录私钥，如 `-i ~/.ssh/id_ed25519` |
| `-v` | 详细过程，登录失败排障用（`-vv` 更详细） |
| `-o ConnectTimeout=秒` | 连接超时，脚本中防挂死 |
| `-L 本地:目标:端口` | 本地端口转发，把内网服务映射到本机访问 |
| `-J 跳板机` | 经跳板机中转登录目标机 |

- **示例**：

```bash
ssh ubuntu@192.0.2.10
ssh -p 2222 -i ~/.ssh/id_ed25519 ubuntu@192.0.2.10 "hostname && uptime"
ssh -v ubuntu@192.0.2.10
```

解读：带远程命令的形式执行完即退出，适合脚本巡检；登录失败先加 `-v` 看卡在网络、认证还是密钥哪一阶段。

- **常见错误**：私钥权限过宽（非 `600`）时 SSH 直接拒绝使用并报错；首次连接的主机指纹提示要核对后再接受，不要无脑输 yes 绕过校验。
- **风险提示**：确认目标主机无误再登录执行写操作——在错的机器上执行正确的命令同样是事故；口令与私钥不要写进脚本或命令参数。

## `scp`

- **用途**：经 SSH 通道复制文件（本机与远程之间、远程与远程之间），小文件传输的速查选择；批量与增量同步改用 `rsync`，完整讲解见 [文件传输与远程执行](../14-ssh/04-transfer-remote-exec.md)。
- **语法**：`scp [选项] 源 目标`（远程一侧写 `用户@主机:路径`）

| 参数 | 说明 |
|------|------|
| `-r` | 递归复制目录 |
| `-P 端口` | 指定 SSH 端口（注意是大写 `P`） |
| `-i 私钥文件` | 指定登录私钥 |
| `-p` | 保留原文件的修改时间与权限 |
| `-C` | 传输时压缩，慢速网络传文本类文件时用 |

- **示例**：

```bash
scp /tmp/report.txt ubuntu@192.0.2.10:/home/ubuntu/
scp -r ubuntu@192.0.2.10:/var/log/nginx /tmp/nginx-logs/
scp -P 2222 ./app.tar.gz ubuntu@192.0.2.10:/srv/app/
```

解读：冒号是远程路径的标志——写错冒号位置会把文件复制到意料之外的本地目录，执行前看清哪一侧带 `用户@主机:`。

- **常见错误**：把端口参数写成小写 `-p`——在 `scp` 里 `-p` 是保留属性，端口是大写 `-P`，与 `ssh` 的小写 `-p` 正好相反，最容易混。
- **风险提示**：目标路径写错会覆盖远程同名文件，传配置文件前先在远程备份原文件；大文件与目录同步优先 `rsync`，支持断点续传与增量传输。

## 本章排坑与安全总则

1. **严格分层，不跳步**：地址（`ip`）→ 路由（`ip route`）→ 连通（`ping` IP）→ 解析（`ping` 域名 / `dig`）→ 监听（`ss`）→ 应用（`curl`），下一层未确认通过不查上一层。
2. **先看监听地址再怪防火墙**：端口不通先看 `ss` 的监听地址列，只绑 `127.0.0.1` 时加再多放行规则也没用。
3. **结论要有量化证据**：丢包看 `ping -c 20` 以上的汇总行，路径问题以 `traceroute`/`mtr` 的最后一跳为准，单次超时、中间跳丢包都不下结论。
4. **对照法分清内外**：`dig` 用 `@` 指定已知 DNS 对照、`curl` 分本机与外部各测一次、`tcpdump` 看报文有无到达——先把故障定界在本机、网络还是对端，再动手改配置。
5. **抓包与扫描守授权边界**：`tcpdump` 先授权、最小范围、文件妥善保管并及时销毁；`nc` 等探测只对自管或已授权目标使用。
6. **远程操作留退路**：改地址、路由、防火墙与 SSH 配置前备好带外通道，`ssh`/`scp`/`rsync` 执行写操作前再次核对目标主机与路径。
