# 模型幻觉与可解释性：成因、缓解与解释方法

## 1. 一句话定义

模型幻觉是模型生成看似合理、实则与事实或给定输入不符的内容；可解释性是让人理解模型为何给出某一输出的方法与程度。

## 2. 为什么需要它

生成式模型最危险的特性不是它会犯错，而是它犯错时看起来胸有成竹：一段编造的引用、一个不存在的法条、一份张冠李戴的病历摘要，都能以流畅、规范、自信的语言呈现，让人很难察觉。使用者越信任模型的语言风格，幻觉的危害就越大。

与此同时，模型一旦出错，使用者需要追问“它为什么这么说”——是训练数据里本来就有错误，还是检索到的资料过时了，还是推理过程走偏了。答不上这个问题，模型就没法调试、没法追责、也没法让人放心地用在医疗、法律、金融这些高风险场景。可解释性不是锦上添花，是幻觉治理与模型可信的前提。

## 3. 核心含义

### 3.1 幻觉的成因

幻觉不是某个可以单独修掉的 bug，它长在语言模型的训练目标与工作方式里：

- **训练目标是语言流畅，不是事实正确**：语言模型训练时优化的是“下一个词出现的概率”，目标是把话说得像人话，而不是把话说对。模型学会的是“什么样的回答看起来合理”，不是“什么样的回答是真的”。流畅与真实是两个目标，训练只对前者负责。
- **知识来自训练数据，且有截止时间**：模型知道的只是训练数据截止时的世界。截止之后发生的事它不知道，训练数据里本来就错的东西它会原样学下来，训练数据里稀少、模糊的东西它只能靠“合理推测”补全——推测补出来的，就是幻觉的高发区。
- **解码采样引入随机性**：生成时模型不是每次都选概率最高的词，而是按概率采样（温度越高，采样越随机）。这给了模型创造力，也给了它“一本正经地编造”的自由度：同一个问题问两遍，可能得到两个不同的答案，其中一个是编的。
- **知识冲突与长上下文遗忘**：训练数据内部存在互相矛盾的说法时，模型可能混着用；输入很长时，模型可能丢掉关键约束、按自己的“惯性”续写。给定的输入越复杂，模型偏离输入的可能性越大。

按与输入的关系，幻觉常分两类：**内在幻觉**——输出与给定的输入直接矛盾（例如摘要里出现了原文没有的数字）；**外在幻觉**——输出无法从给定输入验证（例如凭空给出一个真实存在的引用出处，却与原文无关）。内在幻觉可以用对照输入的方法发现，外在幻觉更难，因为它需要外部知识才能证伪。

### 3.2 可解释性的含义

可解释性问的是“模型为什么给出这个输出”，按范围与方式可以这样理解：

- **全局解释 vs 局部解释**：全局解释问“模型整体按什么规律工作”（例如哪些特征总体上最重要）；局部解释问“对这一个输入，模型为什么给出这个输出”。两者回答的问题不同，不能互相代替。
- **内在可解释 vs 事后解释**：内在可解释的模型（例如浅层决策树、线性模型）结构本身就是可读的；复杂模型（例如深度神经网络、大语言模型）结构不可读，只能事后用额外方法去近似解释它。事后解释回答的是“一个简化模型如何看待这个决策”，不等于模型真实的内部过程——这个区分是理解 4.2 节各类方法局限的关键。

## 4. 分类/关键方法

### 4.1 缓解幻觉的思路

没有任何一种方法能消除幻觉，实践中是多层防线叠加：

- **检索增强生成（RAG）**：回答之前先从可信的知识库里检索相关资料，把资料作为输入的一部分交给模型，让模型“照着资料答”而不是“凭记忆答”。这是目前最常用的缓解手段：它把问题从“模型记不记得”变成了“资料里有没有”。但 RAG 只能缓解，不能根除——检索到的资料本身可能过时、错误或不相关，模型也可能无视资料、继续按记忆编造。
- **引用来源**：要求模型在回答中标明每条关键断言的来源，让使用者能顺着引用去核对原文。引用本身也要核验：模型会编造看起来真实的书名、链接与页码，引用格式正确不等于引用真实存在。
- **约束解码与降低随机性**：对事实性要求高的任务降低采样温度、限制采样范围，让输出更确定、更保守。代价是回答多样性下降，只适用于“求稳不求新”的场景。
- **自我核验与多模型交叉检查**：让模型复核自己的回答、或用另一个模型检查关键事实。能筛掉一部分低级错误，但核验者与被核验者共享同一套训练数据与偏见，系统性错误筛不出来。
- **人工核验与使用边界**：高风险输出（医疗建议、法律文书、财务决策）必须经过人核验才能采用；同时明确告知使用者模型的知识截止时间与能力边界。技术防线之外，流程与人的防线不可少。

### 4.2 可解释性方法

- **特征重要性**：衡量每个输入特征对输出的影响程度。常用做法有排列重要性（打乱某一特征的值，看模型表现下降多少）与 SHAP 值（按博弈论中的 Shapley 值，把一次预测的“功劳”分摊到各个特征上）。这类方法适合表格数据与结构化输入，对语言模型的高维输入解释力有限。
- **注意力可视化及其局限**：把 Transformer 模型中注意力权重画出来，看模型在生成某个词时“关注”了输入的哪些部分。直观，但局限很大：注意力权重高不等于那个输入真的决定了输出，注意力权重低也不等于没影响；已有研究指出注意力权重不能直接当作解释使用（见文末来源 Jain 与 Wallace，2019）。注意力图可以辅助调试，不能作为“模型为什么这么说”的证据。
- **事后解释方法**：LIME（在待解释样本附近用简单、可解释的模型局部拟合复杂模型的行为）与 SHAP（见上）是最常用的两种。它们的共同点是“近似”：解释的是复杂模型在局部的行为，不等于模型全局的真实机制。解释结果本身也可能不稳定——换个参数、换个采样，解释可能变样。
- **反事实解释**：回答“输入改成什么样，输出就会变”。例如“如果这份简历的工作年限多两年，模型就会通过”。反事实解释对使用者最友好——它直接告诉人“要改变结果该改变什么”，在信贷、招聘等场景里常被用作向被拒者说明理由的方式。
- **探针与内部表示分析**：用辅助分类器探测模型内部某一层是否编码了特定信息（例如句法结构）。这是研究方法，主要用于理解模型，不直接服务于终端用户。

## 5. 典型应用

- **问答与摘要**：用 RAG 与引用来源降低幻觉，摘要类任务用内在幻觉检查（对照原文核对数字与人名）发现编造。
- **客服与助手**：对事实性问题约束解码、接知识库，对开放性问题保留创造力；两种任务用不同的温度与核验强度。
- **医疗与法律辅助**：模型输出只作草稿与参考，所有结论必须经专业人员核验；引用来源是这类场景的硬性要求，不是可选项。
- **模型调试**：可解释性方法用于定位模型系统性错误的原因——例如发现模型依赖的是背景而非主体、是措辞而非事实，从而针对性地修数据或改训练。
- **合规与申诉说明**：反事实解释用于向被模型拒绝的申请人说明“改变什么可以改变结果”，满足可解释的合规要求。

## 6. 限制与常见误解

- **“用了 RAG 就不会幻觉了”**：错。RAG 降低幻觉的发生率，不消除它。检索资料可能过时、错误、不相关，模型也可能无视资料自行编造。RAG 之后仍需引用核验与人工抽查。
- **“注意力图就是模型的解释”**：错。见 4.2 节：注意力权重不等于因果影响，把注意力图当作“模型这么想的证据”是过度解读。
- **“事后解释等于模型真实的推理过程”**：错。LIME、SHAP 这类方法是局部近似，解释的是简化模型的行为；解释本身可能不稳定、不忠实。解释可以辅助理解与调试，不能作为模型决策正确的证明。
- **“模型说得很自信，就说明它是对的”**：错。语言模型的自信来自语言流畅度，不是事实把握度。幻觉内容往往表述得比真实内容更自信、更流畅。
- **“可解释性越高，模型就越好”**：不一定。可解释性与模型能力之间常有取舍：最简单的模型最可解释，但能力往往不够；强行要求复杂模型“可解释”，得到的可能是好看但不忠实的解释。选什么解释方法，要看解释是给谁用的、用来做什么决定。
- **幻觉与创造力的边界**：同一个采样机制既是写诗、写代码时的创造力来源，也是编造事实时的幻觉来源。不能既要模型天马行空、又要它在事实上滴水不漏——任务不同，解码策略与核验强度就要不同。

## 7. 小结

幻觉源于“优化语言流畅而非事实正确”的训练目标、知识截止与解码采样，RAG、引用、约束解码与人工核验能缓解但不能消除；可解释性分全局与局部、内在与事后，特征重要性、注意力可视化、LIME/SHAP 与反事实解释各有适用场景与局限，注意力权重不等于解释、事后解释不等于模型真实的推理过程。
