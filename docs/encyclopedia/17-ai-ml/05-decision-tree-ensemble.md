# 决策树与集成方法：会提问的模型，与“三个臭皮匠”

## 1. 一句话定义

决策树是按特征取值一层层提问、把样本一路分到叶节点再做预测的模型；集成方法是把许多个这样的弱模型按装袋、提升等方式组合起来、让整体比单个更准更稳的一类方法。

## 2. 为什么需要它

[线性回归与逻辑回归](04-linear-logistic-regression.md)只能表达线性关系，但现实里的规律常常是“分段”的：收入低于某条线时逾期率陡增、超过某条线后又趋平；某种症状组合出现时才指向某种诊断。决策树天生适合这种“如果……那么……”的分段规律：它不需要假设线性，不需要特征标准化，能同时处理数值与类别特征，单棵树画出来就是一张人能读懂的流程图。

但单棵树有个致命弱点：太容易“背答案”——长得足够深的树能把训练集分到每个叶节点只有一个样本，训练分数满分，新数据上一塌糊涂，而且换一批数据，分出来的树可能面目全非。集成方法就是为治这个弱点而生的：不依赖某一棵树，而是让许多棵树投票或接力，把单棵树的不稳定平均掉、把单棵树的偏差一点点纠掉。表格数据上的强模型，至今大多出自这个家族。

## 3. 核心含义

### 3.1 决策树怎么提问：切分、节点与叶

一棵决策树由三种部件组成：

- **内部节点**：一次提问，例如“年龄 > 30 吗？”“天气是晴天吗？”每个节点按一个特征的一处切分把样本分成两组或多组。
- **分支**：提问的答案指向下一层节点。
- **叶节点**：不再提问的地方，落到这里的样本共享一个预测值——分类任务取多数类别，回归任务取均值。

建树的过程是递归切分：从全部样本出发，每次选一个“最能把样本分纯”的特征与切分点，分完对每组重复这个过程，直到满足停止条件（叶节点样本太少、纯度已够高、达到最大深度）。“分纯”的标准有两个经典度量：

```text
信息熵  H = −Σ pᵢ·log₂ pᵢ        （pᵢ 为第 i 类样本占比，越混乱熵越大）
基尼不纯度  Gini = 1 − Σ pᵢ²     （随机猜两个样本类别不同的概率）
信息增益  = 父节点熵 − 切分后子节点熵的加权平均
```

切分时选信息增益最大（或基尼下降最多）的那个特征与切分点。ID3 用信息增益，C4.5 用信息增益率（纠正信息增益偏爱取值多的特征的毛病），CART 用基尼不纯度——三者是同一思想的不同度量，细节是后续深入篇的范围。

下面这段代码用纯 Python 手算了一次信息增益，演示数据是 14 条“天气（晴 / 雨）→ 是否打球（1 打 / 0 不打）”的编造样本，真实运行输出附后：

```python
import math
# 演示数据（编造，仅用于演示信息增益的计算过程）
weather = ['晴','晴','晴','晴','晴','雨','雨','雨','雨','雨','晴','雨','晴','雨']
y =       [1,   1,   0,   1,   0,   0,   0,   1,   0,   0,   1,   0,   1,   0]
def entropy(labels):
    n = len(labels)
    return -sum((c/n)*math.log2(c/n) for c in (labels.count(0), labels.count(1)) if c)
def gini(labels):
    n = len(labels); p1 = sum(labels)/n
    return 1 - p1**2 - (1-p1)**2
base = entropy(y)
gain = base - sum(
    len([yy for w, yy in zip(weather, y) if w == v]) / len(y)
    * entropy([yy for w, yy in zip(weather, y) if w == v])
    for v in ('晴', '雨'))
print(f"base entropy={base:.3f}")
print(f"info gain (weather)={gain:.3f}")
print(f"gini all={gini(y):.3f}")
```

```text
base entropy=0.985
info gain (weather)=0.258
gini all=0.490
```

读法：切分前 14 条样本的信息熵是 0.985（接近 1，几乎一半一半）；按天气切分后，信息增益是 0.258——天气这个特征确实带来了一些信息，但远没到“分干净”的程度，真实建树还要继续拿其他特征往下分。同样是编造的演示样本，不代表任何真实规律。

### 3.2 单棵树的软肋：过拟合与剪枝

树长得越深，训练误差越低，但泛化误差先降后升——这是[机器学习基础](01-ml-basics.md)第 5 节说的过拟合在树模型上的样子。治它的手段叫**剪枝**，分两种：

- **预剪枝**：长树时提前刹车——限制最大深度、叶节点最少样本数、切分所需最小增益。简单直接，但可能刹早了：一次切分本身增益不大、下一层却很关键的分支会被误杀。
- **后剪枝**：先让树长满，再自底向上把“剪掉后验证集表现不降反升”的子树剪成叶节点。效果通常更好，代价是多一轮验证。

剪枝的本质与[模型训练与评估](03-model-training-evaluation.md)的早停一致：用复杂度换泛化，判断标准永远是验证集，不是训练集。

### 3.3 集成的两种思路：并行平均与串行纠错

集成方法不是“多棵树”这一个做法，而是两条思路：

- **装袋（Bagging，并行）**：从训练集中有放回地抽样，训出多棵结构不同的树，再投票（分类）或平均（回归）。每棵树都见过不同的数据子集、犯不同的错，平均之后方差下来了，偏差基本不变。它的目标是**降方差、治不稳定**。
- **提升（Boosting，串行）**：一棵接一棵地训，后一棵专门纠前一棵的错：分错的样本在下一轮获得更大权重（AdaBoost），或下一棵直接去拟合前一棵的残差（梯度提升）。它的目标是**降偏差、治欠拟合**，但对噪声与异常值更敏感——噪声样本也会被当成“错”反复纠。

|  | 装袋（Bagging） | 提升（Boosting） |
|---|---|---|
| 训练方式 | 并行，各棵树独立 | 串行，后一棵纠前一棵的错 |
| 主要作用 | 降方差，治单棵树不稳定 | 降偏差，治单棵树能力不足 |
| 对噪声 | 相对稳健（平均掉了） | 相对敏感（噪声也被当错纠） |
| 典型代表 | 随机森林 | AdaBoost、梯度提升 |

### 3.4 随机森林：装袋 + 随机选特征

随机森林是装袋的代表做法，在两处加随机性：每棵树用的训练样本是自助抽样（bootstrap，有放回抽样）得到的子集；每个节点切分时，只从随机抽取的一小部分特征里挑最好的切分点，而不是看全部特征。

第二处随机是关键：它逼每棵树用不同的特征提问，树与树之间的相关性下来了，平均的效果才好。随机森林还有一个附赠品——**袋外数据（OOB）**：每棵树总有约三分之一的样本没被抽中，这些样本可以直接用来估计泛化误差，不用再单独划验证集。代价是：森林整体不再是一张能读懂的流程图，可解释性退化成“特征重要性”这种统计量（见第 6 节的提醒）。

### 3.5 梯度提升：顺着残差往下走

梯度提升是提升的代表做法，思路是：先训一棵简单的树，再训下一棵去拟合当前整体的残差（预测与真实值的差距），把新树按一个小于 1 的学习率（收缩系数）加进来，重复多轮。每一轮都在“上一次错在哪”这个方向上修正，轮数越多拟合越深——因此轮数本身就是控制过拟合的超参数，配合学习率与树的深度一起调，调参方法见[超参数调优与交叉验证](12-hyperparameter-tuning-cross-validation.md)。

AdaBoost、梯度提升是算法思想；XGBoost、LightGBM、CatBoost 是梯度提升思想的工程实现，在速度、内存与稀疏数据处理上做了大量优化，名字不同、思想同源。选型时先分清“思想”与“实现”这两个层次，再比较实现之间的工程差异。

### 3.6 投票与堆叠：集成的另外两种组合方式

- **投票（Voting）**：多个不同种类的模型（例如逻辑回归 + 决策树 + 支持向量机）各自预测，少数服从多数或按概率平均。模型之间差异越大，投票收益越大；模型都犯同一个错时，投票帮不上忙。
- **堆叠（Stacking）**：用第一层多个模型的预测结果作为新特征，再训一个第二层模型（元模型）来做最终预测。能力更强，但结构更复杂、泄露风险更高（第一层预测必须用交叉验证产出，不能直接用训练集上的拟合值），细节待后续深入篇。

## 4. 分类与关键方法

| 方法 | 家族 | 核心思想 | 适用场景 |
|---|---|---|---|
| 决策树（CART / ID3 / C4.5） | 单模型 | 递归切分，分到叶节点预测 | 规律分段、可解释性优先的小模型 |
| 随机森林 | 装袋集成 | 自助抽样 + 随机选特征，多树投票 / 平均 | 表格数据分类回归的稳健基线 |
| AdaBoost | 提升集成 | 加大分错样本权重，串行纠错 | 弱分类器组合、二分类 |
| 梯度提升 | 提升集成 | 后一棵拟合前一棵的残差 | 表格数据上精度要求高的场景 |
| XGBoost / LightGBM / CatBoost | 梯度提升的实现 | 工程优化的梯度提升 | 大规模表格数据、竞赛与工业界常用 |
| 投票 / 堆叠 | 通用集成 | 多类模型组合 | 模型差异大、单模型已到瓶颈时 |

选型经验：表格数据先上随机森林或梯度提升当强基线；要可解释先看单棵树（深度受限的）；数据有噪声先考虑装袋，数据干净、要榨精度再考虑提升。调参目标主要是树的深度、树的数量与学习率，见[超参数调优与交叉验证](12-hyperparameter-tuning-cross-validation.md)。

## 5. 典型应用

- **信用风控与反欺诈**：输入收入、负债、历史行为等表格特征，输出逾期或欺诈概率；树模型对分段规律与类别特征友好，是这类场景的常用强手，阈值与指标取舍见[模型训练与评估](03-model-training-evaluation.md)。
- **医疗分诊与辅助诊断**：按症状与检查指标层层判断，单棵树的流程图形式便于医生复核；集成模型用于提精度时，必须保留人工复核环节。
- **推荐与搜索排序的特征模型**：梯度提升常用来给候选内容打分排序，输入是用户、内容与上下文特征，输出是点击或转化概率。
- **工业故障诊断与预测性维护**：传感器读数分段变化时触发不同分支，树模型对这类阈值型规律敏感；异常样本少时要配合类别不平衡的处理。

## 6. 限制与常见误解

- **单棵树极不稳定**：换一批训练数据，分出来的树可能完全不同——这是方差高，不是数据错了。稳定性要靠集成或剪枝换，不是靠多调几次参数。
- **树模型不能外推**：叶节点的预测值是训练样本的均值或多数类，输入超出训练范围时，预测值停在最边缘叶节点的值上不再变化。房价随面积“一直涨”的趋势，树模型学不会——这是它与[线性回归与逻辑回归](04-linear-logistic-regression.md)的根本区别之一。
- **“随机森林不会过拟合”是误解**：它比单棵树稳健得多，但树很深、噪声很大时仍会过拟合；树的数量增加主要降方差，深度与叶节点大小才是控制过拟合的旋钮。
- **特征重要性会骗人**：两个高度相关的特征会互相分走重要性，单个特征的重要性被低估；取值多的特征在切分时天然占优。看重要性要结合相关性一起看，不要只看一张排序图。
- **集成模型的可解释性大幅下降**：几百棵树的投票结果无法画成一张流程图；高风险场景要配事后解释工具或人工复核，不能只报一个分数。
- **提升对噪声敏感**：数据里标签标错的样本会被提升反复当成“错”来纠，越纠越偏；噪声大的数据先清洗、或优先用装袋。
- **“集成总比单模型好”是误解**：数据量小、规律简单、延迟要求高时，单棵树或逻辑回归可能更好；集成要付训练与推理成本，收益要实测验证，不是免费午餐。

## 7. 小结

决策树是按特征取值层层提问、分到叶节点预测的模型，单棵可解释但不稳定、易过拟合；集成用装袋降方差、用提升降偏差，随机森林与梯度提升是表格数据上的两大强手；边界同样清楚——树模型不能外推、集成牺牲可解释性、提升怕噪声，选型要按数据与场景实测决定。
