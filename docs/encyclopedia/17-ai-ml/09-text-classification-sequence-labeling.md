# 文本分类与序列标注：任务方法与微调思路

## 1. 一句话定义

文本分类是给整段文本贴一个或多个标签，序列标注是给文本里的每个词（或字）贴一个标签；前者判断“这段文本是什么”，后者判断“文本里每个位置是什么”。

## 2. 为什么需要它

自然语言处理里的大多数落地任务，落到最后都是这两件事。判断一封邮件是不是垃圾邮件、一段评论是正面还是负面、一篇新闻属于哪个栏目——都是文本分类。从一段文本里抽人名、地名、机构名（命名实体识别），给每个词标词性（词性标注），做分词——都是序列标注。

两者分开讲的理由很实际：输出形态不同，建模难点就不同。文本分类的输出是一个标签，难在“整段文本的意思怎么浓缩成一个判断”；序列标注的输出是一串标签，难在“标签之间互相制约”——“北京大学”里“北京”是地名开头，后面跟的“大学”就不能再标成另一个实体的开头。不知道这个区别，就会拿分类的方法硬套标注任务，结果在边界上错得一塌糊涂。

## 3. 核心含义

### 3.1 文本分类：整段文本，一个判断

输入是一段文本，输出是标签空间里的一个（单标签分类）或多个（多标签分类）标签。情感分析（正面 / 负面）、主题分类（体育 / 财经 / 娱乐）、垃圾邮件识别（是 / 否）都是单标签分类；一篇文章同时属于“科技”和“商业”两个栏目，就是多标签分类。

经典流程分三步：**表示 → 汇聚 → 分类**。先把文本变成向量（词向量或预训练模型表示，见[词向量与语言模型](08-word-embeddings-language-models.md)），再把不定长的词序列汇聚成一个定长向量（取平均、取最大值，或取 BERT 的 [CLS] 位置向量），最后接一个分类器输出各标签的概率。表示决定上限，汇聚决定信息损失，分类器只是最后一层。

### 3.2 序列标注：每个位置，一个标签

输入是一段文本，输出是与输入等长的标签序列。每个位置的标签既要看这个词本身，也要看前后词与前后标签。常用 BIO 标注法：B 表示一个实体的开头，I 表示实体的内部，O 表示不属于任何实体。例如：

```text
词：   北  京  大  学  位  于  海  淀  区
标签：  B-LOC I-LOC I-LOC I-LOC O   O   B-LOC I-LOC O
```

“北京大学”被标成一个地点实体（B-LOC 后跟 I-LOC），“海淀区”是另一个地点实体。BIO 的关键是边界：B 与 I 的区别就是“新实体开始了还是上一个没结束”，标错一个 B，整个实体的边界就错了。

### 3.3 两者的关系

文本分类是“一段文本一个标签”，序列标注是“每个位置一个标签”。序列标注可以看作“带顺序约束的逐位置分类”——约束来自标签之间的转移规律（I-LOC 前面不能是 B-PER，O 后面不能直接出现 I-LOC），这是第 4.2 节 CRF 要处理的核心。反过来，文本分类里常用的“先表示、再分类”思路，在序列标注里也一样，只是分类发生在每个位置上。

## 4. 分类/关键方法

### 4.1 文本分类方法：从词袋到预训练微调

- **词袋与 TF-IDF + 线性模型**：把文本看成词的集合（不计顺序），按词频或 TF-IDF 加权成向量，接逻辑回归或支持向量机。简单、快、可解释，在主题分类这类“关键词就能定胜负”的任务上至今够用；短板是丢了词序与语义，“不喜欢”与“喜欢”只差一个“不”，词袋分不出来。
- **词向量平均 + 分类器**：把词向量取平均作为文本向量，再分类。比词袋多了语义信息，仍丢词序，适合做快速基线。
- **卷积 / 循环网络分类器**：卷积抓局部词组（“非常 好”这样的搭配），循环网络按顺序读文本、把状态传下去。两者都保留了词序信息，是预训练时代之前的主流；长文本上循环网络仍有长程依赖衰减的问题。
- **预训练模型微调**：在 BERT 等预训练模型后接一个分类头，用任务数据微调全部参数（思路见 4.3 节）。当前大多数文本分类任务的首选，代价是算力与推理成本高于传统方法。

### 4.2 序列标注方法：标签之间的约束是关键

- **逐位置独立分类**：每个位置单独判断标签，不考虑前后标签。最简单的基线，边界错误多：模型可能在同一个实体中间突然换一个标签，因为它不知道上一个位置标了什么。
- **隐马尔可夫模型（HMM）**：生成式模型，假设当前标签只依赖上一个标签、当前词只依赖当前标签。结构简单、训练快，但“当前词只依赖当前标签”的假设太强，上下文特征用不上，精度上限低。
- **条件随机场（CRF，2001 年，Lafferty 等人）**：判别式模型，直接建模“给定整句，整串标签”的条件概率。它同时用两类信息：每个位置的词与标签的匹配程度（发射特征），以及相邻标签之间的转移合理性（转移特征）。解码时用维特比算法找整句概率最高的标签序列，而不是每个位置贪心取最高分——全局最优的序列才不会出现“I-LOC 开头”这种非法组合。CRF 是序列标注的经典方法，至今仍常作为神经网络模型之上的解码层（BiLSTM-CRF）。
- **神经网络序列标注**：BiLSTM 或 Transformer 编码器给每个位置算上下文表示，再接 CRF 层或 Softmax 层输出标签。表示能力强，CRF 层补上标签转移约束，两者结合是命名实体识别等任务的常用结构。

### 4.3 BERT 微调思路：不是从头训，是接着训

微调是预训练范式的核心用法，思路分四步：

1. **选预训练模型**：按任务语言与领域选——中文任务选中文预训练模型，领域术语多的任务（如医疗、法律）优先考虑领域预训练模型，而不是直接拿通用模型硬上。
2. **加任务头**：文本分类在 [CLS] 位置向量后接一个线性分类层；序列标注在每个位置的向量后接一个标签分类层（或 CRF 层）。任务头是新加的，随机初始化；底座是预训练好的，带着通用语言知识。
3. **小学习率、全参数更新**：微调通常用比从头训练小得多的学习率更新全部参数，目标是“在保留通用知识的前提下适配任务”，而不是把底座推倒重来。学习率太大，预训练的知识会被迅速冲掉（灾难性遗忘）；太小，任务适配不到位。
4. **防过拟合**：任务标注数据通常只有几千到几万条，远少于预训练语料，微调几轮就容易过拟合。常用手段是早停（验证集指标回升即停，机制见[模型训练与评估](03-model-training-evaluation.md)）、较小的训练轮数，以及只微调顶层若干层。

一句话定位：微调不是“用 BERT 重新学任务”，而是“让已经懂语言的模型，花少量数据学会任务的输出格式与判断标准”。

### 4.4 评估指标：分类看混淆矩阵，标注看实体级 F1

指标定义本身见[模型训练与评估](03-model-training-evaluation.md)第 4.3 节，这里只讲两个任务各自的取舍：

- **文本分类**：先看数据构成再选主指标。类别平衡时准确率可用；类别不平衡时看精确率、召回率与 F1。多分类时分清两种平均：宏平均（macro）是每类 F1 先算再平均，小类与大类权重相同；微平均（micro）是先汇总所有类的 TP、FP、FN 再算 F1，大类主导结果。小类表现重要时看宏平均，只关心整体时看微平均。
- **序列标注（命名实体识别）**：标准指标是**实体级 F1**，不是词级准确率。实体级 F1 要求实体的边界与类型同时正确才算对——“北京大学”整体标对得一分，只标对“北京”不得分。词级准确率会虚高：句子里大部分位置是 O，全部预测 O 就有很高的准确率，却一个实体都没抽出来。报告 NER 结果时，必须说明是实体级 F1，并同时报告精确率与召回率。

下面这段代码用纯 Python 算了一组命名实体识别演示数据的实体级精确率、召回率与 F1（示例未实测）：

```python
# 演示数据：每项为 (预测实体集合, 真实实体集合)，实体用 (起始位置, 结束位置, 类型) 表示
cases = [
    ({(0, 4, "LOC"), (6, 9, "LOC")}, {(0, 4, "LOC"), (6, 9, "LOC")}),  # 全对
    ({(0, 2, "LOC")}, {(0, 4, "LOC")}),                               # 边界错一半，不得分
    ({(0, 3, "PER")}, {(0, 3, "LOC")}),                               # 类型错，不得分
]
tp = sum(len(p & t) for p, t in cases)
pred_total = sum(len(p) for p, t in cases)
true_total = sum(len(t) for p, t in cases)
precision = tp / pred_total
recall = tp / true_total
f1 = 2 * precision * recall / (precision + recall)
print(f"TP={tp} 预测总数={pred_total} 真实总数={true_total}")
print(f"precision={precision:.2f} recall={recall:.2f} f1={f1:.2f}")
```

```text
TP=2 预测总数=4 真实总数=4
precision=0.50 recall=0.50 f1=0.50
```

三组演示里只有第一组全对：边界错一半、类型错的实体在实体级计分里都不得分——这正是实体级 F1 比词级准确率严格的地方。

## 5. 典型应用

- **情感分析与舆情监控**：判断评论、帖子的情感倾向，是文本分类最常见的落地；多标签版本可同时判断情感与提到的产品方面。
- **垃圾邮件与内容审核**：二分类判断是否为垃圾、违规内容；误报（正常内容被拦截）与漏报（违规内容放行）的代价不同，指标取舍按场景定（见[模型训练与评估](03-model-training-evaluation.md)第 4.4 节）。
- **命名实体识别**：从新闻、病历、合同里抽人名、地名、机构名、时间，是信息抽取与知识图谱构建的第一步，输出直接决定下游可用性。
- **分词与词性标注**：中文分词本质上是序列标注（每个字标“词首 / 词中 / 词尾”），词性标注是给每个词标语法类别，两者都是下游句法分析、机器翻译的前置步骤。

## 6. 限制与常见误解

- **“准确率高就是模型好”**：类别不平衡时，全猜多数类就能刷出高准确率；序列标注里全猜 O 也一样。先看数据构成与混淆矩阵，再看精确率、召回率与 F1。
- **“逐位置分类就够了，CRF 是多余的”**：没有标签转移约束，模型会在实体边界上犯低级错误；CRF 或其他全局解码的价值正在于把“整串标签合不合理”算进去，不是装饰。
- **“微调就是把 BERT 当特征提取器”**：只取 BERT 向量、后面接个分类器而不更新 BERT 参数，那叫特征提取，不是微调。微调的含义是任务数据反向更新预训练参数，两者效果与成本都不同，不要混用名词。
- **“数据少，微调几轮总比不训强”**：标注数据太少时，微调很容易过拟合到训练集的 quirks 上，验证集指标反而下降。数据少时先考虑少样本方法、数据增强或规则基线，不要默认微调一定赢。
- **“实体级 F1 低就是模型差”**：标注标准本身会影响分数——嵌套实体、边界歧义（如“北京大学”算一个实体还是两个）在不同标注规范下答案不同。跨数据集比较 F1 之前，先确认标注规范是否一致。

## 7. 小结

文本分类给整段文本贴标签，序列标注给每个位置贴标签；分类的难点在表示与汇聚，标注的难点在标签之间的转移约束，CRF 与全局解码正是为后者而生；BERT 微调是“小学习率、全参数更新、早停防过拟合”的适配过程，不是重新训练；评估时分类看宏/微平均 F1，命名实体识别只认实体级 F1。
