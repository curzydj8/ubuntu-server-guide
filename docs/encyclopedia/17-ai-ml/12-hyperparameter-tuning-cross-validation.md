# 超参数调优与交叉验证：怎么挑模型，而不是猜模型

## 1. 一句话定义

超参数调优是在验证集或交叉验证上系统地比较超参数组合、挑出泛化最好的那一组；交叉验证是把数据轮换着切成训练与验证、多次评估取平均，让这个比较结论更稳的方法。

## 2. 为什么需要它

[模型训练与评估](03-model-training-evaluation.md)里讲过分工：参数是模型自己学的（权重、偏置），超参数是人定的（学习率、层数、正则化强度、训练轮数）。问题在于，人定的这些数对结果影响极大：同一个模型，学习率差十倍，可能一个收敛、一个发散；正则化强度差十倍，可能一个过拟合、一个欠拟合。靠经验猜几个组合、只在一次划分上比一次，结论既不可靠也不可复现。

更麻烦的是评估本身的噪声：[模型训练与评估](03-model-training-evaluation.md)第 5 节说过，留出法快但方差大——换一种划分方式，哪个超参数组合“最好”可能就变了。数据量越小，这个问题越严重。调优需要两个东西配合：一个搜索超参数组合的办法，和一个比单次划分更稳的评估办法。前者是调优方法，后者就是交叉验证。

## 3. 核心含义

### 3.1 调优的目标：验证误差，不是训练误差

调优比较的是超参数组合在**验证数据**上的表现，不是训练集上的表现。训练误差只会随着模型变复杂一路下降，拿它选超参数，永远会选到最复杂的那一组——也就是过拟合最严重的那一组。调优的优化目标是泛化误差的估计，验证集与交叉验证都是这个估计的不同做法。

### 3.2 参数与超参数的分界线

- **参数**：训练过程中由优化算法更新的量，如权重与偏置。调参数靠梯度下降。
- **超参数**：训练开始前由人设定、训练过程中不变的量，如学习率、批量大小、网络层数、正则化强度。调超参数靠“训多个模型、比较验证分数”。

这条线不是绝对的：有些量可以在两个角色之间转换（例如训练轮数既是训练过程的一部分，也常被当作超参数用早停来控制）。分界的标准是“谁在训练循环里更新它”，而不是名字。

### 3.3 交叉验证的思想：轮换着验证，取平均

交叉验证不增加数据，它增加的是**评估的次数**。把数据切成 K 份，轮流拿一份做验证、其余 K−1 份做训练，得到 K 个验证分数，最后取平均。每个样本恰好被验证一次，每次训练用的数据量也差不多，因此平均后的分数比单次划分的分数更稳，结论对“怎么切”的依赖更小。

代价是算力：要训 K 个模型，成本是单次训练的 K 倍。这是交叉验证最核心的取舍——用算力换评估的可信度。

### 3.4 嵌套交叉验证：调参与最终评估要分开

[模型训练与评估](03-model-training-evaluation.md)第 4.5 节讲过，验证集参与了选择，分数会被乐观化。交叉验证也有同样的问题：如果用同一套交叉验证既挑超参数、又报告最终成绩，成绩同样被乐观化——因为超参数是按这套验证挑出来的。

正确做法是**嵌套**：外层交叉验证负责最终评估，内层交叉验证负责调优。外层的每一折里，内层先挑出超参数，再用挑好的超参数在外层验证折上评估。最终报告的是外层各折的平均——这个分数没有参与过任何选择，才是可信的最终成绩。嵌套交叉验证的成本是外层折数 × 内层折数次训练，很贵，只在数据量小、结论要求严的时候用；数据量大时，留出法加独立测试集通常够用。

## 4. 分类与关键方法

### 4.1 超参数搜索方法

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 网格搜索 | 把每个超参数列出候选值，全部组合训一遍 | 简单、可复现、能并行 | 组合数随超参数个数指数增长；大量算力浪费在不重要的超参数上 |
| 随机搜索 | 在给定范围里随机采样组合，训固定次数 | 同样预算下通常优于网格（Bergstra 与 Bengio，2012）；实现简单 | 结果带随机性；仍不利用历史结果 |
| 贝叶斯优化 | 用历史结果拟合一个代理模型，预测哪个组合值得一试，再按采集函数选下一个点 | 评估昂贵时效率高；会利用历史信息 | 本身有超参数；高维、离散超参数上效果打折；实现比前两者复杂 |

三者的选择看评估成本：单次训练便宜（几分钟以内），网格或随机搜索够用；单次训练昂贵（几小时、一个大模型），贝叶斯优化省下的评估次数值回它的复杂度。一个常见的经验是：超参数里通常只有少数几个真正重要，随机搜索因为不把预算平均分给每个维度，更容易撞到重要维度的好取值——这是随机搜索优于网格搜索的主要原因，不是运气。

贝叶斯优化的工作方式可以一句话说清：它维护一个“超参数组合 → 验证分数”的近似模型（常用高斯过程），每次挑“预测分数高、或不确定性大”的下一个组合去真实评估，再把结果喂回模型。利用（挑预测好的）与探索（挑不确定的）之间的平衡由采集函数控制。

### 4.2 交叉验证方法

- **K 折交叉验证**：切成 K 份轮换验证。K 常取 5 或 10：K 越大，每次训练数据越多、评估偏差越小，但成本越高、K 个分数之间的重叠越大。分类任务要用**分层 K 折**：每折里各类别的比例与全量一致，否则某折可能缺一个类别，分数失真。
- **留一法（LOO）**：K 等于样本数，每次只留一个样本做验证。训练数据量最大、偏差最小；但要训 N 次，成本极高，且每次验证只有一个样本，单次分数方差极大。只适合样本极少、模型训练极便宜的场景。
- **重复 K 折**：换不同的随机划分重复做 K 折，再平均。进一步压低“划分方式”带来的方差，成本再翻倍。
- **留出法**：不是交叉验证，但要放在一起比较：一次划分，最快、最省算力，结论最依赖划分方式。数据量大时通常够用。

### 4.3 时间序列划分：不能随机切

时间序列数据（股价、销量、传感器读数）有一条硬规则：**验证集的时间必须晚于训练集**。随机切分会让模型用未来的数据“预测”过去，评估分数虚高，部署后原形毕露——这是[模型训练与评估](03-model-training-evaluation.md)第 4.1 节讲的时间泄露在交叉验证里的版本。

正确做法是**滚动原点（rolling origin）**：训练集从起点开始，验证集取紧接着的一段时间；下一折训练集向后扩展一段，验证集再取下一段。验证窗口始终在训练窗口之后，时间顺序全程保持。scikit-learn 的 `TimeSeriesSplit` 就是这个做法。分组数据同理：同一用户、同一病人的样本要用**分组 K 折**，整组进同一折，不能拆散（同源泄露，见[模型训练与评估](03-model-training-evaluation.md)第 4.1 节）。

### 4.4 一个可跑通的演示：网格搜索 + 5 折交叉验证

下面这段代码用 numpy 手算岭回归（闭式解），在 60 条合成数据（`y = sin(x) + 噪声`）上对正则化强度 λ 做 5 折交叉验证网格搜索。本机实测输出附后（Python 3.12.3、numpy 1.26.4，scikit-learn 未安装，故未用 `GridSearchCV`）：

```python
import numpy as np
rng = np.random.default_rng(0)
x = rng.uniform(0, 2*np.pi, 60)
y = np.sin(x) + rng.normal(0, 0.3, 60)

def poly_design(x, deg):
    return np.vander(x, deg+1, increasing=True)

def ridge_fit(X, y, lam):
    d = X.shape[1]
    A = X.T @ X + lam*np.eye(d); A[0,0] -= lam  # 不罚截距项
    return np.linalg.solve(A, X.T @ y)

def mse(X, y, w):
    return float(np.mean((X @ w - y)**2))

def kfold_cv_mse(x, y, deg, lam, k=5):
    idx = np.arange(len(x))
    fold_mses = []
    for f in range(k):
        va = idx[f::k]; tr = np.setdiff1d(idx, va)
        w = ridge_fit(poly_design(x[tr], deg), y[tr], lam)
        fold_mses.append(mse(poly_design(x[va], deg), y[va], w))
    return float(np.mean(fold_mses)), [round(m, 4) for m in fold_mses]

for lam in [0.0, 0.01, 0.1, 1.0, 10.0, 100.0]:
    mean_mse, folds = kfold_cv_mse(x, y, 9, lam)
    print(f"lam={lam}: cv_mse={mean_mse:.4f} folds={folds}")
```

```text
lam=0.0: cv_mse=0.1372 folds=[0.0367, 0.2346, 0.0961, 0.1785, 0.1399]
lam=0.01: cv_mse=0.1130 folds=[0.036, 0.1403, 0.0943, 0.1546, 0.1398]
lam=0.1: cv_mse=0.1073 folds=[0.0354, 0.1293, 0.0927, 0.1396, 0.1395]
lam=1.0: cv_mse=0.1037 folds=[0.0349, 0.1189, 0.0909, 0.1353, 0.1384]
lam=10.0: cv_mse=0.1066 folds=[0.0378, 0.1293, 0.087, 0.1454, 0.1333]
lam=100.0: cv_mse=0.1083 folds=[0.043, 0.1128, 0.0803, 0.1751, 0.1303]
```

两个值得注意的点：第一，平均交叉验证误差随 λ 呈 U 形，最优点在 λ=1.0 附近（0.1037），λ 太小与太大都更差——调优找的就是这个 U 形的谷底；第二，各折分数差异很大（0.035 到 0.23），这正是单次划分不可靠的证据：只看某一折，结论会完全不同。

## 5. 典型应用

- **正则化强度与学习率的选择**：这是调优最常见的用途。λ、学习率这类连续超参数靠网格或随机搜索在验证集上比较，见第 4.4 节演示。
- **模型选型**：同一任务上比较多个模型（如不同深度的树、不同结构的网络）时，用同一套交叉验证、同一个评估指标比较，结论才可比。
- **小数据下的稳健评估**：数据量小时留出法方差太大，K 折交叉验证是默认做法；样本极少时再考虑留一法或自助法。
- **时间序列模型验证**：滚动原点划分是时间序列任务唯一不泄露的评估方式，预测类任务上线前必须走这一套。

## 6. 限制与常见误解

- **“交叉验证的分数就是最终成绩”**：错。用来挑超参数的交叉验证分数已被乐观化，最终成绩要留独立测试集，或用嵌套交叉验证的外层分数。见第 3.4 节。
- **“K 越大越好”**：K 大只减小偏差，不减小方差到零；留一法的单次验证只有一个样本，方差反而大，成本还高。K=5 或 10 是经验折中，不是标准。
- **“贝叶斯优化一定比随机搜索好”**：评估便宜时，随机搜索简单可靠，贝叶斯优化的建模开销不值；评估昂贵、高维离散超参数多时，贝叶斯优化的优势也会缩水。没有通吃的搜索方法。
- **“调参能解决一切”**：调参只能在给定数据与模型家族里找最优点。数据有偏、特征不对、泄露未除，调参只会把错误结论调得更精确。数据与特征问题要先解决，见[机器学习基础](01-ml-basics.md)第 7 节。
- **“交叉验证能消除数据泄露”**：不能。交叉验证只解决“评估不稳”，不解决“划分方式本身错了”。时间随机切、分组拆散、同源样本混进两边，这些泄露在交叉验证里照样发生，而且会被 K 次重复放大成“稳定的错误结论”。

## 7. 小结

超参数调优是在验证数据上系统比较超参数组合，目标是泛化而不是训练分数；交叉验证用轮换划分取平均，让比较结论更稳，代价是 K 倍算力；时间序列必须按时间滚动划分，随机切分就是泄露；用来挑参的验证分数不能当最终成绩，最终裁决要留测试集或嵌套交叉验证。
