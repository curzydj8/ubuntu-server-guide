# 内存层次与缓存

## 1. 本章目标

读完本篇，能说清为什么计算机要有好几层存储、缓存为什么能让慢速主存“显得快”，以及程序员的写法怎样影响缓存命中。

## 2. 背景与问题

CPU 一秒能执行几十亿次操作，但主存（内存条）一次访问要上百个时钟周期；如果每次取数都等主存，CPU 大部分时间都在空转。另一方面，容量大的存储天生慢、贵的小容量存储天生快——**速度、容量、成本三者不可兼得**。内存层次就是用“分层 + 复制热点数据”的办法，调和这组矛盾。

## 3. 总体架构：金字塔

从上到下，速度变慢、容量变大、单位成本变低：

```
  速度快 ▲
          │  ┌──────────────┐
          │  │ 寄存器        │ 容量最小（KB 级）、CPU 内部、1 周期
          │  ├──────────────┤
          │  │ L1 缓存       │ 每核心独享，分指令 L1i 与数据 L1d
          │  ├──────────────┤
          │  │ L2 缓存       │ 每核心独享，容量大于 L1
          │  ├──────────────┤
          │  │ L3 缓存       │ 多核心共享，容量更大
          │  ├──────────────┤
          │  │ 主存（内存条） │ GB 级，百周期级延迟
          │  ├──────────────┤
          │  │ 外存（SSD/HDD）│ TB 级，毫秒级延迟（相对最慢）
  速度慢 ▼  └──────────────┘
```

关键思想只有一句：**上层是下层的缓存（副本），不是替代**。寄存器里的数据来自 L1，L1 来自主存，主存里的数据来自外存；数据在各层之间按需上下流动。

## 4. 工作机制

### 4.1 命中与缺失

CPU 要一个数据时，先查 L1：**命中**就直接用，几个周期；**缺失**就向下一层要，层层下探直到主存甚至外存，代价逐层放大。缺失时通常不是只取要的那几个字节，而是取一整块（缓存行，一般 64 字节）——多取一点，是为下一次访问铺路。

### 4.2 局部性原理：缓存之所以有效的根本原因

- **时间局部性**：刚用过的数据，很可能马上再用（循环变量、栈顶）。
- **空间局部性**：刚用过的数据附近的数据，很可能马上要用（数组顺序遍历）。

缓存策略（取整行、预取、替换）本质上都是在赌局部性。程序员的写法直接决定这场赌局的胜率：顺序遍历数组命中率高，跳跃式随机访问命中率低——同样的算法，访问顺序不同，实测速度可以差出数量级。

### 4.3 写策略与一致性

- **写直达（write-through）**：写缓存同时写下一层，简单但写操作慢。
- **写回（write-back）**：只写缓存，标记为“脏”，等缓存行被替换时才写回下层，快但断电丢数据风险由下一层机制兜底。
- **多核一致性**：多个核心的 L1/L2 各有副本时，某核改了数据，其他核的旧副本必须失效或更新，否则程序读到 stale 数据。MESI 等一致性协议就是干这个的；程序员一般不用直接处理，但要知道“多线程共享变量为什么需要同步”——根子就在这里。

## 5. 关键设计取舍

- **缓存行大小**：行越大，一次缺失带回的数据越多，空间局部性收益越大；但行太大又会带回用不上的数据，浪费带宽。
- **相联度**：全相联最灵活但电路贵；直接映射最简单但冲突多；组相联是主流折中。
- **容量分配**：L1 求快必须小（离核心近、延迟低），L3 求命中率可以大（共享、延迟容忍度高）。每一层的大小都是延迟与命中率的交换。

## 6. 分类与变体

- 按位置：片上缓存（L1/L2/L3）与片外主存、外存。
- 按独享/共享：L1/L2 每核心独享，L3 多核心共享。
- 按存储介质：SRAM（快、贵、用于缓存）与 DRAM（慢、便宜、用于主存）；外存分 SSD（闪存）与 HDD（机械盘），延迟与随机访问性能差出几个数量级。
- 特殊变体：TLB（地址翻译的缓存）、 victim 缓存、预取器——原理同属“用小快存加速大慢存”，不展开。

## 7. 应用与限制

- 应用：理解缓存是理解性能优化的钥匙——数组遍历顺序、结构体布局、循环分块、避免伪共享，都直接对应缓存行为。
- 限制：缓存不能解决一切——工作集远大于缓存时命中率必然低；随机访问、超大流式数据对缓存不友好；缓存一致性与安全还有另一面：Spectre、Meltdown 这类漏洞正是利用了“缓存状态会泄露访问痕迹”这一点（防御细节属 10 域，本篇不展开）。
- 常见误解：
  - “内存越大越快”：错。容量解决“装得下”，速度看延迟与带宽；内存容量不足会换页变慢，但够用之后再加容量对速度帮助有限。
  - “缓存是另一份内存”：错。缓存是副本，掉电即失，且与主存之间有严格的同步规则。
  - “L3 越大越好”：不全面。还要看延迟、功耗、成本，以及工作集是否真的需要那么大。

## 8. 可核验示例：用 free 与 getconf 看本机的存储层次数字

> 环境：Ubuntu 24.04，普通用户权限，只读命令，无风险。以下输出为本文写作时在代理 VM 上实际运行的结果；不同机器数字不同，命令通用。

```bash
free -h
grep -E '^(MemTotal|MemAvailable|Cached)' /proc/meminfo
getconf -a 2>/dev/null | grep -i 'CACHE'
```

实际输出：

```
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       7.5Gi       152Mi       424Mi       742Mi       228Mi
Swap:             0B          0B          0B
MemTotal:        8124908 kB
MemAvailable:     233852 kB
Cached:           705804 kB
LEVEL1_ICACHE_SIZE                 32768
LEVEL1_ICACHE_ASSOC
LEVEL1_ICACHE_LINESIZE             64
LEVEL1_DCACHE_SIZE                 49152
LEVEL1_DCACHE_ASSOC                12
LEVEL1_DCACHE_LINESIZE             64
LEVEL2_CACHE_SIZE                  1048576
LEVEL2_CACHE_ASSOC                 16
LEVEL2_CACHE_LINESIZE               64
LEVEL3_CACHE_SIZE                  33554432
```

怎么读：这台 VM 的主存约 7.7GiB；L1 指令缓存 32KiB、数据缓存 48KiB，L2 1MiB，L3 32MiB，缓存行 64 字节——与上一篇 `lscpu` 的缓存行一致。注意 `free` 里 `available`（228Mi）远小于 `total`，是因为当时 VM 内存占用已高；读 `free` 要看 available 而不是 free，这是新手最容易误读的一点。另注意：这是虚拟机视角，宿主机真实缓存拓扑可能不同。
