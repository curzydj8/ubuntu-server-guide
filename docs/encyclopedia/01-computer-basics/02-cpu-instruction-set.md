# CPU 组成与指令集

## 1. 本章目标

读完本篇，能说清 CPU 由哪几部分组成、一条指令是怎么被执行下去的，以及指令集架构（ISA）与具体芯片之间的区别。

## 2. 背景与问题

上一篇搭出了门、加法器、寄存器，但一台机器要能“按程序自动算”，还缺三样东西：第一，谁来发号施令、按什么顺序取指令；第二，算数与判断由谁做；第三，程序员看到的机器长什么样——程序员写代码时面对的不是门电路，而是一套指令。CPU 的组成与指令集就是这三件事的答案。

## 3. 总体架构

一颗典型 CPU 的核心部件（文字结构图）：

```
                ┌─────────────┐
  内存 ──总线──▶│  控制单元 CU  │──控制信号──▶ 各部件
                │  （取指、译码、│
                │   发控制信号）│
                └──────┬──────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│  寄存器组    │ │  ALU        │ │  程序计数器  │
│  （通用寄存 │ │  （加减、逻辑│ │  PC（下一条  │
│   器、状态） │ │   运算、比较）│ │   指令地址） │
└─────────────┘ └─────────────┘ └─────────────┘
```

- **控制单元（CU）**：取指令、译码、按节拍发出控制信号，是指挥部。
- **算术逻辑单元（ALU）**：做加减乘除、逻辑运算、比较、移位，是干活的车间。
- **寄存器组**：CPU 内部最快的少量存储，存操作数、中间结果、状态标志。
- **程序计数器（PC）**：永远指向下一条要取的指令地址，是“顺序”本身的硬件化。

## 4. 工作机制：一条指令的旅程

经典五步（取指、译码、执行、访存、写回），以“把内存某数加 1 写回去”为例：

1. **取指（IF）**：PC 给出地址，控制单元从内存（经缓存，见下一篇）取回指令，PC 自增指向下一条。
2. **译码（ID）**：控制单元按操作码查表，知道“这是加法、操作数在哪、结果放哪”，并产生控制信号。
3. **执行（EX）**：ALU 按控制信号完成运算；地址类指令则算出访存地址。
4. **访存（MEM）**：只有读/写内存的指令走这一步，纯寄存器运算跳过。
5. **写回（WB）**：结果写入目标寄存器（或经 MEM 后写回）。

现代 CPU 在此基础上加了**流水线**：五步像工厂流水线一样重叠进行，不同指令处在不同阶段，同一时刻有 5 条指令在跑。流水线的问题是**冒险**：后一条指令等前一条的结果（数据冒险）、跳转打断取指（控制冒险）时，流水线要停顿或冲刷，这是“CPU 频率不等于每周期一条指令”的根本原因之一。

## 5. 关键设计取舍

- **复杂指令 vs 精简指令（CISC vs RISC）**：CISC（如 x86）一条指令能做很多事，硬件译码复杂；RISC（如 ARM、RISC-V）指令简单规整，译码容易、流水线顺畅，复杂功能由多条指令组合。两者没有绝对胜负，是历史与生态的取舍。
- **通用寄存器多 vs 少**：寄存器越多，中间结果越不用跑内存，但编码操作数要占更多指令位、上下文切换保存成本越高。
- **硬件做多少 vs 软件做多少**：例如复杂寻址、字符串操作，硬件做快但芯片复杂；软件做灵活但指令条数多。ISA 划定这条线，改动它就意味着换一代生态。

## 6. 分类与变体：指令集架构（ISA）

ISA 是程序员可见的机器 contract：指令编码、寄存器、寻址方式、内存模型。同一 ISA 可以有不同厂商、不同微架构的实现；反过来，换 ISA 就要重新编译全部软件。

| ISA | 风格 | 典型地盘 | 要点 |
|---|---|---|---|
| x86-64 | CISC | 桌面、服务器 | 历史最久，兼容包袱最重，向后兼容是其生命线 |
| ARM（AArch64） | RISC | 手机、平板、越来越多服务器 | 能效比突出，授权模式使其遍布各厂商 |
| RISC-V | RISC、开放 | 嵌入式、研究、部分服务器 | 指令集本身开放免授权，模块化扩展是其设计特色 |

注意区分三个层次：**ISA（规范）→ 微架构（某厂商某代的实现）→ 芯片（产品）**。说“ARM 芯片快”时，通常指的是某代微架构与工艺，不等于 ARM 这个 ISA 本身永远快。

## 7. 应用与限制

- 应用：一切通用计算的执行核心；理解 CPU 组成是读懂性能问题（为什么缓存、分支预测、向量指令影响速度）的前提。
- 限制：CPU 不是万能加速器——大规模并行算术（图形、AI 推理）更适合 GPU/专用加速器；CPU 的强项是复杂控制流与通用任务。
- 常见误解：
  - “核心数翻倍速度就翻倍”：错。并行收益受任务可并行比例限制（Amdahl 定律），且受内存带宽制约。
  - “主频越高越好”：错。还要看每周期指令数（IPC）、缓存、功耗墙；高主频常伴随高功耗与降频。
  - “指令集决定性能”：不全面。微架构、缓存、工艺、编译器同样决定最终表现。

## 8. 可核验示例：用 lscpu 看一台真实机器的 CPU 面貌

> 环境：Ubuntu 24.04，普通用户权限，只读命令，无风险。以下输出为本文写作时在代理 VM 上实际运行的结果；**这是虚拟机的视角**（vCPU 与宿主机拓扑有关），不是物理硬件参数，不同机器输出不同，命令本身通用。

```bash
lscpu | grep -E '^(Architecture|Model name|CPU\(s\)|Thread|Core|Socket|L1d|L1i|L2|L3)'
grep -m1 'model name' /proc/cpuinfo
grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(sse4_2|avx|avx2|avx512f|aes|popcnt)$'
```

实际输出：

```
Architecture:                            x86_64
CPU(s):                                  4
Model name:                              AMD EPYC 9D25 126-Core Processor
Thread(s) per core:                      1
Core(s) per socket:                      4
Socket(s):                               1
L1d cache:                               96 KiB (2 instances)
L1i cache:                               64 KiB (2 instances)
L2 cache:                                2 MiB (2 instances)
L3 cache:                                32 MiB (1 instance)
model name	: AMD EPYC 9D25 126-Core Processor
sse4_2
popcnt
aes
avx
avx2
avx512f
```

怎么读：架构 x86_64、4 个 vCPU、型号 AMD EPYC；flags 里的 `avx`/`avx2`/`avx512f` 说明这颗 CPU 支持向量指令扩展，`aes` 说明有 AES 硬件加速指令——程序用到对应指令集时，编译器与运行库会据此选择优化路径。缓存三行的含义见下一篇。
