# 硬件选型与评测方法

## 1. 一句话定义

硬件选型是按“用途、负载、硬约束”列出需求，用可验证的评测而不是广告与跑分，在候选硬件中做选择的方法。

## 2. 为什么需要它

没有方法，选型很容易被三个东西带偏：第一，跑分榜——它测的是峰值场景，不是你的负载；第二，参数表——核心数、主频、容量单独看都不能决定体验；第三，“一步到位”的冲动——为用不上的性能付钱，还带来功耗、散热、预算的新问题。选型方法的价值不在帮你挑出“最强”的硬件，而在帮你挑出“在你的约束下够用、且你验证过够用”的硬件。

## 3. 核心含义

### 3.1 先写需求，再看产品

按这个顺序列需求，缺一不可：

1. **用途与负载**：这台机器每天实际干什么？静态网站、数据库、虚拟机、编译、视频转码——负载类型不同，瓶颈完全不同。
2. **硬约束**：预算上限、功耗与散热上限、空间与噪音、必须兼容的软件与接口（例如只认 x86 的软件，见指令集对比篇）。
3. **性能指标**：针对负载定 1–2 个主指标（例如“并发请求下的 P95 延迟”“转码一小时视频的耗时”），而不是“越快越好”。
4. **余量与升级路径**：内存插槽、硬盘位、电源余量——今天够用不等于明天够用，但余量也要花钱，要写清为哪类增长留余量。

### 3.2 评测四步

1. **列候选**：按硬约束先筛掉不合格的，再留 2–3 个候选，不要一开始就列十个。
2. **对照表**：按同一维度对比候选（CPU、内存、存储、功耗、接口、软件兼容），格子写事实，不写“更好”这类判断词。
3. **实测验证**：用自己的负载或最接近的基准测一次，同一条件、多次取平均，看持续性能不只看峰值；虚拟机上测出的数字只代表虚拟机视角。
4. **决策记录**：写下“选了谁、为什么、放弃了谁、放弃的原因”，半年后复盘靠这条记录，不靠记忆。

### 3.3 评测时最容易踩的坑

- 只看峰值跑分，不看持续性能：功耗墙与散热墙会让峰值在几分钟后掉下来，服务器与笔记本都常见。
- 只看平均值，不看尾延迟：P95/P99 才是用户体感的来源，平均值好看、尾延迟难看的机器照样卡。
- 在虚拟机上测出数字就当成物理机结论：vCPU 拓扑、超售、邻居负载都会影响结果，虚拟机数字只用于横向比较与演示。
- 忽视软件兼容：指令集、驱动、发行版支持没确认就下单，到货才发现关键软件跑不起来。

## 4. 分类

按选型对象分三类，方法相同、指标不同：

| 对象 | 主指标示例 | 最易忽视的约束 |
|---|---|---|
| 整机 / 服务器 | 负载下的持续性能、功耗、噪音 | 电源余量、散热、硬盘位 |
| CPU | 你的负载的持续性能，不是跑分 | 功耗墙、主板与散热配套、指令集兼容 |
| 存储 | 随机读写、满盘持续写入、TBW | 接口协议（SATA 还是 NVMe）、预留空间、掉电保护 |

## 5. 典型应用

- **家用服务器**：先定服务清单（静态站、监控、备份），再按清单定 CPU、内存、硬盘，轻负载优先低功耗与静音。
- **旧电脑再利用**：先测现有机器的瓶颈（内存还是存储还是 CPU），只换瓶颈部件；换之前确认接口与功耗。
- **开发机选型**：按编译、虚拟机、容器数量定内存与核心数，存储优先 NVMe；显示器与键盘不属于本篇范围。

## 6. 限制与常见误解

- 本方法不替你做购买决策：它只保证决策有依据；价格、供货、售后不在本篇的评测范围内，下单前自行核对。
- 误解一：“核心数翻倍速度就翻倍”：错。并行收益受任务可并行比例与内存带宽限制（CPU 篇已讲）。
- 误解二：“跑分最高就是最适合”：错。跑分负载与你的负载不同时，排名没有指导意义。
- 误解三：“一次买满就是省钱”：不一定。为用不上的性能付的钱、功耗与散热成本，常常超过日后升级的成本。

## 7. 小结

选型 = 写清用途、负载、硬约束 → 列 2–3 个候选 → 同一维度对照 → 用自己的负载实测 → 记下决策理由。跑分是参考，不是判决。

## 8. 对照举例：两台真实机器的方法演示（举例，不是购买建议）

> 本节是方法演示，不是购买建议，也不是两台机器的性能排名。两台机器用途与约束不同，不直接比高低。EPYC 一侧为本文写作时在代理 VM 上的实测快照；6ix9ine 一侧为 2026-10-31 的既往实测数字（Intel i3-3220、内存 3.2GB、硬盘 59GB），引用时已注明来源时间，不同时间复测数值会变。

| 维度 | 代理 VM（EPYC vCPU） | 6ix9ine（i3-3220） |
|---|---|---|
| 用途 | 演示、轻量开发、代理运行环境 | 轻量静态服务、监控、备份 |
| CPU | 4 vCPU，AMD EPYC（虚拟机视角） | 双核四线程 i3-3220（物理机） |
| 内存 | 7.7GiB（实测时 available 约 499Mi，负载已高） | 3.2GB |
| 存储 | 虚拟盘 vdd 150GB（virtio，报告 discard 能力） | 59GB 磁盘，根 LV 28GB |
| 约束 | 虚拟机：拓扑与性能受宿主机影响 | 物理老机器：功耗低但绝对性能有限，无公网 IP |
| 适合 | 不跑重型数据库、大构建、视频转码 | 不跑重型数据库、大构建、AI 推理 |

用方法读这张表：先看“用途”行——两台机器的用途本就不同，所以“谁更快”不是正确问题；正确问题是“各自的用途下，瓶颈在哪”。VM 一侧当前瓶颈是内存可用量（available 远小于 total，见下节命令）；6ix9ine 一侧的瓶颈是 CPU 绝对性能与内存容量。选型时先找到自己机器的瓶颈行，再决定换什么。

## 9. 可核验示例：用三条命令摸清本机的选型基数

> 环境：Ubuntu 24.04，普通用户权限，只读命令，无风险。以下输出为本文写作时在代理 VM 上实际运行的结果；这是虚拟机视角，不同机器、不同时间输出不同，命令本身通用。

```bash
lscpu | grep -E '^(Architecture|Model name|CPU\(s\)|Thread|Core|Socket)'
free -h | head -2
lsblk -d -o NAME,SIZE,ROTA,TRAN
```

实际输出：

```
Architecture:                            x86_64
Model name:                              AMD EPYC 9D25 126-Core Processor
CPU(s):                                  4
Thread(s) per core:                      1
Core(s) per socket:                      4
Socket(s):                               1
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       7.3Gi       175Mi       115Mi       683Mi       499Mi
NAME  SIZE ROTA TRAN
vda   6.9G    1 virtio
vdb   7.5G    1 virtio
vdc   1.2G    1 virtio
vdd   150G    0 virtio
```

怎么读：CPU 4 vCPU、x86_64；内存总量 7.7GiB，但 `available` 只有约 499Mi——读内存要看 available 而不是 free（内存篇已讲）；磁盘是 virtio 虚拟盘，`ROTA` 标志在虚拟机上不可靠（SSD 篇已讲）。这三条命令就是选型第一步“摸清基数”的标准动作：先知道手头机器的真实家底，再谈换什么。
