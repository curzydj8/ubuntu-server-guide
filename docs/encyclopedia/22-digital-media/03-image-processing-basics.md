# 图像处理基础

## 1. 本章目标

读完本篇能理解：一张数字图像在机器里到底是什么、颜色为什么有好几种表示法、以及亮度、模糊、锐化、缩放这些操作在像素层面究竟改了什么、改不回什么。

## 2. 背景与问题

相机、截图、扫描仪给出的都是“像素阵列”，但人要的是“调亮一点”“背景虚化”“放大看清”。图像处理回答的是：像素阵列经过哪些数学操作，能变成想要的样子？以及哪些愿望在数学上根本做不到（例如凭空变出被裁掉的细节）？

## 3. 总体架构

数字图像在机器里的样子：

```
图像 = 宽 W × 高 H 的像素阵列
每个像素 = 若干通道的数值（8 位最常见，每通道 0–255）
一张 1280×720 的 RGB 图像 = 1280 × 720 × 3 字节 ≈ 2.76 MB（未压缩）
```

处理操作的三个层次：

- **点运算**：只看单个像素的值改值（亮度、对比度、反色），不看邻居。
- **邻域运算**：看一个像素及其周围一小片（卷积），算出新值（模糊、锐化、边缘检测）。
- **几何运算**：改像素的位置关系（缩放、旋转、裁剪），需要插值补新位置的值。

## 4. 工作机制

### 4.1 像素与位深

像素是图像的最小单位，但“一个像素存多少信息”由位深决定：

- 8 位每通道：每通道 256 级，RGB 共 1,677 万色，是日常图像的默认规格。
- 10 位每通道：每通道 1,024 级，约 10.7 亿色，渐变更平滑，HDR 流程的起点。
- 位深不够时，平滑渐变会出现一层层的“色带”（banding）：不是显示器坏了，是信息量本身就不够分。

分辨率（W×H）决定细节上限，位深决定色彩细腻度，两者是不同的维度：高分辨率 + 低位深，细节多但渐变照样分层。

### 4.2 色彩空间：同一颜色的几种账本

颜色本身只有一个物理现实，但记录方法有好几种，因为不同环节关心不同的事：

| 色彩空间 | 记录方式 | 用在哪 |
|---|---|---|
| RGB | 红绿蓝三通道 | 屏幕显示、相机直出、图像文件默认 |
| YCbCr（YUV） | 亮度 + 两个色度 | 视频编码（见编码篇的色度抽样）、JPEG |
| CMYK | 青品黄黑四通道 | 印刷（油墨是减色，屏幕是加色，不能直接混用） |
| HSV / HSL | 色相、饱和度、明度 | 取色器、按颜色筛选、直觉式调色 |
| Lab | 亮度 + 两个对立色轴 | 追求“数值差 ≈ 人眼感觉差”的场合，如色差评估 |

**Gamma**：人眼对暗部变化更敏感，屏幕的发光与电压也不是线性关系。sRGB 标准用约 2.2 的 gamma 曲线做非线性编码：存储时暗部多分几级、亮部少分几级，这样 8 位才够用。忽略 gamma 直接对像素做线性运算（如平均两张图），结果会系统性偏暗或偏亮。

**空间转换的代价**：RGB 转 CMYK、广色域转窄色域时，超出目标色域的颜色会被“裁剪”到边界上，信息永久丢失；转回来也回不去。跨空间操作前先确认目标空间装不装得下。

### 4.3 点运算：改值不改位置

- **亮度**：全体像素加（减）一个常数，直方图整体平移；过曝的高光加无可加，会被截断成一片白。
- **对比度**：以中间值为支点拉伸数值间距；拉过头同样截断两端。
- **Gamma 校正**：按幂函数重映射，提亮暗部而不怎么动亮部（或反过来），是“只动暗部”的标准做法。
- **直方图均衡化**：把像素值的分布拉平，让过暗或过亮的图像恢复层次；代价是可能放大噪声、让颜色关系失真，不适合所有图像。

点运算的共同边界：**只能重排已有信息，不能增加信息**。死黑（0）和死白（255）区域里，原本的细节已经没了，任何点运算都找不回来。

### 4.4 邻域运算：卷积核说了算

卷积是把一个小的权重表（卷积核，通常 3×3 或 5×5）滑过整张图，每个新像素等于邻域像素的加权和。换核就换效果：

- **均值模糊**：核内权重全相等，邻域取平均；去噪的同时边缘也糊了。
- **高斯模糊**：权重按高斯分布，越近权重越大；比均值模糊更自然，是降噪、虚化的主力。
- **锐化**：原图 +（原图 − 模糊图）× 系数，即突出高频部分；本质是把边缘两侧的差值放大，系数过大就会出现白边（halo）。
- **边缘检测（Sobel 等）**：核对水平与垂直方向的灰度变化敏感，输出变化剧烈的位置，就是边缘候选；边缘检测输出的是“变化地图”，不是物体轮廓本身。

邻域运算的共同边界：模糊扔掉的是高频细节，扔了就回不来；锐化放大的不只是边缘，还有噪声——先降噪再锐化，是标准顺序。

### 4.5 几何运算：插值决定缩放质量

缩放、旋转后，新像素位置往往落在原像素之间，值从哪来？靠插值：

- **最近邻**：取最近的原像素，速度最快，放大后锯齿明显。
- **双线性**：取周围 4 个像素加权平均，锯齿减轻，细节稍糊。
- **双三次**：取周围 16 个像素加权，质量最好，计算量最大。

插值的共同边界：**插值只能“猜”出平滑过渡，猜不出真实细节**。把 100×100 放大到 1000×1000，画面变大但信息量不变，模糊是必然的；所谓“AI 超分”是用 learned 先验补细节，那是另一类技术（见 17 域），不在本篇范围内。

### 4.6 与压缩的关系（只做引用，不重复）

JPEG 的做法是：RGB 转 YCbCr → 色度抽样 → 分块 DCT → 量化 → 熵编码。DCT 与量化细节见本组编码篇，JPEG 只是把这套机制用在单张图像上。理解本篇的色彩空间与量化边界，就理解了 JPEG“为什么高压缩会出块效应、颜色渗色”的原因。

## 5. 关键设计取舍

- **质量换体积**：位深、分辨率、压缩强度三者共同决定文件大小；动任何一个都要在质量账上还。
- **全局换局部**：点运算改全图，简单但顾此失彼；局部处理（蒙版、选区）精确但复杂，两者常配合使用。
- **自动化换可控**：直方图均衡、一键美化省事，但可能违背意图；专业流程宁可手动分步调。
- **实时换质量**：视频每帧都要处理时，核越大、算法越重，帧率掉得越快；移动端常用查表（LUT）把复杂点运算预先算好，用空间换时间。

## 6. 分类与变体

- 按作用域：点运算（单像素）、邻域运算（小片）、全局运算（整图统计，如直方图均衡）、几何运算（位置）。
- 按可逆性：无损操作（无损裁剪、元数据旋转）与有损操作（绝大多数像素修改）；“无损编辑”通常指保留原图、只存操作记录，而非操作本身可逆。
- 按颜色处理方式：直接改 RGB 三通道（简单但容易偏色）与先转 HSV/Lab 再改亮度/饱和度（更符合人眼感觉）。

## 7. 应用与限制

- **典型应用**：照片调色、扫描件增强、医学与工业图像预处理、视频前处理（降噪、去隔行）、机器视觉的输入清洗。
- **限制总汇**：截断的信息找不回（过曝、死黑、色域裁剪）；模糊扔掉的高频找不回；插值猜不出真实细节；先降噪再锐化、避免反复有损保存，是两条最实用的保真纪律。
- **反复保存的代价**：JPEG 每存一次就重新量化一次，多次编辑保存会叠加损失；工作流里应保留无损中间档，只在最后导出时转一次有损格式。

## 8. 常见误解

- **“分辨率越高越清晰”**：分辨率是上限，镜头、压缩、对焦、噪声都可能是更短的板；高分辨率 + 重压缩，照样糊。
- **“放大能看清车牌”**：插值放大只能平滑，不能恢复拍摄时就没记录的细节；影视剧里的“增强”不是真实技术。
- **“RAW 就是没处理”**：RAW 是传感器的原始读数，未经过机内色彩与锐化处理，但仍需解马赛克、白平衡、Gamma 才能成图；RAW 的优势是保留了处理前的最大信息量。
- **“调亮就能看清暗部”**：暗部如果已经是死黑（值为 0 的一片），调亮只能得到一片灰，没有细节。

## 9. 可核验示例：同一张测试图，PNG 与 JPEG 的体积对比

> 环境：代理 VM（Ubuntu 24.04），ffmpeg 8.1.2。测试图为 ffmpeg 内置 testsrc2 生成的单帧 1280×720 图像（合成测试图，含大量锐利边缘与色块，非真实照片），结论不直接外推到照片。

```bash
ffmpeg -y -f lavfi -i testsrc2=size=1280x720:rate=1:duration=1 -frames:v 1 frame.png
ffmpeg -y -i frame.png -q:v 2 frame-q2.jpg
ffmpeg -y -i frame.png -q:v 8 frame-q8.jpg
```

本文写作时实际运行结果：

```
frame.png：  94,789 字节（PNG，无损）
frame-q2.jpg：103,294 字节（JPEG 高质量，反而比 PNG 大）
frame-q8.jpg： 55,698 字节（JPEG 中等质量，约比 PNG 小 41%）
```

教训有两个：一是“JPEG 一定比 PNG 小”是错的——对锐利边缘多的合成图，高质量 JPEG 的 DCT 系数反而比 PNG 的无损压缩更占地方，体积取决于内容，不取决于格式名；二是 JPEG 的质量档（q:v）才是体积开关，q2 到 q8 体积差近一倍，选档前先看内容类型，照片与合成图的最优档完全不同。
