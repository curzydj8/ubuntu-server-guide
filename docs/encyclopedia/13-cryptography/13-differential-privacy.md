# 差分隐私入门

## 1. 本章目标

读完本篇，能说清差分隐私给出的到底是哪种保证、ε 这个数在公式里起什么作用、为什么“加了噪声”不等于“满足差分隐私”，以及为什么 ε 的取值没有放之四海而皆准的“标准答案”。

## 2. 背景与问题

发布统计数据时，直觉上的“去掉名字就是匿名”早就被证明不够用：攻击者可以把多份已发布统计、公开信息与背景知识拼在一起，反推出某个个体是否在数据集中、甚至还原其记录。差分隐私换了一个思路：**不再争论“发布的数据里有没有个人信息”，而是给“一个人参与或不参与，对发布结果的影响”定一个数学上限**。影响被限住了，个体也就无法从发布结果中被单独拎出来。

这个定义由 Dwork、McSherry、Nissim 与 Smith 在 2006 年的论文《Calibrating Noise to Sensitivity in Private Data Analysis》中形式化。注意它的定位：差分隐私是一种**关于发布机制的数学保证**，不是一种数据脱敏手法，也不是“把数据弄模糊一点”的泛称。

> 本篇只讲原理与正确应用，不讲任何从已发布统计中反推个体信息、绕过噪声机制或窃取隐私的操作方法。差分隐私的价值恰恰在于让这类反推在数学上被限住。

## 3. 总体架构

差分隐私讨论的是一次“发布”：

```
原始数据集 D ──随机化机制 M──▶ 发布结果（如统计表、模型参数）
   │
   └─ 相邻数据集 D′：与 D 只差一个人的记录
        要求：M(D) 与 M(D′) 的输出分布“几乎一样”
```

“几乎一样”由参数 ε（epsilon）量化。直觉是：**看发布结果的人，无法判断你到底在不在数据集中**——因为你在与不在，发布结果的分布几乎没有变化。

## 4. 工作机制

### 4.1 ε-差分隐私的定义

一个随机化机制 M 满足 ε-差分隐私，如果对于任意两个只差一条记录的数据集 D、D′，以及任意输出集合 S，都有：

```
Pr[M(D) ∈ S] ≤ e^ε × Pr[M(D′) ∈ S]
```

读法：一个人加入或退出数据集，任何一个输出结果出现的概率至多变为原来的 e^ε 倍。ε 越小，这个倍数越接近 1，保护越强；ε 越大，允许的变化越大，保护越弱。ε = 0 意味着输出分布完全不受任何个体影响——那也意味着输出与数据无关、毫无用处，所以实际取值总是在隐私与可用性之间折中。

常用的放宽版本是 (ε, δ)-差分隐私：允许上述不等式以一个极小的概率 δ 被打破。δ 必须远小于 1/n（n 为记录数），否则“小概率打破”本身就可能对应着某些个体的泄露。只报 ε、不报 δ、不报隐私单位的“差分隐私”宣称，都是不完整的宣称。

### 4.2 敏感度：噪声要按“一个人能改变多少”来定

在加噪声之前，必须先算**敏感度（Sensitivity）**：一个人（一条记录）最多能让查询结果改变多少。

- 计数查询的敏感度是 1：一个人加入或退出，总人数至多变 1。
- 求和查询的敏感度取决于单条记录的取值上限：如果一个人最多贡献 10，敏感度就是 10，噪声也要相应放大 10 倍。
- 敏感度算错（例如漏算了一个人可贡献多条记录的情况），整个保证就跟着错。这是实现中最常见的失误来源之一。

### 4.3 拉普拉斯机制：最经典的加噪办法

拉普拉斯机制的做法是：**真实答案 + 从拉普拉斯分布中抽取的噪声**，噪声的尺度（scale）= 敏感度 / ε。

```
发布值 = 真实值 + Lap(敏感度 / ε)
```

计数查询（敏感度 1）时，ε = 1 对应噪声尺度 1，ε = 0.5 对应尺度 2，ε = 2 对应尺度 0.5——ε 越小噪声越大，这正是 4.1 节“ε 越小保护越强”的操作含义。其他机制各有适用场景：高斯机制配合 (ε, δ)-差分隐私（在机器学习训练中常见），指数机制用于输出非数值选项（如“选哪一项”）的场景；本篇不展开它们的公式，只说明“按场景选机制、按敏感度定噪声”这个通用原则。

### 4.4 隐私预算：会花光，也会叠加

ε 有一个预算性质：**组合（Composition）**。对同一数据集做两次 ε₁ 与 ε₂ 的发布，总隐私损失按基本组合定理是 ε₁ + ε₂——预算是累加的，不是每次重新算。实际系统里更精细的组合会计（例如按零集中差分隐私等变体记账）能把累加速度放缓，但“发布越多、总损失越大”这个方向不变。

由此得到两个实践结论：

1. **隐私单位必须先说清楚**：保护的是“一条记录”还是“一个人一天的全部数据”还是“一个人全部历史数据”？单位越大、保护越强、代价也越大。比较两个 ε 数字之前，必须先确认它们的隐私单位、δ、组合口径是否相同，否则数字没有可比性。
2. **预算要集中记账**：没有全局账本、任由各团队各自发布的系统，等于没有预算。预算分配（哪些查询分多少）本身就是一次需要公开论证的设计决策。

### 4.5 本机实测：拉普拉斯机制的数值演示

下面是真实运行过的演示（环境：代理 VM，Python 3.12.3，固定随机种子，仅作教学演示）。假设某疾病的真实患病人数为 100，计数敏感度为 1：

```python
import math, random
random.seed(20261104)
def laplace(scale):
    u = random.random() - 0.5
    return -scale * math.copysign(math.log(1 - 2 * abs(u)), u)
true_count = 100
for eps in (0.5, 1.0, 2.0):
    scale = 1.0 / eps  # 计数敏感度为 1
    noisy = [round(true_count + laplace(scale)) for _ in range(5)]
    print(f"epsilon={eps}, scale={scale}, noisy={noisy}")
```

实际输出：

```
epsilon=0.5, scale=2.0, noisy=[99, 102, 101, 100, 102]
epsilon=1.0, scale=1.0, noisy=[104, 99, 100, 98, 100]
epsilon=2.0, scale=0.5, noisy=[101, 100, 101, 98, 97]
```

三点说明，演示本身不证明差分隐私（单次运行的几个数字证明不了分布性质），它只展示两件事：第一，噪声尺度确实随 ε 增大而缩小；第二，在真实计数较大时，单次发布的相对误差可能很小——差分隐私保护的是“个体是否在其中”这个区分能力，不是“发布值必须离真值很远”。另请注意：演示用的是 Python 普通随机数，仅供教学；**生产实现必须用密码学安全的随机源与经过审查的差分隐私库，自己手写噪声抽样极易在随机源、浮点精度或敏感度上出错**。

## 5. 关键设计取舍

- **隐私 vs 可用性**：ε 越小，个体保护越强，但发布结果越偏离真值；小群体、稀有属性的统计受影响最大——这正是隐私最需要保护、数据最难用的地方，没有免费午餐。
- **中心式 vs 本地式**：中心式由可信的持有方在汇总后加噪，噪声效率高，但要信任持有方；本地式由每个用户在设备端先加噪再上传，不需要信任持有方，但同样精度下噪声大得多。两者保护的前提完全不同，不能拿本地式的 ε 与中心式的 ε 直接比较。
- **一次发布 vs 持续发布**：预算有限时，是把预算花在少数高价值统计上，还是摊薄到大量查询上，取决于发布目标；摊得越薄，单个结果越不准。
- **形式保证 vs 实现风险**：定义本身是数学的，但实现要过随机源、敏感度、预算记账、访问控制等多道关。NIST SP 800-226《Guidelines for Evaluating Differential Privacy Guarantees》（2025 年 3 月）把评估组织成一座“金字塔”：顶层是 ε、δ 等参数，中层是算法与实现是否会破坏保证，底层是数据收集与信任模型——只看顶层数字就采信一个宣称，是不够的。

## 6. 分类与变体

| 类别 | 一句话特征 |
|---|---|
| 纯 ε-差分隐私 | 无 δ 例外，最严格的经典定义 |
| (ε, δ)-差分隐私 | 允许 δ 概率的例外，换取更实用的机制（如高斯机制） |
| 中心式（Central） | 持有方汇总后加噪，噪声效率高，需信任持有方 |
| 本地式（Local） | 用户端先加噪再上传，不信任持有方，噪声代价大 |
| 用户级 / 事件级 / 记录级 | 隐私单位不同：保护“一个人全部数据”最强，“一次事件”最弱；报 ε 时必须同时报单位 |

## 7. 应用与限制

**ε 取值经验（必须带前提读）**：不存在放之四海而皆准的“好 ε”。教学与小规模演示里常按单次查询取 ε ≤ 1 讨论；但真实发布往往要回答成百上千个查询，总预算随之累加——美国人口普查局 2020 年人口普查选区重划数据（PL 94-171）的生产总隐私损失预算就是 ε = 19.61（其中人口文件 17.14、住房文件 2.47），这个数字本身就说明：脱离“查询数量、隐私单位、组合口径”去评判 ε 是大是小，是没有意义的。各厂商对自家部署公布的 ε 口径不一，**以官方发布为准（待核实）**，本篇不采信厂商宣传口径的横向对比。

典型应用：

- **官方统计发布**：人口普查、公共卫生统计在发布细粒度表格时用噪声代替“压制格子”，兼顾可用性与可量化保证。
- **机器学习训练**：差分隐私随机梯度下降（DP-SGD）在训练时给梯度加噪并记账，让模型参数的发布也带隐私保证；代价是模型精度下降与训练成本上升。
- **遥测与行为统计**：在不收集原始明细的前提下发布 aggregate 使用情况（本地式部署的典型场景）。

限制与常见误解：

- **误解：加了噪声就是差分隐私**：噪声分布、尺度、敏感度、预算记账必须同时满足定义才算；随手加的噪声、事后无法复现记账的噪声，都不构成保证。
- **误解：ε 小就万事大吉**：ε 只管“个体参与与否对输出的影响”，不管数据本身有没有偏见、不管原始数据保管得安不安全、不管发布结果会不会被用于歧视。差分隐私不解决数据质量与用途正当性问题。
- **误解：差分隐私能保护原始数据库**：它保护的是**发布结果**，不是数据库本身。原始数据仍需访问控制与加密保护；无限制的查询接口会让预算迅速耗尽，保证随之失效。
- **限制**：小样本、长尾分布、高维数据的发布效果差；实现错误（敏感度低估、随机源不安全、预算漏记）会悄悄掏空保证，而输出看起来一切正常——这正是评估必须覆盖实现层的原因。

## 8. 小结

差分隐私 = 用 ε 量化“一个人对发布结果的影响上限”，用按敏感度校准的噪声实现它，用预算记账管住多次发布。ε 越小保护越强、结果越不准；比较 ε 之前先对齐隐私单位与组合口径；加了噪声不等于满足定义，实现层面的错误同样会掏空保证。
