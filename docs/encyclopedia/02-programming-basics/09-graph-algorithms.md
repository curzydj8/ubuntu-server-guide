# 图算法入门

## 1. 一句话定义

图是由顶点（节点）与边（节点之间的关系）组成的结构；图算法就是在这类结构上做遍历、找最短路、找最省连接方式、排依赖顺序的方法集合。

## 2. 为什么需要它

很多问题天然就是图：路网（地点是点、道路是边）、任务依赖（任务是点、“先做 A 再做 B”是边）、社交关系（人是点、关注是边）。不用图的语言，这些问题只能写成一堆特设的循环；用图的语言，遍历、最短路、依赖排序都有现成且被证明正确的算法，问题变成“认出这是哪种图问题”。本篇是 [01 篇](01-data-structures-algorithms.md)没有的新主题：01 篇只在分类表中提了一行“图形：邻接表、邻接矩阵”，本篇把这行展开成完整机制。

## 3. 核心含义

### 3.1 图的表示：邻接表与邻接矩阵

同一张图有两种主流存法，代价不同：

- **邻接表**：每个顶点存一份“邻居列表”。空间 O(V + E)，遍历某顶点的邻居只花与其度数成正比的时间；稀疏图（边远少于顶点平方）的默认选择，也是下文示例用的存法。
- **邻接矩阵**：V × V 的二维表，`matrix[u][v]` 表示 u 到 v 是否有边（带权图则存权值）。空间 O(V²)，判断“u 到 v 有没有边”是 O(1)，但遍历邻居要扫整行；稠密图、或需频繁判边存在性的场景才划算。

此外要分清两组正交属性：**有向 vs 无向**（边有没有方向；依赖关系是有向的，朋友关系常作无向处理）、**带权 vs 无权**（边有没有代价；路网里程是带权，好友关系通常无权）。算法的前提条件几乎都写在这两组属性上，选错前提，算法给出的答案可能是错的而非慢的。

### 3.2 遍历：BFS 与 DFS，同一张图两种走法

遍历是所有图算法的地基：从起点出发，每个可达顶点恰好访问一次。

- **BFS（广度优先）**：用队列，先近后远、一层一层扩。机制决定了它在**无权图**中第一次到达某顶点时走的边数最少，因此 BFS 同时给出无权最短路（按边数计）。
- **DFS（深度优先）**：沿一条路走到底再回溯，用栈或递归实现。它不保证最短，但擅长“走遍、探路、判环”：连通分量、环检测、拓扑排序都以 DFS 为骨架。递归版在图很深时可能触及递归栈限制，工程上常改迭代版。

```python
from collections import deque

graph = {"A": ["B", "C"], "B": ["D"], "C": ["D", "E"], "D": [], "E": []}

def bfs(g, s):
    seen, order, q = {s}, [], deque([s])
    while q:
        u = q.popleft(); order.append(u)
        for v in g[u]:
            if v not in seen:
                seen.add(v); q.append(v)
    return order

def dfs(g, s):
    seen, order = set(), []
    def go(u):
        seen.add(u); order.append(u)
        for v in g[u]:
            if v not in seen:
                go(v)
    go(s); return order

print("BFS:", bfs(graph, "A"))
print("DFS:", dfs(graph, "A"))
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
BFS: ['A', 'B', 'C', 'D', 'E']
DFS: ['A', 'B', 'D', 'C', 'E']
```

同一张图，BFS 先访问同层邻居 C 再深入 D，DFS 则沿 A→B→D 一条路走到底再回溯到 C。两种遍历在邻接表上均为 O(V + E)：每个顶点出队（或递归进入）一次，每条边被考察一次。

### 3.3 最短路径：从 BFS 到 Dijkstra，再到 Bellman-Ford

三者的分界线是边的权：

- **无权图**：BFS 就是最短路算法，O(V + E)。权都相等时不要上 Dijkstra，白付对数代价。
- **带权非负图**：**Dijkstra 算法**。维护每个顶点“目前已知的最短距离”，每轮用优先队列取出距离最小的未确定顶点，将其距离“定稿”，再用它去松弛（relax）邻居的距离。贪心成立的关键是非负权：一旦取出的距离最小，就不可能再有更短的路绕过来。带二叉堆实现为 O(E log V)。
- **可能含负权图**：Dijkstra 失效——已定稿的顶点可能经一条负权边被绕出更短的路，算法却不会回头修正。此时用 **Bellman-Ford 算法**：对全部边反复松弛 V−1 轮，时间 O(VE)，更慢，但容忍负权；若第 V 轮仍能松弛，说明存在负权环，此时“最短路”本身无定义（绕环可无限变小），算法以此检测负权环。

```python
import heapq

weighted = {"A": [("B", 4), ("C", 2)], "B": [("D", 3)], "C": [("B", 1), ("D", 5)], "D": []}

def dijkstra(g, s):
    dist = {v: float("inf") for v in g}; dist[s] = 0
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in g[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w; heapq.heappush(pq, (dist[v], v))
    return dist

print("dijkstra from A:", dijkstra(weighted, "A"))
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
dijkstra from A: {'A': 0, 'B': 3, 'C': 2, 'D': 6}
```

注意 B 的距离是 3（A→C→B，2 + 1），不是直连的 4——这正是“经中转更短”的松弛过程。Bellman-Ford 本篇未给实测示例，只讲机制与适用条件。

### 3.4 最小生成树：用最省的边连通所有顶点

对**无向连通带权图**，生成树是“连通全部顶点、无环”的边集；最小生成树（MST）是其中总权最小的一个。图不连通时不存在横跨全图的生成树，只能得到每片连通分量的最小生成森林。两个经典算法都是贪心，且都被证明正确：

- **Kruskal 算法**：把所有边按权从小到大排，依次尝试加入，成环的跳过、不成环的收下。用并查集（Union-Find）判环。时间主要花在排序上，为 O(E log E)。边列表现成的稀疏图用它很自然。
- **Prim 算法**：从任意起点长出一棵树，每轮把“连接树内与树外顶点的最便宜边”接进来，用优先队列实现为 O(E log V)。邻接结构现成、图较稠密时常用它。

```python
edges = [("A", "B", 4), ("A", "C", 2), ("C", "B", 1), ("B", "D", 3), ("C", "D", 5)]
parent = {v: v for v in "ABCD"}

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]; x = parent[x]
    return x

mst, total = [], 0
for u, v, w in sorted(edges, key=lambda e: e[2]):
    if find(u) != find(v):
        parent[find(u)] = find(v); mst.append((u, v, w)); total += w
print("kruskal MST:", mst, "total:", total)
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
kruskal MST: [('C', 'B', 1), ('A', 'C', 2), ('B', 'D', 3)] total: 6
```

注意：最短路与最小生成树是两个不同的问题——最短路是“从起点到各点分别最省”，生成树是“把所有点连起来总共最省”；同一张图上两者的边集一般不同，不要混用。

### 3.5 拓扑排序：给依赖排一个可执行顺序

拓扑排序只针对**有向无环图（DAG）**：把顶点排成一列，使每条边 u→v 都有 u 在 v 之前。图中有环时不存在这样的顺序——环上的任务互相等对方先完成。两种标准做法均为 O(V + E)：

- **Kahn 算法（BFS 式）**：统计每个顶点的入度（指向它的边数），反复取出入度为 0 的顶点（无未满足依赖）、输出并把邻居入度减 1。最后输出的顶点数少于 V，说明剩余顶点困在环里，即检出有环。
- **DFS 式**：顶点在“所有后继都已处理完”时才入栈，最后把栈倒过来。遍历中遇到仍在当前递归路径上的顶点，即检出有环。

```python
from collections import deque

deps = {"wash": [], "dry": ["wash"], "iron": ["dry"], "pack": ["iron", "dry"]}
indeg = {v: len(pres) for v, pres in deps.items()}
adj = {v: [] for v in deps}
for task, pres in deps.items():
    for p in pres:
        adj[p].append(task)
q = deque([v for v in deps if indeg[v] == 0]); order = []
while q:
    u = q.popleft(); order.append(u)
    for v in adj[u]:
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)
print("topo:", order)
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
topo: ['wash', 'dry', 'iron', 'pack']
```

拓扑序一般不唯一（同一层中多个入度为 0 的顶点，先取谁都合法）；要求唯一顺序时需另加规则（如字典序），那是扩展要求，不是算法本身的保证。

## 4. 分类

| 算法 | 问题 | 前提 | 时间（邻接表 / 堆实现） |
|---|---|---|---|
| BFS | 遍历、无权最短路 | 无权（或权相等） | O(V + E) |
| DFS | 遍历、判环、连通分量 | 无 | O(V + E) |
| Dijkstra | 单源最短路 | 带权、权非负 | O(E log V)（二叉堆） |
| Bellman-Ford | 单源最短路、负权环检测 | 带权、可含负权、无负权环才有最短路 | O(VE) |
| Kruskal | 最小生成树 | 无向、连通（否则为森林） | O(E log E) |
| Prim | 最小生成树 | 无向、连通（否则为森林） | O(E log V)（二叉堆） |
| Kahn / DFS 拓扑排序 | 依赖排序、判环 | 有向无环图 | O(V + E) |

其中 V 为顶点数、E 为边数。带权最短路的“单源”指从一个起点到所有顶点；任意两点间的最短路、A* 启发式搜索等不在本篇展开，见文末未完成项。

## 5. 典型应用

- **导航与路网**：带权非负图上的 Dijkstra 是路线规划的经典骨架（实际产品还会加启发式与分层加速，本篇只讲骨架）。
- **构建与任务调度**：编译依赖、CI 流水线、课程先修关系都是 DAG，拓扑排序给出可执行顺序，排不出来即依赖成环。
- **网络布线与聚类**：以最小总成本连通全部节点（布线、管道）是最小生成树问题；Kruskal 与 Prim 按输入形态二选一。
- **社交与推荐**：BFS 的“几度好友”、DFS 的连通分量，都是关系网络分析的起点；无权最短路按边数计，与真实距离无关。

## 6. 限制与常见误解

- **“BFS 的最短路就是真实最短距离”**：错。BFS 只按边数最少，不看权；带权路网必须用 Dijkstra（非负）或 Bellman-Ford（含负权）。
- **“Dijkstra 能处理负权，只要最后答案看着合理”**：错。负权下 Dijkstra 可能静默地给出错误答案而不报错；怀疑有负权时，改用 Bellman-Ford 或先验证权非负。
- **“最小生成树就是最短路的集合”**：错。两者目标函数不同：最短路是单点出发分别最优，生成树是全体连通总代价最优。
- **“拓扑排序的结果唯一”**：错。一般不唯一；同一批入度为 0 的顶点取用顺序不同，结果就不同，但都合法。
- **“图算法只在面试里用”**：错。依赖调度、路由、网络连通性都是生产问题；认不出图结构，才会把现成算法写成难维护的特设循环。

## 7. 小结

图先看表示（邻接表 vs 矩阵）与属性（有向、无向、带权、无权），再看问题：遍历用 BFS/DFS，无权最短路用 BFS，带权非负最短路用 Dijkstra，含负权用 Bellman-Ford，连通最省用 Kruskal 或 Prim，依赖排序用拓扑排序——且有环时拓扑排序不存在。前置的复杂度分析方法见 [01 篇](01-data-structures-algorithms.md)。
