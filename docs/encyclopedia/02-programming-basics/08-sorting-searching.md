# 排序与查找算法

## 1. 一句话定义

排序是把一组元素按给定顺序重新排列；查找是在一组元素中定位目标元素（或其位置区间），其中二分查找是“已排序”这一前提下的对半查找。

## 2. 为什么需要它

无序数据只能逐个比对，规模一上来就慢；一旦数据有序，就能用对半排除、区间定位等手段把查找压到对数级。排序的代价是一次性的，换来的是之后每一次查找、去重、范围查询的便宜。本篇只讲算法机制本身：每种算法怎么动、代价从哪来、有什么硬性前提。**按场景选哪个算法，见 [01 篇](01-data-structures-algorithms.md)第 4.5 节与第 5 节的选型依据，本篇不再重复。**

## 3. 核心含义

### 3.1 比较类排序：只靠“比大小”决定顺序

比较类排序唯一能获得的信息就是“两个元素谁在前”。n 个元素有 n! 种可能排列，每次比较最多排除一半可能，所以任何比较类排序在最坏情况下都至少需要 Ω(n log n) 次比较——这是下界，不是某个算法不够好。归并排序、堆排序达到这个下界，快速排序平均达到它。

- **归并排序（分治）**：把数组对半分开，分别排好，再用一次线性扫描合并两个有序段。合并时始终取两段中较小的一方。代价稳定在 O(n log n)，但合并需要 O(n) 额外空间。
- **快速排序（分治，选基准）**：选一个基准（pivot），把小于它的放左边、大于它的放右边，基准就此落到最终位置，再递归处理左右两段。平均 O(n log n) 且常数小，实际常最快；但基准若总是取到最小或最大值，分段极度不均，最坏退化到 O(n²)。随机选基准、取中位数类策略是常见的缓解手段，不是万能保证。
- **堆排序**：先把数组建成堆（自底向上建堆为 O(n)），再反复取出堆顶最大值放到末尾。时间恒为 O(n log n)，额外空间 O(1)，但堆内跳跃访问缓存友好性差，实测常慢于快速排序。
- **插入排序 / 冒泡排序 / 选择排序**：都是 O(n²) 量级，区别在机制与适用面。插入排序是“把当前元素插进前面已排好的段”，对基本有序的数据，每步移动很少，最好可达 O(n)，这正是它仍被用作小规模子程序的原因；冒泡排序是“相邻交换，把大元素逐步冒泡到末尾”，带提前退出时最好 O(n)，但一般只作教学；选择排序是“每轮选最小值换到前面”，交换次数少，但无论输入如何都要做满比较，最好也是 O(n²)。

### 3.2 两个容易混淆的属性：稳定性与原地性

- **稳定性**：相等元素的相对顺序在排序前后是否保持不变。稳定排序（如归并、插入、计数）适合“多关键字排序”：先按次关键字排，再按主关键字稳定地排，次关键字的顺序不会被打乱。不稳定排序（如常规原地快速排序、堆排序、选择排序）则不保证这一点。
- **原地性**：是否只用 O(1) 额外空间（递归栈一般另计）。快速排序、堆排序、插入排序是原地的；归并排序一般不是，需要 O(n) 合并缓冲。内存受限时，原地性与稳定性往往不可兼得，这正是选型时要同时看的两个维度（选型讨论见 [01 篇](01-data-structures-algorithms.md)）。

下面这段实测同时验证了三件事：归并排序的结果、稳定性（`sorted` 按分数排后，同分元素的原有顺序 `b` 在 `d` 前、`a` 在 `c` 前），以及计数排序的结果。

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

def counting_sort(a):
    counts = [0] * (max(a) + 1)
    for v in a:
        counts[v] += 1
    return [v for v, c in enumerate(counts) for _ in range(c)]

print("merge:", merge_sort([5, 2, 9, 1, 7, 2]))
print("counting:", counting_sort([4, 2, 2, 8, 3, 3, 1]))
pairs = [("a", 2), ("b", 1), ("c", 2), ("d", 1)]
print("stable:", sorted(pairs, key=lambda p: p[1]))
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
merge: [1, 2, 2, 5, 7, 9]
counting: [1, 2, 2, 3, 3, 4, 8]
stable: [('b', 1), ('d', 1), ('a', 2), ('c', 2)]
```

### 3.3 非比较类排序：不比较，靠数据的结构取胜

下界 Ω(n log n) 只约束“只靠比较”的算法。如果键本身有结构（整数、定长串、已知范围），就可以绕开它：

- **计数排序**：键是非负整数且范围 k 已知时，数每个值出现几次，再按次数展开。时间 O(n + k)，空间 O(n + k)（计数数组加输出数组）。k 远大于 n 时（例如 1000 个数却分布在 0 到 10⁹ 之间），计数数组的代价会压倒收益，此时不适用。
- **基数排序**：按位（个位、十位、百位……）逐位排序，每一位用稳定的计数排序作子程序，从最低位排到最高位。时间 O(d(n + b))，其中 d 是位数、b 是基数（如十进制 b = 10）。关键点：**每轮子排序必须是稳定的**，否则高位排序会打乱低位已排好的顺序。
- **桶排序**：把元素按值域分到若干桶，桶内再排序后拼接。输入均匀分布时平均接近 O(n)，但分布不均（全部挤进一个桶）时会退化到桶内排序的代价。

### 3.4 二分查找：前提是“有序”，变体是“边界”

二分查找每步取区间中点，比目标小则丢左半、比目标大则丢右半，区间每次减半，时间 O(log n)。它的硬性前提是**数据已按同一顺序排好**；对无序数据用二分查找，结果是错的，不是慢的。标准版本找到“任意一个”匹配位置；有重复元素时，真正常用的是两个边界变体：

- **下界（lower bound）**：第一个 ≥ 目标的位置，即目标可插入且保持有序的位置，也是第一个匹配位置。
- **上界（upper bound）**：第一个 > 目标的位置，即最后一个匹配位置之后一位。两者相减就是目标的出现次数。

Python 标准库的 `bisect_left` / `bisect_right` 就是这两个变体的实现，日常开发优先用它们，而不是手写边界循环（边界条件最容易写错一位）。

```python
from bisect import bisect_left, bisect_right

arr = [1, 2, 2, 2, 3, 5]
print("bisect 2:", bisect_left(arr, 2), bisect_right(arr, 2), "count:", bisect_right(arr, 2) - bisect_left(arr, 2))
print("bisect 4:", bisect_left(arr, 4), bisect_right(arr, 4))
```

实测输出（Python 3.12.3，本地运行，实测通过）：

```
bisect 2: 1 4 count: 3
bisect 4: 5 5
```

`bisect 4` 的两个值都是 5：4 不在数组中，5 是它保持有序的插入位置，下界与上界在此重合。

## 4. 分类

| 算法 | 最好 | 平均 | 最坏 | 额外空间 | 稳定 |
|---|---|---|---|---|---|
| 冒泡排序（带提前退出） | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 插入排序 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | 否 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n)（递归栈，平均） | 否（常规原地版） |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 |
| 计数排序 | O(n + k) | O(n + k) | O(n + k) | O(n + k) | 是 |
| 基数排序 | O(d(n + b)) | O(d(n + b)) | O(d(n + b)) | O(n + b) | 是（子排序稳定时） |
| 二分查找（已排序） | O(1) | O(log n) | O(log n) | O(1) | 不适用 |
| 线性查找（无序可用） | O(1) | O(n) | O(n) | O(1) | 不适用 |

其中 n 为元素数，k 为计数排序的键范围，d 为基数排序的位数、b 为基数。日常开发的内置排序：Python 的 `sorted()` / `list.sort()` 使用 Timsort（归并与插入的混合自适应算法），稳定，最坏 O(n log n)、基本有序时可达 O(n)、额外空间最坏 O(n)；具体实现细节以官方发布为准（待核实），见文末未完成项。

## 5. 典型应用

- **数据库与搜索引擎**：有序索引让范围查询（找某区间内的全部记录）能用二分定位区间端点，而不是全表扫描。
- **多关键字排序**：先按次关键字、再按主关键字做稳定排序，例如先按姓名、再按成绩排榜单。
- **小范围整数排序**：分数（0–100）、年龄（0–120）这类键范围小的场景，计数排序是线性时间的自然选择。
- **定长键批量排序**：身份证号、IP 地址、固定长度字符串等定长键，基数排序按位处理，避免逐对比较。

## 6. 限制与常见误解

- **“O(n log n) 是排序的绝对下限”**：错。它只是比较类排序的下限；计数、基数、桶排序在满足自身前提时可以更快，前提不满足时则不适用甚至更糟。
- **“二分查找比线性查找永远快”**：错。二分查找要求先排序，排序本身要 O(n log n)；只查一次且数据无序时，直接线性找反而便宜。01 篇已讲过“排序代价一次性、查找收益多次”的取舍逻辑。
- **“快速排序最快，所以默认选它”**：错。平均最快不等于处处最优：要求稳定、要求最坏保证、或内存极度受限时，归并、堆排序各有胜场；日常开发则优先用语言内置排序。
- **“基数排序不用比较，所以不用稳定子排序”**：错。逐位排序的正确性恰恰依赖每一轮子排序的稳定性，否则高位轮次会打乱低位结果。
- **递归深度**：快速排序、归并排序的递归实现在极端输入下递归深度可达 O(n)，可能触及递归栈限制；工程实现常改用迭代或尾递归优化，细节以各语言实现为准（待核实）。

## 7. 小结

排序分两大家族：比较类受 Ω(n log n) 下界约束，拼的是常数、稳定性与空间；非比较类靠键的结构取胜，拼的是前提是否成立。查找分两种前提：无序只能线性找，有序才能二分找，重复元素的定位靠上下界。机制讲清了，选型依据见 [01 篇](01-data-structures-algorithms.md)。
