# GPIO/中断与定时器实务

## 1. 本章目标

读完本篇能理解：GPIO 引脚在实际工程中怎么配置才可靠，外部中断如何触发、如何处理按键抖动，定时器如何实现定时、PWM 与输入捕获，以及看门狗在系统里该怎么“喂”才有意义。

## 2. 背景与问题

01 篇已经讲过 GPIO、中断、定时器各自是什么：GPIO 是通用输入输出，中断让外设“喊”CPU，定时器是计数器。但从“知道是什么”到“用得可靠”之间，还有一层实务要补：引脚悬空为什么读数乱跳，按键按下为什么一次触发了好几次中断，定时器分频和重装值怎么算，PWM 占空比变了电机为什么反而抖，看门狗喂得太勤为什么等于没喂。

这些问题有一个共同点：它们不是概念问题，而是配置与时序问题。同一颗芯片，概念都懂，配置错一位，现象就完全不同。本篇是 01 篇的纵深：01 篇讲“有什么”，本篇讲“怎么配、怎么不出错”。具体芯片的寄存器地址、引脚编号与电气参数一律以官方手册为准，本篇不贴这些细节。

## 3. 总体架构

GPIO、中断、定时器、看门狗在系统里的配合关系（文字结构图）：

```
外部信号 / 负载
    │  输入：按键、传感器电平、编码器脉冲
    │  输出：LED、蜂鸣器、驱动级、指示灯
    ▼
GPIO 引脚层
├── 模式配置：输入 / 输出 / 复用功能
├── 上拉 / 下拉电阻：决定引脚空闲时的默认电平
└── 输出类型：推挽 / 开漏
    │
    ├─ 变化 → 外部中断（EXTI）：边沿触发，进 ISR
    ├─ 计数 → 定时器：定时中断、PWM 输出、输入捕获
    └─ 兜底 → 看门狗：独立计时，超时未喂狗则复位
CPU
├── ISR：只做“标记 + 取数”，重活交给主循环或任务
└── 主循环 / 任务：处理事件、更新状态、喂狗
```

理解这张图的关键是分层：引脚层决定“信号长什么样”，中断与定时器决定“什么时候通知 CPU”，看门狗决定“出问题时谁来兜底”。三层各司其职，不要互相代劳。

## 4. 工作机制

### 4.1 GPIO 输入：先定默认电平，再读信号

输入引脚最常见的故障不是“读不到”，而是“读到的数乱跳”。根源是悬空：一个没有接任何确定电平的输入引脚，相当于一根小天线，会拾取周围噪声，读数在高低之间随机翻转。所以配置输入的第一步不是读，而是先给引脚一个确定的默认电平。

做法有两种：

- **片上上拉 / 下拉**：大多数 MCU 的 GPIO 都内置可配置的上拉或下拉电阻，配置寄存器里选一项即可。按键一端接地、另一端接引脚时，选上拉：平时读到高电平，按下读到低电平；反之，选下拉。片上电阻的优点是省外围器件，缺点是阻值以官方手册为准，抗干扰能力弱于外接电阻，长线或干扰强的场合仍要外接。
- **外接上拉 / 下拉**：对干扰敏感或线较长的信号，外接电阻更可靠；阻值取舍是功耗与抗干扰的平衡，阻值越小抗干扰越强、静态功耗越大，具体取值以官方手册与电路设计为准，本篇不给具体数值。

输入还要区分电平有效性：按键“按下”是低电平有效还是高电平有效，取决于电路接法，不是软件能“规定”的。软件读到的永远是引脚上的实际电平，判断逻辑必须与硬件接法一致；接法与代码各说各话，是调试时最容易被忽略的错位。

### 4.2 GPIO 输出：推挽与开漏，选错会烧引脚

输出模式的核心区别在“拉高”这件事上：

- **推挽输出**：引脚内部上下两个开关轮流导通，主动把电平拉高或拉低。驱动能力较强，适合直接驱动 LED、蜂鸣器这类小负载，也适合输出方波与 PWM。缺点是两个推挽输出绝不能直接对接——一个拉高、一个拉低会形成短路通路。
- **开漏输出**：引脚只主动拉低，拉高靠外部上拉电阻。优点是可以多个开漏输出共用一根线（谁拉低、线就是低，典型如 I2C 总线，见 03 篇），不同电压的设备也能通过上拉到各自电平实现电平转换；缺点是拉高速度受上拉电阻与线电容限制，上升沿比推挽慢，不适合高速方波。

选型口诀：只驱动自家负载、要速度，用推挽；要共线、要跨电平，用开漏。还有一条硬边界，01 篇已提过、本篇再强调一次：引脚驱动电流有上限，具体数值以官方手册为准，大负载（电机、继电器、大功率 LED）必须经过三极管、MOS 管或驱动芯片，绝不能由引脚直驱。

### 4.3 引脚复用：一个引脚，多个身份

几乎所有 MCU 的引脚都是复用的：同一个物理引脚可以是 GPIO，也可以是串口发送、定时器 PWM 输出、ADC 输入等。复用由配置决定，同一时刻只能选一个功能。实务上有三条经验：

- **先查复用表再定板子**：原理图阶段就要确认需要的外设功能有没有对应的引脚可用，而不是先画板再发现 PWM 和串口抢了同一个引脚。
- **复用切换不是免费的**：运行中动态切换引脚功能会引入毛刺与时序窗口，常规做法是在初始化时一次定好，运行中不再改。
- **调试引脚别乱占**：SWD/JTAG 调试引脚常与 GPIO 复用，量产可以复用为 GPIO，但开发阶段占掉它们等于自断调试路，调试口的取舍见 01 篇第 7 节。

### 4.4 外部中断：触发方式选错，事件就丢了

外部中断（EXTI）是“引脚电平变化”触发的中断。配置它要定三件事：

- **触发边沿**：上升沿、下降沿、双边沿。按键接上拉、按下变低电平，选下降沿；要测脉冲宽度，选双边沿，两次中断的时间差就是脉宽；只关心“变了”，选双边沿后在 ISR 里读当前电平判断方向。触发方式必须与信号的实际变化方向一致，否则中断永远不来，或者来得比预期多一倍。
- **中断优先级**：外部中断与其他中断共享优先级体系（见 01 篇 4.3 节）。按键中断优先级一般设得较低，真正紧急的信号（故障关断、过零检测）才配高优先级。优先级不是“越高越保险”，高优先级 ISR 拖长了会饿死低优先级中断。
- **中断标志的清除**：大多数芯片要求 ISR 里手动清除中断挂起标志，忘了清，退出 ISR 会立刻再次进入，造成“中断风暴”——表现为主循环永远跑不起来。清除标志的写法以官方手册为准，不同芯片的清除方式不同，照抄别家代码是常见故障源。

ISR 的纪律与 01 篇一致：短、快、不阻塞，只做“标记 + 取数”。外部中断的 ISR 里尤其不要做去抖延时——延时会堵住所有同级与低优先级中断。

### 4.5 去抖：按键的机械真相

机械按键在按下与松开的瞬间，金属触点会反复弹跳几毫秒到十几毫秒（具体时长以所用按键的规格为准），电平在这段时间里上下翻转多次。如果直接把每次边沿都当作一次按键事件，一次按下会被识别成好几次。去抖就是滤掉这段弹跳，办法有两种：

- **硬件去抖**：在按键两端并联小电容，或用 RC 滤波加施密特触发器，把弹跳在电路层面平滑掉。优点是不占 CPU，缺点是多器件、多成本，改参数要改板子。
- **软件去抖**：第一次边沿触发中断后不立即认定，而是启动一个定时器，延时一段时间（例如 10–20ms，具体以按键规格与实测为准）后再读一次引脚电平：如果电平仍是按下状态，才认定为有效按键。软件去抖的要点是“延时”不能放在 ISR 里做——正确做法是 ISR 只记录“边沿到了”，由定时器中断或主循环在延时后复核电平。

两种办法可以叠加，但不要以为“加了电容就不用软件去抖”：电容只能减弱弹跳，不能保证在所有温度与老化条件下都滤干净。关键场合两种都做，普通按键软件去抖通常已够用。

### 4.6 定时器定时：分频、重装值与中断周期

定时器本质是计数器：每个时钟脉冲计数值加一（或减一），计满就触发动作。配一个周期性定时中断，要定三个参数：

- **时钟源与分频（预分频）**：定时器时钟来自系统时钟经分频器得到。预分频值越大，计数越慢。分频的意义是把计数范围拉到需要的量级：系统时钟几十 MHz 时，不分频计满一个 16 位计数器只要零点几毫秒，想定 1 秒的周期必须先分频。
- **重装值（自动重装载值）**：计数器计到这个值就溢出、触发中断并从头再计。定时周期由“分频后的时钟频率”和“重装值”共同决定，换算关系以官方手册的时钟树说明为准，配错时钟源是“定时总不准”的第一嫌疑。
- **计数器位宽**：16 位计数器最大计 65535，32 位计数器范围大得多。长周期定时优先选 32 位定时器或用软件计数器叠加：定时器每 10ms 中断一次，主循环数够 100 次就是 1 秒——这是最常用的长周期做法，比硬凑一个超大分频可靠。

定时中断的 ISR 同样要短：置一个标志位或递增一个计数器就返回，采样、计算、通信都放在主循环或任务里。

### 4.7 PWM：占空比是控制量，不是“亮度”本身

PWM 是定时器最常用的输出功能：输出固定频率的方波，用高电平占整个周期的比例（占空比）来传递“平均值”。调光、调速、蜂鸣器音量，控制的都是这个平均值：

- **频率定“抖不抖”**：LED 调光频率太低会看到闪烁，电机调速频率太低会听到啸叫，频率选多高取决于负载特性与人耳/人眼感知，以实际器件说明为准。
- **占空比定“多少”**：0% 全关，100% 全开，50% 一半。占空比的分辨率由定时器重装值决定：重装值越大，占空比可调的档位越细；想调得细，就要接受频率上限随之下降——这是 PWM 的固有取舍。
- **互补输出与死区**：驱动桥式电路（如电机 H 桥）时，上下两个开关绝不能同时导通，定时器的互补输出加死区时间就是为此而生：一个关断后延迟一小段时间，另一个才导通。死区时间以驱动器件的开关特性为准，配错会烧桥臂。

PWM 输出前要确认引脚复用已切到定时器通道（见 4.3 节），否则引脚上什么都没有——这是“PWM 不出波形”的第一排查点。

### 4.8 输入捕获：用边沿时刻反推频率与脉宽

输入捕获是定时器的反向用法：不输出波形，而是记录外部信号边沿到来时计数器的当前值。两次边沿的时间差，就是信号的周期或脉宽：

- **测频率**：记录两个同向边沿的时间差，取倒数就是频率。适合转速、流量这类周期性信号。
- **测脉宽**：上升沿与下降沿各捕获一次，两次计数值之差就是高电平持续时间。适合超声波测距的回波脉宽、遥控信号解码。
- **溢出处理**：两次边沿之间计数器可能溢出转了一圈甚至多圈，必须在溢出中断里累计溢出次数，否则长周期信号算出的频率会错得离谱。溢出次数的累计与边沿捕获的配合，是输入捕获代码里最容易错的地方。

输入捕获的精度上限由定时器时钟决定：时钟越快，时间分辨率越细；代价是计数器溢出越快，溢出处理越频繁。精度与量程的取舍，同样是分频值说了算。

### 4.9 看门狗：最后的兜底，不是调试工具

看门狗（Watchdog）是一个独立的定时器：系统正常运行时，程序要周期性地“喂狗”（复位计数器）；一旦程序跑飞、死循环或卡在某个环节，喂狗停了，计数器溢出就强制复位整个系统。它的设计哲学是“默认系统会出问题，提前留一条生路”。

实务上有四条原则：

- **喂狗的位置要讲究**：只在主循环确认“关键任务都正常跑过一轮”之后喂狗，而不是在定时器中断里无条件喂。放在中断里喂狗，等于主循环死掉了看门狗还以为一切正常，兜底就失效了。
- **喂狗周期要留余量**：超时时间要大于正常情况下最长的一轮主循环，但又不能大到“系统卡死几秒才复位”。超时取值以系统最坏情况分析为准，本篇不给具体数值。
- **区分独立看门狗与窗口看门狗**：独立看门狗只要求“超时前喂”；窗口看门狗还要求“不能喂得太早”——太早喂狗也被视为异常而复位。窗口看门狗能发现“程序跑得比预期快”（例如中断风暴导致主循环被反复打断、喂狗过于频繁）这类独立看门狗发现不了的故障。选哪种以芯片支持与系统要求为准。
- **调试阶段先关、量产再开**：单步调试时程序停在断点上，没人喂狗，看门狗会反复复位，让调试无法进行。开发阶段通常关闭看门狗或用调试模式暂停它，量产固件必须打开——“调试时关掉、发布时忘了开”是真实发生过的事故。

## 5. 关键设计取舍

- **中断 vs 轮询**：事件稀疏、响应要求高，用中断；事件密集到中断开销超过处理本身（例如高速数据流），用轮询或 DMA。中断不是“越用越高级”，中断频率过高时 CPU 全在进出 ISR，主循环反而饿死。
- **硬件去抖 vs 软件去抖**：硬件去抖不占 CPU 但改参数要改板子；软件去抖灵活但占定时器资源与代码量。普通按键软件去抖已够，关键场合两者叠加。
- **定时器硬件功能 vs 软件计数**：PWM、输入捕获这类对时序精度敏感的功能交给定时器硬件；长周期、慢速调度用软件计数叠加。凡是“差几微秒就不行”的事，别用软件延时循环硬凑。
- **看门狗兜底 vs 故障定位**：看门狗能恢复系统，但不告诉你为什么出故障。量产设备应在复位原因寄存器（以官方手册为准）里区分看门狗复位与上电复位，并把故障计数记下来，否则同一个故障会无限复位、无人知晓。

## 6. 分类与变体

- **按 GPIO 输出类型**：推挽输出（主动拉高拉低）与开漏输出（只拉低，靠上拉拉高），见 4.2 节。
- **按中断触发条件**：电平触发（电平保持期间持续请求）与边沿触发（跳变瞬间请求一次）。电平触发不清除条件会反复进中断，边沿触发漏掉一次跳变就丢一个事件，两者的 ISR 写法不同。
- **按定时器用途**：基本定时器（只做定时）、通用定时器（定时 + PWM + 输入捕获）、高级定时器（再加互补输出与死区，用于电机控制）。具体分档以所选芯片的官方手册为准。
- **按看门狗类型**：独立看门狗（超时未喂即复位）与窗口看门狗（喂早了也复位），见 4.9 节。

## 7. 应用与限制

典型应用：按键与旋钮输入（外部中断 + 软件去抖）、LED 调光与电机调速（PWM）、转速与脉宽测量（输入捕获）、周期采样与超时判断（定时中断）、无人值守设备的故障自恢复（看门狗）。限制有四条：第一，引脚电气参数（驱动电流、输入电平门限）以官方手册为准，超限使用会损坏芯片；第二，中断与定时器的数量是有限的，中断源一多就要排优先级、做取舍；第三，软件去抖与软件计数都会引入延迟与抖动，硬实时要求高的场合要靠硬件功能；第四，本篇所有配置思路都是通用形态，不同芯片的寄存器名、位定义、清除标志的方式都不同，照抄别家代码前必须对照官方手册核对。

## 8. 常见误解

- “输入引脚不接东西时读到的数是随机的，正常”：错。悬空读数乱跳是未配置上下拉的故障表现，不是正常现象。
- “中断里加个延时做去抖最简单”：错。ISR 里延时会堵住所有同级与低优先级中断，去抖的延时必须放在 ISR 之外。
- “PWM 占空比 50% 就是一半亮度”：不准确。占空比 50% 是平均电压一半，人眼感知的亮度与占空比不是线性关系；调光曲线要按实际器件特性校准。
- “喂狗越勤越安全”：错。喂狗太勤（例如在中断里无条件喂）会掩盖主循环卡死的故障，看门狗的意义在于“主循环正常才喂”。
- “看门狗开着，系统就不会死机”：错。看门狗只能复位恢复，不能定位故障；没有复位原因记录与故障计数，同一个故障会无限复位。
