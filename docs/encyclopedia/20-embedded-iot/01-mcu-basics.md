# 嵌入式基础与单片机

## 1. 本章目标

读完本篇能理解：单片机（MCU）内部由哪些部分组成，时钟、复位、中断、GPIO、定时器各自起什么作用，以及裸机开发与实时操作系统（RTOS）的分界在哪。

## 2. 背景与问题

嵌入式系统是“专用计算机”：它不像台式机那样什么都干，而是被放进一台设备里，只负责一类任务——洗衣机的程序控制、空调的温度调节、工业传感器的定时采集。通用 CPU 的思路是“越强越好”，嵌入式系统的思路正好反过来：在够用的前提下，成本越低越好、功耗越小越好、行为越确定越好。

单片机就是为这个目标而生的芯片：它把 CPU 核、存储器和常用外设做进同一颗芯片，一颗芯片加少量外围电路就能工作。理解 MCU，是理解一切嵌入式设备的起点；本篇只讲 MCU 本身，跑完整操作系统的嵌入式 Linux 见下一篇，传感器接线与通信协议见本域第三篇。

## 3. 总体架构

一颗典型 MCU 的内部结构（文字结构图）：

```
片上系统（MCU）
├── CPU 核（执行指令，见 01 域 CPU 篇）
├── 存储器
│   ├── Flash（存程序，掉电不丢失）
│   └── SRAM（存运行数据，掉电丢失）
├── 时钟与复位
│   ├── 时钟源（内部 RC 振荡器 / 外部晶振）与 PLL 倍频
│   └── 复位电路（上电复位、看门狗复位、软件复位）
├── 总线矩阵（连接核、存储器与外设）
└── 外设
    ├── GPIO（通用输入输出）
    ├── 定时器 / 计数器（含 PWM、看门狗）
    ├── 串行接口（UART、I2C、SPI，见本域第三篇）
    └── 模拟外设（ADC、DAC、比较器）
```

与通用计算机的关键区别有三点：第一，存储器和外设都在片上，不需要外接内存条和扩展卡；第二，很多 MCU 没有内存管理单元（MMU），程序直接跑在物理地址上；第三，功耗模式是设计的一部分，停机、睡眠、待机是正常工作状态，不是异常。

## 4. 工作机制

### 4.1 时钟：一切动作的节拍器

MCU 内部所有动作都由时钟驱动。时钟源通常有两种：内部 RC 振荡器（不用外围器件，但精度一般，温漂较大）和外部晶振（精度高，适合对时间敏感的场合，如串口通信）。锁相环（PLL）可以把低频时钟倍频成核需要的高频，再经过分频器分给不同外设——核跑得快、外设跑得慢，各取所需。

时钟配置错了会出两类典型问题：串口波特率对不上（通信乱码），以及定时器计时不准。排查时先查时钟树，再查外设寄存器。

### 4.2 复位：回到已知状态

复位让 MCU 从一个确定的状态重新开始执行。常见复位源：上电复位（POR，电压升到门限才放行）、外部复位引脚、看门狗复位（程序跑飞时由独立定时器强制复位）、软件复位。复位后第一件事是执行启动代码：初始化栈指针、搬运数据段、清零 BSS 段，然后跳到主函数。看门狗不是“出了问题再修”，而是“默认系统会出问题，提前留一条生路”。

### 4.3 中断：让外设“喊”CPU，而不是 CPU 一直“问”

没有中断时，CPU 只能轮询——反复读某个寄存器问“好了没有”，既浪费算力又不及时。中断反过来：外设就绪时发信号打断当前执行，CPU 查中断向量表找到对应的中断服务程序（ISR），处理完返回原处继续。

中断机制有三个要点：

- **向量表**：复位后第一条指令的地址、中断号与 ISR 入口的对应表，是启动代码的一部分。
- **优先级与抢占**：高优先级中断可以打断低优先级 ISR；同级中断按硬件固定顺序排队。优先级设计不好会出现低优先级任务长期饿死。
- **ISR 的纪律**：ISR 要短、不能阻塞、不能等另一个中断、不能做耗时计算。正确做法是在 ISR 里只做“标记 + 取数”，把重活交给主循环或任务处理。在 ISR 里延时、打印、等串口，是新手最常见的错误来源。

### 4.4 GPIO：最基础、也最容易被低估的外设

GPIO 是通用输入输出引脚，每个引脚可以配置为输入或输出。输出模式分推挽（主动拉高和拉低，驱动能力较强）和开漏（只主动拉低，拉高靠外部上拉电阻，适合多设备共线，例如 I2C 总线）。输入模式要关注上拉/下拉电阻：悬空的输入引脚会拾取噪声，读数乱跳。

GPIO 的硬限制必须尊重：单个引脚和整颗芯片的驱动电流都有上限，不能直接驱动电机、继电器、大功率 LED，必须经过三极管、MOS 管或驱动芯片。引脚复用是常态：同一个物理引脚可能兼任 GPIO、串口、定时器输出等多个功能，选型时先查引脚复用表再定板子。

### 4.5 定时器：不只是“定时”

定时器本质是计数器，对时钟脉冲计数，计满就触发动作。由此衍生出四种常用功能：

- **定时**：周期性触发中断，做采样、调度、超时判断。
- **PWM**：按占空比输出方波，调光、调速、蜂鸣器都靠它。
- **输入捕获**：记录外部信号边沿到来的时刻，测频率、脉宽、编码器转速。
- **看门狗**：独立的定时器，超时未“喂狗”就复位系统（见 4.2）。

### 4.6 存储器映射：外设也是“内存地址”

MCU 没有独立的 I/O 指令空间：外设寄存器被映射到统一的地址空间，读写某个地址就是在配置外设。这就是“存储器映射 I/O”。它意味着：指针越界写错地址可能改掉外设配置；调试时看内存窗口就能看到外设寄存器状态；不同芯片的寄存器地址不同，程序换芯片要重写底层驱动——这也是芯片厂商提供 HAL 库的原因。

## 5. 关键设计取舍

### 5.1 裸机还是 RTOS：分界不在“高级”，在复杂度

- **裸机（bare-metal）**：超级循环 + 中断，没有操作系统。优点是行为完全确定、启动快、资源占用极小；缺点是任务一多，超级循环就变成难以维护的“面条代码”，任务间时序全靠人工排布。
- **RTOS**：提供任务、信号量、消息队列、定时器等原语，内核按优先级调度任务。优点是多任务结构清晰、实时性有保障；代价是占用 Flash/RAM、引入调度开销、调试时要理解任务切换。

分界标准（满足两条以上就认真考虑 RTOS）：任务超过 3–4 个且有不同的周期与 deadline；有明确的实时性要求（例如“必须在 10ms 内响应”）；需要网络协议栈、文件系统、图形界面这类成体系的中间件；多人协作，代码要能分工维护。反之，单任务或两三个简单任务的场合，裸机更直接、更可靠。RTOS 不是裸机的“升级版”，是不同复杂度下的不同工具。

### 5.2 性能、功耗、成本的不可能三角

核跑得越快、片上资源越多，成本和功耗越高。选型时先定三件事再看芯片：最坏情况下的实时 deadline、整机功耗预算（电池供电还是市电）、量产成本目标。先定这三项，芯片范围自然收窄；反过来先挑一颗“最强”的芯片，再去迁就它的功耗和价格，是常见的选型弯路。

## 6. 分类与变体

- **按位宽**：8 位（结构简单、成本极低，适合简单控制）、16 位（逐步被 32 位取代）、32 位（当前主流，ARM Cortex-M 系列占多数）。
- **按 Cortex-M 梯度**：M0/M0+（低功耗入门）、M3（通用控制）、M4（带 DSP 指令与可选浮点，适合信号处理）、M7（高性能、带缓存，接近应用处理器的实时控制）。
- **代表芯片（仅作选型示例，未做实测评价）**：ST 的 STM32 系列、Espressif 的 ESP32 系列（带 Wi-Fi/蓝牙，适合联网设备）、Raspberry Pi 的 RP2040（双核 Cortex-M0+，适合学习与原型）、Microchip 的 AVR 系列（8 位经典）。具体型号的外设细节以各厂商官方手册为准，本篇不展开。

## 7. 应用与限制

典型应用：家电控制、工业采集与控制、穿戴设备、汽车车身电子、玩具与消费电子。限制有四条：算力与内存有硬上限，跑不了通用操作系统那套软件栈；没有 MMU 的芯片上，一个任务的指针错误可能拖垮整个系统；功耗预算决定了很多设计（睡眠模式、时钟降频是常规手段）；安全上，固件提取、调试接口滥用是真实风险，量产要关调试口、做固件保护——这部分与 10 域安全内容交叉，本篇不展开。

## 8. 常见误解

- “主频越高越好”：错。实时控制看的是中断延迟与确定性，不是峰值算力；高主频还带来功耗与成本。
- “中断里顺手把活干完”：错。ISR 里耗时操作会拖垮所有低优先级中断，正确做法是 ISR 只标记，主循环或任务干活。
- “GPIO 能直接带负载”：错。引脚电流有限，大负载必须经过驱动级，否则烧引脚甚至烧芯片。
- “RTOS 一定比裸机可靠”：错。RTOS 只是换了组织方式，优先级反转、死锁、栈溢出这些问题在 RTOS 里同样存在，只是换了个样子。
