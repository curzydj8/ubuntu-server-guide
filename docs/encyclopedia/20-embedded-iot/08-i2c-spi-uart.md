# I2C/SPI/UART 总线详解

## 1. 本章目标

读完本篇能理解：I2C、SPI、UART 三种板内总线各自的信号线、拓扑结构、速率与时序特点和主从模式，能按场景选出合适的总线，并能排查上拉、地址冲突、时钟拉伸、波特率误差这四类常见问题。

本篇是[传感器与通信协议](03-sensors-protocols.md)的深入篇：03 篇讲四种协议各自解决什么问题，本篇只讲板内三总线的原理与选型细节，不重复 03 篇的概述段落，不讲 MQTT/CoAP（见下一篇），不贴具体芯片的接线图。

## 2. 为什么是这三种总线

一颗 MCU 要和传感器、存储器、显示屏、通信模组打交道，不可能每种外设都发明一种新接口。板内通信的实际需求只有几条：引脚够不够、速度够不够、能挂几个设备、接线有多麻烦。三种总线是这四条约束下的三种不同取舍：

- **I2C**：引脚最省（两根线），代价是速度慢、时序最讲究。
- **SPI**：速度最快、全双工，代价是引脚随从机数量增长。
- **UART**：最简单、最通用，代价是点对点、没有寻址和总线概念。

三者都是“板级”总线：设计目标是同一块板子、几十厘米量级上的芯片间通信。需要跨板、跨房间、跨建筑的传输，要换差分或现场总线方案，不属于本篇范围。

## 3. I2C：两根线挂一串设备

### 3.1 信号线与拓扑

I2C（Inter-Integrated Circuit）由飞利浦（现 NXP）制定，是多主多从的两线总线，只用两根信号线：

- **SDA**：串行数据线，双向。
- **SCL**：串行时钟线，由当前主机驱动。

拓扑是总线型：所有设备并联挂在同一对线上。关键结构是**开漏输出 + 上拉电阻**：总线平时被上拉电阻拉到高电平，任何设备都只能主动把线拉低，不能主动推高。两个设备同时想说话时，拉低的一方“赢”，想拉高的一方被迫让步——这个“线与”特性是 I2C 能多设备共线、多主仲裁的物理基础。01 篇讲过 GPIO 的开漏模式，这里就是它的典型应用。

### 3.2 帧结构与时序要点

一次 I2C 传输按以下顺序进行（时序示意，示例未实测）：

```
起始条件 → 7 位从机地址 + 1 位读写方向 → 从机应答（ACK）
→ 数据字节（每字节后跟一个 ACK/NACK）→ … → 停止条件
```

- **起始条件**：SCL 为高时 SDA 由高拉低；**停止条件**：SCL 为高时 SDA 由低拉高。起始与停止是总线上唯一的“帧边界”信号，任何设备看到它们都知道一帧开始或结束。
- **地址**：7 位地址加 1 位读写位，寻址空间 128 个地址；另有 10 位地址模式（以规范为准，实际使用较少）。地址由从机硬件或配置引脚决定，见 6.2 节的地址冲突问题。
- **应答**：每个字节后，接收方必须在第 9 个时钟把 SDA 拉低一个周期表示 ACK；不拉低就是 NACK，表示“我不在”或“我收不下了”。ACK/NACK 是 I2C 相对 SPI 的结构性优势：主机能当场知道从机在不在、收没收到。

### 3.3 速率档与真实上限

NXP 规范 UM10204 定义的速率档：标准模式 100kHz、快速模式 400kHz、快速模式+ 1MHz、高速模式 3.4MHz。标称值只是上限，实际能跑多快取决于**总线电容**：SDA/SCL 上的总电容（器件引脚电容 + 走线电容）越大，上拉电阻把线拉回高电平越慢，上升沿越缓。标准模式与快速模式的总线电容上限为 400pF（以 UM10204 为准）；超过上限要么降速、要么减小上拉电阻（代价是功耗与灌电流上升），要么用总线缓冲器分段。

换句话说：I2C 的速率瓶颈不在协议本身，在**上拉电阻与总线电容组成的 RC 时间常数**。挂的设备越多、线越长，上限越低。

### 3.4 主从模式与多主仲裁

I2C 是多主多从总线：总线上可以有多个主机，但同一时刻只有一个主机能控制总线。两个主机同时发起传输时，仲裁按“线与”规则自动进行——主机一边发地址一边读 SDA，发现自己想发 1、线上却是 0，就知道有另一台主机在发 0，自己退出并转为从机监听。仲裁失败的主机不会破坏正在进行的传输，这是 I2C 协议层面的设计，不是软件碰巧。

实际应用中多主很少用（单主多从占绝大多数），但理解仲裁有助于理解“为什么 I2C 从机可以拉低 SCL”——这就是时钟拉伸。

### 3.5 时钟拉伸：从机喊“等一下”的机制

I2C 的时钟由主机驱动，但从机可以在需要更多处理时间时**把 SCL 主动拉低**，主机必须等 SCL 被释放后才能继续发下一个时钟。这叫时钟拉伸（clock stretching），是 I2C 协议允许的合法行为，不是故障。

它带来两个实际后果：第一，主机驱动必须容忍从机拉伸时钟，写驱动时不能假设 SCL 一直由自己掌控；第二，拉伸时间没有协议上限，某个从机长时间拉住 SCL 会拖住整条总线，系统设计时要为“总线被个别设备拖死”留超时与恢复手段（例如主机复位总线）。排查“我发地址没人回”时，除了地址错误，也要看 SCL 是否被某台从机拉住。

### 3.6 上拉电阻：小到可以忽略，大到决定成败

上拉电阻是 I2C 硬件设计里最常见的出错点。阻值选型是两头受限的权衡：

- **阻值太大**：拉高太慢，上升沿拖过时序要求，高速模式下直接丢数据；总线电容越大，这个问题越严重。
- **阻值太小**：拉低时灌电流大，功耗上升，弱驱动的从机可能拉不低 SDA（拉不到有效的低电平门限），通信同样失败。

工程上的常用起点是 4.7kΩ（3.3V 系统，标准/快速模式），再按实际总线电容与速率调整；精确值要按 UM10204 的上升时间公式核算（示例未实测，计算细节以规范为准）。另外两个硬性要求：**每条总线只需要一组上拉**（多个设备各挂一组会并联成更小阻值），以及上拉电源必须与总线电平一致（3.3V 器件挂 5V 上拉可能损坏器件，电平转换要专门处理）。

## 4. SPI：四根线换速度

### 4.1 信号线与拓扑

SPI（Serial Peripheral Interface）是四线全双工同步总线，信号线为：

- **SCLK**：时钟，由主机驱动。
- **MOSI**：主出从入（主机 → 从机）。
- **MISO**：主入从出（从机 → 主机）。
- **CS**（片选，又称 SS）：每从机一根，主机拉低某一路即选中该从机。

拓扑是星型：MOSI、MISO、SCLK 三根线所有从机共用，CS 每从机独占一根。主机与被选中的从机在时钟驱动下**同时收发**：每个时钟周期，主机发一位、从机回一位，全双工是 SPI 相对 I2C 的结构性优势。速率通常可达数 MHz 到数十 MHz，以从机手册为准，远高于 I2C。

### 4.2 四种时钟模式：CPOL 与 CPHA

SPI 没有统一的官方标准（它是业界通用实践，时序细节以从机手册为准），但时钟极性与相位有事实上的四种标准组合，必须主从一致：

| 模式 | CPOL（空闲时钟电平） | CPHA（采样边沿） | 含义 |
|---|---|---|---|
| 0 | 0（低） | 0 | 上升沿采样，下降沿发送 |
| 1 | 0（低） | 1 | 下降沿采样，上升沿发送 |
| 2 | 1（高） | 0 | 下降沿采样，上升沿发送 |
| 3 | 1（高） | 1 | 上升沿采样，下降沿发送 |

模式配错是最常见的 SPI 故障：通信“通了”但读回来的数据全是错位一位的。排查时先查从机手册写明了哪种模式，再核对主机配置，不要靠“换个模式试试”蒙——四个模式试一遍能蒙对，但不知道为什么对，下次换芯片还会错。

### 4.3 片选管理与多从机

SPI 没有寻址，片选就是寻址。主机一次只拉低一路 CS，选中的从机驱动 MISO，未选中的从机必须把 MISO 置为高阻态（不驱动）。两点设计责任全在主机侧：

- **CS 数量**：每多一个从机多一根 CS 引脚，挂一堆低速设备时引脚开销会超过收益——这是 SPI 不适合挂很多低速传感器的原因。
- **MISO 冲突**：某个从机在未选中时没有释放 MISO（高阻失效），会和被选中的从机同时驱动 MISO，数据错乱。单从机场景下 CS 也常用于帧同步：拉低 CS 标志一帧开始，拉高标志结束。

此外还有**菊花链**接法：多个从机的 MOSI/MISO 串联成链，数据像移位寄存器一样依次穿过每个从机，省 CS 引脚但一帧要包含所有从机的数据，任一从机掉线整条链失效。是否用菊花链以从机手册支持为准。

### 4.4 SPI 的取舍：快，但没有安全网

SPI 没有应答机制（不知道从机在不在）、没有校验（不知道数据对不对）、没有仲裁（多主机要自己协调）。这些缺失换来了速度和简单：协议开销极小，时钟一跑数据就走。代价是可靠性责任全部上移：帧同步靠 CS、数据正确性靠上层校验（例如读回校验、CRC）、从机在位检测靠应用层约定。高速传感器、Flash、显示屏选 SPI，是因为它们要的就是“快”，且上层本来就有自己的校验与重传。

### 4.5 速率上限：从机与信号完整性说了算

SPI 的时钟上限不是协议定的，是两件事定的：从机手册标明的最高时钟频率，以及信号完整性（走线长度、阻抗、串扰）。时钟跑得太快，MISO 上的数据还没稳定就被采样，读回来的就是错数。常见错误是“主机能跑 50MHz 就按 50MHz 配”，而不看从机只支持 10MHz。降速排查是 SPI 调试的第一手段：先降到最低速确认逻辑通，再逐步提速找上限（示例未实测）。

## 5. UART：最简单的异步串行

### 5.1 信号线与帧结构

UART（Universal Asynchronous Receiver/Transmitter）是点对点的异步串行通信，最少两根线：

- **TX**：发送；**RX**：接收。两端交叉相连（A 的 TX 接 B 的 RX）。

“异步”指双方**不共享时钟**，靠事先约定的波特率（每秒传多少位）和帧结构同步。一帧的组成（03 篇已述，此处补时序含义）：

```
空闲（高电平）→ 起始位（1 位低电平）→ 数据位（通常 8 位，低位先发）
→ 可选校验位 → 停止位（1 位或更多，回到高电平）→ 空闲
```

起始位的下降沿就是同步信号：接收方检测到下降沿，知道一帧开始，按约定的波特率在每位中间时刻采样。停止位让线路回到空闲，保证下一帧的起始下降沿能被识别。

### 5.2 波特率误差：异步的代价

没有共享时钟，就意味着双方时钟不可能完全一致。接收方按自己的时钟采样发送方按另一时钟发来的数据，误差会在一帧内累积。工程上的通用要求是：**收发双方的波特率偏差控制在 2% 以内**（以芯片手册为准）；超过后，采样点会漂到相邻位上，出现帧错误或乱码。

这个约束决定了几件事：第一，时钟源精度直接决定 UART 可靠性——内部 RC 振荡器温漂大时，高速波特率下先出问题的是串口（01 篇时钟一节讲过，串口是对时钟最敏感的外设）；第二，波特率不是越高越好，超过芯片与线路能力，误码率先于速度收益恶化；第三，常见波特率 9600、115200 是“约定俗成”的档位，双方配错一档（例如一方 9600、一方 115200）时收到的是固定乱码，这是最容易识别的故障特征。

### 5.3 流控与电平：UART 之外的两件事

- **硬件流控（RTS/CTS）**：接收方快满时用 RTS 告诉发送方“暂停”，有空间了再放行。没有流控时高速连续收发容易溢出丢数据——UART 本身没有重传，丢了就是丢了。低速调试可以不要流控，高速或批量传输要评估。
- **电平标准**：MCU 的 UART 是 TTL/CMOS 电平（0–3.3V 或 0–5V），不是 RS-232 的 ±12V，也不是 RS-485 的差分信号。接电脑串口、接长线、接工业设备时，中间要加电平转换或收发器芯片；直接把 RS-232 电平接到 MCU 引脚上会损坏芯片。RS-485 用同一对差分线做半双工多点，是 UART 之上常见的长线扩展，但那是另一层协议，本篇不展开。

### 5.4 UART 的定位：调试与模组通信

UART 的最大优点是“到处都有”：几乎所有 MCU 和通信模组（GPS、蜂窝、Wi-Fi、蓝牙模组常用 AT 指令走 UART）都带 UART，串口打印是嵌入式调试的第一手段。它的限制同样直接：点对点（一个 UART 口只能接一个对端）、没有寻址、没有总线概念、传输距离限于板级。需要一主多从或高速传输时，UART 不是正确工具。

## 6. 三总线对比与选型

### 6.1 对比表

| 维度 | I2C | SPI | UART |
|---|---|---|---|
| 信号线 | 2 根（SDA、SCL）+ 上拉 | 4 根 + 每从机 1 根 CS | 2 根（TX、RX），交叉相连 |
| 拓扑 | 总线型，多主多从 | 星型，一主多从 | 点对点 |
| 寻址 | 7 位/10 位地址 | 片选 CS | 无（点对点不需要） |
| 双工 | 半双工 | 全双工 | 全双工 |
| 同步方式 | 同步（共享 SCL） | 同步（共享 SCLK） | 异步（约定波特率） |
| 典型速率 | 100kHz–3.4MHz（档位） | 数 MHz–数十 MHz（以从机为准） | 波特率档（9600、115200 常见） |
| 应答/校验 | ACK/NACK 每字节 | 无（靠上层） | 可选校验位，无重传 |
| 引脚成本 | 最低 | 随从机数增长 | 低（但一口只能接一端） |
| 典型用途 | 低速传感器、EEPROM、实时时钟 | 高速传感器、Flash、显示屏 | 调试打印、GPS/蜂窝模组 |

### 6.2 选型建议

- **板内低速传感器（温湿度、气压、EEPROM）**：优先 I2C。引脚省、能挂多个、ACK 能当场确认从机在位。
- **高速数据（IMU、高速 ADC、显示屏、Flash）**：优先 SPI。全双工加高时钟是唯一满足速率要求的板内方案。
- **调试输出与模组通信**：用 UART。串口打印是调试标配，模组 AT 指令大多走 UART。
- **同型号多传感器**：先查地址可配性。I2C 同型号默认地址常相同，挂同一总线前要确认地址配置引脚、换地址可配的型号、或加 I2C 多路复用器；否则改走 SPI（每从机独立 CS 天然避开地址问题）。
- **引脚紧张且从机多**：算 CS 账。SPI 每从机一根 CS，超过 3–4 个从机时引脚与布线压力可能超过 I2C 的速率代价。
- **长线或跨板**：三者都不合适。板内总线不是为长线设计的，距离上去后先考虑差分、隔离或现场总线方案（CAN 等，03 篇已提，属后续可补主题）。

## 7. 常见问题排查

| 现象 | 先查什么 | 常见原因 |
|---|---|---|
| I2C 从机无应答（NACK） | 地址、接线、上拉 | 地址配错或冲突；SDA/SCL 接反；无上拉或上拉电源电平不对 |
| I2C 时快时慢、偶发丢数 | 总线电容与上拉阻值 | 上拉太大导致上升沿过缓；线过长或挂载过多 |
| I2C 总线卡死（SCL 一直低） | 哪个从机在拉伸时钟 | 从机异常拉住 SCL；主机无超时恢复机制 |
| SPI 读回数据错位一位 | CPOL/CPHA 模式 | 主从模式不一致；先核对手册，不要逐个试模式蒙答案 |
| SPI 多从机时数据错乱 | MISO 释放情况 | 未选中从机未释放 MISO；CS 时序或极性配错 |
| SPI 高速丢数、低速正常 | 从机最高时钟与信号完整性 | 时钟超过从机上限；走线过长 |
| UART 固定乱码 | 波特率配置 | 收发波特率不一致；时钟源精度不足导致偏差超 2% |
| UART 偶发丢字节 | 流控与接收缓冲 | 高速连续收发无流控；接收方处理不及、缓冲溢出 |
| UART 接上就烧引脚 | 电平标准 | RS-232 电平直连 MCU 引脚；缺少电平转换 |

排查的通用顺序：先确认“物理层对不对”（接线、上拉、电平、电源），再确认“配置对不对”（地址、模式、波特率），最后才怀疑“协议或软件逻辑错”。大部分总线问题出在前两层。

## 8. 常见误解

- “I2C 地址不会冲突”：错。同型号传感器默认地址常相同，挂同一总线前必须核对地址配置位或加多路复用器。
- “SPI 不需要片选也能工作”：错。没有 CS，多个从机同时驱动 MISO 会冲突；单从机场景下 CS 也常用于帧同步。
- “上拉电阻随便找个值就行”：错。阻值决定上升沿速度与灌电流，太大丢数据、太小拉不低，取值要按总线电容与速率核算。
- “时钟拉伸是总线故障”：错。它是 I2C 协议允许的从机流控机制；真正的问题是主机没有超时与恢复手段。
- “波特率/总线速率越高越好”：错。速率受总线电容、线长、从机能力三重限制，超了先丢数据后丢通信。
- “UART 接上就能通”：错。TX/RX 交叉、波特率一致、电平匹配三件事缺一不可。
