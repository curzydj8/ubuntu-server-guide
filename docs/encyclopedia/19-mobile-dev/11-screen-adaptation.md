# 屏幕适配与多机型兼容

## 1. 一句话定义

屏幕适配是让同一套界面在不同尺寸、密度、形态的屏幕上都显示正确、点得到、用得顺；多机型兼容是把这份“正确”在真实机型矩阵上逐项验证通过。

## 2. 为什么需要它

Android 机型的差异是结构性的：尺寸从 5 英寸小屏到 10 英寸平板、密度从低密到超高密、形态有刘海、挖孔、折叠、曲面，系统版本与厂商定制又各不相同。一份“在开发机上刚好”的布局，换一台机器就可能溢出、重叠、按钮被导航条盖住。适配不是上线前的“测几台手机”，而是布局、资源、形态、系统行为四个维度的设计工作；机型矩阵测试只是最后一环，用来验证设计有没有落地。

本篇是 [移动端性能与适配](03-performance-adaptation.md)（本组第三篇，总论）第 4.4 节的纵深：总论讲了尺寸、密度、异形、折叠、系统行为差异五个要点，本篇讲每一点具体怎么做、做到什么程度算合格。

## 3. 屏幕尺寸、密度与形态

### 3.1 尺寸与密度：先分清两个量

- **尺寸**：屏幕对角线英寸数，决定“能放多少内容”。同样 6 英寸屏，比例可能是 16:9 也可能是 21:9，宽高比不同，可用高度差很多。
- **密度**：单位英寸里的像素数（dpi）。密度越高，同样像素数显示得越小。直接写 px 会在高密度屏上缩成一团、在低密度屏上溢出——这是适配最常见的初级错误。

Android 用 **dp（密度无关像素）**描述尺寸、用 **sp（可缩放像素）**描述文字：1dp 在 160dpi 的屏上等于 1px，在 320dpi 的屏上等于 2px，物理大小保持一致；sp 与 dp 的区别是 sp 会跟随系统字体大小设置缩放，文字必须用 sp、布局尺寸用 dp。图片按密度分桶提供（mdpi/hdpi/xhdpi/xxhdpi 等），系统按当前密度自动取最接近的一档；只提供一档图，系统会拉伸，糊或占内存。

iOS 的对应概念是 **pt（点）**与 **@1x/@2x/@3x 图片**：1pt 在 @2x 屏上是 2px、在 @3x 屏上是 3px，思路与 dp 相同、单位不同。iOS 相关内容均为示例未实测，具体以 Apple 官方文档为准。

### 3.2 刘海、挖孔、圆角与手势导航

现代手机屏幕不是完整矩形：顶部有刘海或挖孔、四角是圆角、底部是手势导航条。这些区域都会吃掉可视范围：

- **关键内容与点击区要避开系统窗口 insets**（状态栏、导航栏、刘海区）：标题、按钮、输入框不能画进刘海区，也不能被手势条盖住。Android 上通过 WindowInsets 拿到各区域尺寸、布局时留出边距；iOS 上通过 Safe Area 拿到安全区域（见第 5 节）。
- **沉浸式要留退路**：全屏图片、视频可以延伸到刘海区做背景，但文字与操作按钮必须在安全区内；不要假设“用户会自己避开”。
- **横竖屏切换**：旋转会改变宽高与 insets，界面要能重建恢复（见 [Android 开发基础](01-android-basics.md) 生命周期一节），不能假设“竖屏手机”是唯一形态。

### 3.3 折叠屏与大屏：形态会变

折叠屏展开/折叠、平板横屏，都会触发配置变更，界面要随之重组，而不是等比放大：

- **折叠屏**：展开后宽度接近平板，应显示双栏或更多内容；折叠后回到单栏。只做“拉伸同一布局”的应用，在展开态会显得空、折叠态会显得挤。
- **平板与大屏**：大屏不是“大号手机”：单栏列表在大屏上留白过大，应改双栏（列表 + 详情）、分栏导航或自适应网格。
- **多窗口与分屏**：应用可能只占一半屏幕，布局要按当前窗口尺寸走，不能按“全屏尺寸”写死。

## 4. Android 适配方案

### 4.1 dp/sp 与资源限定符

- **单位纪律**：布局尺寸一律 dp、文字一律 sp、图片按密度分桶。写死 px 是适配债务，迟早要还。
- **资源限定符**：按屏幕宽度、方向、夜间模式提供不同的布局与资源，系统按当前配置自动选取。例如小屏一套布局、宽屏（平板/折叠展开态）一套双栏布局；竖屏与横屏各一套。限定符是“一份布局打天下”的替代方案：布局按配置分档，而不是靠运行时到处判断机型。
- **最小宽度（smallest width）分档**：按 dp 宽度分档（如 600dp 以上算平板宽度），是比“按机型名判断”可靠得多的分档方式——机型名会出新款，宽度分档不会。

### 4.2 约束布局：扁平替代嵌套

多层 LinearLayout 嵌套是适配与性能的双重负担：层级越深，测量次数越多（见 [启动优化与卡顿排查](10-startup-optimization.md) 第 5.2 节），不同尺寸下越容易错位。约束布局（ConstraintLayout）用约束关系描述位置，一层就能表达“这个按钮在标题下方、距右边 16dp”，层级扁平、不同尺寸下按约束自适应。它是 Android 官方推荐的主力布局方式，老项目的深层嵌套应按页面逐步替换，不必一次性重写。

### 4.3 自适应布局：按窗口尺寸走

Android 的自适应布局思路是“布局跟着窗口尺寸变”：

- **窗口尺寸类别（Window Size Classes）**：把宽度/高度按 dp 分档（如紧凑、中等、展开），不同档位用不同布局结构——紧凑宽度单栏、中等宽度双栏、展开宽度多栏。分档依据是当前窗口尺寸，不是设备型号，所以分屏、多窗口下同样生效。
- **自适应组件**：列表在大屏自动变网格、导航栏在宽屏变侧边导航栏、对话框在大屏居中限宽而不是撑满。这些不是“针对平板写的特例”，而是同一套自适应规则在不同尺寸下的自然表现。
- **测试要点**：改窗口尺寸（旋转、分屏、折叠展开）后，布局要重组且状态不丢；只测“竖屏手机”等于只测了一个档位。

窗口尺寸类别的档位划分与 API 细节以官方文档为准（待核实），本文不锁定具体数值。

## 5. iOS 适配要点

以下为 iOS 适配的原理级要点，均为示例未实测（本机无 macOS/iOS 环境），细节以 Apple 官方文档为准。

### 5.1 Safe Area：内容的安全区

Safe Area 是系统划出的“不会被刘海、圆角、Home Indicator、手势条遮挡”的区域。所有文字与可点击内容都要放在 Safe Area 内，背景与装饰可以延伸出去。Auto Layout 里用 Safe Area 锚点而不是屏幕边缘锚点，是 iOS 适配的第一条纪律；写死屏幕尺寸或边缘偏移，换一台带灵动岛的机型就会错位。

### 5.2 Size Classes：横竖与尺寸的组合

iOS 用 Size Classes 描述“横向紧凑/常规 × 纵向紧凑/常规”的组合：iPhone 竖屏是横向紧凑、iPad 是横向常规，同一套界面按 Size Class 切换布局结构（如 iPad 常规宽度下显示双栏、iPhone 紧凑宽度下显示单栏）。思路与 Android 的窗口尺寸类别相通，都是“按尺寸档位换结构”，只是分类维度与 API 不同。

### 5.3 其他要点

- **动态字体**：系统字体大小可调，文字要用支持动态缩放的字体样式，布局要容纳字体放大后的换行与高度变化；写死行高与固定高度，字体一放大就截断。
- **多任务与分屏**：iPad 分屏时应用只占部分屏幕，布局要按当前尺寸走，不能按全屏写死。
- **深色模式与无障碍**：颜色与对比度要同时满足浅色/深色、无障碍大字体与 VoiceOver 读屏顺序，适配验收要把这几项算进去，不能只看截图。

## 6. 多机型兼容测试思路

### 6.1 机型矩阵：按用户分布定优先级

测试量是有限的，矩阵要按“用户机型分布”排优先级，而不是按“理论上所有机型”平均用力：

- **旗舰机**：验证上限体验（高刷、高密度、折叠展开态）。
- **主流机**：验证达标体验（覆盖大多数用户的尺寸与系统版本）。
- **低端机与老系统**：验证底线体验——能用、不崩、不耗电异常。底线机型定错，优化方向全错（见总论第 6 节）。
- **厂商维度**：厂商定制系统对后台、权限、电池优化的实现各有加严，同一功能在不同品牌机型上表现可能不同，发布前要在目标品牌机型上逐项验收，不能只测一台。

### 6.2 测试清单：每台机器过一遍

- **布局**：各尺寸、各密度、各方向下，文字不截断、按钮不重叠、关键内容不被刘海/导航条遮挡。
- **形态**：折叠展开/折叠、分屏、横竖旋转后，布局重组正确、状态不丢。
- **系统行为**：权限申请、后台、通知、省电模式在该品牌机型上的表现与预期一致。
- **性能底线**：低端机上启动、滑动、内存不越过基线（见 [启动优化与卡顿排查](10-startup-optimization.md) 第 6.3 节）。

### 6.3 云测与自动化：补人力测不到的量

真机数量有限时，用云测平台补量：上传包、在云端机型矩阵上跑自动化脚本，覆盖几十上百款机型，抓布局错位、崩溃与兼容异常。云测补的是“广度”，不能替代“深度”——旗舰与底线机型的关键路径，仍要拿真机逐项验收；云测报出的问题也要在真机上复现确认，不能只看截图定性。云测平台的具体选型与价格以官方发布为准（待核实）。

## 7. 限制与常见误解

- “适配就是多测几台手机。”错：适配是尺寸、密度、形态、系统行为四个维度的矩阵，测机只是最后一环，布局与资源设计才是本体（见总论第 8 节）。
- “用 dp 就等于适配好了。”错：dp 只解决密度，尺寸、形态、系统行为还要靠限定符、自适应布局与机型矩阵。
- “平板就是大号手机，等比放大就行。”错：大屏要换结构（双栏、网格、侧边导航），等比放大只是“能用”，不是“好用”。
- “iOS 机型少，不用适配。”错：iOS 也有尺寸、刘海/灵动岛、iPad 分屏、动态字体四重差异，Safe Area 与 Size Classes 缺一不可。

## 8. 小结

适配按尺寸、密度、形态、系统行为四维设计：Android 靠 dp/sp、资源限定符、约束布局与窗口尺寸类别，iOS 靠 Safe Area 与 Size Classes，大屏与折叠屏靠“按窗口尺寸换结构”而不是等比放大；最后按用户机型分布排矩阵，在真机上逐项验收，云测补广度。
