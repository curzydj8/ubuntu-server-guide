# 开源文化与社区

## 1. 一句话定义

开源文化是一种软件协作文化：源代码公开，任何人都可以自由使用、学习、修改、分发，并通过社区协作持续改进软件；它既是一套许可证规则，也是一种“公开做事、靠共识推进”的工作方式。

## 2. 为什么需要它

封闭软件时代，用户拿到的是“黑盒”：程序出问题改不了，厂商停更就只能换产品，学技术也看不到实现。更深的问题是重复劳动：每家公司、每个实验室都要从头写同一类基础软件。开源文化回答的是：**能不能让基础软件成为公共积累**——前人写好的，公开出来，后人接着改，整个行业不再反复造轮子。

## 3. 核心含义

### 3.1 前史：分享本来是常态

1950 年代，计算机还是机构的大型设备，用户常通过用户组交换程序与经验——分享代码在当时不是运动，而是习惯。转折发生在后来：软件开始作为独立商品销售，源代码不再随产品附带，用户能买到的只是可执行文件。**分享从“默认”变成“需要争取的权利”**，自由软件运动正是在这个背景下出现的。

### 3.2 自由软件运动：自由是权利，不是价格

- **1983 年 9 月，GNU 计划**：理查德·斯托曼宣布要写一个完全由自由软件组成的、与 Unix 兼容的操作系统，取名 GNU（“GNU's Not Unix”的递归缩写）。1985 年，他创立自由软件基金会（FSF）支撑这个计划，并发表《GNU 宣言》。
- **自由的四项自由**：自由软件基金会给“自由”下了定义——用户可以自由地运行、学习与修改、再分发、以及发布改进版。关键点：这里的 free 是“自由”（free as in freedom），不是“免费”（free as in beer）。自由软件可以收费，免费软件也未必自由。
- **1989 年，GPL 第一版**：GNU 通用公共许可证（GPL）用版权的办法保护自由：你可以自由使用与修改，但分发修改版时必须同样保持自由，这叫 copyleft（著佐权）。转折在于：**版权第一次被用来保障自由而不是限制自由**，自由从口号变成可执行的法律机制。

### 3.3 另一条线：BSD 与学院派分享

与 GNU 平行的，是加州大学伯克利分校的 BSD Unix 社群：学院研究者在 Unix 基础上持续改进并分享成果。BSD 传统对许可证更宽松——允许把代码用进闭源产品，只要保留版权声明。这条线说明：**“开放”内部也有不同立场**，后来 copyleft 与宽松许可的两大阵营就源于此。

### 3.4 1991 年：Linux 补上最后一块

GNU 到 1990 年代初已经有了编译器（GCC）、C 库、Shell 与大部分工具，唯独缺一个能用的内核。1991 年，赫尔辛基大学学生莱纳斯·托瓦兹把自己写的内核公开出来，后来改用 GPL 发布。GNU 工具 + Linux 内核组成了完整系统（自由软件基金会称之为 GNU/Linux，这个叫法至今仍有争议）。转折在于：**自由软件第一次有了完整可用的操作系统**，从此能真正跑在服务器与个人电脑上。

### 3.5 1998 年：“开源”一词与商业世界接轨

- **1998 年，开放源代码促进会（OSI）成立**：埃里克·雷蒙、布鲁斯·佩伦斯等人提出用“开源”（open source）这个词代替“自由软件”，并制定《开源定义》（十条标准，核心是源代码可得、可自由使用修改分发、不歧视任何人与领域）。同年，网景公司公开浏览器源代码（后来的 Mozilla 项目），Apache 服务器已在网站市场占到显著份额。
- 转折在于：**开源从“运动”变成“方法”**——企业不必先认同自由哲学，只要接受“公开协作更有效”，就能参与。自由软件与开源此后并行：前者讲权利与伦理，后者讲协作与工程效益，许可证高度重叠，理念各有侧重。

### 3.6 社区怎么协作：不是“没人管”，而是“换一种管法”

- **贡献路径**：从用户（提问题、报缺陷）到贡献者（交补丁、写文档）再到维护者（审核合并、定方向），权限靠持续贡献赢得，不靠职位任命。
- **公开讨论**：设计与决策发生在公开的邮件列表、议题区与代码评审里，结论可追溯；私下拍板再宣布结果，在开源社区通常不被接受。
- **分叉（fork）权**：任何人不满意方向都可以复制一份自己做，这是对维护者的制衡，也是社区分裂的来源——分叉自由不等于分裂无代价，分裂会分散人力，所以重大分歧往往先经过漫长讨论。
- **治理形态**：有个人主导（如早期 Linux 的托瓦兹）、基金会托管（如 Apache 基金会、Linux 基金会）、公司主导（如某些由企业发起的项目）三种常见形态，没有唯一正确的一种。
- **工具演进**：从邮件列表发补丁，到 2005 年 Git 分布式版本控制，再到 2008 年 GitHub 上线带来的“fork + 拉取请求”流程，协作门槛一路降低——但工具只是载体，评审、讨论、许可证这些规则才是社区的本体。

### 3.7 开源怎么活下来：几种常见模式

- 服务与支持收费：软件免费，靠部署、培训、技术支持赚钱（早期 Red Hat 的路线）。
- 开放核心：核心开源，高级功能闭源收费。
- 双许可：同一份代码，社区用 copyleft 许可，企业付费拿宽松许可。
- 基金会与赞助：企业捐款、基金会雇人维护基础设施。
- 这些模式没有哪一种“最纯粹”；判断标准只有一个：**许可证承诺有没有被遵守**，而不是项目赚不赚钱。

## 4. 分类

- 按许可证：copyleft 类（GPL 等：分发修改版必须保持同样自由）与宽松类（MIT、Apache、BSD 等：允许用进闭源产品，条件较少）。
- 按治理：个人主导、基金会托管、公司主导。
- 按参与角色：用户、贡献者、维护者（同一人可以在不同项目里同时是这三种角色）。
- 按与“自由软件”的关系：自由软件（讲权利与伦理）与开源（讲协作与效益）——许可证高度重叠，理念侧重不同，不要混为一谈，也不要对立起来。

## 5. 典型应用：开源文化在今天的延续

- 服务器与云：Linux、Apache、Nginx 等开源软件是今天互联网基础设施的主体，本站的服务器指南本身就跑在这样的软件栈上。
- 编程语言与工具：Python、Git、VS Code 的开源构建等，开发者日常工具大多有开源实现。
- 浏览器：Firefox（Mozilla 项目）直接源于 1998 年网景公开源代码的决定。
- 本站的写作方式：公开协作、版本控制、评审后再发布——与开源社区的工作方式同源。

## 6. 限制与常见误解

- **“开源就是免费”是误解**：开源管的是使用、修改、分发的自由，不管价格；开源软件可以收费，开源公司也可以盈利。
- **“开源就是没人管”是误解**：开源项目有维护者、有评审、有发布流程；“人人能改”不等于“改动都会被采纳”，不被接受的改动只能存在于自己的分叉里。
- **“开源就没有版权”是误解**：恰恰相反，开源许可证就是版权人行使版权的方式——不遵守许可证（如去掉版权声明、违反 copyleft）就是侵权。
- **“自由软件与开源是一回事”是简化**：两者许可证高度重叠，但自由软件讲的是用户权利，开放源代码讲的是协作方法；写文章时提到哪一方，最好按它的自称来写。
- **开源不是万能药**：冷门项目可能长期缺维护者，许可证选错可能引发合规纠纷，社区治理失败可能导致分裂——这些是开源文化的真实成本，不是“公开了就自动变好”。

## 7. 小结

开源文化从“分享是常态”出发，经自由软件运动立下权利与许可证，再经“开源”一词走进商业世界，最后长成一套公开讨论、分层贡献、靠许可证兜底的协作方式。它不是免费午餐，而是一套让软件成为公共积累的规则。
