# 开源与开放标准思想史

## 1. 一句话定义

开放标准思想史，是一部“让不同人、不同厂商造的东西能够互相连通”的思想史：从电报与电话时代的互联互通需求出发，经 TCP/IP 战胜 OSI 参考模型、IETF“粗糙共识与可运行代码”的工作方式、W3C 的 Web 标准开放过程，到开放标准与开源软件互相成就的今天——核心主张始终是：**互联互通的规则应当公开、免费可用、由实现来检验，而不是由一家厂商或一个委员会说了算**。

## 2. 为什么需要它

没有共同标准，网络只是孤岛：A 厂的电话打不通 B 厂的电话，A 公司的电脑连不上 B 公司的网络，每接一个新伙伴都要重新谈判、重新接线。开放标准回答的是：**能不能先把“怎么说话”这件事公开定下来，让所有人按同一套规则造东西**。这件事之所以值得写成一部思想史，是因为它从来不只是技术选择：标准由谁定、定多细、定下来之后谁说了算，背后是商业利益、国家意志与工程师文化的长期拉锯。今天我们习以为常的“任何浏览器都能打开任何网站、任何设备都能接入互联网”，正是这场拉锯打出来的结果，而不是一开始就有的默认状态。

## 3. 核心含义：思想演进时间线

### 3.1 源头：电报与电话时代的互联互通

- **1844 年，电报联网**：塞缪尔·莫尔斯在华盛顿与巴尔的摩之间发出了第一封公开电报，通信时代由此开始。电报线很快跨越国界，但问题也随之出现：各国设备不统一、操作规程不同、资费各算各的，电报跨过国境就可能“说不通”。
- **1865 年，国际电报联盟**：20 个欧洲国家在巴黎签署第一份《国际电报公约》，成立国际电报联盟（今国际电信联盟 ITU 的前身），统一以莫尔斯电码为国际电报字母，统一操作规程与国际资费结算办法。转折在于：**互联互通第一次有了国际组织与条约背书**——标准从“各家约定俗成”变成“多国共同承诺”。电话发明（1876 年）后，同一套机制又延伸到电话：联盟自 1885 年起着手制定国际电话规则。
- 这一段留下的思想遗产有两条，至今有效：第一，**互联互通是公共品**，需要有人出面协调，光靠市场自发形不成；第二，标准一旦定下来，就有巨大的惯性——莫尔斯电码作为国际标准沿用了上百年，选错标准的代价与选对标准的收益一样持久。

### 3.2 计算机联网：RFC 与“先跑起来再说”

- **1969 年，RFC 系列诞生**：ARPANET 建设期间，史蒂夫·克罗克发表了第一份 RFC（Request for Comments，征求意见稿），编号 RFC 1。RFC 的名字本身就是一种姿态：**这不是命令，是“请提意见”**——任何人都可以写一份 RFC 参与讨论，草稿公开，讨论公开，结论公开。
- **1974 年，TCP 的设计发表**：文顿·瑟夫与罗伯特·卡恩发表 TCP 的设计；随后 TCP 被拆分为 IP（负责在网络之间递送数据包）与 TCP（负责端到端的可靠传输）两个协议。1981 年，RFC 791（IP）与 RFC 793（TCP）定稿；**1983 年 1 月 1 日“换旗日”（Flag Day）**，ARPANET 全网从旧协议 NCP 切换到 TCP/IP——这一天常被视为互联网技术上的诞生日。同一时期，BSD Unix 4.2 把 TCP/IP 与套接字（socket）接口一起发出来，让任何一台 Unix 机器装上就能联网。
- 转折在于：**互联网的标准流程是“实现先行”**——先有人把东西做出来、跑起来、互联起来，再把行之有效的做法写成标准；而不是先由委员会写好全套规范，再等各家照着实现。这个顺序，决定了后来二十年标准之争的胜负手。

### 3.3 TCP/IP 战胜 OSI：两条路线的对决

- **OSI 参考模型**：1970 年代末到 1980 年代，国际标准化组织（ISO）与国际电报电话咨询委员会（CCITT，今 ITU-T）推动 OSI（开放系统互连）参考模型：七层分层，理论严整，每一层都有对应的正式协议（如电子邮件 X.400、目录服务 X.500、传输协议 TP0–TP4）。它在各国政府与大型电信机构中一度是“官方路线”，美国政府采购也曾要求遵循 OSI（即 GOSIP 政策）。
- **对决的结果**：TCP/IP 赢了。原因不在理论高下，而在几件很实际的事：第一，**TCP/IP 有能跑的代码**，而且是免费的、随 BSD Unix 一起发行的代码，想用就能用；OSI 的协议大多还停留在文档里，实现又晚又贵。第二，**TCP/IP 简单够用**：四层结构、尽力而为的 IP、把智能放在端点而不是网络中间，部署成本低。第三，**TCP/IP 先占了网络**：到各家真正想联网的时候，互联网上已经跑着成千上万台 TCP/IP 主机，换标准的迁移成本高得不划算。1990 年代初，美国联邦网络委员会采纳 TCP/IP、放弃对 OSI 的政府采购要求，标志着这场争夺在事实上落幕。
- 转折在于：**OSI 赢了词汇，TCP/IP 赢了网络**——今天全世界讲网络仍用 OSI 的七层来说话（物理层、网络层、传输层……），但实际跑的协议是 TCP/IP。七层模型作为教学框架留了下来，作为协议套件却没有。教训是：**标准的胜负不由理论的优雅决定，而由“有没有人真的在用”决定**。

### 3.4 IETF 的工作方式：粗糙共识与可运行代码

- **1986 年，IETF 成立**：互联网工程任务组（Internet Engineering Task Force，IETF）于 1986 年 1 月举行第一次会议，由 ARPANET 相关工作的技术协调者演变而来。它没有会员、没有投票、没有法律地位——任何个人都可以参加，工作在公开的邮件列表与工作组里进行，会议每年举行三次。
- **“粗糙共识与可运行代码”**：IETF 的信条出自戴维·克拉克 1992 年在 IETF 会议上的发言：“我们拒绝国王、总统与投票；我们相信粗糙共识与可运行代码。”（We reject: kings, presidents and voting. We believe in: rough consensus and running code.）它的含义是：标准不是靠投票表决出来的，而是当**大致的共识**（rough consensus，即没有人强烈反对、而不是全票通过）加上**至少两个能互通的独立实现**同时出现时，标准才算成立。
- **流程长什么样**：一个人或一群人先写一份互联网草案（Internet-Draft），在工作组里公开讨论、反复修改；草案要成为 RFC（标准），必须先有可运行的实现、通过互操作测试，再经互联网工程指导组（IESG）审核批准。RFC 从 1969 年的第一份起连续编号，至今仍是互联网标准的正本。转折在于：**IETF 把“标准”从“写出来的文件”重新定义为“跑起来的共识”**——文件只是共识的记录，运行中的实现才是标准的本体。

### 3.5 W3C 与 Web 标准的开放过程

- **1989–1990 年，Web 诞生**：蒂姆·伯纳斯-李在欧洲核子研究中心（CERN）提出万维网设想，写出第一个浏览器与服务器，定下 HTML（写网页的语言）、HTTP（取网页的协议）与 URL（网页的地址）三件套。1993 年，CERN 把 Web 技术公开，任何人都可以免费使用——这是 Web 能爆炸式扩散的前提。
- **1994 年 10 月，W3C 成立**：伯纳斯-李离开 CERN 后，在麻省理工学院计算机科学实验室创立万维网联盟（World Wide Web Consortium，W3C），与 CERN 合作、并得到欧洲委员会与美国国防高级研究计划局的支持，目标是制定 Web 的共同标准、保证互操作。1995 年、1996 年，欧洲（INRIA，后为 ERCIM）与日本（庆应义塾大学）先后成为 W3C 的联合主办机构。
- **浏览器大战与标准的考验**：1990 年代中期，网景与微软的浏览器大战中，双方都往 HTML 里加自家专属的扩展标签，同一个网页在不同浏览器里长得不一样。W3C 的回应是把 HTML、CSS 等核心标准继续公开制定，并坚持**免版税（royalty-free）**原则：W3C 标准所涉及的专利，成员必须免费许可，任何人实现标准都不用交专利费。这一条保证了“做浏览器”这件事永远向新人开放。
- **开放过程本身也在演进**：W3C 的标准制定比 IETF 更正式——有会员制、工作组、候选推荐标准、正式推荐标准等阶段，公众可以对草案提意见。2004 年，苹果、Mozilla 与 Opera 的工程师另组 WHATWG（Web 超文本应用技术工作组），主张用更贴近浏览器实现的节奏推进 HTML（后来成为 HTML5 的主要动力）；W3C 与 WHATWG 的分工后来逐步协调。转折在于：**Web 标准的开放不是一次到位的决定，而是一场持续三十年的拉锯**——正式流程与快速实现之间，始终在找平衡。

### 3.6 开放标准与开源软件：互相成就

- **开源实现是最好的标准推广**：TCP/IP 能赢，离不开 BSD Unix 把它免费发出来；HTTP 能普及，离不开 Apache 服务器的开源实现；HTML 能统一，离不开各家浏览器（包括后来的 Firefox 与 Chromium）对同一套标准的开源实现。**标准给了开源软件“往哪里对齐”的靶子，开源软件给了标准“有人真的在用”的证据**。
- **开源社区反过来也塑造标准组织**：IETF 的邮件列表文化、公开评审、靠实现说话，与开源社区的协作方式同源（见 [开源文化与社区](03-open-source-culture.md)）；W3C 的工作组里同样坐着大量开源项目的维护者。标准组织与开源社区不是两拨人，而是同一群工程师在两个场合用同一套方法做事。
- **分叉权是最后的制衡**：标准组织也可能走偏——流程僵化、被少数厂商绑架、标准迟迟定不下来。这时，开源社区的“分叉”与“另起炉灶”就是制衡：WHATWG 的出现本身就是一次对 W3C 节奏的分叉式回应。转折在于：**开放标准与开源软件互相成就，也互相制衡**——任何一方垄断了“怎么定规则”的权力，另一方都能用脚投票。

### 3.7 标准之争的历史教训

- **先有实现，再有标准**：TCP/IP、HTTP、HTML 都是先跑起来、再写成标准；反过来，先写全套规范、再等实现的 OSI，则输掉了时间。标准最怕的不是不完美，而是**在没人用的时候就把自己定死了**。
- **简单够用胜过理论完备**：IP 的“尽力而为”、TCP 的“端到端可靠”，都不如 OSI 的七层理论漂亮，但部署成本低、容错性强，先活下来的是它们。
- **免费许可是护城河**：W3C 的免版税原则与 IETF 的免费 RFC，是 Web 与互联网能成为公共基础设施的关键——一旦核心标准要收费，互联互通就会按付费能力分层。
- **胜利者也会留下债务**：TCP/IP 的地址空间（IPv4 约 43 亿个地址）在设计时显得绰绰有余，后来不够用了，才有了 IPv6 的漫长迁移；这提醒我们：**开放标准不是一劳永逸**，每一代标准都要为下一代留出路。

## 4. 分类

- 按制定主体：政府间组织（ITU：条约与建议书）、行业标准组织（ISO、IEEE）、开放社区组织（IETF、W3C：公开参与、免费文档）。
- 按约束力：事实标准（de facto：大家都在用的做法，如早期 TCP/IP）、正式标准（de jure：经组织批准发布的规范，如 RFC 标准、W3C 推荐标准）——两者经常互相转化，事实标准事后会被追认为正式标准。
- 按开放程度：开放标准（规范公开、免费实现、免版税或合理许可）与专有标准（规范不公开或实现要交费）；开放与专有之间还有许多中间形态，判断时看三条：文档能不能免费看到、实现要不要交费、参与制定有没有门槛。
- 按与开源的关系：有开源实现的开放标准（TCP/IP、HTTP、HTML）与缺少开源实现的标准——后者即使写在纸上，也很难真正落地。

## 5. 典型应用：这些思想在今天的延续

- 互联网接入：今天任何设备接入互联网、任何两个网络互联，跑的仍是 TCP/IP 这一套开放标准；地址耗尽后的 IPv6 迁移正在进行中，见 [IPv6 部署入门](../07-network-comms/01-ipv6-deployment.md)。
- 网页与浏览器：今天任何浏览器都能打开任何网站，靠的是 W3C 与 WHATWG 维护的 HTML、CSS 等开放标准；浏览器内部如何按标准渲染页面，见 [渲染引擎与渲染流程](../15-browser-internals/01-rendering-pipeline.md)。
- 安全连接：今天浏览器地址栏的那把锁，背后是 TLS 协议——同样是 IETF 的开放标准、同样有多个开源实现互相验证，见 [TLS 与 PKI](../13-cryptography/03-tls-pki.md)。
- 开源基础设施：今天的服务器、云平台与开发工具大多跑在开源软件上，而这些软件彼此协作的前提，正是一套开放标准（见 [开源文化与社区](03-open-source-culture.md)中“开源怎么活下来”一节的对照）。
- 新标准的制定方式：今天任何一项互联网新标准（例如 HTTP/3 背后的 QUIC），仍走 IETF 那条老路——先写草案、先做实现、先互通测试，再谈“标准”二字。

## 6. 限制与常见误解

- **“开放标准就是没有标准”是误解**：开放标准恰恰是最严格的标准——规范公开、实现要互通测试、修订要公开讨论；“开放”指的是制定与使用不设门槛，不是“怎么写都行”。
- **“标准是委员会投票投出来的”是误解**：至少在 IETF，标准靠“粗糙共识加可运行代码”成立，没有投票环节；投票表决是另一类组织的做法，不能一概而论。
- **“OSI 是错的、TCP/IP 是对的”是简化**：OSI 的七层模型作为理解网络的框架至今仍在教学与工程中使用，它输掉的是协议套件的竞争，不是思想的全部；把对手说成一无是处，会错过它留下的真正遗产。
- **“开源就等于开放标准”是误解**：开源管的是代码的自由（见 [开源文化与社区](03-open-source-culture.md)），开放标准管的是互联互通的规则；一个项目可以代码开源但用专有协议，也可以遵循开放标准但代码闭源——两者有关联，不是同一件事。
- **“标准定下来就一劳永逸”是误解**：IPv4 地址耗尽、HTML 从 4 到 5 的漫长演进都说明，标准需要持续修订；定标准只是开始，维护标准才是常态。
- **“开放标准没有商业利益”是误解**：标准之争历来有商业利益在场——厂商参与制定标准，往往是想让自家技术成为标准；开放流程的意义不在于消除利益，而在于让利益在公开场合博弈，而不是在密室里决定。

## 7. 小结

开放标准的思想始于电报时代的互联互通需求，在 TCP/IP 与 OSI 的对决中确立了“实现先行、共识加代码”的路线，经 IETF 与 W3C 长成两套公开的制定机制，最后与开源软件结成互相成就、互相制衡的关系。它留下的教训很简单：标准不是写出来的，是跑出来的；不是投出来的，是用出来的。
