# IPv6 部署入门

## 1. 一句话定义

IPv6 是互联网协议的第 6 版：用 128 位地址取代 IPv4 的 32 位地址，让每一台联网设备都有机会直接拥有全球可达的地址，而不必长期依赖地址转换。

## 2. 为什么需要它

IPv4 地址只有 32 位，理论上限约 43 亿个。地址耗尽之后，互联网靠 NAT（网络地址转换）续命：一大批设备共用少数几个公网地址，对外隐藏在转换器后面。这能撑住存量，却带来三个长期代价：端到端直连变难（点对点应用、入站服务要做端口映射）、排障变难（一个公网地址背后是谁，需要查转换日志）、地址本身成了稀缺资源（申请、买卖、复用都产生管理成本）。

IPv6 把地址长度扩到 128 位，从根本上取消“地址不够分”这个约束。它的目标不是“让网速变快”——IPv6 本身不提速——而是恢复端到端可达性，让地址规划重新变得简单：内网不再需要为了省地址而层层 NAT，设备地址可以按拓扑规律分配，出了问题按地址就能定位到子网。

现实是：IPv4 不会一夜消失。未来很长一段时间是两者共存，部署 IPv6 的真正工作，是在不断 IPv4 的前提下，把 IPv6 安全、平稳地接进来。本篇讲地址怎么分、两边怎么共存、落地按什么顺序检查；具体的 DNS 服务器搭建与代理、隧道配置属本站 04-network 章节，本篇只做相对链接，不重复步骤。

## 3. 核心含义

### 3.1 协议地位与报文头

IPv6 的现行规范是 RFC 8200（2017 年 7 月发布，互联网标准 STD 86，取代了 1998 年的 RFC 2460）。与 IPv4 相比，报文头被简化为固定 40 字节：版本号、流量类别、20 位流标签、净荷长度、下一个头部、跳数限制，以及源地址与目的地址。固定长度意味着路由器解析更快；没有头部校验和（差错检测交给链路层与上层），分片只能由源端做——中间路由器不再替发送方分片，超大报文由源端根据路径 MTU 发现（RFC 8201）提前切好。IPv6 要求每条链路的 MTU 不低于 1280 字节，这是部署时链路设备必须满足的下限。

可选功能不再塞进主头部，而是挂成一条“扩展头部链”：逐跳选项、路由、目的选项、分片、认证、封装安全净荷等，按需串联。这种设计让新功能不必改动主头部格式就能加入，但也带来一条运维教训：防火墙与中间设备必须正确处理扩展头部链，粗暴丢弃“带扩展头部的报文”会把正常流量一并掐断。

### 3.2 地址写法

IPv6 地址写成 8 组 16 进制数，每组 16 位，组间用冒号分隔，例如 `2001:db8:0:0:0:0:0:1`。两条压缩规则让它能读：

- 每组前导的 0 可以省略（`0db8` 写成 `db8`）；
- 一段连续的全 0 组可以用一对冒号 `::` 代替，但**一个地址里只能用一次**，否则展开后无法确定补了几组 0。

于是上例可写成 `2001:db8::1`。地址后可跟斜杠前缀长度表示网段，如 `2001:db8::/32` 表示前 32 位是网络前缀。注意区分两件事：`::` 是“补 0”的写法，全 0 地址本身（未指定地址）也恰好写作 `::`；读到 `::` 先看上下文，不要把压缩符号与地址值混为一谈。

地址结构遵循 RFC 4291 定义的寻址架构：地址的前半部分通常是网络前缀，后半部分是接口标识符。局域网子网按惯例划为 /64——前缀 64 位、接口标识符 64 位，这正是无状态地址自动配置（SLAAC）的工作前提：路由器通告一个 /64 前缀，主机自己在后 64 位生成接口标识符并组合成完整地址。

### 3.3 地址类型：先分清“这个地址能走多远”

| 类型 | 前缀 | 含义与边界 |
| --- | --- | --- |
| 全球单播地址（GUA） | `2000::/3` | 全球路由的公网地址，相当于 IPv4 的公网地址，是部署的目标 |
| 链路本地地址 | `fe80::/10` | 只在同一条链路内有效，不可路由出链路；每个启用 IPv6 的接口都会自动生成一个，用于邻居发现等本链路协议 |
| 唯一本地地址（ULA） | `fc00::/7`（RFC 4193） | 私网地址，相当于 IPv4 的 10/172.16/192.168 段；站内自用、不向全球路由宣告，`fd00::/8` 一段由站点自行随机生成 |
| 回环地址 | `::1/128` | 本机自己，相当于 IPv4 的 127.0.0.1 |
| 未指定地址 | `::/128` | 表示“还没有地址”，只用作源地址占位，不可作为目的地址 |
| 组播地址 | `ff00::/8` | 一对多，取代了 IPv4 的广播：IPv6 没有广播，邻居发现、路由通告这类“喊一嗓子”的需求改由组播实现 |
| 文档专用前缀 | `2001:db8::/32`（RFC 3849） | 只许出现在文档与示例中，任何一方都不得实际分配使用；写教程、画拓扑时用它，避免误用真实地址段 |

ULA 值得单独提醒：它“私网”的性质与 IPv4 私网地址相同——出了站就不可达。于是同一台主机常常同时有多个地址：一个链路本地地址（本链路用）、一个 ULA（站内用）、一个全球单播地址（出站用）。主机按地址选择规则（RFC 6724）在其中挑：访问全球目标时优先用全球地址，访问站内目标时用 ULA。地址多不是故障，是 IPv6 的正常形态；排障时先确认“这次连接用的是哪一个源地址”，能省掉大量弯路。

### 3.4 地址怎么来：SLAAC 与 DHCPv6

主机获得 IPv6 地址有两条主路线，常常配合使用：

- **SLAAC（无状态地址自动配置，RFC 4862）**：路由器周期性发送路由通告（RA），其中带有前缀信息；主机收到后自行组合出地址，并用邻居发现协议做重复地址检测。无状态的意思是：路由器不记录“谁拿了哪个地址”，配置简单、适合终端数量大的网络。代价是：只靠 SLAAC 拿不到 DNS 服务器地址以外的集中管控信息（历史上 SLAAC 本身不分发 DNS，需要配合 RA 中的 DNS 选项或其他方式），也不便于做“按设备固定地址”的审计。
- **DHCPv6（RFC 8415）**：由服务器集中分配地址并记录租约，还能下发 DNS、域名搜索后缀等选项，适合需要可审计、可固定分配的网络。DHCPv6 也可以只做“无状态”模式：地址仍由 SLAAC 生成，DHCPv6 只补发 DNS 等其他配置——这种组合在很多企业网里最常见。

选型原则不复杂：终端多、变动快、审计要求低的场景优先 SLAAC；服务器、打印机、需要固定地址与集中记录的场景用 DHCPv6；两者混用时要约定清楚“谁负责地址、谁负责其他选项”，避免同一功能两处配置互相打架。

### 3.5 IPv6 不是“更安全的 IPv4”

一个流传很广的误解是“IPv6 自带加密，所以更安全”。事实是：IPsec 曾被写进早期 IPv6 规范的必备项，后来改为可选，实际部署中 IPv6 的安全与 IPv4 一样，依赖 TLS、防火墙、访问控制这些上层与周边机制。地址空间大确实让“全网扫描找主机”变得不现实，但这只是提高了扫描成本，不是访问控制——任何地址只要可达，就必须有防火墙策略管着。部署 IPv6 时，防火墙规则、入侵检测、日志采集必须同步覆盖 v6 流量；只给 IPv4 上锁、让 IPv6 裸奔，是最常见的部署事故。

## 4. 分类：与 IPv4 共存的三条路线

IPv4 与 IPv6 报文头互不兼容，无法直接互通。过渡机制按原理分三类，选型看“你缺的是哪一边的连通性”：

### 4.1 双栈（Dual-Stack）：两套协议同时跑

主机、路由器、应用同时启用 IPv4 与 IPv6，目标同时有 A 记录（IPv4）与 AAAA 记录（IPv6）时优先尝试 IPv6。这是目前最主流、也最推荐的路线：没有封装开销、没有翻译状态，出了问题也最容易定位。客户端用“Happy Eyeballs”（RFC 8305）算法并行尝试两种协议、取先通的那个，避免“IPv6 通告了却不通、用户干等超时”的体验。双栈的代价是运维负担翻倍：地址规划、DNS、防火墙、监控都要做两套——但这正是向纯 IPv6 演进的必经阶段，省不掉。

### 4.2 隧道：把一种报文装进另一种里穿过去

当中间一段网络只支持一种协议时，用隧道把另一种协议的报文封装起来运过去。基本机制见 RFC 4213，常见形态有：

- **6in4**：IPv6 报文装进 IPv4 报文中，适合手动配置的固定隧道；
- **6rd（RFC 5969）**：运营商用自家 IPv4 地址派生 IPv6 前缀，批量给用户快速开通 IPv6，隧道按 IPv4 路由自动走最优路径；
- **Teredo（RFC 4380）**：为位于 NAT 后的主机提供 IPv6 连通，靠 UDP 封装穿 NAT；
- **隧道代理（Tunnel Broker）**：第三方提供隧道端点，用户通过注册获得一条隧道，适合早期尝鲜与实验。

隧道的代价是封装开销与 MTU 缩水（外层头部吃掉一部分净荷空间），以及排障链路变长：报文出问题要分清是内层还是外层。隧道适合“过渡期搭桥”，不适合作为长期主力——能拿到原生 IPv6 的地方，优先原生。

### 4.3 翻译：让纯 IPv6 侧访问 IPv4 资源

当一侧已经纯 IPv6、另一侧仍是 IPv4 时，在边界做协议翻译：

- **NAT64（RFC 6146）+ DNS64（RFC 6147）**：DNS64 在只查到 A 记录时合成一条 AAAA 记录（把 IPv4 地址嵌进约定的翻译前缀 `64:ff9b::/96` 中）；客户端按这条合成地址发包，NAT64 网关把报文翻译成 IPv4 发给目标，返回流量再翻译回来。移动网络大规模用这套组合跑纯 IPv6 终端。
- **464XLAT（RFC 6877）**：在 NAT64 基础上再加一层客户端侧翻译，让那些直接写死 IPv4 字面地址、不走 DNS 的应用也能在纯 IPv6 网络上工作。

翻译的代价与 NAT44 同源：网关要维护状态、部分应用（尤其在报文中内嵌地址的应用）会出问题、端到端透明性被破坏。翻译是“让纯 IPv6 侧不断粮”的兜底，不是部署目标；能双栈的地方不要用翻译代替双栈。

三条路线可以组合：典型演进是“双栈起步 → 内部逐步纯 IPv6 + 边界 NAT64 保底 → 远期纯 IPv6”。每一步都以前一步的监控数据为依据，不要凭感觉跳阶段。

## 5. 典型应用

- **家庭与小型办公网络**：宽带开通双栈后，终端自动获得全球地址，远程访问家里的 NAS、摄像头不再依赖运营商的端口映射（仍需防火墙显式放行，不是“有了地址就敞开大门”）。
- **移动网络**：运营商在核心网跑纯 IPv6 + NAT64/464XLAT，终端侧省去 IPv4 地址分配，地址池压力随用户增长而消失。
- **云与数据中心**：新集群直接按 /64 划子网，容器与虚拟机地址按拓扑规律生成，服务发现与排障不再受 NAT 层遮挡。
- **物联网与专网**：设备量大、地址需求大的场景用 ULA 做站内编址，需要出站时再经网关翻译或代理，避免为每个传感器申请公网地址。

## 6. 部署 checklist

按顺序核对，每一步确认后再进下一步；回退预案与每一阶段同行：

1. **清点现状**：列出所有网络设备、操作系统、应用与安全设备，确认各自是否支持 IPv6（不支持的列入替换或隔离清单，不要假设“新设备都支持”）。
2. **向上游确认**：向宽带或云厂商确认是否提供 IPv6 接入与地址分配（前缀长度、是否支持前缀委派 PD）；拿不到原生接入时，先评估隧道方案的 MTU 与稳定性，再决定是否接受。
3. **地址规划**：向上游申请地址段；站内按 /64 划子网，预留 ULA 段做内部编址；文档、示例一律用 `2001:db8::/32`，不要把真实地址段写进公开文档。
4. **先内后外**：先在实验 VLAN 或一台测试机上启用，验证 SLAAC/DHCPv6、DNS 解析、默认路由；再推广到办公网，最后才是对外服务。
5. **DNS 同步**：对外服务加 AAAA 记录前，先确认服务本身已在 IPv6 上可达；AAAA 一旦发布，全球客户端就会开始尝试 IPv6，发布顺序反了等于主动制造故障。
6. **防火墙同步覆盖**：把 IPv4 的入站、出站策略逐条翻译到 IPv6；放行邻居发现与“报文过大”等必需的 ICMPv6 类型（ICMPv6 在 IPv6 里是基础协议，不是可选项，整段封掉会让邻居发现与路径 MTU 发现同时失效）。
7. **监控与日志双栈化**：流量统计、告警、审计日志要能区分 v4/v6 流量；上线初期重点看“IPv6 尝试失败率”，Happy Eyeballs 会掩盖单边故障，失败率指标是唯一能发现它的办法。
8. **应用验证**：逐个验证对外服务在 IPv6 下的真实行为，特别是那些在报文中内嵌地址、做 IP 白名单、按 IP 限流的应用——这类应用最容易在翻译与双栈下出问题。
9. **回退预案**：每一步保留“关掉 IPv6 通告/撤掉 AAAA”的操作路径与负责人；回退不是失败，是 checklist 的一部分。

> 本机观察（实测）：2026-11-04 在代理 VM 上运行 `ip -6 addr show` 与 `ip -6 route show`，网卡上只有回环地址 `::1`、一条 ULA 前缀（`fd8b:…::/64`，属 `fc00::/7` 私网段）与链路本地地址，没有全球单播地址，默认路由指向 ULA 网关。这正是“有 IPv6 协议栈、有私网地址、但未获得全球地址”的典型状态：`ip -6` 能看到地址，不等于能访问全球 IPv6 互联网，判断标准是是否存在全球单播地址与指向公网的默认路由。

```bash
# 查看本机 IPv6 地址与路由（只读命令；输出因环境而异）
# 示例未实测：以下命令本身未在本机逐条跑通，仅作排查示例
ip -6 addr show
ip -6 route show
ping -6 -c 3 2001:4860:4860::8888
```

## 7. 限制与常见误解

- “开了 IPv6 网就变快”：错。IPv6 不提速；感觉变快通常是因为绕开了 NAT 或运营商的 CGNAT 瓶颈，不是协议本身的功劳。
- “IPv6 地址多到不用规划”：错。地址多解决的是“够不够分”，不是“好不好管”；不做前缀规划，排障与防火墙策略照样失控。
- “IPv6 自带安全”：错。见 3.5，IPsec 可选，防火墙必须同步覆盖。
- “只要加了 AAAA 记录就算部署完成”：错。AAAA 只是宣告“我支持 IPv6”，服务、防火墙、监控没跟上时，宣告本身就是故障源。
- “IPv4 迟早要关掉，现在就可以不管它”：错。共存期以十年计，部署目标是“双栈跑稳”，不是“立刻纯 v6”。

## 8. 小结

IPv6 用 128 位地址解决地址枯竭，恢复端到端可达；SLAAC 与 DHCPv6 分工负责地址分发；与 IPv4 共存靠双栈为主、隧道搭桥、翻译兜底三条路线；落地的关键不在协议本身，而在 DNS、防火墙、监控同步跟上与否——按 checklist 一步步验过去，IPv6 就是一次平稳升级。
