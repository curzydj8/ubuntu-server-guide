# WSL 安装与发行版管理

> **实测说明**：Windows / WSL 专属命令无法在当前 Linux 虚拟机上实测。本文所有命令示例一律为**示例未实测**，仅按微软官方文档的命令形式给出；执行前请以官方文档为准，并在自己的 Windows 设备上先小范围验证。

## 1. 一句话定义

WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）是 Windows 内置的、在 Windows 上运行 Linux 发行版的组件；安装与发行版管理就是围绕“装哪个版本、装哪个发行版、如何查看、切换、更新、备份与迁移”的一整套操作。

## 2. 为什么需要它

开发、运维与学习常常要在同一台机器上同时用到两个世界：Windows 一侧是 Office、浏览器、桌面工具与硬件驱动，Linux 一侧是 Bash、包管理器、开源工具链与服务器同款环境。过去的解法是双系统（切换成本高）或虚拟机（资源占用大、启动慢）。WSL 的定位介于两者之间：不用重启进另一个系统，也不用装一台完整的虚拟机，就能在 Windows 里跑一个真正的 Linux 用户空间，两个世界的命令行与文件可以互相调用（互操作细节见[WSL 与 Windows 互操作](17-wsl-windows-interop.md)）。

但“装上就能用”只对默认路径成立：一旦要装第二个发行版、把某个发行版从 WSL 1 升到 WSL 2、把配好的环境搬到另一台电脑、或者删掉一个不再用的发行版，就必须分清 WSL 1 与 WSL 2、管理命令各自管什么、以及导出导入时数据存在哪里。本篇只讲安装与管理，互操作另起一篇，不重复。

## 3. 核心含义

### 3.1 WSL 1 与 WSL 2 的区别：不是版本号递增，是实现换了

WSL 1 与 WSL 2 都叫 WSL，但底层实现不同，选错会直接影响性能与兼容性：

| 维度 | WSL 1 | WSL 2 |
|---|---|---|
| 实现方式 | 翻译层：把 Linux 系统调用翻译成 Windows 内核调用，没有 Linux 内核 | 轻量级虚拟机：内置真正的 Linux 内核，运行在 Hyper-V 架构的子集之上 |
| 内核 | 无独立 Linux 内核 | 有完整 Linux 内核，由微软提供并可更新 |
| 文件系统性能 | 访问 Windows 文件较快，Linux 文件系统操作相对较慢 | Linux 文件系统内的操作快得多；跨文件系统（Linux 工具读写 `/mnt/c` 下的 Windows 文件）则较慢 |
| 系统调用兼容性 | 部分 Linux 系统调用未实现，个别软件跑不起来 | 兼容性好得多，绝大多数 Linux 软件可直接运行 |
| 启动与资源 | 启动快、内存占用小 | 启动仍很快，但会占用一块虚拟机内存；内存占用可通过配置限制（具体配置项以官方文档为准） |
| 适用场景 | 对 Linux 文件性能不敏感、只跑少量命令行工具 | 开发、编译、容器相关工作、需要完整 Linux 内核行为的场景 |

结论先说清楚：**新安装默认选 WSL 2**。微软官方安装文档明确写着，使用 `wsl --install` 安装的新 Linux 环境默认就是 WSL 2。只有在明确知道某个旧工具在 WSL 1 下表现更好、或 WSL 2 的虚拟化前提无法满足时，才考虑 WSL 1。两个版本可以在同一台机器上共存，不同发行版可以分别设为版本 1 或 2。

一个常见误解要纠正：WSL 2 用了虚拟化技术，不等于它就是一台“传统虚拟机”。它没有独立的虚拟机窗口、不需要单独分配虚拟磁盘与安装介质，发行版以应用形式安装在 Windows 里，由 `wsl` 命令统一管理；同时它也不是容器，里面跑的是完整的 Linux 用户空间。

### 3.2 安装前提：先核对版本，再开虚拟化

装 WSL 之前先过三道检查，缺一道都可能装到一半报错：

1. **Windows 版本**：`wsl --install` 命令要求 Windows 10 版本 2004 及更高版本（内部版本 19041 及更高版本）或 Windows 11。低于该版本的 Windows 10 需要先更新系统，或走微软官方文档里的手动安装步骤（旧版手动安装不在本文展开，以官方发布为准）。查看版本的方法是按 `Win + R`，输入 `winver` 回车，对照对话框里的版本号。
2. **虚拟化开启**：WSL 2 需要 CPU 虚拟化支持并在 BIOS/UEFI 里开启（常见名称为 Intel VT-x 或 AMD-V）。如果在任务管理器的“性能 → CPU”里看到“虚拟化：已启用”，一般说明已开启；若显示已禁用，需要重启进入 BIOS/UEFI 开启——这一步在 Windows 里改不了设置，只能重启进固件改。
3. **可选功能**：WSL 2 需要启用“Windows Subsystem for Linux”与“Virtual Machine Platform”两个可选功能。走 `wsl --install` 会自动启用这两个功能，不用手工勾选；走手动安装时才需要用 DISM 命令或“启用或关闭 Windows 功能”面板逐项启用。

版本档位方面：WSL 2 可用于全部桌面版，包括 Windows 10/11 家庭版（微软 FAQ 的说明）；不需要专业版。这一点与本地组策略编辑器不同——家庭版没有 gpedit.msc（见[Windows 系统管理](01-system-management.md)），但家庭版可以装 WSL 2。

### 3.3 安装：一条命令装默认发行版，指定发行版加参数

推荐路径只有一条命令。以管理员身份打开 PowerShell（右键“以管理员身份运行”，提权机制见[Windows 系统管理](01-system-management.md)的 UAC 一节），执行（示例未实测）：

```powershell
wsl --install
```

这条命令一次做四件事：启用运行 WSL 所需的可选功能、下载并安装最新的 Linux 内核、把 WSL 2 设为默认值、下载并安装默认的 Linux 发行版 Ubuntu。安装过程可能要求重启，重启后发行版会继续完成初始化。

首次启动发行版时，系统会要求创建一个 Linux 用户名与密码：这个账户是发行版内部的普通用户，与 Windows 账户不是同一个；密码用于发行版内的 `sudo` 等操作，请按发行版常规做法妥善保存。

想装 Ubuntu 以外的发行版，有两种做法：

- **先看再装**：先列出可在线安装的发行版（示例未实测）：
  ```powershell
  wsl --list --online
  ```
  再按列表里的名称指定安装，例如安装 Debian（示例未实测）：
  ```powershell
  wsl --install -d Debian
  ```
- **从 Microsoft Store 安装**：在 Microsoft Store 里搜索发行版名称（如 Ubuntu、Debian、openSUSE、Kali 等），点击获取即可安装；装好后同样由 `wsl` 命令管理。

发行版名称以 `wsl --list --online` 的输出为准，不同学名、不同版本的上架情况会变，本文不逐个罗列发行版清单（以官方发布为准，待核实）。

## 4. 管理命令：先查，再改

`wsl` 命令是管理入口。日常管理按“查看 → 切换 → 更新 → 停止”这个顺序用，改动类操作执行前先用查看类命令确认对象。以下命令均在 Windows 的 PowerShell 或命令提示符里执行，均为**示例未实测**：

| 用途 | 命令（示例未实测） | 说明 |
|---|---|---|
| 查看已安装的发行版及版本 | `wsl --list --verbose` | 列出各发行版的名称、状态（运行中/已停止）与 WSL 版本（1 或 2） |
| 查看可在线安装的发行版 | `wsl --list --online` | 安装前的选型依据，名称以输出为准 |
| 进入默认发行版 | `wsl` | 不带参数时进入默认发行版的 shell |
| 进入指定发行版 | `wsl -d <发行版名称>` | 多发行版并存时指定进入哪一个 |
| 设默认发行版 | `wsl --set-default <发行版名称>` | 决定不带参数的 `wsl` 进入哪一个 |
| 设默认版本 | `wsl --set-default-version 2` | 此后新装的发行版默认用 WSL 2；已装的发行版不受影响 |
| 切换单个发行版版本 | `wsl --set-version <发行版名称> 2` | 在 WSL 1 与 2 之间转换；转换需要时间，转换前建议先备份（见第 5 节） |
| 更新 WSL 内核与组件 | `wsl --update` | 更新的是 WSL 本身，不是发行版内的 Linux 软件包；发行版内的软件包用发行版自己的包管理器更新 |
| 停止指定发行版 | `wsl --terminate <发行版名称>` | 停止该发行版的运行，不删除数据 |
| 停止全部发行版 | `wsl --shutdown` | 停止所有发行版与 WSL 2 的轻量级虚拟机 |
| 注销发行版 | `wsl --unregister <发行版名称>` | **删除该发行版的全部数据且不可恢复**，执行前必须先备份 |

几条使用纪律：

- **先查后改**：`--set-version`、`--unregister` 这类改动执行前，先用 `wsl --list --verbose` 确认发行版名称拼写正确；名称输错可能改到或删掉另一个发行版。
- **区分两类“更新”**：`wsl --update` 管 WSL 组件与内核；发行版里的软件包更新（如 Ubuntu 的 `apt update && apt upgrade`）管发行版内的软件。只跑其中一类，另一类不会跟着更新。
- **注销不是卸载应用**：`--unregister` 删的是发行版的数据与注册信息；若之后想彻底清理，还需在 Windows 设置里卸载对应的发行版应用。两者不要混为一谈。
- **版本转换要留出时间**：`--set-version` 在两个版本之间转换发行版时需要复制与转换文件系统，数据量越大耗时越长；转换中途不要强制关机或中断。

## 5. 发行版的备份与迁移：导出与导入

WSL 官方推荐的备份与迁移方式是导出为 tar 包、再导入回来。核心是两条命令（示例未实测）：

```powershell
wsl --export Ubuntu D:\Backup\ubuntu-backup.tar
wsl --import Ubuntu-Restore D:\WSL\Ubuntu-Restore D:\Backup\ubuntu-backup.tar
```

读法：

- `--export <发行版名称> <备份文件路径>` 把整个发行版（系统文件、已装软件、用户文件、配置）导出成一个 `.tar` 文件。导出前建议先用 `wsl --terminate <发行版名称>` 停掉该发行版，避免导出进行中的写入导致备份不一致。
- `--import <新发行版名称> <安装位置> <备份文件路径>` 把 tar 包注册成一个新的发行版。三个参数缺一不可：新名称可以与原来相同（同一台机器上恢复）也可以不同（迁移或复制一份时用新名避免冲突）；安装位置是导入后发行版数据存放的文件夹，迁移到大容量磁盘时就改这里。
- 导入时可通过附加参数指定 WSL 版本，例如 `--version 2` 强制导入为 WSL 2；不指定时按默认值处理（默认行为以官方发布为准，待核实）。

典型用法：

- **本机备份**：定期导出一份 tar 包存到非系统盘或外部存储；发行版损坏、误删文件后，注销旧发行版再导入备份即可恢复。
- **换机迁移**：旧机器导出 tar 包，拷到新机器上导入；新机器只需装好 WSL，不需要重装发行版里的软件与配置。
- **复制一份做实验**：导入时起一个新名字，就得到一个与原环境相同的副本；在副本里折腾，搞坏了删掉重导，不影响原发行版。

注意事项：

- **备份文件包含全部数据**：tar 包里有发行版内的全部文件，包括 shell 历史、SSH 密钥、缓存的云服务凭据等敏感内容。备份文件要按敏感数据保管：存放在可信位置，传输过程注意加密与删除旧副本，不要把它随手发给别人或上传到公开位置。
- **导出不是增量备份**：每次导出都是完整的一份，文件较大；备份频率按“环境变化频率”定，配好环境后导一份、之后大改动后再导一份，比每天导更实际。
- **新版 WSL 的 VHD 格式**：据微软 FAQ，新版 WSL 支持以 VHD 格式导出与导入（`--format vhd` / `--vhd` 相关参数），适合在机器之间直接搬运虚拟磁盘文件；该功能的可用版本与具体参数以官方发布为准（待核实），本文不展开。
- **不要直接复制发行版的数据文件**：发行版的数据以虚拟磁盘文件形式存放在 Windows 用户配置目录下，直接复制、移动或用 Windows 工具改写这些文件可能损坏发行版；备份与迁移只走 `--export` / `--import`。

## 6. 典型应用

- **开发环境搭建**：一台 Windows 笔记本上装 Ubuntu 做开发，Windows 一侧跑浏览器与桌面工具，Linux 一侧跑编译与测试；环境配好后导出一份 tar 包当基线。
- **多发行版并存**：主力用 Ubuntu，另装一个 Debian 或 Alpine 做兼容性验证；默认发行版设为主力，验证时用 `wsl -d <名称>` 进入另一个。
- **教学与实验**：课堂或自学时每学一个主题导一份备份，实验做坏了用导入恢复，比重装系统快得多。
- **换机不断档**：换新电脑时把旧发行版导出、到新电脑导入，开发环境与配置基本原样搬走，不用从头再配一遍。

## 7. 限制与常见误解

- **WSL 不是完整的虚拟机，也不是双系统**：它不提供独立的虚拟机窗口与硬件直通，图形界面应用的支持情况因版本而异；需要完整桌面或硬件直通的场景，应评估虚拟机或双系统方案（具体支持范围以官方发布为准，待核实）。
- **WSL 1 不能只靠“升级命令”变成 WSL 2 的全部好处**：`--set-version` 能转换版本，但转换前要确认虚拟化前提已满足，否则会失败；失败时先查版本与虚拟化状态，不要反复重试同一条命令。
- **`wsl --update` 不更新发行版软件**：它只更新 WSL 组件与内核；发行版内的软件包要用发行版自己的包管理器更新。
- **注销发行版没有回收站**：`wsl --unregister` 一执行数据即删，不可恢复；执行前必须确认已导出备份。
- **跨文件系统操作慢**：在 WSL 2 里用 Linux 工具频繁读写 `/mnt/c` 下的 Windows 文件会比读写 Linux 文件系统慢；项目文件应放在 Linux 文件系统内（互访与性能细节见[WSL 与 Windows 互操作](17-wsl-windows-interop.md)）。
- **本文不展开旧版手动安装**：低于 `wsl --install` 版本要求的 Windows 10 的手动安装步骤（DISM 启用功能、手动下载内核与发行版包）以微软官方手动安装文档为准，本文不逐条复述。

## 8. 小结

WSL 安装与发行版管理 = 版本先核对（Windows 10 2004+ / Windows 11、虚拟化开启）→ 一条命令装默认发行版（`wsl --install`）→ 用 `wsl --list`、`--set-default`、`--set-version`、`--update` 做日常管理 → 用 `--export` / `--import` 做备份与迁移。默认选 WSL 2，改动前先查看、注销前先备份。
