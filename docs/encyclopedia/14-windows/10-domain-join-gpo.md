# AD 域加入与组策略下发

## 1. 本章目标

读完本篇，能说清域与工作组在管理方式上的根本区别，能按检查清单完成一台 Windows 设备的加域准备与加域操作，能描述组策略从域控制器下发到客户端的流程与生效范围，并能处理脱域与常见的加域失败。

> **实测说明**：本文撰写于 Linux 虚拟机，Windows 专属命令无法在当前环境实测。文中所有 Windows 命令示例一律标“示例未实测”，请在真实 Windows 环境中核对后再执行；命令的具体参数以微软官方文档为准。

## 2. 背景与问题

一台 Windows 设备刚装好系统时，默认属于一个叫 WORKGROUP 的工作组：每台机器自己管自己的账户、密码与设置。两三台电脑这样用没有问题，但一个组织有几十、几百台设备时，问题就来了：新员工入职要在每台机器上建账户、改密码要逐台改、想统一关掉所有电脑的 USB 存储要一台一台点。工作组的模型是“每台机器各自为政”，管理成本随设备数量线性增长。

Active Directory（AD）域是 Windows 世界解决这个问题的集中管理模型：由域控制器（Domain Controller，DC）统一保存账户、计算机与策略，设备“加入域”后就接受域的统一管理。加域是设备从“单机”变成“组织成员”的分界点，而组策略则是域控制器把管理意图批量下发到每台设备的主要手段。域的账户与身份模型见[Windows 系统管理](01-system-management.md)，组策略的内部处理顺序（LSDOU）与排障方法见[注册表与组策略](02-registry-group-policy.md)，本文只讲“加入域”和“策略怎么下来”这两个动作本身，不重复讲 LSDOU 的细节。

## 3. 域与工作组的区别

| 维度 | 工作组（Workgroup） | 域（Domain） |
|---|---|---|
| 身份来源 | 每台机器有自己的本地账户数据库 | 域控制器统一保存账户，域账户全域通用 |
| 登录方式 | 只能用本机账户登录本机 | 可用域账户登录域内任意设备（权限允许时） |
| 密码与策略 | 每台机器各自设置，互不同步 | 密码策略、锁定策略由域统一下发 |
| 集中管理 | 没有，逐台操作 | 组策略、软件部署、脚本下发，批量生效 |
| 适用规模 | 几台设备的家庭或小型办公 | 几十台以上的组织环境 |
| 管理入口 | 本机设置与本地组策略 | 域控制器上的 AD 管理工具与组策略管理控制台（GPMC） |
| 版本要求 | 各版本均可 | 客户端需专业版及以上（家庭版不能加域，见[Windows 系统管理](01-system-management.md)） |

一个容易混淆的概念是 **Microsoft 账户**：它是在线身份，可同步个人设置，但它既不是工作组也不是域，不能替代域的集中管理。三者不要混用：工作组管“几台机器的松散组合”，域管“组织的集中管理”，Microsoft 账户管“个人的在线身份”。

## 4. 加域的前提：先过检查清单，再点加入

加域失败十有八九不是“点错了按钮”，而是前提没满足。按下面顺序逐项检查，卡在哪一项就先修哪一项：

### 4.1 版本与权限

- **客户端版本**：Windows 10/11 专业版、企业版或教育版。家庭版没有加域功能，点加入时会直接找不到入口——这是版本问题，不是网络问题。
- **本地管理员权限**：加域操作要改系统级成员身份，必须以本地管理员身份执行。
- **域侧权限**：执行加域的域账户需要有“将计算机加入域”的权限。默认情况下，普通域用户最多可将 10 台计算机加入域（该上限由域管理员配置，以官方发布为准（待核实））；超出上限或权限不足时，加域会报权限错误，应联系域管理员。

### 4.2 DNS 必须指向域控制器

这是最常见的失败原因，值得单独讲透。

加域时客户端要靠 DNS 找到域控制器：它向 DNS 查询域的 SRV 记录（一种标明“某服务由哪台服务器提供”的 DNS 记录），拿到域控制器的地址后才去联系它。如果客户端的 DNS 指向的是公网 DNS（例如运营商或 8.8.8.8），它查不到内网域的 SRV 记录，加域就会报“找不到域控制器”或“找不到域”。

检查方法：客户端的首选 DNS 服务器应为域控制器（或能解析内网域记录的 DNS 服务器）。在加域前先确认 `ipconfig /all`（示例未实测）输出的 DNS 服务器地址是域控制器地址，而不是公网 DNS。DNS 解析本身的排障见[DNS/DHCP 与网络排错](11-dns-dhcp-network-troubleshooting.md)。

### 4.3 时间同步

域的身份验证（Kerberos）对时间敏感：客户端与域控制器的时间偏差过大（通常以分钟计，具体容忍上限以官方发布为准（待核实）），认证会被拒绝，加域可能直接失败，或加域后登录域账户失败。

加域前确认客户端时间与域控制器基本一致；域内设备通常通过域的时间同步机制自动对时，刚加域前如时间偏差明显，先手工把系统时间调准，再执行加域。

### 4.4 网络连通与名称

- **网络连通**：客户端能 ping 通域控制器，且必要的域服务端口可达；防火墙或网段隔离挡住了域控制器时，加域会超时失败。
- **计算机名**：计算机名在域内必须唯一。重名时加域会失败或覆盖已有计算机账户；加域前确认名称不与域内已有计算机重复。
- **域名的写法**：用域的完整域名（FQDN，例如 `corp.example.com`）加域，比只写 NetBIOS 短名更可靠；短名依赖 NetBIOS 解析，在现代网络中更容易出问题。

## 5. 加域步骤

### 5.1 图形界面方式（Windows 10/11）

1. 打开“设置 → 系统 → 关于”，或在“系统属性 → 计算机名”中选择“更改”。
2. 在“隶属于”中选择“域”，输入域的完整域名，确定。
3. 输入有加域权限的域账户与密码，确认后看到“欢迎加入域”的提示。
4. 按提示重启计算机。重启后登录界面会出现“登录到域”的选项，用域账户登录即完成。

服务器版的入口在“服务器管理器 → 本地服务器”中，操作逻辑相同。

### 5.2 命令行方式（示例未实测）

需要把加域写进装机脚本时，用命令行更合适。以下命令为示例，未在 Windows 上实测，参数以微软官方文档为准：

```powershell
# PowerShell 方式（示例未实测）
Add-Computer -DomainName corp.example.com -Credential (Get-Credential) -Restart
```

```cmd
:: netdom 方式，需以管理员身份运行命令提示符（示例未实测）
netdom join %COMPUTERNAME% /domain:corp.example.com /userd:域用户名 /passwordd:*
```

两条命令都会在域中创建该计算机的计算机账户（如果不存在），并把本机切换为域成员；`/passwordd:*` 表示交互输入密码，不要把明文密码写进脚本或命令行历史。离线加域（先在域控制器上预配计算机账户文件、再在客户端导入，命令为 `djoin`）适用于无网络连通的装机场景，步骤以微软官方文档为准，本文不展开。

### 5.3 加域后验证

重启并用域账户登录后，逐项确认：

- “系统属性”中显示“域：corp.example.com”，不再是工作组。
- `whoami`（示例未实测）输出域用户名，确认当前登录的是域账户。
- 在域控制器上打开“Active Directory 用户和计算机”，能在 Computers 容器（或指定的 OU）中找到该计算机账户。
- 执行 `gpupdate /force`（示例未实测）后无报错，确认客户端能正常拉取组策略；策略是否实际生效用 `gpresult /r`（示例未实测）核对，方法见[注册表与组策略](02-registry-group-policy.md)。

## 6. 组策略下发的流程与生效范围

### 6.1 下发流程：策略存在域控，客户端定期来取

组策略下发不是域控制器“推”给客户端，而是客户端“拉”：

1. **定义**：管理员在组策略管理控制台（GPMC）中创建组策略对象（GPO），并把它链接到站点、域或组织单位（OU）。
2. **存放**：GPO 的定义存放在域控制器上，其中基于注册表的设置以策略文件形式存放在域的共享目录 SYSVOL 中。
3. **拉取**：客户端开机、用户登录以及后台定期刷新时，联系域控制器，查询适用于自己的 GPO 列表，并从 SYSVOL 下载策略文件。
4. **落地**：客户端的策略引擎把设置写入注册表对应位置（或执行脚本、安装软件等），设置开始生效。

这就是“组策略最终多落为注册表值”的含义，注册表与组策略的关系见[注册表与组策略](02-registry-group-policy.md)。

### 6.2 生效范围：跟设备走，还是跟人走

GPO 分两类配置，生效范围不同：

- **计算机配置**：作用于设备。无论谁登录这台设备，计算机配置都生效。适用场景：安全基线、开机脚本、软件部署、防火墙规则。
- **用户配置**：作用于登录的用户。无论该用户在哪台域设备上登录，用户配置都生效。适用场景：桌面设置、文件夹重定向、登录脚本。

GPO 必须链接到容器（站点、域、OU）才生效；链接到哪个容器，就作用于其中包含的计算机或用户。计算机账户放在哪个 OU，决定了它收到哪些计算机配置；用户账户放在哪个 OU，决定了它收到哪些用户配置。对象放错 OU，是“策略下不来”的常见原因。

### 6.3 刷新节奏与手动刷新

客户端不会实时盯着域控制器：后台约每 90 分钟刷新一次（另有随机偏移），开机与登录时也会处理一次。改完 GPO 后不要期望所有设备秒级生效；需要立即验证时，在客户端手动刷新（示例未实测）：

```cmd
gpupdate /force
```

只刷新计算机配置或只刷新用户配置时加 `/target:computer` 或 `/target:user`。注意：有些设置（软件安装、文件夹重定向、部分安全策略）需要注销或重启才生效，`gpupdate` 刷新完不代表它们已经落地；多个 GPO 对同一设置有冲突时按什么顺序取胜，见[注册表与组策略](02-registry-group-policy.md)的 LSDOU 一节，本文不重复。

## 7. 脱域与常见错误

### 7.1 脱域：回到工作组

设备退役、转给其他组织或长期脱离域时，需要脱域：

1. 在“系统属性 → 计算机名 → 更改”中把“隶属于”改回“工作组”（例如默认的 WORKGROUP），输入本地管理员凭据，重启。
2. 重启后该设备只能用本地账户登录，域账户无法再登录；此前通过组策略下发的部分设置可能残留（首选项类设置不会自动收回，见[注册表与组策略](02-registry-group-policy.md)）。
3. 命令行方式（示例未实测）：`netdom remove %COMPUTERNAME% /domain:corp.example.com /userd:域用户名 /passwordd:*`。
4. 脱域后应在域控制器上清理残留的计算机账户，避免过期账户堆积；已重装系统的设备重新加域时，如域内还留着同名旧计算机账户，应先由域管理员删除或重置旧账户。

脱域前确认：本机至少有一个可用的本地管理员账户，否则脱域后可能无人能登录本机。

### 7.2 常见错误速查

| 现象 | 最可能的原因 | 先查什么 |
|---|---|---|
| “找不到域”/“找不到域控制器” | DNS 没指向域控制器 | `ipconfig /all` 看 DNS 服务器；`nslookup` 查域的 SRV 记录（示例未实测） |
| “访问被拒绝”/权限错误 | 加域账户权限不足，或已达加域数量上限 | 换有权限的域账户，或联系域管理员 |
| “计算机名已存在”/重名 | 域内已有同名计算机账户 | 在 AD 用户和计算机中查同名账户，由域管理员处理 |
| 加域后域账户登录失败 | 客户端与域控制器时间偏差过大 | 核对双方系统时间 |
| “此工作站与主域间的信任关系失败” | 计算机账户密码与域不同步（常见于系统还原、镜像克隆后） | 重新加域（先脱域再加域），或由域管理员重置计算机账户 |
| 加域成功但组策略不下来 | 计算机不在预期的 OU、GPO 未链接、安全筛选排除 | `gpresult /r` 看已应用与被拒绝的 GPO（示例未实测） |
| 加域后重启很慢、登录卡住 | 客户端联系不上域控制器（DNS 或网络问题） | 先查 DNS 与到域控制器的连通性，见[DNS/DHCP 与网络排错](11-dns-dhcp-network-troubleshooting.md) |

“信任关系失败”值得单独提醒：它的根源是计算机账户在域中的密码与本地保存的不一致，常见于用旧镜像恢复系统、或克隆的虚拟机共用同一计算机账户。治标是重新加域，治本是每台设备用唯一的计算机账户、不要克隆已加域的系统镜像。

## 8. 常见误解

- **“加域就是改了个名字”**：错。加域是在域中创建计算机账户、建立信任关系，本机从此接受域的身份验证与策略管理；改计算机名只是改本地标识。
- **“DNS 随便填个能上网的就行”**：错。加域与域登录依赖内网 DNS 解析域的 SRV 记录，首选 DNS 必须指向域控制器或内网 DNS；公网 DNS 解析不了内网域。
- **“gpupdate /force 能解决一切策略问题”**：错。它只重新处理适用的策略，绕不过链接位置错误、安全筛选、OU 放错、域复制未完成这些根本原因；先 `gpresult` 再 `gpupdate`。
- **“脱域后所有域策略就都没了”**：不完全对。管理模板类策略值会恢复，但首选项类设置会残留；退役设备如需彻底清理，应重装系统或按清单逐项核对。
