# 启动故障与蓝屏分析：启动流程、停止代码与转储分析

## 1. 本章目标

读完本篇，能说清 Windows 从加电到登录经历了哪几个阶段、卡在哪一阶段对应哪一类故障，能用启动修复与安全模式把“进不去系统”的问题先缩小范围，能读懂蓝屏停止代码与内存转储文件提供的基本信息，并知道何时该自己修、何时该备份数据后重装或送修。

> **实测声明**：本文作者环境为 Linux 虚拟机，Windows 专属命令与操作无法在当前环境实测。文中所有 Windows 命令、操作步骤与示例输出一律标“示例未实测”，请以微软官方文档为准，在测试机或确认已备份的前提下操作。

## 2. 背景与问题

一台 Windows 设备出问题，最让人焦虑的两种表现是“开不了机”和“用着用着蓝屏”。两者的共同点是：故障发生在系统还没准备好、或内核已经无法继续运行的时候，屏幕上往往只剩一行错误提示，甚至什么都没有。

排障的第一步不是立刻重装，而是先定位：**故障卡在哪一阶段**。启动流程分阶段，每一阶段的责任方不同——固件、引导加载器、内核、驱动、登录服务——卡在哪一阶段，修的方向就完全不同。蓝屏同理：停止代码（Stop Code）与转储文件是内核留下的“遗言”，读懂它们，多数蓝屏都能归到驱动、硬件或系统文件这三类原因之一。

本文只讲故障排查：如何定位、如何修复、如何读证据。**不涉及任何入侵、提权、绕过检测的操作步骤**。系统管理基础见[Windows 系统管理](01-system-management.md)，注册表与组策略见[注册表与组策略](02-registry-group-policy.md)，命令行工具的使用见[PowerShell 自动化](03-powershell-automation.md)。

## 3. 启动流程：从加电到登录的四个阶段

### 3.1 阶段一：固件自检（UEFI / BIOS）

按下电源后先运行的是主板固件，负责初始化硬件、做加电自检（POST），再按启动顺序找可启动设备。

- **传统 BIOS**：老式固件接口，用 MBR 分区表引导，引导代码放在磁盘开头，容量与功能受限。
- **UEFI**：现代固件接口，用 GPT 分区表，引导程序以文件形式存放在 EFI 系统分区（ESP）中，支持安全启动（Secure Boot）等机制。新出厂设备基本都是 UEFI。

**卡在这一阶段的表现**：黑屏无任何显示、停在主板 Logo、提示“未找到启动设备”（No bootable device）、反复重启但连 Windows 标志都没出现。责任方在固件与硬件层面：先查启动顺序、硬盘是否被识别、线缆与内存是否松动，而不是去修 Windows。

两个常见概念不要混淆：**安全启动**是 UEFI 的一项功能，校验引导程序的签名，防止未签名的引导代码运行；它与 Windows 的“安全模式”是两回事（见 4.2 节）。安全启动导致的问题通常是：换了非官方引导或某些 Linux 双系统引导后被拦截，处理方式是进固件设置确认启动项，而不是在 Windows 里改设置。

### 3.2 阶段二：引导加载器（Windows Boot Manager）

固件找到启动设备后，加载 Windows 引导管理器（`bootmgfw.efi`，UEFI 下）或 `bootmgr`（BIOS/MBR 下）。它的任务是读启动配置数据（BCD，Boot Configuration Data），决定启动哪个系统、用什么参数。

BCD 存放启动项、默认系统、超时时间、安全模式标志等配置。BCD 损坏或丢失时，常见提示是 `0xc000000f`（所需设备无法访问）或“启动配置数据丢失”。这类故障的修复思路在 4.1 节。

### 3.3 阶段三：内核加载（Winload 与内核初始化）

引导管理器加载 `winload.efi`（或 `winload.exe`），由它加载 Windows 内核（`ntoskrnl.exe`）、硬件抽象层（HAL）与启动必需的驱动，再把控制权交给内核。内核初始化硬件、挂载系统卷、启动会话管理器与服务。

**卡在这一阶段的表现**：Windows 标志出现后转圈很久、黑屏只有鼠标光标、蓝屏（见第 5 节）。责任方多在驱动与系统文件：最近装的驱动、更新失败的系统文件、损坏的磁盘，都会在这里暴露。

### 3.4 阶段四：登录与会话

内核就绪后，启动登录进程（Winlogon）与服务，出现登录界面。登录后加载用户配置文件、启动项与桌面。

**卡在这一阶段的表现**：能到登录界面但输完密码黑屏或转圈、桌面迟迟不出来、登录后立即注销。责任方多在用户配置文件损坏、登录后自启程序冲突、域环境下的策略或网络问题。先分清是“某个用户登录不了”还是“所有用户都登录不了”：前者多为用户配置文件问题，后者多为系统级问题。

### 3.5 四阶段对照：卡在哪，就查哪

| 阶段 | 屏幕表现 | 先查什么 |
|---|---|---|
| 固件自检 | 黑屏、主板 Logo、未找到启动设备 | 启动顺序、硬盘识别、内存与线缆 |
| 引导加载器 | BCD 相关错误代码 | 启动配置数据、EFI 分区、启动项 |
| 内核加载 | 转圈过久、黑屏、蓝屏 | 最近的驱动与更新、磁盘健康、系统文件 |
| 登录与会话 | 登录界面后黑屏、转圈、立即注销 | 用户配置文件、自启程序、域策略与网络 |

定位时先问一句：“上一次正常之后，动过什么？”——新装的驱动、刚打的更新、刚换的硬件、刚改的固件设置，答案往往就藏在最近一次改动里。

## 4. 启动修复：先缩小范围，再动手修

动手修之前先遵守一条铁律：**有重要数据先想办法备份，再修**。启动修复类操作多数是安全的，但磁盘故障、误操作导致的后果不可逆；能进 WinRE（Windows 恢复环境）时，优先用命令行或启动修复把数据拷出来，再动系统分区。

### 4.1 自动启动修复与 WinRE

Windows 启动失败多次后，通常会自动进入 Windows 恢复环境（WinRE），提供“启动修复”“系统还原”“命令提示符”等入口；也可以用 Windows 安装介质启动后选择“修复计算机”进入。

- **启动修复**：自动检测并修复常见的引导问题（例如 BCD 损坏、引导扇区问题）。先跑它，多数引导类故障到这一步就解决了。
- **系统还原**：把系统文件与注册表回滚到之前建立的还原点，不动个人文件。适用于“昨天还好好的，今天更新/装驱动后起不来”的场景。还原点不是备份，不能替代数据备份（见[Windows 系统管理](01-system-management.md)）。
- **卸载更新**：最近一次质量更新或功能更新后无法启动时，WinRE 提供卸载最近更新的入口；先卸载，再观察是否恢复。

### 4.2 安全模式：最小驱动集启动

安全模式只加载最基本的驱动与服务，是“缩小范围”的利器：

- **能进安全模式**：问题大概率出在正常启动才加载的驱动、服务或自启程序上。下一步是在安全模式里卸载最近安装的驱动或软件、禁用可疑的自启项，逐个排查。
- **进不了安全模式**：问题更可能在内核、系统文件或硬件层面，优先走启动修复、系统文件检查与硬件排查。

进入方式（示例未实测）：在 WinRE 中选择“疑难解答 → 高级选项 → 启动设置 → 重新启动”，再按提示选择安全模式；也可以在 BCD 中设置。安全模式有三种常见变体：普通安全模式、带网络的安全模式、带命令提示符的安全模式——排障时优先用普通安全模式，需要下载驱动或查资料时再用带网络的版本。

### 4.3 命令行修复工具（示例未实测）

在 WinRE 的命令提示符里，常用的修复命令有以下几类（以下命令均为示例未实测，参数以微软官方文档为准）：

- **修复启动配置数据**：`bootrec /fixmbr`、`bootrec /fixboot`、`bootrec /scanos`、`bootrec /rebuildbcd`。用于 BCD 损坏、引导记录异常的场景；UEFI/GPT 环境下部分命令的适用性与 MBR 环境不同，执行前先确认磁盘分区方式。
- **检查系统文件**：`sfc /scannow`。扫描并修复受保护的系统文件，适用于系统文件损坏导致的启动或运行异常；离线修复时需加 `/offbootdir` 与 `/offwindir` 参数指定系统位置。
- **修复组件存储**：`DISM /Online /Cleanup-Image /RestoreHealth`（在线）或离线等价命令。SFC 修不好时，先修组件存储再跑一次 SFC。
- **检查磁盘**：`chkdsk C: /f /r`。检查并修复文件系统错误与坏扇区；磁盘有物理坏道时，chkdsk 只能标记隔离，不能让坏盘变好盘，数据要先备份。

使用顺序建议：先启动修复 → 再 SFC → 再 DISM → 再 chkdsk；每做一步验证一次，不要一次把所有修复全跑完再看结果——那样出问题也说不清是哪一步起的作用。

## 5. 蓝屏（BSOD）：停止代码与转储文件

### 5.1 蓝屏是什么

蓝屏（Blue Screen of Death，BSOD）是 Windows 内核遇到无法安全继续的错误时主动停机、并显示错误信息的保护机制。蓝屏本身不是“系统坏了”，而是内核在说：“再跑下去可能损坏数据，我先停下来。”所以蓝屏后的第一反应不应该是恐慌，而是**记下停止代码**。

现代 Windows 10/11 的蓝屏界面会显示一个停止代码（例如 `SYSTEM_SERVICE_EXCEPTION`）与一个二维码（链接到微软支持页面），以及“正在收集错误信息”的进度。收集完成后系统通常会自动重启，并把现场信息写进内存转储文件（见 5.3 节）。

### 5.2 常见停止代码的含义

停止代码分两部分：英文名称与十六进制代码（例如 `0x0000007B`）。下表列出排障中最常见的几类（代码含义以微软官方文档为准，个别代码的具体成因需结合转储分析确认）：

| 停止代码 | 英文名称 | 常见含义与排查方向 |
|---|---|---|
| `0x0000007B` | INACCESSIBLE_BOOT_DEVICE | 启动时访问不到系统盘：磁盘模式（AHCI/RAID）被改、存储驱动丢失或损坏、系统盘故障 |
| `0x00000050` | PAGE_FAULT_IN_NONPAGED_AREA | 访问了不存在的内存页： faulty 驱动、内存故障、杀毒软件驱动冲突 |
| `0x0000003B` | SYSTEM_SERVICE_EXCEPTION | 系统服务执行异常：多为第三方驱动或系统服务缺陷 |
| `0x0000001E` | KMODE_EXCEPTION_NOT_HANDLED | 内核模式异常未处理：驱动缺陷是常见原因，转储中会指明涉事模块 |
| `0x0000000A` | IRQL_NOT_LESS_OR_EQUAL | 内核在错误的中断级别访问内存：驱动缺陷、内存故障、超频不稳定 |
| `0x000000D1` | DRIVER_IRQL_NOT_LESS_OR_EQUAL | 驱动在错误的中断级别访问内存：涉事驱动名常出现在蓝屏或转储中 |
| `0x0000007E` | SYSTEM_THREAD_EXCEPTION_NOT_HANDLED | 系统线程异常未处理：驱动或系统文件问题 |
| `0x000000EF` | CRITICAL_PROCESS_DIED | 关键系统进程意外终止：系统文件损坏、磁盘故障、恶意软件破坏 |
| `0x0000009F` | DRIVER_POWER_STATE_FAILURE | 驱动电源状态转换失败：多与睡眠/唤醒、电源管理驱动有关 |
| `0x0000007A` | KERNEL_DATA_INPAGE_ERROR | 内核数据页无法读入：磁盘故障、内存故障、存储驱动问题 |
| `0x00000116` | VIDEO_TDR_FAILURE | 显卡驱动超时无响应：显卡驱动或显卡硬件问题（代码以官方发布为准，待核实） |

读代码的要点：

1. **先看涉事模块名**：蓝屏界面或转储中常会给出驱动文件名（例如 `xxx.sys`），它比停止代码本身更能定位责任方。
2. **同一代码、不同原因**：`0x00000050` 既可能是内存条坏了，也可能是驱动写错地址；只凭代码下结论会误诊，必须结合转储与最近改动。
3. **看时间规律**：开机即蓝屏、运行特定程序才蓝屏、睡眠唤醒后蓝屏、随机蓝屏——规律不同，排查方向不同。随机蓝屏优先查内存与散热，固定场景蓝屏优先查该场景涉及的驱动。

### 5.3 内存转储文件：内核留下的现场

蓝屏时系统会把内存内容写成转储文件，供事后分析。转储类型与位置（示例未实测，路径以系统设置为准）：

| 转储类型 | 位置（默认） | 说明 |
|---|---|---|
| 小型转储（Minidump） | `%SystemRoot%\Minidump\` | 约数百 KB，只含蓝屏时的关键信息；日常排障够用 |
| 内核内存转储 | `%SystemRoot%\MEMORY.DMP` | 含内核空间内容，体积较大 |
| 完整内存转储 | `%SystemRoot%\MEMORY.DMP` | 含全部物理内存，体积最大，用于深入分析 |

转储的生成受系统设置控制（“系统属性 → 高级 → 启动和故障恢复”中的写入调试信息选项），也受页面文件大小与磁盘剩余空间影响：磁盘满了或页面文件太小，转储可能写不出来——“蓝屏了但没有转储文件”时先查这两点，而不是认定系统没记录。

### 5.4 WinDbg 入门分析思路

WinDbg 是微软提供的调试器，可用于分析转储文件（属于 Windows SDK / Windows 驱动程序工具包的一部分，需另行安装；具体获取渠道以微软官方发布为准）。入门分析不需要精通调试命令，掌握一条主线即可：

1. **打开转储**：用 WinDbg 打开小型转储文件，设置符号路径（符号文件让分析结果显示函数名而不是地址，缺符号时结论可信度大打折扣）。
2. **跑自动分析**：执行 `!analyze -v`（示例未实测），输出会给出停止代码、可能的原因、涉事模块与调用栈摘要。
3. **读三个关键字段**：`BUGCHECK_CODE`（停止代码）、`MODULE_NAME` / `IMAGE_NAME`（涉事模块，通常是某个 `.sys` 驱动文件）、`STACK_TEXT`（调用栈，显示崩溃时正在执行的调用链）。
4. **按模块定方向**：涉事模块是第三方驱动 → 更新、回滚或卸载该驱动；是微软系统模块 → 优先查磁盘与内存硬件、再查系统文件；是杀毒软件或安全软件驱动 → 临时禁用该软件验证。
5. **不要只看一次**：单次蓝屏可能是偶发；同一模块反复出现，才值得认定为责任方。多次转储的结论一致时，再动手换驱动或硬件。

WinDbg 的深入用法（手动设断点、分析完整转储、驱动开发级调试）超出本篇范围，需要时以微软官方调试文档为准。

## 6. 常见启动故障对照表

| 现象 | 可能原因 | 优先排查步骤 |
|---|---|---|
| 按电源无任何反应 | 电源、主板、电源键故障 | 查电源线与插座、电源指示灯、最小化硬件启动 |
| 停在主板 Logo | 固件设置、外设冲突、硬盘识别异常 | 拔掉外接设备、恢复固件默认设置、查硬盘识别 |
| 提示未找到启动设备 | 启动顺序错、系统盘未识别、引导分区损坏 | 进固件确认启动顺序与硬盘识别、修复 BCD |
| BCD 错误 `0xc000000f` | BCD 损坏或丢失 | WinRE 启动修复、`bootrec /rebuildbcd`（示例未实测） |
| Windows 标志后无限转圈 | 驱动、更新、磁盘故障 | 安全模式、卸载最近更新、chkdsk（示例未实测） |
| 蓝屏 `0x7B` | 存储驱动或磁盘模式问题 | 查磁盘模式是否被改、存储驱动、磁盘健康 |
| 蓝屏 `0x50` / `0x0A` / `0xD1` | 驱动缺陷或内存故障 | 看涉事模块、内存检测、回滚最近驱动 |
| 能进安全模式，正常启动蓝屏 | 第三方驱动或自启程序 | 安全模式卸载最近驱动、禁用自启项逐个排查 |
| 登录后黑屏只有鼠标 | 显卡驱动、用户配置文件、自启程序 | 安全模式卸载显卡驱动、换用户登录测试 |
| 登录后立即注销 | 用户配置文件损坏 | 新建管理员账户登录测试、修复或重建配置文件 |

## 7. 排障流程与记录方法

推荐的通用流程（与[性能瓶颈定位](15-performance-bottleneck.md)的定位流程思路一致，先定位、再动手）：

1. **记录现象**：卡在哪一阶段、停止代码是什么、最近动过什么（驱动、更新、硬件、设置）。
2. **缩小范围**：安全模式能进吗？最近一次改动是什么？换一个用户能登录吗？
3. **先备份，再修复**：有重要数据时，先用 WinRE 或外接方式备份，再跑修复命令。
4. **一次只改一处，改完验证一次**：同时换驱动又改设置，出问题说不清是谁的责任。
5. **保留证据**：把停止代码、转储文件、事件查看器里的关键错误（来源与事件 ID）记下来；送修或求助时，这些是别人能直接用的信息，比“开不了机”四个字有用得多。
6. **知道停手点**：磁盘有异响、S.M.A.R.T. 报错、多次修复无效、数据无价——出现这些情况时，停手备份或送专业数据恢复，不要反复通电尝试。

## 8. 限制与常见误解

- **“蓝屏就是系统坏了，要重装”**：错。多数蓝屏是驱动或硬件问题，重装系统不换驱动，蓝屏还会回来；先读停止代码与转储。
- **“安全模式能进，系统就没问题”**：错。安全模式只说明最小驱动集能工作，正常启动加载的驱动仍可能有问题。
- **“网上搜到某个代码的‘万能修复’照做就行”**：错。同一停止代码有多种成因，照抄注册表修改或删系统文件可能把小问题修成大问题；先定位再动手。
- **“chkdsk 能修好坏硬盘”**：错。它只能修复文件系统错误、隔离坏扇区；物理损坏的盘要备份换盘。
- **“转储文件没用，占地方删掉”**：不建议删正在排障的转储；它是定位蓝屏责任方的关键证据，删了就只能靠猜。
- **本文不展开的内容**：UEFI 固件的深入配置、RAID 阵列重建、域控制器与服务器启动故障、数据恢复的专业操作——这些各有专门的篇目与工具，超出本篇范围。

## 9. 小结

启动故障按阶段定位：固件、引导、内核、登录，卡在哪就查哪；蓝屏先记停止代码，再读转储找涉事模块，不要只凭代码下结论；修之前先备份，一次只改一处，改完验证一次。多数启动与蓝屏问题，用安全模式缩小范围 + 启动修复 + 驱动回滚这三板斧就能解决；解决不了的，保留证据再送修。
