# Windows 系统管理：版本、账户、服务与任务计划

## 1. 一句话定义

Windows 系统管理是指对 Windows 设备的版本与更新通道、用户账户与权限、后台服务、计划任务、磁盘与文件系统进行配置、监控与排障的一整套日常管理工作。

## 2. 为什么需要它

一台 Windows 设备装好系统只是开始：它要以哪个版本、哪种更新节奏运行，谁能登录、谁能提权，哪些后台服务随开机启动，哪些维护工作定时执行，磁盘空间与文件系统是否健康——这些问题不回答，设备迟早会在某个周一早上以蓝屏、登录失败、磁盘写满或更新卡住的方式回答你。系统管理的目标就是把这些问题从“事后救火”变成“事前有章法”。

与 Linux 的对照贯穿本篇：很多概念在两个世界里名字不同、机制相近（例如服务对应 systemd 服务、任务计划对应 systemd timer、UAC 对应 sudo 提权），但实现细节不能直接套用。Linux 侧的对应内容见本站 06 域文章，本文只写 Windows 侧，差异处明确对照，不重复讲 Linux 原理。

## 3. 核心含义

### 3.1 版本与服务通道：先分清“版本”和“更新节奏”是两回事

Windows 的版本由三个维度组成，初学者最容易把它们混成一团：

- **版本（Edition）**：面向人群的功能档位，常见有家庭版、专业版、企业版、教育版。档位决定功能集合，例如域加入、组策略管理、BitLocker 等管理功能只在专业版及以上提供；本地组策略编辑器（gpedit.msc）不在家庭版中提供。
- **版本号（Version）**：功能更新的代际，用“年 + H1/H2”命名，例如 24H2 表示 2024 年下半年的功能更新。版本号越大，功能基线越新；但同一版本号下每月还有质量更新（安全修复与小修补），不改变版本号。
- **服务通道（Servicing Channel）**：设备接收更新的节奏，决定“功能更新来不来、多快来”。这是选型时最关键、也最容易被忽视的一维。

服务通道分两条主线（微软官方文档，见文末来源）：

| 通道 | 适用版本 | 更新行为 | 适用场景 |
|---|---|---|---|
| 通用可用通道（General Availability Channel，GAC） | 除 LTSC 外的全部 Windows 10/11 版本（默认） | 每年一次功能更新 + 每月质量更新 | 绝大多数通用设备：办公、开发、日常使用 |
| 长期服务通道（Long-Term Servicing Channel，LTSC） | 仅 Windows 企业版 LTSC（需批量许可） | 只接收质量更新，不接收功能更新；新 LTSC 版本每数年发布一次 | 专用设备：医疗仪器、收银终端、ATM、工控机等人机交互少、功能需冻结的场景 |

两个要点：

1. **LTSC 不是“更干净的日常系统”**。它的设计目标是“功能冻结”，代价是长期拿不到新功能，且不面向通用设备部署。把办公电脑装成 LTSC，迟早会遇到新版软件、新驱动要求更新功能基线的问题。
2. **LTSC 2024 对应通用通道的 24H2 功能基线**（微软 LTSC 概览页）。也就是说 LTSC 不是另一套系统，而是同一代功能在某个时间点拍下的快照，之后只修补、不演进。

版本选型的检查顺序建议：先定用途（通用还是专用）→ 再定通道（GAC 还是 LTSC）→ 再定版本档位（家庭/专业/企业）→ 最后核对硬件与软件对版本号的最低要求。顺序反过来（先挑版本号）最容易选错。

### 3.2 用户账户与权限模型：账户分三类，提权靠 UAC

Windows 的账户按来源分三类：

- **本地账户**：只存在于本机，适合单机、离线或专用设备。
- **Microsoft 账户**：与微软在线身份绑定，可同步设置与应用许可，适合个人设备。
- **域账户**：由 Active Directory 域控制器统一管理，适合组织环境；账户策略（密码、锁定、组成员）由域统一下发，本地改不了。

账户的权限不由“账户名”决定，而由它所属的**组**决定。最常用的两个内置组：

- **Administrators（管理员组）**：拥有对本机的完全管理权。
- **Users（标准用户组）**：日常使用权限，不能改系统级配置、不能装需要写系统目录的软件。

关键机制是 **UAC（用户账户控制）**：即使你登录的是管理员组成员，日常进程拿到的也只是一个**过滤后的标准用户令牌**；只有当操作需要提权时，系统才弹出同意提示，确认后以完整管理员令牌执行。这与 Linux 的 sudo 有相似的目标（平时不用最高权限），但机制不同：

| 维度 | Windows UAC | Linux sudo |
|---|---|---|
| 平时身份 | 管理员登录也先拿过滤令牌 | 普通用户身份，需要时 sudo 提权 |
| 提权动作 | 同意提示（管理员组）或输入管理员凭据（标准用户） | 输入密码（通常是自己的密码，取决于配置） |
| 提权范围 | 按进程：整个进程以管理员令牌运行 | 按命令：单条命令以 root 身份运行 |
| 对照文章 | 本文 | [用户、Sudo 与 PAM](../../02-security/02-users-sudo-pam.md) |

常见误解必须纠正：**UAC 不是杀毒软件，也不是安全边界**。它防的是“误触”和“静默提权”，防不住已经拿到管理员同意的恶意操作。点“是”之前，先看清是哪个程序在请求提权——这与 Linux 下“不要无脑 sudo”是一个道理。

### 3.3 服务：开机就运行的后台程序

Windows 服务是由服务控制管理器（Service Control Manager，SCM）统一管理的后台进程：没有界面，随系统启动或按需运行，例如打印、更新、数据库、杀毒软件的常驻部分都以服务形式存在。管理入口是 `services.msc`（服务控制台），也可以用 PowerShell 的 `Get-Service` / `Set-Service` 查看与配置（详见[PowerShell 自动化](03-powershell-automation.md)）。

服务的两个核心属性：

- **启动类型**：自动（随系统启动）、自动（延迟启动，随系统启动但延后加载，用于缓解开机争抢）、手动（需要时由系统或用户触发）、禁用（不能启动）。
- **登录身份（服务账户）**：服务以哪个身份运行。内置三类：LocalSystem（本机最高权限，慎用）、NetworkService（以计算机身份访问网络）、LocalService（本机低权限服务）。给服务配过高权限是常见的安全隐患：服务一旦被攻破，攻击者就继承它的权限。

排障思路：某功能异常时，先查它依赖的服务是否在运行（服务控制台里看“状态”列），再看启动类型是不是被改成了禁用或手动，最后看事件查看器里该服务的报错。**不要把“禁用不用的服务”当成优化手段**：服务之间有依赖关系，禁掉一个可能连带停掉一串功能；先查依赖项，再决定。

### 3.4 任务计划：让维护工作自己发生

任务计划程序（Task Scheduler）是 Windows 的定时任务机制：按触发器（时间、日历、事件、开机、登录等）执行操作（启动程序、发邮件已废弃、显示消息已废弃，现代做法是启动脚本或程序）。每个任务由触发器、操作、条件（例如仅在交流电源下运行、仅在空闲时运行）、设置（失败重试、超时停止）四部分组成。

与 Linux 的对照：任务计划对应 systemd timer / cron，但触发器更丰富（事件触发是 Windows 的特色，例如“某日志事件出现时执行脚本”）。Linux 侧的定时任务做法见[systemd Timer](../../07-automation/02-systemd-timers.md)。跨平台运维时，记住两边的触发语义不同，不要把 cron 表达式直接往任务计划里套。

### 3.5 磁盘与文件系统要点

磁盘管理（`diskmgmt.msc`）负责分区、卷、盘符、动态磁盘等；文件系统层面，日常打交道的是两个：

| 文件系统 | 定位 | 要点 |
|---|---|---|
| NTFS | 默认系统与数据卷 | 支持权限（ACL）、加密（EFS）、压缩、配额、日志；系统启动卷用 NTFS |
| ReFS | 面向数据卷的弹性文件系统 | 侧重数据完整性校验与大容量存储，主要用于数据卷，不用于系统启动卷 |

与 Linux 的对照：NTFS 的 ACL 权限模型比 Linux 传统的 rwx 三组九位更细（可针对单个用户、单个操作授权），但也更复杂；排障时先看“有效访问”而不是只看表面权限。存储原理（SSD 为什么需要 TRIM、写入放大）见[SSD 存储原理](../01-computer-basics/04-ssd-storage.md)，本文不重复。

磁盘空间告警的处理顺序：先看是哪个卷满（系统卷满会影响更新与虚拟内存），再看大文件分布（不要上来就删系统目录），最后考虑扩容或迁移数据卷。删文件之前先确认它是不是系统或应用正在使用的文件。

## 4. 分类

按管理对象分，Windows 系统管理分五类（与 3.1–3.5 对应）：版本与更新管理、账户与权限管理、服务管理、任务计划管理、磁盘与存储管理。按管理手段分，有三层：

- **图形控制台**：设置应用、服务控制台、任务计划程序、磁盘管理——适合单机、少量操作。
- **命令行与脚本**：PowerShell、reg 命令、schtasks、sc——适合批量、可重复、可审计的操作（详见[PowerShell 自动化](03-powershell-automation.md)）。
- **集中策略**：组策略、Intune 等——适合组织内成百上千台设备统一下发（详见[注册表与组策略](02-registry-group-policy.md)）。

单机先用图形控制台熟悉概念，批量操作尽早转脚本与策略：图形界面点十台机器不出错，点一百台一定出错。

## 5. 典型应用

- **新设备装机验收**：核对版本档位与通道是否符合采购要求（专用设备误装 GAC、办公设备误装 LTSC 都要在这个环节拦住），再建管理员与标准用户分工。
- **办公电脑权限收敛**：日常用标准用户账户，需要时 UAC 提权；既减少误操作，也减少恶意软件静默拿到管理员权限的概率。
- **业务服务保活**：把业务程序注册为服务并设为自动启动、配好失败重启策略，比“放一个开机自启快捷方式”可靠得多。
- **夜间维护窗口**：用任务计划在凌晨跑备份、清理、报表脚本，条件设为“仅交流电源 + 空闲时”，避免打扰白天使用。

## 6. 限制与常见误解

- **UAC 不是安全边界**：它防误触，不防已获同意的恶意操作；点“是”之前先看清请求方。
- **LTSC 不是“纯净版日常系统”**：它是功能冻结的专用版本，通用设备用 LTSC 会在软件与驱动兼容上吃亏。
- **禁用服务不等于优化**：服务有依赖关系，禁错一个可能连带停掉一串功能；先查依赖，再动手。
- **家庭版没有组策略编辑器**：需要组策略管理的场景，版本档位要选专业版及以上；不要在家庭版上找 gpedit.msc。
- **本文不展开服务器版**：Windows Server 的角色、域控制器、群集等内容属于服务器管理，与桌面版系统管理有重叠但不等同，后续如需补充应另起篇目。

## 7. 小结

Windows 系统管理 = 版本与通道选对、账户与权限分清、服务与任务管好、磁盘与文件系统盯住。选型时先定通道再定档位，权限上坚持“平时标准用户、需要时提权”，批量操作尽早从图形界面转向脚本与策略。
