# 账户与权限最小化加固

> **实测声明**：本文写作环境为 Linux 虚拟机，无法运行 Windows。文中所有 Windows 命令、界面操作与示例输出均为**示例未实测**，请在自有设备或授权系统上核对后再执行；具体默认值与策略路径因 Windows 版本而异，以官方发布为准（待核实）。

## 1. 一句话定义

账户与权限最小化加固是指：让每个账户只拥有完成其工作所必需的最小权限，并通过禁用或管控高权限账户、收紧提权提示、设定口令与锁定策略、定期审计账户，来缩小“一个账户出问题能造成的破坏面”的一整套配置与管理做法。

## 2. 为什么需要它

大多数 Windows 安全事件的破坏程度，不取决于入侵者最初拿到的是什么，而取决于那个账户**能做什么**。日常用管理员账户上网、收邮件、跑来历不明的安装程序，等于把整台机器的钥匙交给了每一个路过的程序；一个常年不用的旧管理员账户、一个永不过期的弱口令、一个被遗忘的已离职员工账户，都是不需要任何技术含量就能利用的入口。

最小权限原则（Principle of Least Privilege）就是对这个问题的回答：权限不是“越多越方便”，而是“刚好够用”。本篇讲的是如何把这条原则落到 Windows 账户上。UAC 的提权机制与账户的三分类（本地账户、Microsoft 账户、域账户）见[Windows 系统管理](01-system-management.md)，本文不重复讲机制，只讲**加固配置与管理动作**。

## 3. 核心含义

### 3.1 内置管理员账户：不用就禁用，启用也要单独管

内置 Administrator 账户是系统安装时就存在的最高权限账户，特点是：权限最大、名字固定（人人都知道它叫 Administrator）、且默认不受 UAC 的管理员批准模式约束——也就是说，用它登录后，提权操作不会再弹出确认提示。这三个特点叠加，使它成为口令猜测攻击的首选目标。

处理原则：

- **日常不用**：全新安装的 Windows 10/11 客户端上，该账户默认处于禁用状态（以官方发布为准，待核实），保持禁用就是最安全的状态；不要为了图方便启用它当日常账户。
- **必须启用时，单独管控**：只在确实需要本地应急管理账户的场景启用，并做到三点：设置足够强的口令（见 3.5 节）、不在日常使用中登录它、把它排除在远程登录之外（见 3.6 节的审计项）。
- **考虑改名**：通过安全策略可以重命名该账户（本地安全策略 → 安全选项中的“账户：重命名系统管理员账户”）。改名不是万能药（账户的 SID 不变，有经验的检查仍能认出它），但能挡住只按名字猜测的批量尝试；把它当作纵深防御的一层，不要当作唯一的防线。
- **另建具名管理员账户**：需要管理员权限时，用一个名字能对应到具体责任人的管理员账户，而不是共用内置 Administrator。出了问题，审计日志里才能看出是谁做的。

域环境下内置本地管理员的口令管理属于域控侧的集中管理范畴，单机做法不适用，本文不展开。

### 3.2 UAC 设置：把“点一下就过”改成“想清楚再过”

UAC 本身的机制见[Windows 系统管理](01-system-management.md)（过滤令牌、按进程提权）；本节只讲加固时要调的几处设置。入口有两处：控制面板/设置中的 UAC 滑块（面向个人用户，只有四档粗调），与本地安全策略 / 组策略中的 UAC 相关安全选项（面向管理员，可逐项调，见[注册表与组策略](02-registry-group-policy.md)）。

建议的收紧方向（按从宽到严）：

| 设置 | 较宽松的做法 | 较严格的加固做法 |
|---|---|---|
| 内置管理员的管理员批准模式 | 保持默认（内置管理员不受批准模式约束） | 启用该模式，让内置管理员提权时也要经过提示；若内置管理员已禁用，本项无实际影响 |
| 管理员提权提示行为 | 仅对非 Windows 二进制程序提示同意（默认值，以官方发布为准，待核实） | 改为“在安全桌面上提示凭据”：每次提权都要重新输入管理员凭据，而不是点一下“是” |
| 标准用户提权提示行为 | 在安全桌面上提示凭据（默认值，以官方发布为准，待核实） | 改为“自动拒绝提权请求”：标准用户无法靠输入凭据提权，需要管理员亲自登录操作；适合多人共用的固定用途设备 |
| 安全桌面提示 | 保持启用 | 保持启用；不要关闭——安全桌面能防止其他程序冒充或遮挡提权提示 |
| 仅提升已签名并验证的可执行文件 | 默认关闭 | 在高安全要求的环境可启用，但要先确认业务软件都有有效签名，否则正常软件会被拦住 |

两条纪律：

1. **不要把 UAC 滑块拉到最低（从不通知）来“解决”软件频繁弹提示的问题**。那等于关掉了误触保护，之后任何程序请求提权都不会再有人把关；正确做法是找出是哪个软件在反复请求提权，修软件或改它的运行方式。
2. **UAC 不是杀毒软件，也不是安全边界**。它防的是误触与静默提权，防不住已经拿到管理员同意的恶意操作（见[Windows 系统管理](01-system-management.md)）。加固 UAC 要和本篇其他措施（最小权限、口令策略、审计）一起做，单靠 UAC 一项守不住。

### 3.3 最小权限原则：日常用标准用户，需要时再提权

落到日常操作上，最小权限原则只有三条：

- **日常账户用标准用户**：上网、办公、收邮件都在标准用户账户下进行。需要管理员权限时，UAC 会提示输入管理员凭据（见 3.2 节），用完即回到标准权限。这个习惯本身就是最有效的加固：恶意软件在标准用户会话里能做的事，比在管理员会话里少得多。
- **管理员账户与日常账户分开**：不要让同一个账户既是日常身份又是管理员身份。做法是建两个账户：一个标准用户做日常工作，一个单独的管理员账户只在需要时用于提权；管理员账户的口令不要告诉日常使用者（多人共用设备时尤其如此）。
- **服务与计划任务也用最小权限**：以哪个身份运行服务、计划任务，决定了它出问题时的破坏面。新建服务或任务时，先问“它最低需要什么权限”，再选账户；不要图省事一律用 LocalSystem 或管理员账户。服务的启动类型与登录身份见[Windows 系统管理](01-system-management.md)。

一个常见的反模式是“为了装某个软件，全员加进 Administrators 组”。装完软件就该把临时权限收回；长期留在管理员组里的账户越多，审计时要盯的面就越大（见 3.6 节）。

### 3.4 本地用户与组管理：账户要建得少、管得清

管理入口是本地用户和组管理单元（`lusrmgr.msc`，示例未实测）与 PowerShell 的本地账户命令（`Get-LocalUser`、`Get-LocalGroupMember`，用法见[PowerShell 自动化](03-powershell-automation.md)）。家庭版不提供 `lusrmgr.msc` 图形入口（见[Windows 系统管理](01-system-management.md)），可用设置应用与命令行工具管理。

日常管理清单：

- **只建需要的账户**：每多一个账户就多一个口令、多一个入口；临时测试账户用完即删，不要留着“以后可能用”。
- **Guest 账户保持禁用**：Guest 是匿名访问用的内置账户，默认禁用（以官方发布为准，待核实）；没有明确的匿名访问需求就不要启用它。
- **管住高权限组**：重点看三个组的成员——Administrators（本机完全管理权）、Remote Desktop Users（可远程桌面登录）、Backup Operators（可绕过文件权限备份数据）。加人进组之前先确认业务上确实需要；加完要记录原因与有效期。
- **离职与换岗即处理**：人员离职、换岗当天就禁用或删除其本地账户、移出高权限组；不要等“下次审计再说”。域账户由域侧统一处理，本地账户要靠本机管理员自己记得处理。
- **禁用长期不用的账户**：超过一段时间无人登录的账户先禁用，确认无人认领后再删除；直接删除会丢掉该账户的配置与审计线索，禁用是更稳妥的第一步。

查看本机管理员组成员的命令示例（示例未实测）：

```powershell
Get-LocalGroupMember -Group Administrators
```

### 3.5 口令策略与账户锁定策略：让猜口令变得不划算

口令策略与账户锁定策略在单机上由本地安全策略（`secpol.msc`，示例未实测）管理，在域环境由域组策略统一下发（本地改不了，见[注册表与组策略](02-registry-group-policy.md)）。两类策略管的是不同的事：

**口令策略（密码必须达到的强度与更换节奏）**，常见项：

- **密码长度最小值**：越长越难猜；只设 6 位在今天已经不够。示例基线：普通账户不低于 12 位，管理员账户更长（示例基线，非官方默认值，以组织策略与官方发布为准，待核实）。
- **密码必须符合复杂性要求**：要求混合大小写字母、数字与符号；但要注意，复杂性不等于安全性——“P@ssw0rd”符合复杂性却极易被猜到，长度与不可预测性更重要。
- **密码最长使用期限与最短使用期限**：上限防止口令多年不变，下限防止用户短时间内反复改回旧口令；两者要配合“强制密码历史”（记住最近用过的若干个口令、禁止立即重用）一起用，单设一项容易被绕过。
- **用长度与唯一性代替频繁更换**：微软近年来的安全基线已不再主张无故频繁更换口令（以官方发布为准，待核实）；更合理的做法是：口令足够长、每个账户不同、有泄露嫌疑时立即更换。

**账户锁定策略（猜错多少次就锁住）**，常见项：

- **账户锁定阈值**：连续输错几次口令后锁定账户，例如 5 次（示例基线，以组织策略为准，待核实）。阈值太小会让正常用户被误锁、还容易被故意锁住他人账户；太大则起不到防猜测的作用。
- **账户锁定时间与锁定计数器复位时间**：锁住后多久自动解锁、输错计数多久清零；两者要配对设置，否则“锁定 30 分钟、计数 29 分钟清零”之类的错配会让策略形同虚设。

补充：有条件时优先用 Windows Hello（PIN、指纹、人脸）或多重身份验证代替“只靠口令”，口令策略只是防线之一；本文不展开生物识别与 MFA 的部署细节。

### 3.6 定期审计账户：加固不是配一次就完事

策略配完会漂移：有人临时加了管理员、有人走了账户没删、有人把口令改回了弱口令。审计就是定期把这些漂移找出来。建议的审计节奏：高权限组成员每月看一次，全部本地账户每季度看一次，离职与换岗事件发生时立即处理。

审计清单：

1. **Administrators 组成员**：逐个核对，是否每个人都确实需要管理员权限（命令示例见 3.4 节，示例未实测）。
2. **已启用但长期无人登录的账户**：结合上次登录时间判断，禁用后观察一段时间再删除。
3. **内置 Administrator 与 Guest 的状态**：确认仍处于期望的状态（禁用或按 3.1 节管控）。
4. **口令策略的实际生效值**：用 `net accounts`（示例未实测）或组策略结果（`gpresult`，见[注册表与组策略](02-registry-group-policy.md)）核对，区分“配了策略”和“策略真生效了”。
5. **安全日志里的账户事件**：事件查看器中与账户相关的事件，例如登录失败、账户创建、组成员变更（常用事件 ID 如 4625 登录失败、4720 账户创建、4732 本地组成员变更，均为例行审计参考值，以官方发布为准，待核实）。发现异常后先保留日志、再处理账户，不要先删账户再查日志。

审计结果要留档：谁在什么时候查了、发现了什么、处理了什么。没有记录的审计，下次出问题时无法证明“当时是干净的”。

## 4. 分类

按加固对象分，账户与权限加固分四类：高权限账户管控（3.1 节）、提权提示收紧（3.2 节）、日常权限收敛（3.3–3.4 节）、口令与锁定策略（3.5 节），再加贯穿始终的定期审计（3.6 节）。按管理手段分，单机用本地安全策略与本地用户和组，多台设备用组策略统一下发（见[注册表与组策略](02-registry-group-policy.md)）；规模越大，越要靠策略下发而不是逐台点鼠标。

## 5. 典型应用

- **新设备装机验收**：确认内置 Administrator 处于期望状态、日常账户为标准用户、管理员账户单独建好并记录在案，再交付使用。
- **办公电脑权限收敛**：把全员日常账户降为标准用户，只留少数具名管理员；软件安装与系统配置走 UAC 提权流程。
- **离职交接检查单**：离职当天禁用本地账户、移出高权限组、核对该账户名下没有遗留的计划任务或服务在用它运行。
- **定期合规自查**：按 3.6 节清单每月出一份账户审计记录，作为“当时权限是收敛的”证据。

## 6. 限制与常见误解

- **改名不等于隐藏**：重命名内置 Administrator 只能挡住按名字猜测，账户 SID 不变，检查 SID 仍能认出它；不要把改名当作唯一的保护。
- **UAC 拉到最低不是“优化”**：从不通知等于关掉误触保护；软件频繁弹提示要修软件，不要关 UAC。
- **口令策略管不住已泄露的口令**：策略只能管“新口令够不够强”，管不了“口令是不是已经在别处泄露了”；有泄露嫌疑时立即更换，不要等到期。
- **锁定策略可能被利用来锁人**：阈值设得太小，攻击者可以故意输错口令把他人账户锁住（拒绝服务）；阈值与锁定时间的配对设置要按实际环境权衡。
- **域环境下本地策略说了不算**：域账户的口令与锁定策略由域组策略统一下发，本地安全策略改了也会被域策略覆盖；排障时先用 `gpresult` 确认生效来源（见[注册表与组策略](02-registry-group-policy.md)）。
- **本文不讲攻击与绕过**：不提供提权、绕过 UAC、猜测口令或规避审计的操作方法；发现绕过手段属于安全研究与修复范畴，应按负责任的渠道报告与修复。

## 7. 小结

账户与权限最小化加固 = 内置管理员不用就禁用、UAC 提示收紧到“想清楚再过”、日常用标准用户、本地用户与组管得清、口令够长且唯一、猜错有锁定、定期审计防漂移。权限收敛是一次性配置加持续审计，配完不管，迟早漂移回去。
