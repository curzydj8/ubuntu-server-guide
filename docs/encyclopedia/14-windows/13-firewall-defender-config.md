# 防火墙与 Defender 配置

> **实测声明**：本文写作环境为 Linux 虚拟机，无法运行 Windows。文中所有 Windows 命令、界面操作与示例输出均为**示例未实测**，请在自有设备或授权系统上核对后再执行；具体默认值、界面位置与策略路径因 Windows 版本而异，以官方发布为准（待核实）。
>
> **安全边界**：本文只讲防御、检测与加固配置。不讲关闭防火墙或 Defender 来“解决问题”的方法，也不讲用排除项隐藏恶意程序；排除项只讲其风险（见 3.5 节）。

## 1. 一句话定义

防火墙与 Defender 配置是指：用 Windows Defender 防火墙控制哪些网络流量可以进出本机，用 Microsoft Defender 防病毒实时检查文件与程序是否恶意，并通过更新与运行状况检查让这两层防护持续处于工作状态的一整套配置与管理做法。

## 2. 为什么需要它

一台 Windows 设备连上网络的那一刻起，就同时面对两个方向的风险：外面有人试图连进来（例如扫描开放端口、尝试远程登录），里面有程序试图连出去（例如恶意软件回传数据、被篡改的软件下载更多载荷）。防火墙管的是“流量能不能走”，防病毒管的是“文件与程序是不是恶意”；两者各守一面，缺一面都不完整。

很多人的第一反应是“某个软件连不上网，先把防火墙关了试试”——这是最要避免的习惯。防火墙拦住连接时，正确做法是查日志、确认是哪个规则拦的、再为这个软件补一条**足够窄**的放行规则（见 3.3 节），而不是把整面墙拆掉。本文的目标就是讲清这套“先查、再补窄规则”的做法。

## 3. 核心含义

### 3.1 防火墙是什么：默认拦入站、默认放出站

Windows Defender 防火墙是 Windows 内置的主机防火墙，随系统提供，无需另行安装。它的默认姿态是：

- **入站连接默认阻止**：外面主动发起的连接，没有明确放行规则的一律拦住。这就是“新装系统不对外暴露服务”的原因。
- **出站连接默认允许**：本机程序主动向外发起的连接，默认放行；需要时可再加出站规则收紧（见 3.3 节）。

管理入口有两层：Windows 安全中心（Windows Security → 防火墙和网络保护，面向个人用户，只看当前配置文件状态与“允许应用通过防火墙”）与**高级安全 Windows Defender 防火墙**管理单元（`wf.msc`，示例未实测，面向管理员，可看全部规则与三个配置文件）。日常排障先用前者确认“防火墙是不是开着”，要改规则时用后者。

### 3.2 按配置文件管理：域、专用、公用是三套不同的松紧度

防火墙按设备当前所连网络的类型，套用三套不同的配置，称为**配置文件（Profile）**：

| 配置文件 | 适用的网络 | 含义与松紧度 |
|---|---|---|
| 域（Domain） | 设备已加入域，且能联系到域控制器 | 组织内网环境；规则通常由域组策略统一下发，本地改动可能被域策略覆盖 |
| 专用（Private） | 被用户或应用标识为受信任的网络 | 例如家庭或小型办公网络；只把真正信任的网络标为专用 |
| 公用（Public） | 其他所有网络 | 初始默认值；机场、咖啡馆等公共场所的网络都应保持公用，是最严格的一档 |

关键规则：**同一时间只生效一个配置文件**，生效顺序是域优先、其次专用、最后公用（以官方文档为准，待核实）。也就是说，设备一旦连上域网络就用域配置；否则若连的是专用网络就用专用配置；其余情况一律按公用配置处理。

管理要点：

- **三个配置文件都要保持防火墙开启**。只开公用、不开专用是最常见的配置漂移；检查时三个都要看，不要只看当前生效的那一个。
- **不要把公共 Wi-Fi 标为专用**。标为专用等于告诉系统“这个网络可信”，防火墙会按更宽松的规则放行；不确定就保持公用。
- **网络类型变了，生效的规则就变了**。同一个应用“在家里能连、在咖啡馆连不上”，很可能不是应用坏了，而是配置文件切换后规则变了；排障时先确认当前生效的是哪个配置文件。
- **域环境下以域策略为准**：域下发的防火墙规则由组策略管理，本地手工改的规则可能被下次刷新覆盖；要改就去改组策略对象（见[注册表与组策略](02-registry-group-policy.md)）。

### 3.3 入站与出站规则：一条规则由什么组成，怎么补才够窄

防火墙规则是“符合这些条件，就放行或阻止”的判定条目。新建规则时要填的要素（以高级安全防火墙管理单元的向导为准）：

- **规则类型**：程序（按可执行文件放行）、端口（按 TCP/UDP 端口号放行）、预定义（系统内置的服务模板）、自定义（组合条件）。
- **方向**：入站规则（外面连进来）与出站规则（本机连出去）分开管理；需要对外提供服务时加的是入站规则，需要限制某个程序联网时加的是出站规则。
- **操作**：允许连接、阻止连接。注意：入站方向的默认值已经是阻止，所以“补规则”通常是为某个合法服务加一条**允许**规则；而“阻止”规则用于明确拦住某个已知不需要的流量。
- **作用域**：规则对哪些本地/远程 IP 地址生效。把远程地址限定为“仅内网网段”或“仅某台管理机”，比“对所有地址放行”安全得多。
- **配置文件**：规则在域、专用、公用中的哪几个上生效；只在需要的配置文件上勾选，不要三个全勾。

补规则的正确顺序（应用连不上时的排障做法）：

1. **先确认防火墙是不是原因**：看防火墙日志（见 3.6 节）或临时观察，不要一上来就关防火墙。
2. **确认要放行的对象**：是哪个程序、哪个端口、哪个协议（TCP 还是 UDP），以及它需要被谁访问（内网还是公网）。
3. **补一条最窄的规则**：只放行这个程序或这个端口、只限定必要的远程地址、只勾选必要的配置文件；规则命名写清用途与负责人，方便日后审计。
4. **验证并收尾**：确认应用恢复后，复查规则没有多放、多勾；不再需要的规则及时删除或禁用，规则越攒越多等于墙越拆越薄。

查看现有规则的命令示例（示例未实测）：

```powershell
Get-NetFirewallRule | Select-Object DisplayName, Direction, Action, Enabled
```

```cmd
netsh advfirewall firewall show rule name=all
```

### 3.4 Microsoft Defender 防病毒：实时保护与扫描

Microsoft Defender 防病毒（Microsoft Defender Antivirus）是 Windows 内置的防病毒组件，随 Windows 安全中心提供。它的两层工作方式：

**实时保护（Real-time protection）**：文件被打开、下载、复制或执行时即时检查，发现已知恶意特征就拦截。配套的还有云提供的保护（把可疑文件特征发到云端比对）与自动提交样本（把可疑样本发给微软分析；涉及隐私考量，组织环境应按自身政策决定是否开启）。实时保护是防病毒的主防线，**应始终保持开启**；它变慢或拦截某个文件时，正确做法是查检测记录、确认文件来源（见 3.5 节），不是关掉实时保护。

**扫描（Scan）**：分三种，按需使用：

| 扫描类型 | 作用 | 适用场景 |
|---|---|---|
| 快速扫描 | 检查系统最常被恶意软件藏身的位置 | 日常定期检查，速度快 |
| 全面扫描 | 检查全部文件与正在运行的程序 | 怀疑已感染、或定期深度检查时用，耗时较长 |
| 自定义扫描 | 只检查指定的文件或文件夹 | 针对某个可疑位置定向检查 |
| 脱机扫描（Microsoft Defender Offline） | 重启后在系统完全加载前扫描 | 常规扫描清不掉的顽固恶意软件，可作为升级手段 |

发起扫描的命令示例（示例未实测）：

```powershell
Start-MpScan -ScanType QuickScan
```

```cmd
"%ProgramFiles%\Windows Defender\MpCmdRun.exe" -Scan -ScanType 1
```

**篡改防护（Tamper protection）**：防止未授权的程序或人员改动 Defender 的关键设置（例如悄悄关掉实时保护或删掉排除项之外的配置）。个人设备上保持开启；组织环境由 Intune 或组策略统一管理。篡改防护本身就是一道防线——如果发现它被人关过，要当作安全事件来查，而不是默默重新打开了事。

### 3.5 排除项：只讲风险，不教隐藏

排除项（Exclusions）是指告诉 Defender“这些文件、文件夹、文件类型或进程不用扫描”。微软官方文档的原意是：**排除会降低防护，只排除你确认无害的项**。本节只讲风险与管理纪律，不提供“用排除项放行可疑程序”的操作指导。

四种排除类型与各自的风险：

| 排除类型 | 风险 |
|---|---|
| 文件 | 该文件此后不再被扫描；若文件后来被替换为恶意版本，Defender 不会察觉 |
| 文件夹 | 该文件夹及全部子文件夹都不再被扫描；恶意软件只要落进这个文件夹就畅通无阻 |
| 文件类型（扩展名） | 所有带该扩展名的文件在任何位置都不再被扫描；排除 `.exe`、`.zip` 这类常见类型尤其危险 |
| 进程 | 该进程打开的文件跳过实时扫描（但计划扫描与手动扫描仍可能检查它们，以官方文档为准，待核实）；进程本身仍会被扫描 |

管理纪律：

- **能不排除就不排除**：先确认是不是确实需要排除（例如某个可信的开发工具因实时扫描明显变慢），再考虑排除；很多“扫描太慢”的问题靠换扫描时间（见 3.4 节）就能解决。
- **排除要尽可能窄**：排除单个文件比排除整个文件夹安全，排除文件夹比排除整个驱动器安全；永远不要排除“下载”文件夹、桌面或整个驱动器。
- **排除项要定期复查**：程序卸载后，它的排除项不会自动消失；每季度打开排除项列表，删掉不再需要的项。
- **排除项不是藏恶意程序的工具**：把未知或可疑的程序加进排除项，等于主动关掉对它的检查；来源不明的程序应先在隔离环境（例如 Windows 沙盒）中验证，而不是靠排除项放行。
- **篡改防护与排除项的关系**：开启篡改防护后，未授权的改动（包括偷偷加排除项）会被阻止；这是排除项管理的一道技术防线（以官方发布为准，待核实）。

### 3.6 更新与运行状况检查：防护会过期，要定期确认它还活着

防病毒与防火墙不是“装好就不用管”的组件；病毒特征库（安全智能更新）会过期，配置会漂移，第三方软件的安装还可能改变防护状态。建议的检查节奏：安全智能更新随 Windows 更新自动获取，每周看一次防护状态，每月做一次完整检查。

**更新**：安全智能更新通常随 Windows 更新自动下发；也可以在 Windows 安全中心 → 病毒和威胁防护 → 病毒和威胁防护更新中手动检查更新。服务器版（Server 2022/2025）同样通过 Windows 更新获取，Server Core 环境用 PowerShell 命令检查（示例未实测，见下）。

**运行状况检查清单**：

1. **Windows 安全中心总览**：三个区域（病毒和威胁防护、防火墙和网络保护、设备安全性）是否都显示正常（绿色勾选），有没有黄色警告或红色告警。
2. **实时保护状态**：确认实时保护与云提供的保护处于开启状态。
3. **安全智能版本与上次扫描时间**：确认特征库是最近几天内的版本、上次扫描不是几个月前。
4. **防火墙三个配置文件状态**：确认域、专用、公用三个配置文件都处于开启状态（见 3.2 节）。
5. **规则与排除项复查**：按 3.3 节与 3.5 节复查规则与排除项，删掉不再需要的项。

查看 Defender 运行状态的命令示例（示例未实测）：

```powershell
Get-MpComputerStatus | Select-Object AMServiceEnabled, RealTimeProtectionEnabled, AntivirusSignatureLastUpdated, QuickScanAge, FullScanAge
```

```powershell
Update-MpSignature
```

**日志与告警**：Defender 的检测与运行事件记录在事件查看器中（Microsoft-Windows-Windows Defender/Operational 日志，示例未实测）；防火墙的放行与阻止记录在防火墙日志文件（默认路径 `%systemroot%\system32\LogFiles\Firewall\pfirewall.log`，示例未实测）中，需先在配置文件属性中启用日志记录。排障时先看这两处，再决定改什么。

## 4. 分类

按防护面分，本文内容分三类：网络面（防火墙规则与配置文件，3.1–3.3 节）、文件与程序面（Defender 防病毒实时保护与扫描，3.4 节）、管理面（排除项纪律与更新及运行状况检查，3.5–3.6 节）。按管理手段分，单机用 Windows 安全中心与高级安全防火墙管理单元，多台设备用组策略或 Intune 统一下发（见[注册表与组策略](02-registry-group-policy.md)）。

## 5. 典型应用

- **新设备装机验收**：确认三个防火墙配置文件全部开启、实时保护开启、安全智能为最新版本、做一次快速扫描，再交付使用。
- **业务软件联网排障**：应用连不上时查防火墙日志、补一条最窄的入站或出站规则，而不是关闭防火墙（见 3.3 节）。
- **公共 Wi-Fi 出行检查**：确认当前网络被识别为公用、防火墙公用配置文件开启，再连接公共网络。
- **月度安全自查**：按 3.6 节清单出一份运行状况记录，作为“当时防护在工作”的证据；发现篡改防护被关过或排除项异常增多时，按安全事件处理。

## 6. 限制与常见误解

- **“关防火墙试试是不是它的问题”**：错。关防火墙期间设备完全暴露；正确做法是查日志、补窄规则（见 3.3 节）。
- **“装了第三方杀毒软件，Defender 就没用了”**：不完全对。安装第三方防病毒软件后，Defender 通常会进入被动模式或停用实时保护（以官方发布为准，待核实）；卸载第三方软件后要确认 Defender 已恢复工作，不要留下“两边都没在防”的空窗。
- **“排除项能解决软件被误报的问题”**：要分清误报与真威胁。确认是误报（软件来源可信、官方渠道下载）才考虑窄排除；来源不明的程序被拦截时，排除它等于放行威胁。
- **“防火墙能防病毒”**：错。防火墙管流量进出，防病毒管文件是否恶意；两者互补，不能互相代替。
- **“出站默认放行就不用管出站规则”**：出站默认放行是便利与安全的折中；高安全要求的环境应对出站也做收紧，但要先摸清业务软件的出站需求，否则会大面积误拦。
- **服务器版差异**：Windows Server 2022/2025 的 Defender 与防火墙同样内置，但 Server Core 没有图形界面，管理靠 PowerShell 与组策略；本文命令示例未在服务器版上实测，服务器侧的具体命令以官方文档为准（待核实）。

## 7. 小结

防火墙与 Defender 配置 = 三个配置文件全开、入站默认拦、出站按需收、补规则要够窄、实时保护常开、扫描定期做、排除项能少则少且定期复查、更新与运行状况每周确认。防护是持续工作的状态，不是装好就忘的开关；发现它被关过、改过，要当作事件来查，而不是默默恢复了事。
