# 多机器人协作

本篇是[具身智能总览](07-embodied-intelligence.md)的三级展开，只讲“多台机器人怎么一起干活”这一层：任务怎么分、信息怎么共享、冲突怎么消解、以及一台出故障时整体怎么办。单机导航见[视觉、定位、导航与运动规划](57-vision-navigation-planning.md)，软件栈见[ROS 2 与机器人软件架构](56-ros2-architecture.md)，安全见[机器人边缘计算与安全](61-robot-edge-safety.md)。多智能体协作的纯软件侧见[AI Agent 前沿：多智能体与自主研究](06-frontier-ai-agents.md)，本篇只讲物理多机，不展开纯软件多智能体。

## 1. 研究问题

一台机器人能做的事有限：搬运量、覆盖面积、任务并行度都有天花板。多台机器人协作要解决的是：怎么把一个大任务拆成多台机器人能并行做的子任务，怎么在动态环境中重新分配，怎么避免它们互相挡路、抢资源、重复劳动，以及怎么在一台故障时不拖垮整体。

物理多机协作比纯软件多智能体难在三个地方：第一，机器人占物理空间，两台不能同时出现在同一位置，冲突是真实的碰撞而不只是逻辑冲突；第二，通信不可靠——Wi-Fi 丢包、延迟、多机发现风暴都会让“共享状态”不一致；第三，异构——不同形态、不同能力、不同速度的机器人混在一起，任务分配不能只看“谁闲着”，还要看“谁能干”。

## 2. 基础理论

- **任务分配（task allocation）**：把任务集合分配给机器人集合，优化总时间、总能耗、负载均衡等目标；经典问题是多机器人任务分配（MRTA），在一般形式下是 NP 难问题，实际用拍卖、匈牙利算法、启发式等近似方法。
- **拍卖机制（auction）**：机器人对任务出价（代价估计），出价最低（或效用最高）者中标；分布式拍卖不需要中央调度器，但出价估计不准、通信延迟都会影响分配质量。
- **集中式 vs 分布式**：集中式由中央调度器全局优化，解的质量高、但单点故障与通信瓶颈；分布式由各机器人本地决策，鲁棒性好、但全局最优性差，且可能出现局部冲突。
- **编队与一致性（formation & consensus）**：多机保持几何队形、或对某个量（目标位置、任务状态）达成一致；一致性算法在通信拓扑变化、延迟、丢包下仍要收敛，是分布式协作的理论基础。
- **冲突消解与优先级**：两台机器人路径交叉时，谁让谁；优先级可以是静态的（按 ID、按任务紧急度），也可以是动态协商的；没有冲突消解机制的多机系统，在交叉路口必然死锁或碰撞。
- **异构能力模型**：每台机器人的能力（负载、速度、续航、操作能力、传感器配置）建模为能力向量；任务分配要匹配能力向量与任务需求向量，不是只看“谁闲着”。
- **容错与降级**：一台机器人故障、通信中断、传感器失效时，系统怎么重分配、怎么降级；容错不是“故障后人工重启”，而是系统自己能检测、隔离、重分配。

## 3. 技术路线

多机协作的主流路线有三条：

- **集中调度路线**：中央调度器（常在云端或边缘服务器）掌握全局状态，做任务分配与路径协调；仓储 AMR 车队是这条路线的最成熟落地——调度器给每台车派任务、规划无冲突路径、监控执行。优点是全局最优、易监控；缺点是单点故障、通信依赖、规模上限受调度器算力制约。
- **分布式协商路线**：各机器人通过拍卖、一致性、局部协商做决策，没有中央调度器；优点是鲁棒、可扩展，缺点是全局最优性差、收敛时间与通信开销难保证。适合通信不可靠、规模大、任务动态变化的场景。
- **混合路线**：中央做粗粒度分配（任务级），各机器人做细粒度协调（路径级避让、局部冲突消解）；是目前工程上最常见的折中——既利用全局信息，又保留局部鲁棒性。
- **学习式协作路线（研究前沿）**：用多智能体强化学习（MARL）让机器人从仿真交互中学会协作策略；优点是能学出人类难设计的协作行为，缺点是训练成本高、仿真到现实迁移难（见 60 篇）、可验证性差，目前多停留在仿真与小规模真机演示。

四条路线没有胜负：仓储车队选集中，野外集群选分布式，异构协作选混合，学习式协作仍在研究验证中。

## 4. 系统架构

一个典型的多机器人协作系统由以下部分组成：

- **任务层**：任务分解（大任务拆子任务）、任务表示（任务需求、优先级、截止时间、能力需求）。
- **分配层**：集中调度器或分布式拍卖/协商机制，输出“任务—机器人”匹配。
- **协调层**：路径协调（无冲突路径规划、路口优先级）、资源协调（充电桩、窄道、货架的互斥使用）、时间协调（多机时序同步，如双臂协作、接力搬运）。
- **通信层**：机器人间通信（DDS、ROS 2 多机发现、云端消息总线）与通信健康监控；见 56 篇的多机通信瓶颈。
- **定位与地图共享层**：多机共享地图（集中建图或分布式建图融合）、相对定位（机器人互相定位）、坐标系统一；没有统一的地图与坐标系，协作无从谈起。
- **执行层**：单机导航（57 篇）、操作、感知；协作层发目标，执行层落地。
- **监控与容错层**：各机器人健康状态、任务进度、故障检测、重分配触发；故障隔离（把故障机从任务池中摘掉）是容错的第一步。
- **安全层**：多机场景的安全——碰撞避免、速度与分离监控（见 61 篇）、急停的全局传播（一台急停时，相关机器人也要停下）。

## 5. 代表性实现与开源项目

只列真实存在的项目与系统类别，不写未核实的性能排名：

- **仓储 AMR 车队系统**：亚马逊、京东等仓储物流的 AMR 车队是集中调度路线的最成熟落地；任务是货架搬运、订单分拣类窄任务，环境是结构化仓库，调度器与路径协调是系统核心。具体厂商的车队规模与调度算法属于商业机密，以官方发布为准（待核实）。
- **OpenRMF（Open Robotics Middleware Framework）**：Open Robotics 的多机器人车队管理框架，面向多机、多楼层、多厂商的车队互操作；提供任务分配、路径协调、车队适配器等基础设施，是研究与原型开发的代表性框架。
- **ROS 2 多机支持**：命名空间、ROS_DOMAIN_ID 隔离、DDS 发现是 ROS 2 多机的基础机制；但“同一网络跑多台机器人”的发现风暴与跨网段问题仍是工程瓶颈（见 56 篇）。
- **无人机集群演示**：灯光秀无人机集群是编队控制的代表性演示；演示环境高度结构化（预设轨迹、室外 GPS、人工监控），不等于开放环境的自主协作。
- **多智能体强化学习框架**：MAPPO、QMIX 等多智能体强化学习算法与仿真环境（见 AI Agent 总览 06 篇的对应方向）；目前多停留在仿真验证，小规模真机演示为主。
- **尚无代表性商用系统**：按“异构多机在开放环境自主协作、按商用标准交付”的定义，今天不存在这样的系统；现有商用多机系统多为同构车队、结构化环境、集中调度的窄场景。

## 6. 关键论文与标准

- Gerkey 与 Matarić《A Formal Analysis and Taxonomy of Task Allocation in Multi-Robot Systems》（2004）：多机器人任务分配的经典分类（单任务/多任务机器人、单机器人/多机器人任务、即时/时序分配），是 MRTA 的标准 taxonomy。
- 多智能体强化学习代表性工作：MAPPO、QMIX 等算法论文（2017–2021 年前后）；方法以仿真训练为主，真机迁移仍是开放问题。
- 一致性算法经典文献：Olfati-Saber 等关于多智能体一致性的论述（2007 年前后）：通信拓扑、延迟、丢包下的一致性收敛条件。
- 标准：暂无统一的多机器人协作国际标准；OpenRMF 是事实上的车队互操作框架，不是 ISO 标准；多机安全沿用 ISO 10218 与移动机器人安全标准（见 61 篇），异构协作的安全评估仍是空白。

## 7. 当前实验结果

本节不写横向数字：不同系统的机器人数量、任务、环境与评判标准各不相同，数字脱离条件没有可比性。只写经核查的定性结论：

- 集中调度的同构 AMR 车队在结构化仓储环境已有大规模工程部署，是多机协作中最成熟的一块；但它成熟的是“同构、结构化、集中调度”的窄场景，不是通用多机协作。
- 分布式拍卖与一致性算法在仿真与小规模真机（数台到数十台）上已有验证；规模上到数百台时，通信开销、收敛时间与冲突率的变化规律仍是研究问题，具体数字以论文实验条件为准。
- 异构协作（人形 + 轮式 + 机械臂混编）的公开案例极少，多为演示与试点；异构能力建模、任务匹配、跨形态通信是未解决的工程问题。
- 学习式协作（MARL）在仿真环境中能学出协作行为，但仿真到现实迁移（见 60 篇）与可验证性仍是瓶颈；真机多机学习演示的规模与可复现性，以论文实验条件为准（待核实）。

## 8. 技术瓶颈

- **通信不可靠**：Wi-Fi 丢包、延迟、多机发现风暴使共享状态不一致；不一致的状态会导致重复分配、路径冲突、甚至碰撞。
- **规模扩展**：机器人数量上规模时，通信开销、协调复杂度、冲突概率都上升；集中调度的算力瓶颈与分布式算法的收敛时间都是规模瓶颈。
- **异构性**：不同形态、能力、速度的机器人混编时，任务分配、路径协调、时间同步都要考虑能力差异；同构车队的经验不能直接推广到异构。
- **动态与不确定性**：任务动态到达、机器人动态故障、环境动态变化，使“一次分配管全程”不可行；重分配的频率与稳定性（避免抖动式重分配）是调参难题。
- **死锁与活锁**：窄道、路口、充电桩等共享资源处的死锁（互相等待）与活锁（互相让路、谁也走不了）是多机系统的经典故障，需要形式化验证或充分的压力测试。
- **安全与责任**：多机碰撞的责任划分、急停的全局传播、故障机的隔离，都是单机安全标准未覆盖的问题（见 61 篇）。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：同构车队在结构化环境的集中调度已有工程部署，但异构协作、分布式大规模协作、学习式协作、开放环境多机安全均未解决，本篇作为“多机器人协作”整体取实验研究中，且同构车队部分单独判断为工程发展中——把两者混为一谈是错的。

## 10. 未来研究问题

- **已有研究在做**：混合编排——中央粗分配 + 局部细协调的架构优化，兼顾全局最优与局部鲁棒。
- **已有研究在做**：多机共享地图与相对定位的鲁棒方法，解决“没有统一地图就无法协作”的前提问题。
- **已有研究在做**：学习式协作的仿真到现实迁移与小规模真机验证。
- **本文推测**：多机协作可能先在“同构车队 + 结构化环境”上继续深化（更大规模、更动态的任务），而不是先攻克异构开放环境；检验标准是同构车队的规模与动态任务处理能力是否先出现可复现的提升。
- **本文推测**：多机协作的标准可能先以“车队互操作接口”（如 OpenRMF 的适配器模式）形式出现，而不是先出一部通用协作标准；检验标准是多厂商车队互操作案例是否先于通用标准出现。
