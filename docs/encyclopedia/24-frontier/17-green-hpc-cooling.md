# 液冷、能效与绿色超算

## 1. 研究问题

超算的功耗问题不是“电费贵”这么简单，而是三重约束同时收紧：第一，算力上去了，功耗跟着上去——exaflop 级系统的功耗已达数十兆瓦量级（见总览 03 篇第 8 节），供电容量本身就是建站门槛；第二，单机架功率密度上去了，风冷到物理极限——高功率加速器集中在一个机架里，空气带走热量的能力跟不上发热速度，降频、宕机、硬件寿命都会受影响；第三，碳与水的约束上来了——数据中心与超算中心的能耗、水耗与碳排放正在进入监管与公众视野，机房不能只算“算得快”，还要算“每瓦特算出多少科学结果、每升水换来多少算力”。

绿色超算要解决的问题因此是：在功耗、供电、散热三重封顶的前提下，最大化科学产出，而不是最大化榜单名次。具体分三个子问题：热量怎么带走（冷却技术）、效率怎么度量（能效指标）、热量与电力怎么少浪费（余热利用与能效调度）。

本篇只讲散热与能效，不重复超算总览的集群组成、并行模型与调度命令。超算的组织方式见 [超算与高性能计算入门](03-hpc-supercomputing.md)；AI 与 HPC 融合带来的功耗结构变化见本域 16 篇。

## 2. 基础理论

- **PUE（Power Usage Effectiveness，电源使用效率）**：机房总耗电除以 IT 设备耗电；PUE 越接近 1，说明用于冷却、配电等非 IT 环节的电越少。注意：PUE 只衡量“机房 overhead”，不衡量“IT 设备本身算得是否高效”——一台算得慢但 PUE 很低的系统，科学产出仍可能很差。
- **能效（性能每瓦特）**：单位功耗换来的计算性能，Green500 的口径是 HPL 性能除以功耗，单位为 Gflop/W；与 PUE 互补——PUE 看机房，性能每瓦特看系统本身。
- **WUE（Water Usage Effectiveness，水使用效率）**：单位 IT 能耗对应的水耗；蒸发冷却省电但耗水、干冷省水但在高温环境下效率下降，PUE 与 WUE 常常需要权衡，不能只优化一个。
- **热量传递的基本约束**：空气的单位体积载热能力远低于液体，这是液冷的物理出发点——同样热量，液体需要的流量与温差远小于空气；因此高密度机架转向液冷不是“偏好”，而是空气的载热能力到顶后的必然选择。
- **温水冷却（warm-water cooling）**：用较高温度（例如 30°C 以上量级，具体以系统官方发布为准）的冷却水带走热量；水温越高，越容易用自然冷却（干冷器、冷却塔）而不开压缩机制冷，冷却能耗随之下降。代价是换热温差变小、对换热器与流量设计要求更高。
- **检查点与功耗的关系**：见总览 03 篇第 6 节。能效调度常与检查点、作业抢占联动——降频、暂停、迁移作业都会影响检查点成本，调优时不能只算瞬时功耗。

## 3. 技术路线

按冷却介质与接触方式分四条路线，每条一句话讲清做法与适用场景：

- **风冷（空气冷却）**：风扇驱动冷空气流过机架、带走热量；做法最简单、改造成本最低，适合中低功率密度机架；瓶颈是空气载热能力与风扇自身功耗随密度急剧上升，高密度下先到极限。
- **直接液冷（Direct Liquid Cooling，DLC；亦称直接芯片液冷）**：冷板贴在处理器、加速器等发热器件上，液体在冷板内循环把热量带到冷却分配单元（CDU，Coolant Distribution Unit），再交给机房一次侧水路；做法是当前高密度超算的主流，热量在源头就被液体带走，剩余部件仍可风冷或辅助液冷。
- **单相浸没式冷却**：整台服务器浸入不导电的介电液体中，液体不沸腾、靠循环带走热量；做法是热量分布最均匀、无风扇噪声，代价是运维方式彻底改变（换件要出液、液体维护与兼容性验证），适合新建的高密度机房。
- **两相浸没式冷却**：浸没液受热沸腾成蒸气、冷凝后回流，靠相变潜热带走热量；做法的单位面积换热能力最高，代价是液体成本、安全性验证与运维复杂度最高，目前适用面最窄。

还有两条常被并列、但层次不同的东西：**余热利用**（把机房废热用于供暖、温室、区域供热等，见第 4 节）与**能效调度**（在功耗封顶下安排作业、调频、调压，见第 4 节）——它们不改变冷却方式，而是改变“热量与电力的去向与使用方式”，本篇把它们放在架构节，不与四条冷却路线并列。

## 4. 系统架构

一个绿色超算机房由五部分组成，关系如下：

1. **一次侧与二次侧水路**：二次侧是机架内的冷却液循环（经 CDU 与冷板），一次侧是机房的供水回路（经干冷器、冷却塔或冷水机组排热）；CDU 是两次侧之间的换热与隔离点，也是漏液检测与流量控制的关键位置。
2. **冷却分配与末端**：干冷器（用室外空气排热，不耗水）、冷却塔（蒸发排热，省电但耗水）、冷水机组（压缩机制冷，能耗最高）三者按气候与负荷组合；温水冷却的意义正在于让干冷器在更多时间里替代冷水机组。
3. **供电与功耗封顶**：机房供电容量是硬上限，调度器与功率管理系统据此给作业分区设功耗帽（power cap）；超功耗的作业会被降频或排队，不是“先跑再说”。
4. **余热利用接口**：把一次侧回水的高温热量引出机房，供区域供热、建筑供暖或其他用热场景；余热利用的收益取决于“附近有没有稳定用热需求”与“回水温度够不够”，不是所有机房都划算。
5. **能效调度层**：在功耗封顶内做三件事——按作业类型设功耗策略（如仿真长作业保吞吐、AI 训练在功耗帽内调频）、在低谷时段安排可延迟作业、结合检查点做抢占与迁移；能效调度的度量是“单位功耗的科学产出”，不是“瞬时功耗最低”。

### 4.1 PUE 估算示例（示例未实测）

以下脚本只演示 PUE 的定义算法（总耗电除以 IT 耗电），输入数字为示意、非任何真实机房数据，**示例未实测**（代理 VM 上无机房电表、无真实集群，读者须以自家电表与计量口径为准）：

```python
# 示例未实测：仅演示 PUE 定义，不代表任何真实机房
total_kwh = 1200.0  # 示意：机房总耗电（含冷却、配电损耗）
it_kwh = 1000.0     # 示意：IT 设备耗电

```

## 5. 代表性实现与开源项目

只列真实存在的项目与系统，数字只写已核查的项：

- **Green500 榜单**：按 HPL 性能每瓦特排名的能效榜，见第 7 节；它是“系统能效”的参考坐标，不是机房 PUE 的排名——两者口径不同，不要互相替代。
- **exaflop 级系统的液冷实践**：El Capitan、Frontier 等系统（见总览 03 篇第 5 节）的机架功率密度已超出纯风冷的舒适区，液冷是其机房设计的组成部分；各系统具体的冷却形式（直接液冷、温水温度等）以各实验室官方发布为准（待核实），本篇不转载二手机房参数表。
- **液冷设备与标准组织**：冷却分配单元（CDU）、冷板、歧管等部件由机房设备厂商提供；机房能效与液冷接口的相关标准涉及 ASHRAE（美国供暖制冷与空调工程师学会）的数据中心热指南等公开标准，具体条款与版本以官方发布为准（待核实）。
- **开源监控与调度工具**：功耗采集、作业能耗记账常基于各超算中心自研或开源的监控栈（如基于 Slurm 记账扩展功耗字段的做法），各中心实现不同、没有统一的开箱即用产品；本篇不做具体工具选型推荐。

## 6. 关键论文与标准

本专题没有单一的“绿色超算标准”；以下列出的是指标与标准层面的真实存在，具体条款与版本以官方发布为准（待核实）：

- **TOP500 / Green500 方法论**：HPL 实测 Rmax 与榜单申报功耗是 Green500 能效数字的测试条件，见第 7 节；换测试条件（例如换 HPCG、换混合精度）得出的“能效”不可与 Green500 数字直接比较。
- **PUE / WUE 定义**：源自数据中心能效领域的通用指标定义（The Green Grid 等组织曾推动 PUE 的标准化定义），具体定义版本与计量边界以相关组织官方发布为准（待核实）。
- **ASHRAE 数据中心热指南**：关于数据中心温湿度与冷却设计范围的公开指南，具体版本以 ASHRAE 官方发布为准（待核实）。
- **暂无公开标准**：浸没式冷却液的兼容性验证、余热利用的并网与计价规则，目前没有全球统一的强制标准，各项目以当地规范与厂商验证为准。

不写进本节的数字：任何单个机房的 PUE、任何厂商的“液冷省电百分之几”宣传数字——PUE 的计量边界各不相同、厂商宣传的对照基线（与哪种风冷比、在什么气候下）通常不公开，缺一件就不写；本篇不转载此类数字为事实。

## 8. 技术瓶颈

- **漏液与运维风险**：液体进机架意味着漏液检测、接头维护、液体水质管理成为日常运维项；一次漏液的损失可能超过长期省下的电费，运维流程与保险责任必须先于规模部署。
- **液体兼容性与寿命**：浸没液与元器件、密封件、线缆的长期兼容性需要验证周期，换液、补液、废液处理的成本与环保要求常被低估。
- **温水与余热的“最后一公里”**：回水温度够不够用、附近有没有稳定用热需求、供热管网改造成本，是余热利用能否落地的决定因素；没有用热方的机房，余热只是“排出去的热量换了个出口”。
- **PUE 与 WUE 的权衡**：蒸发冷却省电但耗水、干冷省水但高温时效率下降；在缺水地区优化 PUE 可能恶化 WUE，两个指标必须联合报告。
- **能效调度的度量难题**：“单位功耗的科学产出”没有统一定义——按作业数、按仿真步数、按论文数都各有偏差；没有可信的度量，能效调度就容易退化成“降频省电、产出也降”的表面文章。
- **成本结构**：液冷机房的前期改造成本（管路、CDU、承重、防水）高于风冷，收益体现在长期电费与密度上；只算一年电费的采购模型会系统性低估液冷、只算峰值密度的模型又会高估它。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：直接液冷已在 exaflop 级生产系统与高密度机房中实际部署（Green500 榜单与 TOP500 前列系统为证），但浸没式冷却、余热规模化利用、统一的能效调度度量仍未成为超算中心的通用标配，因此绿色超算整体判为工程发展中，而非成熟应用。

## 10. 未来研究问题

- **已有研究在做**：更高功率密度的冷板与两相冷却——单器件功耗继续上升时，冷板换热能力与流量分配是否跟得上。
- **已有研究在做**：能效感知的作业调度与动态功耗帽——在供电封顶内实时调整各作业的功耗分配，目标是系统级科学产出最大化而非单作业最快。
- **已有研究在做**：余热与区域能源系统的耦合——机房作为城市供热网络的热源之一参与调度，涉及热价、管网与季节性需求匹配。
- **本文推测**：PUE 可能逐渐让位于“单位科学产出的全生命周期成本”（含水、碳、设备折旧）作为绿色超算的主指标；检验标准是主流榜单或采购规范是否开始要求联合报告 PUE、WUE 与碳强度。
- **本文推测**：液冷可能从“高密度机房的选项”变成“新建超算机房的默认项”；检验标准是未来 TOP500 前列新系统是否普遍以液冷作为首选设计，而非改造项。
