# 量子通信网络（网络架构视角）

> 本篇只写网络架构视角：节点、链路、组网方式、协议分层与信任模型。量子密钥分发（QKD）的协议细节、量子中继的物理实现、量子硬件路线，见 [量子网络](68-quantum-networks.md)，本篇不重复其内容。

## 1. 研究问题

经典网络的安全建立在计算复杂度假设上（大数分解、离散对数难解），而量子计算可能动摇其中一部分假设；另一方面，经典信号可以被放大、复制、监听而不留痕迹。量子通信网络要回答的网络架构问题是：如果节点之间能分发量子态（或用量子信号协商密钥），网络的拓扑、路由、信任模型与协议分层应该长什么样？它与经典网络的区别首先在架构层：量子态不可克隆、不可放大，经典的“中继放大”思路在量子链路上是非法物理。

本篇的边界：讲“怎么组网”，不讲“量子器件怎么做”；后者归 [量子网络](68-quantum-networks.md)。

## 2. 基础理论

- **不可克隆定理**：未知量子态不能被复制，因此量子中继不能像经典中继那样放大信号；长距离必须靠纠缠交换等机制（物理细节见 [量子网络](68-quantum-networks.md)）。
- **QKD（量子密钥分发）**：用量子信号协商经典密钥，窃听会改变量子态从而被发现；QKD 协商的是密钥，不是直接传业务数据——业务数据仍走经典信道加密传输。
- **可信中继**：把长链路切成多段短链路，每段做 QKD，中继节点持有密钥并转发；代价是必须信任中继节点本身。
- **纠缠分发**：在节点间建立纠缠对，再通过隐形传态传量子态或做分布式量子计算；这是“量子互联网”的长期目标，与 QKD 组网是两代架构。
- **量子互联网分层**：IETF RFC 9340 提出的架构原则，把量子网络按物理、链路、网络等层类比经典分层，但各层的功能与经典层不同（例如“网络层”分发的是纠缠而非数据包）。

## 3. 技术路线

- **点对点 QKD 路线**：两节点间直接做 QKD，距离受光纤损耗限制（直接光纤 QKD 约百公里量级，超出后成码率急剧下降）；适合城域、园区、数据中心互连。
- **可信中继组网路线**：多段 QKD 串联，中继节点逐段解密再加密转发；已建成跨城、跨国的 QKD 骨干（如京沪干线量级的骨干，具体里程以官方发布为准，待核实）。这是今天唯一大规模落地的量子组网方式，代价是信任模型变了——中继节点被攻陷，密钥就不再安全。
- **测量设备无关（MDI）QKD 组网路线**：用不信任的中间测量节点组网，消除探测器侧信道攻击面；组网拓扑从“链”变成“星”（多用户共享一个测量节点），但成码率与距离仍受限。
- **卫星 QKD 路线**：用卫星做中继或纠缠源，绕过地面光纤损耗；卫星 QKD 已有演示与试验网络，但星地链路受天气、过顶窗口限制，尚不是连续商用服务。
- **纠缠分发组网路线（长期）**：量子中继 + 量子存储 + 纠缠交换，目标是端到端纠缠分发；今天仍处实验阶段，城域纠缠分发演示的速率在每秒数次量级，远未达到商用组网要求。
- **混合组网路线**：QKD 网络与后量子密码（PQC）并存、经典信道承载业务的混合架构；这是当前务实的主流——QKD 负责密钥，PQC 负责算法敏捷性，两者互补而非互斥。

## 4. 系统架构

按组网代际，量子通信网络有三代架构：

- **第一代：可信中继 QKD 网**：节点 = QKD 终端 + 密钥管理；链路 = 光纤 QKD 链路；中继节点持有密钥；控制面 = 密钥管理与路由（哪对用户用哪条中继路径）；业务面 = 经典加密信道。信任假设：中继节点物理安全。
- **第二代：MDI / 卫星辅助网**：中间节点不可信（MDI）或天基（卫星），信任假设放宽，但组网复杂度与成本上升。
- **第三代：纠缠分发网（量子互联网）**：节点 = 量子处理器/存储器；链路 = 纠缠链路；网络层 = 纠缠路由与纯化；应用 = 分布式量子计算、分布式传感、盲量子计算。RFC 9340 的架构原则与 RFC 9583 的应用场景是这一代的公开参考。

三代不是“升级替代”关系：第一代已部署，第二代在试点，第三代在实验；一张务实的量子通信网今天是第一代为主、混合 PQC 的架构。

## 5. 代表性实现与开源项目

- **QKD 骨干网**：中国京沪干线量级的 QKD 骨干是可信中继组网的最大公开案例；欧洲 EuroQCI 正在建设泛欧量子通信基础设施（各国网络互联阶段，具体进度以 EuroQCI 官方发布为准，待核实）。
- **QKD 商用设备**：ID Quantique 等厂商的 QKD 系统已有面向金融、政府的部署；具体型号与成码率以厂商数据表为准（待核实）。
- **量子网络仿真与软件栈**：量子网络协议仿真工具（如 NetSquid、SimulaQron 等研究工具）用于纠缠路由与中继协议验证；软件栈细节见 [量子网络](68-quantum-networks.md)。
- **尚无商用纠缠分发网**：按“端到端纠缠、多用户、连续服务”定义，今天不存在商用量子互联网；现有纠缠分发均为城域实验演示。

## 6. 关键论文与标准

- IETF RFC 9340：量子互联网架构原则。
- IETF RFC 9583：量子互联网应用场景。
- ETSI QKD 技术委员会标准群：QKD 设备、接口与网络的相关标准（具体编号以 ETSI 官方发布为准）。
- QKD 协议基础：BB84（Bennett 与 Brassard，1984 年）是多数 QKD 系统的协议起点；协议细节见 [量子网络](68-quantum-networks.md)。
- 量子中继原始提议：Briegel 等人（1998 年）、DLCZ 方案（Duan、Lukin、Cirac、Zoller，2001 年）；物理细节见 [量子网络](68-quantum-networks.md)。

## 7. 当前实验结果

本节不写脱离距离、器件与测试条件的成码率数字。只写经核查的定性结论：

- 可信中继 QKD 组网是唯一大规模落地的代际；其安全性的上限就是中继节点的物理安全水平。
- 城域纠缠分发已有演示，但速率低（每秒数次量级）、距离短，未达到组网商用要求；量子中继的完整工程化尚未实现。
- 卫星 QKD 已演示，但受天气与过顶窗口限制，连续性不如地面光纤。

## 8. 技术瓶颈

- **距离与损耗**：光纤损耗指数衰减，QKD 成码率随距离急剧下降；没有量子中继，长距离只能靠可信中继，而可信中继改变了信任模型。
- **量子中继未工程化**：量子存储、纠缠纯化、高效 Bell 测量等组件各有演示，但组装成可连续运行的中继仍是研究问题。
- **信任模型**：可信中继要求信任中间节点，这与 QKD“物理安全”的宣传口径有张力；用户必须理解自己到底信任了什么。
- **与经典网的集成**：密钥管理、路由、认证、运维如何与现有经典网络集成，缺乏统一的组网运维标准。
- **成本**：QKD 终端、单光子探测器、卫星载荷的成本限制了普及；PQC 的边际成本远低于 QKD，是 QKD 推广的结构性对手。
- **标准化**：QKD 接口、密钥管理、网络架构的标准仍在演进中，跨厂商互通有限。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：可信中继 QKD 网已有骨干部署，但纠缠分发组网（量子互联网的本意）仍处实验阶段；把 QKD 骨干写成“量子互联网已建成”是虚标，本篇按架构代际分开判断。

## 10. 未来研究问题

- **已有研究在做**：量子中继工程化（存储、纯化、交换）；MDI 组网的成码率与距离提升；卫星 QKD 的连续服务能力。
- **已有研究在做**：QKD 与 PQC 的混合组网架构与密钥管理标准；量子网络的路由与资源分配协议。
- **本文推测**：量子通信网的务实未来可能是“QKD + PQC 混合骨干”，而非纯量子网；检验标准是运营商是否把 QKD 密钥管理纳入现有密钥管理体系，而非另建一套孤岛。
- **本文推测**：纠缠分发网的第一个杀手应用可能不是加密，而是分布式量子计算与分布式传感；检验标准是是否出现跨节点的分布式量子计算演示（而非仅纠缠分发演示）。
