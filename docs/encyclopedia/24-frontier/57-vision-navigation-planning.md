# 视觉、定位、导航与运动规划

本篇是[具身智能总览](07-embodied-intelligence.md)的三级展开，只讲机器人“知道自己在哪、知道往哪走、知道手怎么动”这一层：定位、建图、导航与运动规划。软件栈见[ROS 2 与机器人软件架构](56-ros2-architecture.md)，多传感器融合的滤波算法见[多传感器融合](58-multisensor-fusion.md)，仿真中的规划验证见[仿真训练与 Sim-to-Real](60-sim-to-real.md)。

## 1. 研究问题

机器人要自主移动，必须同时回答三个问题：我在哪（定位）、周围长什么样（建图）、怎么从 A 到 B 且不撞上东西（规划）。更难的是，这三个问题互相依赖：没有地图没法定位，没有定位没法建图，没有地图与定位没法规划——这就是 SLAM（同步定位与建图）这个名字的由来。

机械臂的规划问题与移动机器人不同：它不问“底盘往哪走”，而问“七个关节怎么转，才能让手到达目标姿态且不碰到自己、不碰到环境”。两者共享“在约束下找一条可行路径”的数学形式，但约束（关节限位、自碰撞、奇异点）与代价（时间、能量、平滑度）完全不同。

## 2. 基础理论

- **SLAM**：在未知环境中，机器人一边估计自身位姿、一边构建环境地图；位姿与地图互相作为对方的观测，误差会累积，必须用回环检测（loop closure）与图优化消除漂移。
- **占用栅格地图（occupancy grid）**：把环境切成小格子，每格标记“空闲 / 占据 / 未知”；2D 激光 SLAM 的标准输出，Nav2 导航就跑在这张图上。
- **粒子滤波定位（AMCL）**：用一群带权重的粒子表示位姿的概率分布，粒子按运动模型扩散、按观测模型加权、重采样收敛；AMCL 是“已知地图上定位”的经典方法，需要预先建好的地图。
- **图优化 SLAM**：把位姿与观测约束建成图，用非线性最小二乘（如 Ceres、g2o）优化整条轨迹；SLAM Toolbox 的定位模式就用图优化代替粒子滤波。
- **代价地图（costmap）**：在占用栅格之上叠加膨胀、障碍物距离、禁行区等代价层；规划器在代价地图上找路，而不是在原始栅格上找路。
- **全局规划与局部规划**：全局规划在整张地图上找一条从起点到终点的路径（不考虑机器人实时动力学）；局部规划在机器人附近的小窗口内把全局路径变成可执行的速度指令（考虑动力学、实时障碍物）。
- **运动规划（motion planning）**：在构型空间（关节角度的组合空间）中找一条从起始构型到目标构型、无碰撞的路径；采样类算法（RRT、PRM）与优化类算法（TrajOpt、CHOMP）是两大流派。
- **行为树**：导航任务的编排结构（见 56 篇）；Nav2 用行为树把“规划—跟随—恢复”组织成可组合、可重试的行为。

## 3. 技术路线

定位与建图的主流路线有三条：

- **激光 SLAM 路线**：2D/3D 激光雷达 + 里程计 + IMU，用扫描匹配与图优化建图；室内结构化环境最成熟，SLAM Toolbox 是 ROS 2 侧的代表。短板是：对玻璃、镜面、动态行人、长走廊（几何退化）敏感。
- **视觉 SLAM 路线**：单目、双目或 RGB-D 相机做视觉里程计与建图（ORB-SLAM 系列为代表）；优点是不需要激光雷达、能利用语义信息，短板是对光照变化、弱纹理、快速运动敏感，且尺度估计需要额外约束。
- **激光—视觉—惯性融合路线**：把激光、相机、IMU、轮速计放在同一个估计框架里（滤波或图优化），互相补短板；这是目前鲁棒性最好的方向，但标定、时间同步与调参成本最高（融合算法见 58 篇）。

导航与规划的主流路线有两层：

- **导航栈路线（Nav2）**：规划器服务器（全局规划）+ 控制器服务器（局部跟随）+ 行为服务器（恢复行为）+ 行为树编排；插件化，换规划器或控制器不用改栈。这是移动机器人导航的工程主流。
- **机械臂规划路线（MoveIt 2）**：采样规划（OMPL 库）+ 碰撞检测 + 轨迹时间参数化；规划结果是关节轨迹，再交给 ros2_control 执行。近年研究把学习式规划（从演示或仿真中学路径先验）与采样规划结合，以缩短规划时间。

## 4. 系统架构

一个典型的移动机器人导航系统（以 Nav2 为例）由以下部分组成：

- **感知输入**：激光扫描、点云、里程计、IMU、TF 变换树（map → odom → base_link，见 56 篇）。
- **定位**：AMCL（已知地图）或 SLAM Toolbox（建图或定位模式），输出 map → odom 变换。
- **地图服务**：map_server 提供保存的占用栅格地图；建图阶段由 SLAM Toolbox 实时发布地图。
- **代价地图**：全局代价地图（整张地图、静态障碍物为主）与局部代价地图（机器人周围小窗口、实时障碍物为主），各自由插件层叠加。
- **规划器服务器**：全局规划器（如 NavFn、Smac Planner 2D）在全局代价地图上算路径。
- **控制器服务器**：局部控制器（如 Regulated Pure Pursuit、DWB）在局部代价地图上跟随路径、输出速度指令，并做碰撞前瞻刹车。
- **行为服务器与行为树**：导航行为树编排“规划—跟随—失败恢复”（后退、原地旋转、清代价地图、重规划）；恢复行为的设计质量，决定了机器人被卡住时是自己脱困还是等人来救。
- **机械臂侧（MoveIt 2）**：场景表示（碰撞物体、机器人模型）+ 规划请求（目标姿态、约束）+ 规划器（OMPL）+ 轨迹执行（ros2_control）；与导航栈共享 TF 与 ros2_control，但规划空间完全不同。

## 5. 代表性实现与开源项目

只列真实存在的项目，不写未核实的性能排名：

- **Nav2（Navigation2）**：ROS 2 官方导航框架，ROS 1 导航栈的继任者，行为树编排、插件化组件；是移动机器人导航的工程主流，不是“唯一正确”的导航方案。
- **SLAM Toolbox**：ROS 2 官方支持的 2D 激光 SLAM 库，模式有在线异步（online_async）、在线同步（online_sync）、离线（offline），以及定位模式（localization）；建图与定位可共用同一套图优化后端。
- **AMCL（nav2_amcl）**：Nav2 自带的粒子滤波定位包，需要预先建好的地图；适合地图已固定、环境变化不大的场景。
- **ORB-SLAM3**：视觉—惯性 SLAM 的代表性开源系统，支持单目、双目、RGB-D 与 IMU 融合；研究引用率高，但工程落地需要针对具体相机与场景调参。
- **MoveIt 2**：ROS 2 机械臂运动规划框架，集成 OMPL 采样规划库与碰撞检测。
- **OMPL（Open Motion Planning Library）**：采样式运动规划算法库（RRT、PRM 及其变体），被 MoveIt 2 等框架集成。
- **Cartographer（谷歌）**：2D/3D 激光 SLAM 系统，图优化与回环检测的代表性实现；ROS 2 侧的维护状态以官方发布为准（待核实）。

## 6. 关键论文与标准

- Leonard 与 Durrant-Whyte 的 SLAM 奠基性工作（1991 年前后）：同步定位与建图问题的数学表述。
- Grisetti 等关于图优化 SLAM 的论述（g2o 框架论文，2011）：把 SLAM 表示为图优化问题，是现代 SLAM 的标准框架。
- Macenski 等 Nav2 相关论文与文档：Nav2 架构（行为树、插件化、生命周期）的系统论述。
- 标准：REP-105（ROS 坐标系约定，map/odom/base_link 的含义）；暂无统一的导航性能国际标准——“导航成功率”在不同实验室、不同地图、不同障碍物密度下不可直接比较。

## 7. 当前实验结果

本节不写横向成功率数字：不同论文的地图、机器人、障碍物设置与评判标准各不相同，数字脱离条件没有可比性。只写经核查的定性结论与带条件的事实：

- Nav2 + SLAM Toolbox + AMCL 的组合，在室内平坦结构化环境（办公室、仓库、实验室）已被大量项目验证为“能跑通”的工程组合；验证主体是社区项目与产品原型，不是统一基准。
- 激光 SLAM 在长走廊、空旷大厅、玻璃幕墙环境会出现退化与误匹配，这是几何特征不足的固有问题，不是某个库的 bug；缓解靠多传感器融合（见 58 篇）与语义信息。
- 视觉 SLAM 在光照稳定、纹理丰富的室内环境表现好，在弱光、弱纹理、快速运动下退化明显；视觉与激光的取舍取决于部署环境，不是“谁更好”的通用结论。
- 机械臂采样规划在 6–7 自由度、无复杂约束的场景已是工程常规；带复杂约束（保持杯口朝上、避开动态障碍物、双臂协调）的规划仍是研究问题，规划时间与成功率随约束复杂度快速恶化。

## 8. 技术瓶颈

- **动态环境**：行人、叉车、移动的货架使地图与定位假设（静态世界）失效；动态物体检测、跟踪与预测是导航鲁棒性的关键缺口。
- **长程与大规模**：地图越大，回环检测与图优化的计算与内存代价越高；多楼层、多建筑的定位与导航需要分层地图，目前缺乏统一方案。
- **退化场景**：长走廊、空旷地、重复结构（停车场、货架区）会让激光与视觉同时退化；单一传感器路线在这些场景必然失手。
- **人机共存**：导航不仅要“不撞上”，还要“不吓人、不挡路、符合社会规范”（如靠右行走、保持社交距离）；社会导航（social navigation）是研究热点，尚无统一评判标准。
- **规划与执行的落差**：全局路径在地图上可行，不等于底盘动力学上可执行（转弯半径、加速度限制、地面摩擦）；局部控制器与全局规划器的参数不匹配，是现场调试最耗时的部分。
- **机械臂约束规划**：带任务约束的运动规划（方向约束、力约束、双臂协调）仍难做到“又快又可靠”，学习式方法有潜力但可验证性不足。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：室内结构化环境的激光导航与机械臂无约束规划已有大量工程验证，但动态环境、大规模场景、退化场景与带约束规划仍是开放问题，离“任意环境开箱即用”还有距离。

## 10. 未来研究问题

- **已有研究在做**：语义 SLAM（把“这是门、这是货架”写进地图，让规划能用语义推理）；动态 SLAM（把动态物体从地图中分离、跟踪与预测）。
- **已有研究在做**：学习式规划与经典规划的结合——用学习给采样规划提供先验分布，缩短规划时间而不牺牲可验证性。
- **已有研究在做**：社会导航的评判标准与数据集，让“导航得体”可度量。
- **本文推测**：导航的突破口可能不在“更好的规划算法”，而在“更好的地图表示”（语义、分层、动态更新）；检验标准是语义地图是否在真实部署中稳定降低导航失败率。
- **本文推测**：机械臂规划可能走向“采样规划保底、学习方法加速”的混合常态，而不是学习完全取代采样；检验标准是混合方法是否在带约束任务上同时做到规划时间短与成功率高。
