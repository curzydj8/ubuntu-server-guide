# 下一代身份、命名和服务发现

## 1. 研究问题

今天的互联网把三件事绑在一起又互相脱节：名字（DNS 域名）、地址（IP 地址）、身份（证书与账号）。问题有三：第一，名字与地址分离——DNS 把名字解析成地址，但网络层只认地址不认名字，应用层的名字语义在网络层丢失；第二，身份依赖中心——证书靠 CA 层级签发，账号靠平台持有，主体不能自带身份；第三，发现依赖中心——找服务要靠 DNS、注册中心或平台目录，去中心化与边缘场景下没有可用的发现机制。

下一代身份、命名与服务发现要回答的问题是：能不能把“名字、地址、身份”重新分工——名字直接可路由、身份自带可验证、发现不依赖单一中心——同时与现有 DNS/IP 互联网共存？

## 2. 基础理论

- **DNS 与 WebPKI**：DNS 分层解析、DNSSEC 签名、CA 证书链，是今天名字与身份的事实标准；其信任根是 ICANN 根区与商业 CA，层级式信任。
- **DID（去中心化标识符）**：W3C 标准化（DID Core）的自带身份机制——标识符形如 did:方法:特有串，解析到 DID 文档（含公钥、服务端点）；主体自己生成标识符，不依赖中心注册机构。
- **NDN（命名数据网络）**：以名字而非地址路由的未来互联网架构——兴趣包按名字请求数据，数据包按名字返回并签名；网络层直接认名字，缓存是网络原生能力。
- **SCION**：面向域间路由的未来架构——报文携带路径（发送方选路），自治域组成信任域，替代 BGP 的“默认信任邻居宣告”模型。
- **服务发现**：DNS-SD/mDNS（局域网）、CoAP 资源目录、NDN 的 NDNSD（基于数据同步的分布式发现）等机制，解决“局域网/边缘网内找服务”的问题。

## 3. 技术路线

- **DID 与可验证凭证路线**：主体自带 DID，凭证由签发方签名、持有方出示、验证方核验；适用于个人身份、设备身份、组织身份；难点是 DID 方法碎片化（方法众多、互通差）、密钥丢失恢复、凭证吊销与隐私（凭证出示会泄露关联信息，需选择性披露与零知识证明）。
- **NDN 名字路由路线**：名字分层（如 /edu/abc/library/printer1），路由器按名字转发兴趣包、缓存数据包、签名验证数据；优势是内容验证内生、多播与缓存天然；难点是名字空间治理、路由表规模、与 IP 网的互通（隧道、网关、混合部署）。
- **SCION 路径感知路由路线**：发送方在报头中选定自治域路径，路径可验证、防劫持；由 ETH Zürich 团队提出，Anapaya 等公司推进商用，学术上与 ICN/NDN 的结合（如 ICN+SCION 全球名字服务）正在研究中。注意：SCION 是研究与早期商用架构，不是互联网的替代标准。
- **RHINE 等 DNS 改进路线**：针对 DNS 的已知弱点（如上级域可覆盖下级域记录、DNSSEC 的信任链问题）做改进的名字解析系统；代表下一代命名研究中“改良 DNS”的一支，与“重做命名”（NDN）相对。
- **分布式服务发现路线**：NDNSD 用 NDN 数据同步协议在节点间同步服务信息，实现无中心发现；局域网侧 mDNS/DNS-SD 已是成熟应用（打印机、智能家居发现）；广域无中心发现仍是研究问题。
- **AI 智能体身份与发现（新兴）**：智能体需要“按能力发现、按委托授权”的身份与发现机制，DNS/WebPKI 是为人设计的（人工管理、会话粒度），智能体间高速委托需要新的命名、能力描述与信任模式；NDNComm 2026 等学术讨论已提出这一问题，但尚无标准答案。

## 4. 系统架构

按“名字—身份—发现”三分，下一代系统大致由以下部分组成：

- **名字层**：NDN 名字、SCION 路径、DNS 名字三类名字体系并存，网关与隧道负责互通。
- **身份层**：DID 文档解析（DID 解析器）、可验证凭证签发/出示/核验、密钥管理与恢复机制。
- **发现层**：局域发现（mDNS）、目录服务（CoAP 资源目录）、分布式同步发现（NDNSD）、搜索引擎式发现（复杂匹配仍需索引服务）。
- **信任层**：信任模式（trust schema）——谁可以为哪个名字空间签名、哪个凭证可信；NDN 的信任模式与 DID 的信任注册表是两种不同的信任表达。
- **互通层**：DNSLink（DNS 指向 IPFS/DID 内容）、DID 与 WebPKI 的桥接、SCION 与 BGP 的共存网关。

## 5. 代表性实现与开源项目

- **W3C DID 生态**：DID Core 规范已发布，多种 DID 方法（如 did:web、did:key、did:ion 等）各有实现；方法碎片化与互通性以 W3C 与 DIF（Decentralized Identity Foundation）官方发布为准（待核实）。
- **NDN 项目**：NDN 官方实现（NFD 转发守护进程、ndn-cxx 库）与 NDN 试验网（testbed）是研究社区的主要平台；NDNSD 是 NDN 服务发现的研究原型。
- **SCION 开源实现**：SCION 协议的开源实现与试验部署存在，商用推进以 Anapaya 等公司官方发布为准（待核实）。
- **mDNS / DNS-SD**：Avahi、Bonjour 等实现已是成熟应用，智能家居与打印机发现的事实标准。
- **尚无统一的下一代命名商用系统**：DID、NDN、SCION 均未进入主流互联网基础设施；DNS 仍是唯一全球商用的名字系统。

## 6. 关键论文与标准

- W3C DID Core：去中心化标识符核心规范（W3C 推荐标准）。
- NDN 架构论文：Zhang 等人《Named Data Networking》（2014 年，ACM SIGCOMM CCR）是 NDN 的架构总述。
- SCION 专著：Perrig 等人《The Complete Guide to SCION》（Springer，2022 年）。
- RHINE 论文：Duan 等人《RHINE: Robust and High-performance Internet Naming with E2E Authenticity》（NSDI 2023）。
- NDNSD 论文：Dulal 与 Wang《NDNSD: Service Publishing and Discovery in NDN》（NDN 相关会议论文，具体年份以论文原文为准，待核实）。
- 暂无统一的下一代身份与命名标准：DID 方法、NDN 名字空间、SCION 路径格式各有标准，彼此之间无统一互通标准。

## 7. 当前实验结果

本节不写部署规模数字（试验网规模易变且口径不一）。只写经核查的定性结论：

- DID 已有 W3C 标准，但方法碎片化与互通性仍是落地障碍；个人身份场景的试点多于规模商用。
- NDN 在试验网与学术部署中验证了名字路由、缓存与签名数据的可行性，但路由表规模、名字治理与 IP 互通仍是规模化障碍。
- SCION 在研究网与部分商用试点中验证了路径感知路由的可行性，但全球部署仍远未实现。
- mDNS/DNS-SD 是唯一已规模商用的“下一代发现”机制，但其范围限于局域网。

## 8. 技术瓶颈

- **迁移成本**：DNS/IP/BGP 是全球基础设施，任何新命名与路由方案都必须回答分阶段迁移与共存问题；“推倒重来”在政治与经济上都不可行。
- **名字空间治理**：谁分配名字、谁解决名字冲突、名字是否可读（人类可读名字与自认证名字不可兼得）——这是命名系统的根本张力。
- **信任模型碎片化**：DID 方法、NDN 信任模式、SCION 信任域各有信任根，彼此不互通；“统一信任”本身就是未解问题。
- **密钥管理**：DID 的密钥丢失恢复、设备更换、凭证吊销，对普通用户门槛高；丢密钥等于丢身份，是自带身份的阿喀琉斯之踵。
- **隐私**：名字本身泄露语义（NDN 名字是明文语义），DID 文档与凭证出示泄露关联；隐私保护需要额外的混淆与选择性披露机制。
- **性能**：名字路由的查表、签名验证的开销，在高速转发面是瓶颈；NDN 的逐包签名验证成本高于 IP 转发。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：DID 有标准但落地碎片化，NDN/SCION 有试验网但无主流部署，唯一规模商用的是局域网发现（mDNS），整体远未达到工程发展中的主流门槛。

## 10. 未来研究问题

- **已有研究在做**：DID 方法互通与密钥恢复；NDN 与 SCION 的结合（全球名字服务）；AI 智能体的身份、能力描述与发现机制。
- **已有研究在做**：名字隐私（加密名字、混淆名字）与可验证凭证的选择性披露。
- **本文推测**：下一代身份最可能先落地的场景是设备与组织身份（物联网、供应链），而非个人身份——因为设备身份的密钥管理可由运营方兜底；检验标准是主流物联网平台是否默认采用 DID 或同类自带身份。
- **本文推测**：命名层的变革可能比路由层更慢，因为名字涉及全球治理与商标、主权争议；检验标准是 ICANN/ITU 是否启动下一代命名的正式程序，而非学术试验。
