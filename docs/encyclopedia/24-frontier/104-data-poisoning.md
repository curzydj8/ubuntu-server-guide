# 数据投毒和模型窃取

## 1. 研究问题

模型的行为由训练数据与权重决定，而现代训练数据往往来自公开网络、第三方数据集、外包标注与用户反馈——来源多、规模大、逐条人工审查不现实。如果训练数据中混入了有意构造的异常样本，模型可能在正常任务上表现正常，却在特定条件下表现出训练者不希望的行为；这就是数据投毒的防御视角。另一方面，部署后的模型通过 API 对外提供服务，查询者可能通过大量查询推断模型行为、还原训练信息或复制模型功能；这就是模型窃取与隐私推断的防御视角。两类问题共享一个前提：数据与模型都是资产，都需要来源可信与访问控制。

本篇只讲原理、风险、检测、防御与评估。本篇不写投毒样本的构造方法，不写模型窃取的操作步骤与查询策略；拿不准的写法一律不写。

合法研究范围声明：防御研究只在自有系统、授权系统或隔离靶场上进行；未授权测试他人系统是违法行为，本文不提供相关指导。

## 2. 基础理论

- **数据投毒（data poisoning）**：在训练阶段引入异常数据，改变模型学到的行为；NIST AI 100-2e2025 将其编为 NISTAML.010，并区分预训练语料投毒与指令微调、偏好数据投毒等不同环节。
- **后门（backdoor）**：投毒的一种表现形态——模型在普通输入上正常，只在特定触发条件下偏离预期；防御上它比“整体性能下降”更难发现，因为常规精度指标可能完全看不出异常。
- **模型提取（model extraction）**：通过查询部署模型的输入输出，推断或复制其功能；NIST AI 100-2e2025 将其编为 NISTAML.031。
- **成员推断与数据重建**：通过查询判断某条记录是否在训练集中，或从模型输出中还原训练数据的片段；属于隐私攻击家族，与模型提取并列讨论。
- **数据来源可信**：数据集的版本、哈希、采集方式、许可与处理链路都应有记录；没有来源记录的数据集，其风险无法评估。

## 3. 技术路线

- **来源治理路线**：数据集与模型权重入库时登记来源、版本与哈希；第三方数据与模型只从可信渠道获取，变更即重新登记；高风险来源的数据先隔离、后评估。
- **数据清洗与异常检测路线**：在训练前对数据做统计与语义层面的异常筛查——重复样本、标签不一致、分布突变、来源集中的异常簇都值得人工复核；筛查的重点是“发现值得怀疑的数据”，而不是“自动判定某条数据一定有毒”。
- **训练过程防护路线**：限制单批、单来源数据对模型的影响权重；保留训练过程记录，使问题模型可以追溯到可疑数据批次；关键模型训练后做针对性行为评估（见 111 篇）。
- **查询侧防护路线**：对推理 API 做身份认证、速率限制、配额管理与查询模式监控；对输出做必要的脱敏与截断；高价值模型的查询日志应可审计。

## 4. 系统架构

一个覆盖数据与模型资产的防护系统通常包括：

- **数据登记库**：每个数据集版本的来源、哈希、许可、处理脚本与负责人。
- **训练流水线**：数据清洗、异常筛查、训练记录、模型版本管理串联，任何一步的产物都可追溯。
- **模型仓库**：模型权重与配置的签名与版本管理；加载前校验签名，签名不符即拒绝加载（与 109 篇的供应链签名衔接）。
- **推理网关**：认证、限流、配额、查询审计；异常查询模式（如短时间内高度相似的大量查询）触发告警或限流。
- **评估与响应**：定期对已部署模型做行为评估，发现异常即按“定位可疑数据—复核—重训或下线”的流程处置。

## 5. 代表性实现与开源项目

只列防御侧的真实项目与机制：

- **数据集与模型托管平台的完整性机制**：主流模型托管平台提供文件哈希、提交记录与模型卡（model card）等来源信息；具体字段以平台官方文档为准（待核实）。
- **模型签名与 provenance 工具**：Sigstore 等开源签名生态可用于为模型产物签名（见 109 篇）；签名只能证明“产物未被篡改且来自某签名方”，不能证明“训练数据本身无毒”，两者不可混淆。
- **差分隐私与数据脱敏技术**：在训练与发布环节降低单条记录被还原的风险；属于隐私保护技术，适用性需按场景评估（见 110 篇的相关讨论）。
- 尚无“自动判定数据集是否被投毒”的通用可靠产品：现有筛查多为异常提示 + 人工复核，完全自动化判定仍是研究问题。

## 6. 关键论文与标准

- NIST AI 100-2e2025（2025 年 3 月）：NISTAML.010 数据投毒、NISTAML.031 模型提取等类别。
- Biggio 等关于支持向量机投毒的早期工作（2012 年前后）：投毒研究在深度学习普及前已存在；具体标题与年份以原文为准（待核实），本篇不展开其方法细节。
- MITRE ATLAS：数据投毒、模型提取等技术的战术归类与公开案例索引。
- 暂无统一的数据投毒检测强制标准：检测方法与阈值以各组织内部制度与公开研究为准（待核实）。

## 7. 当前实验结果

本节不写脱离测试条件的“投毒比例—效果”数字：投毒效果高度依赖模型、任务、数据规模与触发条件，跨研究数字不可直接比较。只写定性结论：公开研究一致表明，少量异常数据即可在特定条件下改变模型行为，而常规精度指标未必能发现这种改变；因此“训练集精度正常”不能作为“数据干净”的证据，必须辅以来源治理与针对性行为评估。具体的公开案例细节未系统核对，未写入正文。

## 8. 技术瓶颈

- **检测的根本困难**：投毒样本在单条层面可能与正常样本难以区分，尤其当投毒者模仿正常数据分布时；检测往往只能在聚合层面发现异常簇。
- **规模与成本**：现代训练数据以 TB 计，逐条审查不可行，自动化筛查的误报又会淹没人工复核。
- **查询防护与可用性的权衡**：限流过严影响正常用户，过松则给批量查询留出空间；按身份、按场景分级限流是常见折中，但调校依赖业务数据。
- **隐私与安全的交叉**：防提取的输出截断可能损害正常用户的体验与调试能力；需要按模型价值与场景分级处理。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：来源登记、签名、限流等工程手段已可用，但投毒的可靠自动检测、后门的行为级发现与提取风险的量化评估仍主要停留在研究阶段，缺乏统一基准。

## 10. 未来研究问题

- **已有研究在做**：数据 provenance 的标准化——能否像软件物料清单一样，给数据集一份机器可读的来源清单。
- **已有研究在做**：后门行为的评估方法——不依赖已知触发条件，如何发现“只在特定条件下偏离”的模型。
- **已有研究在做**：提取风险的度量——用查询预算与输出信息量刻画模型被复制的难度。
- **本文推测**：数据治理可能先以“高价值模型强制登记来源与签名”的合规要求落地，再逐步扩展到全部模型；检验标准是主流模型托管平台是否把来源登记设为默认必填。
