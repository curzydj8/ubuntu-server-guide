# RVA23 与扩展规范

> 本篇是 [RISC-V 生态总览](04-riscv-ecosystem.md) 的下级专题，只讲 RVA23 这一条兼容性基线及其背后的扩展规范机制，不重复总览的生态结构、厂商与发行版内容。读本篇前建议先读总览第 2 节对 profile 的定义。

## 1. 研究问题

RISC-V 允许厂商自由实现扩展，这带来一个直接问题：如果每家芯片实现的扩展子集都不一样，发行版与应用软件要怎么做到“编译一次、到处运行”？RVA23 要解决的正是这个问题：为 64 位应用处理器规定一套“必须实现哪些扩展”的基线，让面向该基线编译的软件能在不同厂商的合规芯片上运行。

这个问题与“指令集本身好不好”是两个层面。指令集定义了可以有哪些指令；profile 定义了某一类处理器必须提供哪一部分，从而把“开放实现”与“软件可移植”结合起来。没有 profile，开放会退化为碎片化；有了 profile，发行版才敢把某个基线定为最低支持目标。

## 2. 基础理论

- **基础 ISA 与扩展**：RISC-V 的基础整数指令集（如 RV64I）之上可叠加标准扩展，单字母扩展（如 M、A、F、D、C、B、V）与 Z 字母开头的扩展（如 Zcb、Zfa）是不同的命名类别，具体每个扩展的语义以其批准规范文本为准。
- **Profile（兼容性基线）**：一个有名字、有版本的强制与可选扩展组合。RVA 中的 A 表示应用处理器（Application），23 表示该系列的年份代号，U64 表示用户态 64 位，S64 表示管理态 64 位；S64 在 U64 的基础上追加管理态扩展。
- **批准（ratification）**：扩展或 profile 只有走完 RISC-V International 的审查与投票流程、成为正式标准后，才叫“已批准”；批准前的草案版本不保证稳定，软件不应把草案行为当作承诺。
- **扩展类别**：profile 文本把扩展分为强制（mandatory）、发展选项（development option，意在未来版本转为强制的候选）、本地化选项与扩展选项等；不同类别对软件的承诺强度不同，读清单时必须区分，不能把“可选”读成“保证有”。

## 3. 技术路线

RVA23 的基线内容按“从 RVA22 继承 + 本代新增 + 本代删减”三条线理解：

- **继承线**：RVA22 已强制的扩展在 RVA23 中继续强制，构成稳定底座，包括整数乘除（M）、原子操作（A）、单精度与双精度浮点（F、D）、压缩指令（C）、位操作（B），以及主存物理属性（PMA）相关的一组扩展。
- **新增线**：本代最关键的变化是向量扩展（V）由 RVA22 的可选转为 RVA23 的强制，并随之强制一批向量配套扩展（见第 4 节）；同时新增条件操作、指针掩码等扩展，补齐应用处理器常见的编程模型缺口。
- **删减与替代线**：标量密码扩展（Zkn、Zks）在 RVA23 中不再作为选项，替代路线是向量密码扩展（Zvkng、Zvksg）作为本地化选项。逻辑是：既然向量已是强制，密码运算走向量路线更合理，软件不必再为“有无标量密码”做两套分支。但这不等于“所有 RVA23 芯片都有向量密码”——本地化选项仍是可选的，读清单时要以官方 profile 文本为准。

## 4. 系统架构

RVA23 由两个互相嵌套的 profile 组成，基线是小端序的 RV64I：

- **RVA23U64（用户态）**：面向用户程序的保证。强制扩展除继承的 M、A、F、D、C、B 外，新增的核心是 V（完整向量扩展），配套 Zvfhmin（向量半精度浮点最小集）、Zvbb（向量位操作）、Zvkt（向量常数时间操作），以及标量侧的 Zfhmin、Zicond（条件置零）、Zimop、Zcmop、Zcb、Zfa、Zawrs 与指针掩码 Supm，另有一组主存 PMA 扩展（Ziccif、Ziccrse、Ziccamoa、Zicclsm 等）。各扩展的精确版本与可选细节以官方发布为准（待核实）。
- **RVA23S64（管理态）**：在 U64 全部强制内容之上，追加管理态扩展，包括指令屏障（Zifencei）、特权规范版本要求（Ss1p13）、裸页表与地址翻译相关扩展（Svbare、Sv39、Svade、Svnapot）、定时器与性能计数相关扩展（Sstc、Sscofpmf）、指针掩码管理态部分（Ssnpm）以及增强的管理程序支持（Sha）。管理态清单较长且版本敏感，本文只列类别与代表性扩展名，完整清单以官方文本为准（待核实）。
- **发展选项**：RVA23U64 列出的发展选项包括 Zabha（字节与半字原子操作）、Zacas（比较并交换）与 Ziccamoc（主存比较并交换的 PMA 支持）。它们的含义是“向实现者发出信号：现在设计硬件时应考虑加入，未来版本可能转为强制”，而不是“现在已强制”。把发展选项写成已强制，是读 RVA23 时最常见的误读。
- **与 RVB23 的区别**：RVB23 是面向另一类应用处理器市场的并行系列，其向量扩展为可选，适合更小、更便宜的设计；RVA23 与 RVB23 的取舍不在本篇展开，选型时以官方 profile 文本与发行版基线声明为准。

## 5. 代表性实现与开源项目

本节只列规范与实现载体，不列芯片性能排名：

- **RISC-V International 发布的 profile 规范仓库**：riscv-profiles 仓库中的 rva23-profile.adoc 是 RVA23 的规范文本来源（经多个二手解读页引用，原文以仓库当前批准版本为准）。
- **GCC 与 LLVM 工具链**：面向 RVA23 编译时，工具链需支持该基线的扩展组合；具体哪个工具链版本开始完整支持 RVA23，以各工具链发布说明为准（待核实）。本篇不给出本地未实测的工具链命令示例。
- **Linux 内核与发行版**：发行版把 RVA23 定为 riscv64 最低基线，意味着新版发行版二进制默认假定 RVA23 保证存在；具体哪个发行版版本切换基线，以各发行版官方发布为准（待核实），本篇不转载二手消息中的切换时间点。
- **尚无统一结论**：市面上自称符合 RVA23 的芯片与开发板，其合规程度需以厂商声明与兼容性测试结果为准；本篇不做合规认证，也不列未经核实的型号清单。

## 6. 关键论文与标准

- RISC-V Profiles 规范，RVA23 章节（riscv-profiles 仓库，批准状态文本）：RVA23U64 与 RVA23S64 的强制、发展选项与本地化选项清单的权威来源；版本号与批准细节以仓库文本为准。
- RISC-V International 规范开发生命周期说明（riscv.org 规范开发页）：从提议、规划、开发、冻结、公开评审到批准的流程总述。
- RISC-V 技术委员会政策与程序文件：任务组阶段、架构评审、公开评审与批准投票的规则细节；具体条款以该文件当前版本为准。
- 暂无单一论文可作为本篇理论来源：profile 是标准工程产物，不是某一篇论文的结果；本篇事实主张以标准组织官方发布为准。

## 7. 当前实验结果

本节不写性能数字：RVA23 是兼容性基线而非某一颗芯片，没有统一的测试条件可供横向比较，任何“RVA23 芯片比上一代快多少”的数字都缺来源与测试条件三件套，故不写。只写两条经核查的定性事实：

- RVA23 已批准（ratified），且向量扩展由可选转为强制，是相对 RVA22 的结构性变化；这一判断有规范文本与多个解读页交叉印证。
- 发行版与硬件对 RVA23 的覆盖仍在追赶中：有公开报道称硬件与测试覆盖是剩余短板，但具体覆盖率数字未见可核查的统一口径，本篇不转载。

## 8. 技术瓶颈

- **基线抬升的成本**：强制向量意味着面积与功耗门槛上升，小型设计若不想要向量，只能走 RVB23 等其他系列或停留在旧基线，基线统一与产品分层之间存在张力。
- **清单版本敏感**：扩展各自有版本，profile 引用的是特定版本组合；工具链、内核与芯片三方对同一扩展名理解的版本不一致时，仍会出现“名义合规、实际跑不通”。
- **发现机制缺口**：软件如何可靠地发现一颗芯片实际实现了哪些可选扩展与发展选项，依赖发现机制与固件描述；发现机制不完善时，可选扩展等于不可用。
- **批准节奏与市场节奏错位**：标准批准、芯片流片、发行版切换三者的时间表不同步，基线宣布后仍需一段时间才能在可买到的硬件与可安装的发行版上同时落地。
- **未来基线的不确定性**：发展选项是否、在何时转为强制，取决于后续 profile 的官方发布；在官方发布前，任何“下一代一定强制某某扩展”的说法都是推测，本篇不采信。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：RVA23 作为标准文本已批准、向量强制这一核心变化已确立，但合规硬件的覆盖、工具链与发行版的完整切换仍在推进中，尚未达到“买到的主流硬件与发行版默认就是 RVA23”的成熟应用水平。

## 10. 未来研究问题

- **已有研究在做**：后续 profile 如何把发展选项（Zabha、Zacas 等）转为强制，以及矩阵类扩展是否进入未来应用处理器基线；两者均以官方发布为准，当前状态为进行中、未定论。
- **已有研究在做**：兼容性测试与发现机制的完善，让“声称合规”可验证、可比较。
- **本文推测**：RVA23 的真正检验不在批准那一刻，而在主流发行版把 RVA23 作为默认基线、且市面主流开发板均可跑该基线发行版的那一天；检验标准是发行版官方基线声明与可买到的硬件清单同时成立，而非标准文本本身。
- **本文推测**：未来基线之争可能从“要不要向量”转向“向量之上还要不要矩阵、机密计算等扩展”，基线清单会继续变长，小型设计的分层系列因而长期存在。
