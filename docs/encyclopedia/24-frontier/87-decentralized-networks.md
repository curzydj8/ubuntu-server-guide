# 去中心化网络和 P2P

## 1. 研究问题

今天的互联网应用大多是“客户端—服务器”结构：数据存在中心服务器上，服务由中心运营方控制。这一结构简单、高效，但有三类代价：单点故障（服务器宕机服务即停）、单点控制（运营方可删帖、封号、改规则）、单点审查与单点数据泄露。去中心化网络要回答的问题是：能不能让节点既是客户端又是服务器，数据按内容寻址、服务由节点共同维持，从而去掉单点——同时不丢掉可用性、性能与可治理性？

本篇讲网络结构与协议机制，不讲代币经济与具体区块链项目；身份与命名侧见 [下一代身份、命名和服务发现](88-nextgen-identity.md)。

## 2. 基础理论

- **内容寻址**：按内容的哈希值寻址（而非按服务器位置寻址）；同一内容哈希相同，可验证、可去重、位置无关。
- **分布式哈希表（DHT）**：Kademlia 等 DHT 把键空间按 XOR 距离划分到节点上，查找复杂度约 O(log N)；是 P2P 网络“找数据、找节点”的基本机制。
- **Merkle DAG**：内容分块后用哈希链接成有向无环图，改一块则根哈希变，天然支持版本与验证。
- **Gossip 协议**：节点向随机邻居传播消息，靠冗余换可靠性，是 P2P 消息广播的常用机制。
- **NAT 穿透**：打洞（hole punching）、STUN/TURN、中继，是 P2P 节点在家庭 NAT 后的互联基础；穿透失败率直接影响网络可用性。

## 3. 技术路线

- **文件共享 P2P 路线**：BitTorrent 是最成功的 P2P 协议之一——文件分块、并行下载、按贡献激励（tit-for-tat）；它证明了 P2P 在带宽分发上的效率，但也暴露了“做种激励衰减、内容持久性靠志愿”的问题。
- **内容寻址存储路线**：IPFS 把文件分块、内容寻址（CID）、Merkle DAG、Bitswap 块交换、Kademlia DHT 组合成分布式文件系统；IPNS 提供可变指针（把可变名字指向最新 CID）。关键取舍：内容本身可验证，但“谁长期保存”需要 pin（固定）或激励层，IPFS 本身不承诺持久性。
- **模块化 P2P 协议栈路线**：libp2p（源自 IPFS 网络层，现为独立项目）把传输（TCP/QUIC/WebSocket）、加密（Noise/TLS）、发现（DHT/mDNS）、路由（GossipSub）做成可插拔模块；Ethereum、Polkadot 等网络也用 libp2p，说明它已是 P2P 领域的事实标准栈之一。
- **网状网络（Mesh）路线**：节点间直接组网、多跳转发，用于社区网络、灾后应急、偏远覆盖；无线 Mesh 的容量随跳数下降、路由开销大，是其规模上限。
- **匿名覆盖网络路线**：Tor（洋葱路由）、I2P 用多层加密与多跳中继隐藏通信双方；代价是延迟高、带宽低，适合隐私场景而非通用宽带。
- **联邦制路线**：介于中心化与纯 P2P 之间——多个独立运营的服务器互联互通（如 ActivityPub 联邦、Matrix 联邦）；它去掉了“单一运营方”，但每个实例仍是中心节点；严格说它是去中心化的折中形态，本篇把它列为对照而非 P2P 本身。

## 4. 系统架构

一个典型的内容寻址 P2P 系统（如 IPFS/libp2p）由以下部分组成：

- **节点**：每个节点有 PeerID（公钥派生）、多地址（监听地址集合）。
- **传输与加密**：TCP/QUIC/WebSocket 传输 + Noise/TLS 加密 + 协议协商。
- **发现**：引导节点（bootstrap）、mDNS（局域网发现）、Kademlia DHT（广域发现）。
- **路由与交换**：DHT 查“谁有这块内容”，Bitswap 按 want-list 交换块，GossipSub 做消息广播。
- **命名**：IPNS（可变指针）、DNSLink（DNS 指向 IPFS 内容）等桥接机制，解决“内容不变、名字要变”的问题（命名深度见 [下一代身份、命名和服务发现](88-nextgen-identity.md)）。
- **持久性层**：pin、集群（IPFS Cluster）、激励层（Filecoin 等存储市场）——注意：激励层是独立项目，不是 IPFS 本身的承诺。

## 5. 代表性实现与开源项目

- **BitTorrent**：文件共享 P2P 的代表协议，客户端与 Tracker/DHT 生态成熟。
- **IPFS / Kubo / Helia**：内容寻址分布式文件系统的代表实现（Kubo 为 Go 实现、Helia 为 JS 实现）；网关（公共网关）是 IPFS 与普通浏览器之间的桥，但网关本身是中心化瓶颈。
- **libp2p**：模块化 P2P 协议栈，Go、Rust、JS 等多语言实现。
- **Tor / I2P**：匿名覆盖网络的代表实现。
- **Dat / Hypercore、SSB（Secure Scuttlebutt）**：面向离线优先、社交场景的 P2P 协议探索，规模小于 IPFS，但设计思路（追加日志、社交图谱复制）有参考价值。

## 6. 关键论文与标准

- Kademlia 论文：Maymounkov 与 Mazières《Kademlia: A Peer-to-Peer Information System Based on the XOR Metric》（2002 年），DHT 的经典设计。
- BitTorrent 协议（BEP 系列）：BEP 3（BitTorrent 协议规范）等公开规范。
- IPFS 相关论文与规范：Benet《IPFS - Content Addressed, Versioned, P2P File System》（2014 年，arXiv 论文）是 IPFS 的设计白皮书；libp2p 规范见 libp2p 官方文档。
- Tor 设计论文：Dingledine、Mathewson、Syverson《Tor: The Second-Generation Onion Router》（2004 年）。
- 暂无统一的去中心化网络标准：P2P 协议多为事实标准与项目规范，IETF 层面无统一的去中心化互联网标准。

## 7. 当前实验结果

本节不写节点数、下载速率倍数等易变数字。只写经核查的定性结论：

- BitTorrent 在带宽分发上的效率已被大规模实践验证；但其内容持久性依赖做种者志愿，冷门内容易消失。
- IPFS 的内容寻址与验证机制已被验证；但“无激励的公共 IPFS 网络能否长期保存冷门内容”仍是开放问题，pin 与激励层是补丁而非根治。
- libp2p 的模块化已被多个区块链与 P2P 项目采用，是 P2P 协议栈事实标准的有力候选。
- 网状网络在社区与应急场景有成功案例，但容量与规模上限明显，未成为通用接入网。

## 8. 技术瓶颈

- **持久性**：谁为冷门内容买单？无激励则内容随节点下线而消失，有激励则引入代币经济的复杂性与投机问题。
- **性能**：DHT 查找延迟、Bitswap 交换开销、NAT 穿透失败率，使 P2P 在交互延迟上弱于中心化 CDN。
- **可发现性**：内容寻址解决了“验证”，没解决“发现”——用户怎么知道 CID？搜索、索引、推荐仍需中心化或半中心化服务。
- **可治理性**：去中心化网络难以删除非法内容、难以执行版权与合规要求；“无法删除”既是抗审查优点，也是治理难题。
- **隐私**：DHT 查询、Bitswap want-list 会泄露节点兴趣；P2P 的开放性使流量分析更容易。
- **用户体验**：节点运维（在线率、存储、带宽）对普通用户门槛高；网关缓解了体验问题，但重新引入了中心化瓶颈。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：BitTorrent、IPFS/libp2p、Tor 均有大规模运行的网络，但去中心化网络作为“互联网的替代结构”尚未成为主流，持久性、发现与治理三大问题未解决。

## 10. 未来研究问题

- **已有研究在做**：持久性激励机制（存储市场、按需 pin 服务）；P2P 搜索与索引；NAT 穿透成功率提升（DCUtR 等打洞协议）。
- **已有研究在做**：P2P 与 CDN 的混合架构（P2P 分发 + 中心化网关兜底）；隐私保护的 DHT 查询。
- **本文推测**：去中心化网络的务实未来可能是“混合形态”而非“纯 P2P 替代互联网”——热内容走 P2P、冷内容走中心化存储、发现走搜索引擎；检验标准是主流应用是否默认启用 P2P 分发，而非仅极客工具。
- **本文推测**：治理问题可能比技术问题更难——“无法删除”与各国合规要求的冲突，最终可能迫使去中心化网络分化为“合规网关版”与“纯 P2P 版”两条线；检验标准是主要司法辖区对 P2P 网关的监管态度。
