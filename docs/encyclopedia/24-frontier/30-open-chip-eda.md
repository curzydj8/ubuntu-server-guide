# 开源芯片设计与 EDA

> 本篇是 [RISC-V 生态](04-riscv-ecosystem.md) 的三级专题，只讲开源芯片设计与 EDA 这一分支：开源处理器核、硬件生成语言与 SoC 生成器、以及从 RTL 到版图（GDS）的开源工具链与开放工艺库。生态总貌、标准组织与产业结构归总览篇，不在此重复；开发板型号与发行版支持归 [31 篇](31-boards-software-ecosystem.md)，不在此重复。

## 1. 研究问题

做一颗芯片历来有两道高门槛：第一，处理器核与 SoC 的设计本身需要大量人力；第二，EDA 工具与工艺库（PDK）通常要签保密协议、付授权费，个人与小团队很难拿到。开源芯片设计与 EDA 要回答的问题是：能不能用公开的核、公开的工具链与公开的工艺库，走完从硬件描述到可制造版图的完整流程，让“做芯片”不再只是大公司的专利？

这个问题与 RISC-V 直接相关，但不等同于 RISC-V。RISC-V 开放的是指令集标准；开源芯片设计开放的则是实现本身——核的 RTL 代码、SoC 生成器、EDA 工具与部分工艺库。两者叠加才出现今天的局面：一个人可以用开源核起步，用开源工具链做后端，再通过多项目晶圆（MPW）把设计拼到同一张晶圆上流片验证。但“能走完流程”不等于“能做出有竞争力的商用芯片”：工艺节点、签核（signoff）深度与量产良率，仍是区分教学演示与商业产品的分水岭，本篇处处守住这条线。

## 2. 基础理论

- **RTL 与综合**：RTL（寄存器传输级）是用 Verilog、SystemVerilog 或 Chisel 等语言写出的硬件描述；逻辑综合把它映射成标准单元组成的门级网表。综合的质量取决于工具与单元库，不是“代码能仿真就能流片”。
- **物理设计**：从网表到版图（GDS）的一系列步骤，包括布图规划（floorplan）、布局（placement）、时钟树综合（CTS）、布线（routing）与时序、功耗分析。这一段传统上最依赖商业 EDA 工具。
- **PDK（工艺设计套件）**：晶圆厂提供的工艺数据包，包括晶体管模型、设计规则（DRC）、版图对照（LVS）规则、标准单元库与 I/O 库。没有 PDK，版图只是一张画不出来的图；PDK 是否开放，决定了开源流程能不能落到真实制造。
- **MPW（多项目晶圆）**：多个设计共享一次流片，分摊掩模与晶圆成本的服务模式。开源芯片能“真的做出来”，很大程度上靠 MPW 把单次流片成本降到小团队可承受的范围；现行 MPW 的价格、排期与准入条件以官方发布为准（待核实）。
- **签核（signoff）**：流片前必须通过的一组最终检查，包括时序签核、DRC、LVS、功耗与可靠性检查。开源流程在成熟工艺上可以做其中大部分，但签核的完整性与晶圆厂的认可程度，是开源流程与商业流程差距最大的地方之一。

## 3. 技术路线

开源芯片设计分三条线，做法各不相同：

- **开源核路线**：直接复用已有的开源处理器核（如 Rocket、BOOM、CVA6、Ibex），把精力放在 SoC 集成与应用上。这条线最适合“先跑起来一个系统”，核本身的验证成本由社区分摊。
- **生成器路线**：不用手写固定配置的核，而是用参数化生成器（如 Rocket Chip、Chipyard）按参数生成不同配置的 SoC——核的数量、缓存大小、外设组合都可以调。生成器的代价是学习成本：使用者要理解生成器的参数模型与互连（如 TileLink），而不是只读一份固定 RTL。
- **开源后端路线**：用 Yosys 综合、OpenROAD 做物理设计、KLayout/Magic 做版图查看与检查，走完 RTL 到 GDS。这条线在 130nm、180nm 这类成熟工艺上已有完整实践；在先进工艺上，开放 PDK 本身就不存在，后端路线也就无从谈起——这是路线边界，不是工具作者努力不够。

三条线经常组合使用：生成器产出 RTL，开源后端把它做成版图，再经 MPW 流片；也可以只走前半段，在 FPGA 上验证而不流片。FPGA 验证与真实流片是两回事，本篇不把“在 FPGA 上跑通”等同于“流片成功”。

## 4. 系统架构

一条典型的开源芯片设计链路由以下部分组成：

- **前端描述层**：Chisel（基于 Scala 的硬件构造语言）或 Verilog/SystemVerilog 写出的 RTL；Chisel 代码需先生成 Verilog 才能进入常规综合流程。
- **仿真与验证层**：Verilator（开源仿真器，可把 Verilog 编译成 C++ 模型加速仿真）、Cocotb（用 Python 写测试平台的协同仿真库）、以及各核自带的测试与形式化验证手段。仿真通过不等于硬件正确，验证覆盖率是独立指标。
- **综合层**：Yosys 负责 RTL 综合与技术映射，产出门级网表；OpenROAD 本身不含综合器，公开流程中综合一律由 Yosys 承担。
- **物理设计层**：OpenROAD 负责布图、布局、时钟树与布线；OpenSTA 做静态时序分析；OpenROAD-flow-scripts（ORFS）或 OpenLane 把上述工具串成自动化流程。
- **版图与检查层**：KLayout 查看与处理 GDS，Magic 与 Netgen 做 DRC/LVS 类检查；最终 GDS 是否可制造，还要看目标 PDK 与晶圆厂的签核要求。
- **制造层**：开放 PDK 对应的晶圆厂工艺（如 SkyWater 130nm）与 MPW 服务。这一层是开源链路里最不“开源”的部分：工艺本身仍是晶圆厂的产能，开放的只是设计数据与准入方式。

各层的关系是单向流水线：前端错了，后端再好也救不回来；后端时序不过，前端功能再正确也不能流片。开源流程的价值在于这条流水线第一次可以不依赖商业授权完整跑通，代价是每一层的成熟度参差不齐。

## 5. 代表性实现与开源项目

只列真实存在的项目，不写传闻项目；每个项目一句话定位，现状细节以各自官方发布为准：

- **Chisel**：基于 Scala 的硬件构造语言，加州大学伯克利分校的硬件设计路线用它写核与生成器，再生成 Verilog 进入常规流程。
- **Rocket Chip**：伯克利的可参数化 RISC-V SoC 生成器，产出基于 Rocket 核（顺序、RV64）的 SoC；它是一个生成器，不是一颗固定芯片。
- **BOOM（Berkeley Out-of-Order Machine）**：伯克利的开源乱序超标量 RV64 核，同样用 Chisel 写成，面向高性能研究；与 Rocket 的关系是“同一生成器生态里的不同核选项”，不是同一核的两个版本。
- **Chipyard**：伯克利的敏捷硬件开发框架，把 Rocket、BOOM、加速器与仿真（含 FireSim）集成进同一套构建流程，面向 SoC 级研究。
- **CVA6（原 Ariane）**：OpenHW Group 维护的应用级开源 RISC-V 核，可跑 Linux，是开源应用核的代表性实现之一；OpenHW Group 另有 CV32E40X 等嵌入式核，本篇不展开。
- **Ibex**：lowRISC 维护的开源 RV32 嵌入式核，面向资源受限的嵌入式与安全场景，与 CVA6 的应用级定位不同。
- **OpenTitan**：开源的硅片信任根（silicon root of trust）参考设计，基于 RISC-V，用于安全启动与密码加速等安全子系统；它是一个安全子系统设计，不是通用处理器产品。
- **Yosys**：开源 RTL 综合框架，支持 Verilog 与可综合的 SystemVerilog 子集，是开源后端流程的综合环节。
- **Verilator**：开源的 Verilog/SystemVerilog 仿真与 Lint 工具，把 RTL 编译成快速模型，用于大规模回归仿真。
- **Cocotb**：用 Python 写硬件测试平台的协同仿真库，测试代码与仿真器通过接口协同运行。
- **OpenROAD 与 OpenROAD-flow-scripts（ORFS）**：开源物理设计引擎与参考流程，覆盖布图、布局、时钟树、布线与优化；ORFS 用 Makefile 把 Yosys、OpenROAD、KLayout 串成 RTL 到 GDS 的自动化流程。
- **OpenLane**：另一条开源 RTL 到 GDS 流程基础设施，同样基于 Yosys、OpenROAD、Magic、Netgen 与 KLayout；OpenLane 与 ORFS 是两条并行的开源流程，不是同一项目的两个名字。
- **SkyWater SKY130 PDK**：Google 与 SkyWater 合作开放的 130nm CMOS 工艺库，2020 年前后公开，Apache 2.0 许可，是开源流片最常用的成熟工艺；GlobalFoundries GF180MCU 是另一套经 open_pdks 支持的开放工艺（180nm 级）。先进工艺的 PDK 仍须签保密协议获取，不在开放之列。
- **Caravel 与 Efabless MPW**：Caravel 是面向 SkyWater 工艺的开源芯片参考 harness（测试框架与外围），Efabless 曾运营面向开源设计的 MPW  shuttle 计划；现行 shuttle 是否开放、价格与准入条件以官方发布为准（待核实），本篇不把历史上的免费 shuttle 写成现行政策。

## 6. 关键论文与标准

- RISC-V 指令集规范与 profile 规范：见 RISC-V International 官网的批准规范文本，开源核实现哪些扩展以各项目文档为准。
- OpenROAD 项目公开介绍：DARPA IDEA 计划背景下于 2018 年前后启动的开源 RTL 到 GDS 项目，目标是全自动、无需人工干预的数字芯片设计流程。
- SkyWater SKY130 PDK 公开文档：Google 与 SkyWater 的合作 PDK，工艺为 130nm CMOS，文档见 skywater-pdk 仓库与配套说明。
- 暂无单一论文可作为本篇的理论来源：开源 EDA 是工具链与工艺开放的工程结果，不是某一篇论文的产物；本篇事实主张以各项目与晶圆厂的官方发布为准。

## 7. 当前实验结果

本节不写性能与面积数字：综合与物理设计的结果高度依赖设计本身、目标单元库、约束（SDC）与工具版本，脱离这三件套的数字没有可比性。只写经核查的定性事实：

- 开源流程已能把小型数字设计从 Verilog 做到 GDS：ORFS 的默认示例设计（如 gcd）可在普通机器上跑通全流程，这是教学与入门验证的常用路径；但示例跑通不等于任意设计都能签核流片。
- SkyWater SKY130 是真实可制造的开放工艺，已有开源设计经 MPW 流片；但“可制造”限定在该工艺与配套签核流程内，不能外推到先进工艺。
- 开源核中，CVA6、Rocket 等已有可跑 Linux 的实现；BOOM 面向高性能研究，其“高性能”是在研究语境下的定位，不是与商用高性能核的横向排名。
- 厂商与社区宣传的“开源流程已可替代商业 EDA”“某核性能达到某商用核水平”等说法，一律视为口径或预测，本篇不采信、不转载，以各项目与晶圆厂的官方发布为准。

## 8. 技术瓶颈

- **先进工艺缺位**：开放 PDK 停留在 130nm、180nm 级成熟工艺；先进工艺的 PDK、单元库与签核规则仍在保密协议之后，开源流程无法直接用于先进节点产品。
- **签核深度不足**：时序、DRC、LVS 之外的签核项（如功耗完整性、可靠性、电迁移、良率分析）在开源流程里覆盖不全；晶圆厂对开源签核结果的认可程度，决定了设计能不能真正量产，而不只是“做出一片样片”。
- **模拟与混合信号短板**：开源流程以数字流程为主；模拟电路、射频、高速 I/O 与存储器编译器等环节的开源工具链远不如数字流程完整，一颗实用 SoC 往往仍需商业工具补位。
- **验证成本**：核与 SoC 的验证工作量远大于写 RTL 本身；开源核的验证深度因项目而异，复用者须自行评估测试覆盖，不能把“开源”等同于“已充分验证”。
- **人才与维护**：开源 EDA 工具的安装、版本搭配与排障门槛较高；工具链版本稍有错位就可能在流程末段报错（如 ORFS 脚本调用了所装 OpenROAD 版本没有的命令），这是入门者最常见的失败模式，也是本篇把命令标为示例未实测的原因之一。
- **生态碎片化**：ORFS 与 OpenLane 两条流程、多种 PDK 处理方式（open_pdks、ciel 等）并存，文档与版本分散；学习者需要先选定一条流程再深入，混用两条流程的配置容易出错。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：开源核、Yosys 综合与 OpenROAD 物理设计已能把成熟工艺上的中小规模数字设计做到可制造的 GDS，且已有经 MPW 流片的实践；但先进工艺缺位、签核深度与模拟环节不足，决定了它尚未达到可替代商业 EDA 做量产产品的成熟度。

## 10. 未来研究问题

- **已有研究在做**：开源流程对更多成熟工艺的支持、签核检查项的补齐、以及把开源核的验证深度做到可复用、可审计的水平。
- **已有研究在做**：生成器路线的验证方法——参数化生成的 SoC 如何保证每种配置都经过充分验证，而不是只验证了默认配置。
- **本文推测**：开源芯片设计的下一道门槛不是“能不能跑通流程”，而是“跑通之后谁为签核与良率负责”；检验标准是晶圆厂是否把开源签核流程写进正式的量产准入文件，而不是只接受 MPW 样片。
- **本文推测**：模拟与混合信号环节可能长期是开源流程的短板，数字流程先行、模拟环节靠商业工具或外购 IP 补位的混合模式会持续存在；用“全开源”要求每一环节会误读现实。
