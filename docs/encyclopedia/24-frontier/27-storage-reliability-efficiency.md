# 存储可靠性与能效

本篇是[新型存储与互连总览](09-new-storage-interconnect.md)的下级专题，讲存储系统一级的可靠性与能效怎么度量、怎么取舍。度量口径是本篇的重点：同一个数字在不同口径下含义不同，跨厂商、跨介质直接比数字是常见误读。机房制冷方式（包括液冷）的技术细节属于超算分支 17 篇的范围，本篇只在“能效分母怎么算”处与之衔接，不重复其内容。

## 1. 研究问题

存储系统要回答的可靠性问题不是“这块盘会不会坏”，而是“在可接受的成本下，系统一年丢数据的概率有多低、坏盘后多久能恢复”。能效问题也不是“这块盘省不省电”，而是“每 TB 有效数据、每单位可靠性的总能耗是多少”。本篇把这两个问题拆成可度量的指标，并讲清每个指标的口径陷阱。

## 2. 基础理论

- **AFR（Annualized Failure Rate，年化故障率）**：一年内设备故障的比例估计，常用公式为故障数 ÷（设备运行天数 ÷ 365）× 100%；是群体统计量，不是“这块盘今年会不会坏”的承诺。
- **MTBF（Mean Time Between Failures，平均无故障时间）**：可修复系统的平均故障间隔；指数分布假设下 AFR ≈ 8760 ÷ MTBF（小时）；MTBF 越大不等于单块盘寿命越长，只代表群体故障率越低。
- **UBER（Uncorrectable Bit Error Rate，不可纠正比特误码率）**：读出数据中超出纠错能力（ECC）的比特错误比例；常以“每读 10^X 比特出现一次不可纠正错误”的形式标称。UBER 是“读错”的概率，不是“盘坏”的概率。
- **NRRE（Non-Recoverable Read Error，不可恢复读错误）**：与 UBER 相关的另一表述，指读操作中无法恢复的错误事件；不同厂商的标称口径（按比特、按扇区、按操作）不同，直接比数字前必须先对齐口径。
- **TBW / DWPD（ endurance 口径）**：TBW 为闪存盘生命周期内可写入的总字节数，DWPD 为每天可全盘写入的次数；两者都是“写寿命”口径，不度量读可靠性，也不度量突发故障。
- **PUE（Power Usage Effectiveness，电源使用效率）**：数据中心总能耗 ÷ IT 设备能耗；PUE 越接近 1，制冷、配电等非 IT 开销占比越低。PUE 是机房级指标，不是存储设备级指标。
- **WUE（Water Usage Effectiveness，水资源使用效率）**：数据中心用水量 ÷ IT 设备能耗；与 PUE 同为机房级指标，口径（取水、耗水、回用）随统计方法而异，跨机房比较前必须先对齐口径。
- **存储侧的能效口径**：把机房级 PUE/WUE 落到存储，需要再乘一层分摊——存储占 IT 能耗的比例、存储的有效容量（去重、压缩、纠删码后的可用容量，而非裸容量）；用裸容量算能效会系统性高估存储效率。

## 3. 技术路线

- **器件级可靠性路线**：HDD 靠冗余磁头、振动补偿与企业级标称（更严的 UBER、更高的年工作负载）换可靠性；SSD 靠 ECC、磨损均衡、掉电保护与预留空间（Over-Provisioning）换可靠性；两条路线的失效模式不同（机械 vs 闪存磨损与控制器故障），指标不能直接互换。
- **系统级可靠性路线**：RAID、复制、纠删码（见[数据压缩、去重与纠删码](26-compression-dedup-erasure.md)）把单盘故障变成“可重建事件”；系统可靠性取决于单盘 AFR、重建速度、重建期间的 UBER 风险三者的乘积，不是单盘指标的简单叠加。
- **能效路线**：器件级（低功耗盘、按需休眠、SMR/QLC 等高密度介质摊薄每 TB 功耗）、系统级（纠删码替代 3 副本直接省掉约一半物理盘，是最有效的存储节能之一）、机房级（制冷与供电效率，即 PUE 的改善）；三层节能的效果与代价各不相同，不能只算一层。
- **可观测性路线**：SMART 等健康信号、重建进度、降级读比例是可靠性指标的“过程量”；只看 AFR/UBER 的静态标称、不看运行中的过程量，会错过故障前兆。

## 4. 系统架构

一个可度量可靠性与能效的存储系统分三层看指标：

- **器件层**：AFR、MTBF、UBER/NRRE、TBW/DWPD、单盘功耗；来源是厂商规格书，口径以规格书的测试条件为准。
- **系统层**：数据丢失概率（器件 AFR、冗余方案、重建窗口的函数）、重建时间、降级读比例、有效容量（裸容量经去重、压缩、纠删码开销折算后）；来源是系统设计与运行数据，不是规格书数字的直接搬运。
- **机房层**：PUE、WUE、存储分摊能耗（存储 IT 能耗 × PUE 折算为机房总能耗）；来源是机房计量，存储侧只能分摊、不能独占。

三层指标的换算必须注明口径：器件 AFR 不能直接当系统丢数据概率，机房 PUE 不能直接当存储 PUE，裸容量不能直接当有效容量。

## 5. 代表性实现与开源项目

只列指标体系的来源方向，不写具体产品的指标排名：

- **JEDEC JESD218**：固态盘的可靠性与 endurance 要求标准，定义了 SSD 类别的使用条件与验证要求；UBER 等指标的 SSD 口径以该标准与厂商规格书为准。
- **厂商规格书体系**：企业级 HDD/SSD 的 AFR、MTBF、UBER/NRRE、TBW、工作负载（TB/年）均以各厂商规格书为准；同一指标在不同厂商、不同产品线的测试条件可能不同，跨产品比较前必须先对齐条件（待核实）。
- **公开故障统计**：Backblaze 等运营商发布的硬盘故障统计是群体运行数据的公开来源，可用于理解 AFR 的量级与随役龄的变化趋势；但其机型、环境与负载与自有机房不同，不能直接当作自有系统的 AFR 预测。
- **尚无统一结论**：存储侧 PUE/WUE 没有统一的行业分摊标准；“存储 PUE”一词在不同报告中可能指不同分摊方法，引用时必须注明方法。

## 6. 关键论文与标准

- JEDEC JESD218（SSD 要求标准）：SSD 类别的使用条件与 endurance 验证要求；UBER 口径的 SSD 侧来源。
- AFR/MTBF 的统计定义：AFR 为一年内故障比例估计，MTBF 与 AFR 在指数分布假设下可换算；换算成立的前提是指数分布假设，役龄相关的故障（早期失效、磨损期）不服从该假设，换算结果仅供参考。
- 暂无单一论文可作为本篇的全部来源：可靠性指标体系是标准、规格书与运营统计的综合，各指标的精确口径以原始来源为准。

## 7. 当前实验结果

本节不写具体产品的指标数字：AFR、UBER、TBW 均为产品线与测试条件相关的规格值，脱离产品型号与条件没有可比性；本篇不转载二手规格表。只写经定义与公开讨论支撑的定性结论与口径关系：

- **AFR 是群体量，不是单盘寿命**：AFR 0.5% 不代表“这块盘 200 年才坏一次”，而代表“每 200 块盘一年约坏 1 块”；10 块盘的阵列一年至少坏 1 块的概率约 5%（按二项分布估算，AFR 0.5% 时 1-(1-0.005)^10 ≈ 4.9%），阵列越大、年内见故障的概率越高——这是阵列规模本身带来的统计效应，不是盘变差了。
- **UBER 在重建时才真正咬人**：日常读的单次 UBER 风险很低；但重建要读出整盘或整条带的数据量，累计比特数巨大，命中一次不可纠正错误的概率随之上升；大容量盘的重建风险高于小容量盘，这是“盘越大、RAID 越危险”说法的统计来源，也是纠删码与定期 scrub（巡检读）存在的理由。
- **SSD 与 HDD 的 UBER 口径不在一个量级**：企业级 SSD 的 UBER 标称通常比 HDD 严苛数个数量级（如 10^-17 vs 10^-15 量级，具体以规格书为准，待核实），原因在 SSD 的读量级（高 IOPS）远高于 HDD；直接比标称数字而不比“每 TB 读量的风险”会误判。
- **纠删码是最有效的存储节能之一**：把 3 副本（3.0 倍）换成 RS(10,4)（1.4 倍），物理盘数省约一半，能耗与机柜空间同比例下降；代价是重建流量与 CPU，见[数据压缩、去重与纠删码](26-compression-dedup-erasure.md)。
- **PUE 改善的收益要按存储占比折算**：机房 PUE 从 1.5 降到 1.2，存储分摊能耗下降约 20%（1.2/1.5），不是“存储能耗降 20%”的全部故事——器件功耗与物理盘数不变时，PUE 改善只省制冷与配电部分。
- **能效比较必须用有效容量**：同样裸容量下，去重、压缩后的有效容量可能差数倍；用裸容量算“每 TB 功耗”会奖励“存得多但多是重复数据”的系统，正确的分母是去重、压缩、纠删码折算后的可用容量。

## 8. 技术瓶颈

- **口径不统一**：AFR 的测试条件（温度、负载、役龄）、UBER 的标称单位（按比特、按扇区、按操作）、PUE/WUE 的统计边界（取水 vs 耗水、IT 能耗口径）都不统一；跨厂商、跨机房比较前必须先对齐口径，否则比较结果无意义。
- **役龄效应**：早期失效期与磨损期的故障率高于稳定期；单点 AFR 掩盖了随时间变化的故障曲线，长期规划需要按役龄分段的故障率，而非一个常数。
- **重建窗口与二次故障**：重建越慢，窗口期内再丢盘导致不可恢复的概率越高；大容量盘、纠删码高重建代价、重建节流都会拉长窗口，三者叠加时风险非线性上升。
- **节能与可靠性的冲突**：盘休眠、降速省电，但唤醒延迟影响读写、频繁启停影响机械盘寿命；高密度介质（QLC、SMR）摊薄每 TB 功耗，但 endurance 与写性能下降——节能不能只算功耗一栏。
- **机房级指标落到存储的难题**：PUE/WUE 是机房总量，存储、计算、网络的分摊方法没有统一标准；任何“存储 PUE”数字都必须附带分摊方法，否则不可复现。

## 9. 成熟度判断

- **成熟度：成熟应用。** 判断依据一句话：AFR、MTBF、UBER、PUE 均已是厂商规格书与机房运营的量产级指标体系，定义与换算关系明确；仍在演进的是口径统一（跨厂商可比性）与存储侧分摊方法，不是这些指标本身。

## 10. 未来研究问题

- **已有研究在做**：按役龄分段的故障预测（基于 SMART 与运行数据的预测性维护）、纠删码感知的重建调度（缩短重建窗口）。
- **已有研究在做**：存储侧能效分摊方法的标准化（有效容量口径、PUE/WUE 分摊规则）。
- **本文推测**：可靠性指标的下一道门槛可能不是“更低的 AFR”，而是“可预测的故障”——即提前数周预警单盘失效并完成数据迁移；检验标准是预测性维护是否从运营商实践变为厂商规格书的一部分。
- **本文推测**：能效指标可能从“每 TB 功耗”转向“每 TB 可靠数据功耗”（分母同时计入冗余开销与可靠性等级）；检验标准是未来规格书或机房报告是否同时公布有效容量与冗余方案。
