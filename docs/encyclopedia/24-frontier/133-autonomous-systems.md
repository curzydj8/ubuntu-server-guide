# 计算机自动化与自主系统：总览

本篇是本方向的总览：介绍“计算机自动化与自主系统”下 10 个三级主题各是什么、解决什么问题、成熟到什么程度，不展开三级细节——细节各归其专篇。本方向的共同问题是：系统规模与变更速度已经超过了人工逐项操作的能力，系统能否在人的目标与护栏之内，自己感知、自己决策、自己行动，并在出错时自己收敛？

一个需要先讲清的区分：**自动化 ≠ 自主**。自动化是“按人事先写好的步骤执行”；自主是“系统在运行中自己感知状态、自己选择动作、自己承担后果范围内的执行”。自动化的失败模式是步骤写错；自主的失败模式还包括感知错、判断错、目标理解错。因此本方向的每一篇都要回答同一个问题：自主的边界画在哪、出错时谁接管、凭什么证据相信它。

本方向共享一条技术主线：始于 IBM 自主计算愿景的 MAPE-K 反馈环（监测 Monitor、分析 Analyze、规划 Plan、执行 Execute，共享知识库 Knowledge），见 Kephart 与 Chess 2003 年《The vision of autonomic computing》（《Computer》36(1):41–50）。此后各领域把这条环具体化：运维叫 AIOps 与自愈，网络叫闭环与意图驱动，软件工程叫 Agent 与自动修复，调度叫控制环与弹性伸缩。环的形式相同，难的是每一环的可靠性与它们组合后的可审计性。

## 1. 研究问题

本方向要解决的核心问题有三层：

- **规模问题**：服务、设备、代码库、告警的数量与变化速度超过人工处理能力，人工逐项响应必然滞后与遗漏。
- **速度问题**：故障扩散、流量突增、安全事件的窗口以分钟甚至秒计，等人开会决策就来不及。
- **一致性问题**：人工操作因人而异、不可复现；系统自己执行同一策略，行为才可审计、可回滚、可复现。

但自主也带来新问题：系统替人决策后，责任如何界定？系统在分布、噪声、不完整信息下做出的决策如何验证？系统目标与人的真实意图不一致时（例如为降成本而牺牲可用性），谁来纠正？这些问题贯穿本方向全部 10 篇。

## 2. 基础理论

- **MAPE-K 反馈环**：自主系统的经典架构模式，监测—分析—规划—执行四步共享知识库；本方向各篇的架构节多是它的实例化。
- **控制论与反馈控制**：设定目标值、观测偏差、输出纠正动作；Kubernetes 的弹性伸缩、网络闭环都属于这一思想的工程化。
- **自主等级（levels of autonomy）**：Sheridan 与 Verplank 1978 年的十级自动化量表，以及 Parasuraman、Sheridan 与 Wickens 2000 年把自动化按信息获取、信息分析、决策选择、行动执行四类功能分别分级的模型；是 [143 篇](143-human-machine-collaboration.md)讨论“人在环内/环上/环外”的理论依据。
- **意图驱动（intent-based）**：人不写操作步骤，只声明期望的终态与约束，系统自己推导并维持该终态；是网络与资源调度方向的共同抽象。
- **可观测性（observability）**：没有日志、指标、追踪三类信号，自主系统就是盲的；可观测性是 [142 篇](142-multi-agent-workflows.md)与 [140 篇](140-self-healing.md)的共同前提。

## 3. 技术路线

本方向 10 个三级主题各一小段，细节见专篇：

- **[自主软件开发](134-autonomous-dev.md)**：以 Agent 为主体的软件工程——Agent 理解需求、改代码、跑测试、提合并请求，人在审查与验收环节把关。工程发展中：单任务修复已有可复现基准进展，端到端交付仍需人工验收。
- **[AI 自动编程和代码维护](135-ai-programming.md)**：代码补全、重构、依赖升级、文档同步等日常维护工作的自动化；补全类工具已广泛落地，自主维护（无人值守的大规模重构与升级）仍在发展中。
- **[自动测试、调试和修复](136-auto-testing-repair.md)**：自动生成测试、定位缺陷、生成并验证补丁的闭环；测试生成与执行相对成熟，自动修复仍以小范围、可验证的补丁为主。
- **[自主网络管理](137-autonomous-network-mgmt.md)**：电信与园区网络的闭环运维——自配置、自愈、自优化；按 TM Forum 自主网络等级 L0–L5 逐场景评估，多数场景处于 L2–L3，全网 L5 仍是愿景。
- **[自主安全响应](138-autonomous-security-response.md)**：只讲防御与响应：告警关联、隔离、阻断、取证支撑的自动化与自主化；高风险动作（断网、封禁）必须有护栏与人工接管路径，本篇不写攻击操作内容。
- **[自适应计算系统](139-adaptive-computing.md)**：系统在运行中根据负载、环境、能耗改变自身结构与策略；从阈值规则到基于学习的自适应，是自主系统中最通用的理论层。
- **[自愈系统和自动恢复](140-self-healing.md)**：故障发生后系统自己检测、隔离、恢复服务；重启、切换、回滚等恢复动作已成熟，根因诊断的自主化仍在发展中。
- **[自动资源调度](141-auto-resource-scheduling.md)**：算力、内存、网络、能耗资源的自动分配与弹性伸缩；以 Kubernetes 调度与弹性伸缩为代表，是本方向最成熟的一支。
- **[多 Agent 工作流](142-multi-agent-workflows.md)**：系统视角：多个 Agent 如何编排、调度、容错与可观测，而不是 Agent 个体如何研究与协作（后者见 [49 篇](49-multi-agent-collaboration.md)）。实验研究中：编排框架众多，系统级可靠性与成本可控性尚未成熟。
- **[人机协同和可控自主系统](143-human-machine-collaboration.md)**：自主的边界与治理：人在环内、环上、环外的分工，否决权、接管、审计与责任；是本方向所有“敢不敢放手”的答案所在。

## 4. 系统架构

本方向各系统的共同骨架是 MAPE-K 环的实例化：

- **感知层**：指标、日志、追踪、事件、代码库状态、网络遥测——自主系统的数据来源；信号质量决定一切上层判断的上限。
- **决策层**：规则引擎、策略、规划器或模型；把“当前状态与目标状态的差距”翻译成动作序列，并做冲突消解与风险评估。
- **执行层**：带护栏的执行器——动作有权限边界、有灰度、有回滚、有熔断；执行层不可信，决策层再聪明也不可用。
- **知识库与审计层**：策略、历史、模型、动作记录；审计记录是事后追责与事前复盘的唯一依据，也是人机协同篇的落点。
- **人机接口层**：审批、否决、接管、告警升级的通道；接口失效时系统必须默认回到保守行为（停手、报警），而不是继续自主行动。

## 5. 代表性实现与开源项目

只列真实存在的方向与项目，不写未核实的落地数字：

- **Kubernetes 弹性伸缩与调度**：HorizontalPodAutoscaler、Cluster Autoscaler 等控制环，是自动资源调度最广泛的量产实例（见 [141 篇](141-auto-resource-scheduling.md)）。
- **SWE-agent 等编码 Agent 研究原型**：Yang 等 2024 年 NeurIPS 论文提出的 Agent—计算机接口（ACI）路线，是自主软件开发的代表性研究工作（见 [134 篇](134-autonomous-dev.md)）。
- **AIOps 与事件驱动自动化平台**：以可观测性数据驱动告警关联与预审批修复的平台类产品，是自愈方向的工程载体（见 [140 篇](140-self-healing.md)）。
- **SOAR（安全编排、自动化与响应）平台**：安全响应剧本的自动化执行载体，是自主安全响应的工程前身（见 [138 篇](138-autonomous-security-response.md)）。
- **多 Agent 编排框架**：以图与状态机编排多个 Agent 的开源框架，是 [142 篇](142-multi-agent-workflows.md)讨论的系统层对象；各框架的具体版本与性能数字以官方发布为准（待核实）。

## 6. 关键论文与标准

- Kephart, J. O. 与 Chess, D. M.（2003）《The vision of autonomic computing》，《Computer》36(1):41–50——自主计算愿景与自管理四属性（自配置、自愈、自优化、自保护）的来源。
- Sheridan, T. B. 与 Verplank, W. L.（1978）《Human and Computer Control of Undersea Teleoperators》，MIT 人机系统实验室技术报告——十级自动化量表的来源。
- Parasuraman, R.、Sheridan, T. B. 与 Wickens, C. D.（2000）《A Model for Types and Levels of Human Interaction with Automation》，《IEEE Transactions on Systems, Man, and Cybernetics – Part A》30(3):286–297——按四类功能分别分级的模型。
- Jimenez 等（2024）《SWE-bench: Can Language Models Resolve Real-World GitHub Issues?》，ICLR 2024，arXiv:2310.06770——自主开发方向的评测基准来源。
- TM Forum 自主网络等级框架（IG1218 业务框架、IG1252 评估方法、ANLET 评估工具）：L0–L5 六级，是 [137 篇](137-autonomous-network-mgmt.md)的等级依据；具体条款以 TM Forum 官方发布为准（待核实）。

## 7. 当前实验结果

本节不写厂商宣传数字与未经核对的榜单分数：自主方向的基准分数高度依赖执行框架（harness）与模型版本，不同来源的同一基准数字常常不一致，达不到“数字 + 来源 + 测试条件”三件套的，本篇一律不采信。只写经核查的定性结论：

- 原始 SWE-agent 论文报告：以 GPT-4 Turbo 为底座，在 SWE-bench 全部 2294 项任务上 pass@1 为 12.47%，在 HumanEvalFix 上为 87.7%（Yang 等，NeurIPS 2024，arXiv:2405.15793）。这是 2024 年的原始结果，不是今天的水平；今天的榜单数字以 SWE-bench 官方发布为准（待核实）。
- Kubernetes 弹性伸缩是量产验证过的控制环：控制器按固定周期（默认 15 秒同步周期，见官方文档）比对指标与目标并调整副本数；这是“控制环”思想最可复现的工程证据。
- 电信自主网络按场景分级评估是行业共识：同一运营商的不同场景（如故障管理与容量规划）可以处于不同等级；“全网 L5”不是一张证书，而是一组场景等级的集合。
- 自愈与自动修复的共同规律：恢复动作越是“已知条件、已知动作、可验证结果”，自主化越可靠；条件越开放，人工接管越不可少。

## 8. 技术瓶颈

- **感知不可靠**：信号缺失、噪声、延迟都会让决策层在错误的世界模型上行动；自主系统的第一瓶颈常常不是模型，而是可观测性。
- **验证难**：自主动作的正确性难以事前穷举验证，只能靠护栏、灰度、回滚与事后审计兜底；开放任务尤其如此。
- **目标错位**：系统优化的代理指标（如降成本、提速度）与人的真实目标（如不中断服务、不泄露数据）不一致时，自主会“高效地做错事”。
- **组合复杂性**：多个自主环、多个 Agent 同时行动时互相干扰，整体行为难以预测；这是 [142 篇](142-multi-agent-workflows.md)的核心难题。
- **信任与责任**：没有可审计的决策记录与明确的接管路径，组织不敢把高风险动作交给系统；技术之外的组织瓶颈。
- **成本失控**：自主 Agent 的长链路推理与反复试错可能产生不可预期的算力与调用成本；成本护栏是量产的前提之一。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：本方向的单点能力（弹性伸缩、代码补全、剧本化响应、单域闭环）已有量产实例，但跨域、全流程、无人值守的自主系统尚未证明其可靠性与可审计性，仍处工程化爬坡期。

## 10. 未来研究问题

- **已有研究在做**：自主动作的形式化验证与护栏语言——如何事前证明一类动作在约束内安全。
- **已有研究在做**：多自主环的协调与冲突消解——多个闭环同时作用于同一系统时的稳定性。
- **已有研究在做**：自主系统的可审计决策记录标准——决策依据、数据版本、模型版本如何一并存档。
- **本文推测**：本方向的量产路径将是“按场景逐级放权”而非“一夜全自主”：每个场景先在人在环上跑通，再放宽到人在环外；检验标准是各场景是否有公开的等级评估与事故复盘。
- **本文推测**：成本与能耗约束可能成为下一阶段自主系统设计的一级目标，而不只是性能目标；检验标准是调度与编排框架是否把成本护栏作为默认能力。
