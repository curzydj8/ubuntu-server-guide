# 存算一体与近存计算

> 本篇是 [新型计算架构：光子与存算一体](08-new-computing-arch.md) 总览下存算方向的三级展开。总览已讲存算一体的范式定位（权重不动、数据少搬），本篇讲存算一体与近存计算本身的组织方式、器件路线与瓶颈，不重复总览。交叉处理：神经形态分支的类脑芯片只链接 [神经形态计算](02-neuromorphic-computing.md)，不重复其产品；新型存储器件的物理细节归 [MRAM、ReRAM 与 PCM](18-mram-reram-pcm.md) 与 [新型非易失性存储](19-novel-nvm.md)，只链接、不重复；计算型存储（把算力放进 SSD 等存储设备）归 [计算型存储](20-computational-storage.md)，本篇只在边界处点名区分。

## 1. 研究问题

冯·诺依曼架构下，一次矩阵乘法要反复做三件事：从存储器读权重、把权重搬到处理器、算完把结果搬回去。权重规模越大，这三件事的代价越大。存算一体要回答的问题是：**能不能让权重留在存储阵列里不动，计算发生在权重所在的地方，从而把“搬运”从系统级开销降为阵列内操作？**

近存计算回答的是同一个问题的温和版：**如果把计算放进存储阵列内部太难，能不能把计算单元放在存储器旁边（同一芯片、同一封装或同一板卡），把搬运距离从“跨芯片、跨总线”缩短到“片内、封装内”？** 两者的区别不是程度，而是结构：存算一体动的是“存储阵列本身是否算”，近存计算动的是“计算单元离存储器多远”。这个区分决定了各自的瓶颈与量产距离，混为一谈是读存算文献时最常见的误解。

## 2. 基础理论

- **冯·诺依曼瓶颈与存储墙**：处理器与存储器分离导致的搬运代价；背景见 [后冯·诺依曼架构](72-post-von-neumann.md) 与 [新型存储与互连：HBM 与 CXL](09-new-storage-interconnect.md)。
- **欧姆定律与基尔霍夫定律做乘积累加**：电压乘电导得电流，多路电流在位线/字线节点求和，一次并行完成矩阵向量乘法的核心步骤；这是模拟存算的物理基础（模拟侧见 [模拟计算](74-analog-computing.md)）。
- **数字存算**：用数字逻辑在存储阵列内或周边做位运算与累加；精度由位数保证，不受模拟噪声制约，但并行度与能效通常低于模拟存算。
- **数据局部性原理**：程序访问的数据有时间与空间局部性；缓存层级就是利用局部性的冯·诺依曼内解法。存算一体可以看作把局部性推到极致——计算发生在数据所在之处，局部性不再是优化目标，而是结构本身。
- **存算阵列的读取即计算**：在交叉阵列（crossbar）中，一次读取操作同时完成一次乘积累加；读取的语义从“取数据”变成了“取结果”，这是存算一体与传统存储器最本质的接口差异，也是它难以兼容现有软件栈的根源。

## 3. 技术路线

按“算在哪里”与“用什么器件”两个维度划分：

- **阵列内模拟存算**：在存储阵列内部用电流求和做乘积累加。并行度最高、能效潜力最大，但精度受噪声、失配与器件差异制约，且 ADC 开销不可忽略。
- **阵列周边数字存算**：计算单元放在阵列周边（periphery），用数字逻辑做运算，存储阵列本身仍是普通存储器。精度有保证、与现有流程兼容性好，但搬运只是从“片外”缩短到“阵列周边”，收益小于阵列内计算。
- **近存计算（near-memory）**：计算单元放在存储器旁边——同一芯片上的专用逻辑、同一封装内的逻辑层（例如 HBM 的逻辑层）、或紧贴存储器的加速器。它不改动存储阵列本身，因此量产阻力最小；代价是权重仍要搬，只是搬得近。这是目前离工程最近的一条。
- **按器件分的四条路线**：SRAM 存算（快、CMOS 兼容、面积大、断电丢失）、RRAM 存算（非易失、密度高、写能耗与耐久性受限）、PCM 存算（非易失、多值存储、写速度与漂移受限）、MRAM 存算（快、耐久好、开关比低、易受噪声影响）。器件物理细节归 [MRAM、ReRAM 与 PCM](18-mram-reram-pcm.md)，本篇只讲它们作为存算载体的系统级取舍，不重复器件物理。
- **混合存算**：用两种器件组合取长补短，例如 SRAM 保证精度与训练、RRAM/MRAM 提供密度与非易失——这是近年研究中常见的折中方向，但混合本身带来异构阵列的调度与映射复杂度。
- **与计算型存储的边界**：[计算型存储](20-computational-storage.md) 是把计算放进 SSD/存储设备（设备级），存算一体是把计算放进存储阵列（阵列级），近存计算介于两者之间（芯片/封装级）。三者解决的都是“数据搬运”问题，但层次不同、接口不同，不可混用。

## 4. 系统架构

一个典型的存算推理系统由以下部分组成：

- **存算阵列（tile）**：多个存算 tile 拼成大阵列；每个 tile 含存储阵列、字线/位线驱动、求和节点与局部 ADC/DAC。Tile 是存算系统的基本扩展单元，系统规模问题首先是 tile 间互连与调度问题。
- **转换接口**：DAC（输入转模拟）与 ADC（求和结果转数字）；模拟存算的系统瓶颈常在这里——阵列本身的并行收益，常被 ADC 的面积、功耗与延迟吃掉一部分。数字存算没有模拟转换问题，但有位宽与吞吐的取舍。
- **片上互连与调度**：Tile 之间、Tile 与数字控制逻辑之间的数据通路；大模型切分到多个 tile 时，切分策略决定通信量，切分不好则存算的收益被 tile 间搬运抵消。
- **数字控制与存储层级**：数字存储器存不能进存算阵列的数据（激活、偏置、控制信息），数字控制器做非线性激活、数据调度、校准与结果校验。
- **编译与映射工具**：把神经网络切分、量化、映射到存算 tile，并处理精度损失；没有它，存算硬件只能跑演示用的固定网络。这是目前最薄弱的一层。

## 5. 代表性实现与开源项目

只列真实存在的研究方向，不写未核实的性能倍数：

- **SRAM 存算原型**：学术与工业界均有 SRAM 存算芯片原型；优势是 CMOS 兼容与速度，短板是面积与易失性。
- **RRAM/PCM 存算原型**：学术与工业界均有阻变与相变存算原型；优势是非易失与密度，短板是写能耗、耐久性与器件差异。
- **MRAM 存算原型**：磁存储存算研究在进行；优势是速度与耐久，短板是开关比与噪声。
- **近存计算产品化方向**：HBM 逻辑层集成计算、存算一体推理加速器的早期产品化尝试，属于“近存”而非“阵列内存算”的口径；读产品宣传时要先确认它是哪一档。
- **尚无代表性通用商用系统**：按“通用可编程、能跑用户自有模型”的定义，今天不存在商用的通用存算一体计算机；现有交付物是特定推理场景的加速器原型或研究芯片。

## 6. 关键论文与标准

- 存算一体器件与架构的公开综述：SRAM、RRAM、PCM 存算的取舍（速度、能效、面积、精度）与系统级瓶颈（器件差异、漂移、有限耐久性、片上训练支撑不足），见文末来源中的综述文献。
- 混合存算研究：RRAM/SRAM 混合存算系统的低秩补偿等工作（2025 年前后），说明“单一器件通吃”不是研究主流，混合与补偿才是。
- 暂无公开标准：存算一体没有统一的阵列接口、精度度量或编程模型标准；不同原型的精度定义、是否含 ADC 开销、是否含校准时间的口径不一，结果不可直接比较。

## 7. 当前实验结果

本节不写性能倍数：存算原型的“比传统加速器高一到两个数量级能效”类说法，几乎都脱离了统一测试条件（模型、精度、批量、是否含 ADC/DAC 开销、是否含校准与映射时间），达不到“数字 + 来源 + 测试条件”三件套的标准，本篇一律不采信。只写经核查的定性结论：

- 存算一体在“特定规模、特定精度的推理”上有原型验证；电流求和的并行性与权重不动的收益是真实的。
- 但器件差异、漂移、有限耐久性与模拟精度约束，是从原型走向产品的系统性障碍，不是单点工程问题。
- 近存计算的量产距离最近，因为它不改动存储阵列本身；但它的收益上限也最低——权重仍要搬，只是搬得近。

## 8. 技术瓶颈

- **器件差异与漂移**：RRAM/PCM 的阻值差异、漂移（随时间变化）与有限耐久性，直接表现为计算误差；系统必须用训练补偿、校准或冗余来压住，都有成本。
- **模拟精度天花板**：模拟存算的有效精度受噪声与失配制约；大阵列的求和节点寄生参数随规模恶化，精度与规模之间存在张力。
- **ADC/DAC 开销**：转换接口的面积、功耗与延迟常吃掉阵列收益；这是模拟存算系统级的头号瓶颈之一。
- **写代价**：非易失存算器件的写速度慢、写能耗高、耐久有限；推理（权重基本不动）友好，训练（权重频繁更新）不友好——存算一体目前基本是推理技术，不是训练技术。
- **软件栈与映射**：把任意网络切分、量化、映射到存算 tile 并保证精度的工具链不成熟；用户模型一换，映射可能要重做。
- **良率与代工**：新型存储器件的良率、代工兼容性与规模化集成仍在验证中；SRAM 存算兼容性好但面积大，是另一维度的取舍。
- **评估口径混乱**：是否含转换开销、是否含校准时间、精度定义是否一致，各家口径不一；跨原型比较需要先统一口径（方法见 [计算架构仿真与基准测试](79-arch-simulation-benchmarks.md)）。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：各类存算原型均有特定规模推理验证，但器件差异、耐久性、ADC 开销与软件栈问题均未解决，尚无通用可编程的商用存算一体系统；近存计算离工程更近，但按“阵列内存算”的严格定义，它不算存算一体，口径要分清。

## 10. 未来研究问题

- **已有研究在做**：器件差异与漂移的补偿方法（训练侧补偿、电路侧校准、混合器件组合）。
- **已有研究在做**：存算编译与映射工具链——把用户模型自动切分、量化、映射到存算 tile 并保证精度。
- **已有研究在做**：支持片上训练的存算架构——克服写耐久与精度约束，让存算从推理走向训练（目前仍是难题，不是已解决的问题）。
- **本文推测**：存算一体最可能先以“特定推理加速器”（固定或少量模型、低功耗边缘推理）的形态落地，而不是以通用存算计算机的形态落地；检验标准是是否出现可跑用户自有模型、可量产交付的加速器产品。
- **本文推测**：近存计算与存算一体的界限可能随封装技术（3D 集成、Chiplet）模糊——逻辑层离存储阵列越近，“近存”与“存算”的收益差距越小；但接口与编程模型的差异仍会存在。
