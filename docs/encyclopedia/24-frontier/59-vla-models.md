# 视觉-语言-动作模型

本篇是[具身智能总览](07-embodied-intelligence.md)的三级展开，只讲 VLA（vision-language-action）这一类模型：它怎么把“看”与“听”变成“动”，动作表示有哪些选择，以及它的边界在哪。基础模型通论见[具身智能与机器人基础模型](54-embodied-foundation-models.md)，训练与迁移见[仿真训练与 Sim-to-Real](60-sim-to-real.md)。多智能体协作的纯软件侧见[AI Agent 前沿：多智能体与自主研究](06-frontier-ai-agents.md)，本篇不展开多智能体内容。

## 1. 研究问题

给机器人一个语言指令（“把红色的杯子放到盘子里”）与一张摄像头图像，它能不能直接输出下一步该怎么动——手往哪移、转多少、夹持器开合到什么程度？VLA 要解决的就是这个“从语言 + 视觉到动作”的端到端映射问题。

这个问题与“视觉—语言模型回答问题”有本质区别：回答问题输出的是文本，错了可以重说；VLA 输出的是物理动作，错了会打翻杯子。而且动作是连续的、高频的、有物理约束的——手不能瞬移、力不能无限大、关节有行程限制。VLA 的研究问题因此是双重的：既要借用图文预训练的语义能力，又要输出物理上可执行、时间上跟得上的动作。

## 2. 基础理论

- **VLM（视觉—语言模型）**：在图文数据上预训练、能理解图像内容并回答语言问题的模型；VLA 的骨干大多是 VLM，VLA 是在 VLM 之后再接动作能力。
- **动作 token 化**：把连续动作的每个维度切成若干档（bin），每档对应一个 token，让模型像输出文字一样输出动作 token 序列；RT-2 把每个动作维切成 256 档、一个动作写成 8 个整数 token（见第 7 节）。优点是复用语言模型的训练与推理框架，缺点是量化误差与 token 序列长度。
- **动作块（action chunking）**：一次输出未来若干步的动作序列，而不是一步一步输出；减少模型调用频率、动作更平滑，是 ACT（Action Chunking with Transformers）等方法的核心思想。
- **扩散策略（diffusion policy）**：把动作生成表示为去噪扩散过程，从噪声中逐步生成动作序列；优点是能表示多模态动作分布（同一个场景下有多种合理的抓法），缺点是推理需要多步去噪、延迟较高。
- **自回归 vs 并行解码**：自回归是一个 token 一个 token 地生成，延迟随序列长度线性增长；并行解码一次生成整段动作，延迟低但建模能力受限。VLA 的推理延迟问题，很大程度上是解码方式的选择问题。
- **具身数据（embodiment data）**：机器人轨迹数据——观测、指令、动作的序列；与图文数据不同，具身数据与本体强绑定（关节数、自由度、末端执行器都不同），跨本体复用是 VLA 的核心难题。

## 3. 技术路线

VLA 的主流路线按“动作怎么表示”分三条：

- **离散 token 路线（RT-2、OpenVLA）**：动作写成文本 token，与图文任务联合微调。优点是框架统一、能直接复用 VLM 的预训练与推理基础设施；缺点是量化误差、动作频率受 token 序列长度制约、难以表达高速精细动作。
- **连续扩散路线（Diffusion Policy、Octo 等）**：动作头用扩散模型生成连续动作序列。优点是动作平滑、能表示多模态分布；缺点是推理延迟高、需要额外的去噪步数调参。
- **分层路线（VLA 管规划、传统控制器管执行）**：VLA 输出高层中间表示——关键点、轨迹草图、子目标、affordance——再由传统控制器或小策略模型翻译成低频关节指令。优点是把“可验证的部分”留给传统方法、延迟与安全性更好；缺点是中间表示的设计本身就是研究问题，设计不好会成为新的瓶颈。

三条路线没有胜负：离散 token 路线在“借用 VLM 能力”上最直接，扩散路线在“动作质量”上最有潜力，分层路线在“可部署性”上最现实。目前的研究趋势是混合——VLA 做语义与粗规划，扩散或传统控制器做精细执行。

## 4. 系统架构

一个典型的 VLA 系统由以下部分组成：

- **视觉编码器**：把摄像头图像编码为视觉特征；OpenVLA 的做法是融合 DINOv2 与 SigLIP 两路预训练特征，兼顾细粒度几何与语义。
- **语言模型骨干**：融合视觉特征与语言指令、做推理的主体；OpenVLA 用 Llama 2 7B 作为骨干（见第 7 节）。
- **投影层**：把视觉特征映射到语言嵌入空间，使图像与文本能在同一表示空间里交互。
- **动作解码器**：按路线不同，可能是 token 解码（离散）、扩散去噪（连续）、或中间表示输出（分层）。
- **低层控制器**：把 VLA 输出的动作目标变成关节力矩与速度；这层通常仍是传统控制器（见 54 篇），因为 VLA 的输出频率（约每秒几次决策）远低于控制频率（毫秒级）。
- **安全层**：动作限幅、速度与力矩限制、碰撞检测、人工急停；VLA 的幻觉会变成物理动作，安全层不是可选项（见 61 篇）。
- **部署形态**：云端推理（算力足、延迟高）vs 机载推理（延迟低、算力受限）vs 混合（VLA 在云端做粗规划、机载小模型做精执行）；部署形态的选择直接决定任务类型——云端 VLA 做不了高速动态任务。

## 5. 代表性实现与开源项目

只列真实存在的项目，不写未核实的性能排名：

- **RT-2（谷歌 DeepMind，2023）**：VLA 路线的奠基性模型，基于 PaLI-X（55B）与 PaLM-E（12B）两个 VLM 骨干，把动作写成文本 token、与图文任务联合微调；是闭源研究模型，不是商用产品。
- **RT-X（2023）**：跨本体训练的 VLA 路线，汇集多机器人数据（见 54 篇）；证明了“多本体数据混合训练”在研究层面可行，但跨本体泛化的边界仍在探索中。
- **OpenVLA（2024，CoRL 2024）**：开源 VLA 的代表，模型、代码、微调工具公开；定位是研究社区的 VLA 基线与微调起点，不是针对某一台机器人的产品。
- **Octo（2024）**：开源通用机器人策略，基于 Transformer 与扩散式动作头，在 Open X-Embodiment 数据上训练；定位是“可微调的通用策略骨干”。
- **ACT（Action Chunking with Transformers，2023）**：动作块思想的代表性工作，用 Transformer 一次输出一段动作序列，在精细操作任务上表现突出；是 VLA 动作表示的重要参照。
- **Diffusion Policy（2023）**：扩散式动作生成的代表性工作，把动作生成表示为条件去噪扩散过程。
- **Open X-Embodiment 数据集**：上述模型共用的数据底座；规模与统计口径以数据集官方发布为准。

## 7. 当前实验结果

数字只写带来源与测试条件的，缺一件就不写：

- RT-2 论文报告：在约 6,000 次真机评估试验中，未见场景的平均成功率约 62%，高于 RT-1 的约 32%（测试条件：谷歌实验室的厨房场景机械臂、论文自定的未见物体/背景/环境划分；RT-2 的两个骨干版本——PaLI-X 55B 与 PaLM-E 12B——在未见场景上均为约 62%，见论文报告的二手整理；具体数字以论文原文为准）。
- RT-2 的动作表示：每个连续动作维切成 256 档，一个动作写成 8 个整数 token，分别编码末端执行器的 6 自由度位姿变化、夹持器开合与终止标志（来源：RT-2 论文；这是方法事实，不是性能结论）。
- OpenVLA 论文报告：7B 参数模型（Llama 2 骨干 + DINOv2 与 SigLIP 视觉编码器），在 97 万条 Open X-Embodiment 真实机器人轨迹上训练；在 29 项评估任务上，绝对任务成功率比 55B 参数的 RT-2-X 高 16.5 个百分点（测试条件：WidowX 与谷歌机器人本体、论文自定的 29 项任务；该比较只在论文的评估设定内成立）。
- 定性结论（RT-2 论文作者自己指出）：图文预训练带来的主要是语义泛化（认出新物体、理解新措辞、做简单推理），而不是新的物理技能；模型的物理动作仍在机器人演示数据的分布之内。
- 推理延迟是 VLA 的显性约束：大模型自回归解码的决策频率约每秒几次（具体数字随模型、硬件与部署形态而变，以实测为准），远低于低层控制的毫秒级需求；高速、精细、动态任务目前不在 VLA 端到端的舒适区内。

厂商“比某某快多少倍”“成功率第一”类宣传数字，本篇一律不采信为结论。

## 8. 技术瓶颈

- **数据瓶颈**：机器人轨迹数据比图文数据小几个数量级，且跨本体难以复用；VLA 的泛化能力受演示覆盖面硬约束。
- **推理延迟**：自回归解码 + 大模型推理的延迟，限制了 VLA 在动态、精细任务上的表现；扩散路线的多步去噪进一步加重延迟。
- **物理 grounding 缺失**：VLA 从图文中学到的是语义，不是物理——重量、摩擦、形变、接触力等只能从交互数据中学，而交互数据正是稀缺的。
- **幻觉的物理后果**：VLM 的幻觉在文本里只是错一句话，在 VLA 上可能变成错误的抓取、碰撞或危险动作；验证与纠错机制是部署的前提。
- **长程任务**：VLA 擅长单步或短程操作，长程任务（收拾桌子、做一顿饭）需要规划、记忆与失败恢复，单靠端到端 VLA 目前做不到稳定完成。
- **评估缺失**：缺乏跨平台、跨本体的统一基准；论文自选任务、自定评判标准的现状，使 VLA 的“进步”难以横向度量。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：VLA 在受限桌面操作任务上已有可复现的研究进展（RT-2、OpenVLA 的论文结果），但数据规模、推理延迟、物理 grounding、安全验证与统一评估五大问题均未解决，离开放环境的通用部署仍有距离。

## 10. 未来研究问题

- **已有研究在做**：动作表示的改进（离散 token、扩散、动作块的混合）、推理加速（并行解码、模型蒸馏、小模型机载部署）。
- **已有研究在做**：VLA 与世界模型的结合——先预测物理后果、再选动作，而不是直接输出动作。
- **已有研究在做**：分层 VLA——大模型管语义与规划、小模型或传统控制器管精细执行，兼顾泛化与延迟。
- **本文推测**：VLA 可能先在“低速、准静态、容错空间大”的操作任务落地（如分拣、摆盘），而不是先进入高速动态任务；检验标准是低速任务是否先出现可复现的商用部署。
- **本文推测**：VLA 的评估可能先从“统一基准”走向“任务族 + 失效模式清单”（即先定义好“在哪些场景下必须不犯错”），而不是先追求一个总分；检验标准是后续论文是否普遍报告失效模式而非只报告成功率。
