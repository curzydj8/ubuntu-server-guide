# 缓存、互联与内存控制器

本篇是[先进芯片与 Chiplet 总览](05-advanced-chips-chiplet.md)的三级深挖篇之一：总览讲“芯片为什么拆、拼法有哪几条路线”，本篇只讲拆开之后芯片内部的一层——数据怎么在缓存、互联与内存控制器之间走、走多远、以及“远”带来的代价。封装本身怎么拼（中介层、硅桥、3D 堆叠）归同分支的 [Chiplet、先进封装与 3D IC](37-chiplet-packaging-3d.md)，本篇不重复；HBM 的代际参数归 [HBM 各代](25-hbm-generations.md)，CXL 内存池化归 [内存池化与 CXL](24-memory-pooling-cxl.md)，两者的结构定位归 [新型存储与互连总览](09-new-storage-interconnect.md)，本篇只在涉及处链接，不展开。

## 1. 研究问题

单颗芯片时代，缓存、互联与内存控制器都在同一裸片上：核访问末级缓存是“片内一跳”，访问内存是“出核、过互联、到控制器”的短路径，延迟与带宽的账相对好算。芯片拆成多个 chiplet 之后，这条路径被拉长了：核可能在一个裸片上，共享缓存可能在另一个裸片上，内存控制器可能在第三个裸片（I/O 裸片）上，中间还要经过裸片间互连。于是同一个问题要重新问一遍：数据放在哪一级、哪一块、哪个控制器后面，访问代价还一不一样？

本篇要解决的问题是：跨裸片之后，缓存层次怎么分、一致性怎么维持、互联怎么选拓扑、内存控制器怎么布局，才能让“拆开的芯片”在软件看来仍然像“一台机器”，而不是一堆各顾各的裸片。

## 2. 基础理论

- **缓存层次（cache hierarchy）**：L1 私有（每核独占，容量最小、延迟最低）、L2 私有或每核组共享、末级缓存（LLC，last-level cache）全芯片共享；层次越往下容量越大、延迟越高。跨裸片后，LLC 可能被切分到多个裸片上，成为“分布式共享缓存”，访问不同分片的延迟不再相等。
- **缓存一致性（cache coherence）**：多个私有缓存里可能存着同一地址的不同副本，一致性协议保证程序看到的内存像只有一份。常见协议家族是 MESI / MOESI（按缓存行状态：修改、独占、共享、失效等组织）；实现方式分监听式（snooping，广播问一圈）与目录式（directory，只问持有者），核数多了之后目录式更省带宽。
- **片上网络（NoC，network-on-chip）**：核、缓存、内存控制器之间的数据高速公路，由路由器与链路组成；拓扑决定了“从 A 到 B 要过几跳”，常见的有总线、环、Mesh（网格）、Crossbar（交叉开关）。Mesh 是多核芯片最常见的选择：扩展性好，但对角线的核到内存控制器的跳数多。
- **内存控制器（memory controller）**：CPU 与 DRAM 之间的翻译官，负责时序、刷新、地址映射与调度；通道数、位宽与调度策略决定了内存带宽的上限与延迟分布。控制器放在哪个裸片上，决定了“访存要先跨几次裸片”。
- **NUMA（非一致内存访问）**：访存延迟取决于“数据在哪个节点的内存上”；单芯片内的 chiplet 结构也会呈现 NUMA 效应——本地 chiplet 的内存快、远端 chiplet 的内存慢，操作系统若不感知，就会把热数据放错地方。芯片内也常有子 NUMA 簇（SNC，sub-NUMA clustering）的划分，即一颗芯片内再分几个 NUMA 节点。
- **内存交织（memory interleaving）**：把连续地址按固定粒度（如若干 KB 一条）条带化地分到多个内存通道或多个裸片的控制器上，目的是摊平带宽、避免单通道瓶颈；代价是失去了“本地性”——所有访问都变成“平均距离”的访问，NUMA 感知的优化空间被摊平。
- **裸片间互连（die-to-die interconnect，D2D）**：裸片之间的物理与协议接口；它是本篇的“跨裸片一跳”的载体，标准形态以 UCIe 为代表，厂商私有形态如 AMD 的 Infinity Fabric、英特尔的 AIB（高级接口总线）也属此类。D2D 的带宽、延迟与能效决定了“拆开”之后缓存与内存路径的额外税。

## 3. 技术路线

按“一致性与内存做到哪一层”分三条路线：

- **非一致多裸片路线**：裸片之间不维护硬件缓存一致性，各裸片像独立的加速单元，靠软件显式搬运数据（如 GPU 式编程模型）。实现最简单、互连要求最低，但软件改造成本最高，适合加速器类裸片，不适合通用 CPU 的多核共享内存模型。
- **一致多裸片路线（ccNUMA）**：裸片之间用硬件一致性协议连成一个共享内存域，软件看到的仍是单一地址空间；这是通用服务器 CPU 的主流路线。代价是一致性流量要过 D2D 互连，互连带宽与延迟直接影响多核扩展效率。
- **混合路线**：计算裸片内部一致、裸片之间按需一致或非一致——例如 CPU 裸片之间一致、AI 加速裸片与 CPU 之间用非一致的显式搬运。这条路线在异构芯片里常见：不是所有裸片都需要同一种一致性语义，按需取舍。

三条路线不是优劣排序：一致性是“花互连带宽买软件简单”，非一致是“花软件功夫省互连带宽”，选哪条取决于裸片的用途。

## 4. 系统架构

一个跨裸片芯片的缓存—互联—内存子系统通常由以下部分组成：

- **计算裸片内的 NoC**：核、L1/L2 与本地 LLC 分片通过 Mesh 或环互连；NoC 路由器负责包的转发与死锁避免（虚拟通道、转弯限制等经典手段）。
- **分布式末级缓存**：LLC 按地址哈希切分到各裸片，访问某地址先算它属于哪个分片，再路由到对应裸片；这意味着“缓存命中”也可能是“跨裸片命中”，命中延迟不再是常数。
- **D2D 互连层**：裸片之间的物理层与适配层（重传、可靠性）加协议层（一致性协议或 PCIe/CXL 语义）；以 UCIe 为例，规范分物理层、适配层与协议层，标准封装与先进封装是两个物理层档位，细节以 UCIe 联盟官方发布为准（待核实）。
- **I/O 裸片与内存控制器**：内存控制器常集中在 I/O 裸片上（成熟工艺即可，省先进工艺成本），计算裸片访存都要先经过 D2D 到 I/O 裸片；另一种布局是每个计算裸片各带一部分内存控制器，访存距离更短，但控制器与物理接口（PHY）的面积与功耗要乘以裸片数。
- **服务质量（QoS）与流量整形**：多类流量（核访存、一致性、I/O、加速器 DMA）共享同一 NoC 与 D2D 链路时，需要按流量类别分配带宽、限制低优先级流量的抢占，否则一个带宽饥渴的加速器会把 CPU 的延迟敏感流量挤垮。
- **地址映射与 NUMA 暴露**：硬件把“哪个地址在哪个控制器后面”以 NUMA 节点形式暴露给操作系统，操作系统再做页分配与任务绑定；硬件与操作系统的接口是 NUMA 拓扑表，错配的拓扑表会让调度器做出错误决策。

## 5. 代表性实现与开源项目

只列真实存在的架构方向与工具，不写未核实的性能数字：

- **AMD Infinity Fabric**：AMD 多裸片处理器的片内与裸片间一致互连方向，是“一致多裸片路线”的量产代表之一；其具体代际速率与拓扑细节以 AMD 官方发布为准（待核实）。
- **英特尔 AIB 与 EMIB/Foveros 上的互连**：AIB 是英特尔的裸片间接口总线方向，与其 2.5D/3D 封装平台配合使用；接口的具体速率档位以英特尔官方发布为准（待核实），封装平台本身归 37 篇。
- **Arm CHI 与 CML 网关方向**：Arm 的 AMBA CHI（Coherent Hub Interface）是一致互连协议方向，公开研究中提及的 CML（Coherent Multichip Link）网关概念是把 CHI 扩展到多芯片一致域的代理结构；本篇只记录其存在与方向，具体规范版本以 Arm 官方发布为准（待核实）。
- **开源研究模型**：gem5 等体系结构模拟器被公开研究用于 chiplet 间通信建模（如 C2C 网关与 CHI 跨裸片一致性的建模工作）；这类模型是研究工具，不是产品性能结论，引用其结论时须直读论文原文。
- **操作系统与性能工具（示例未实测）**：`numactl`（绑定任务与内存到 NUMA 节点）、`perf c2c`（定位跨核/跨节点的缓存行争用）是 NUMA 感知调优的常用工具方向；本篇所列命令为示例，未在本地实测，实际用法以工具官方文档为准。

## 6. 关键论文与标准

- **UCIe 规范（UCIe 联盟）**：1.0 版于 2022 年 3 月批准，基于 PCIe 与 CXL 协议；2.0 版（2024 年 8 月）加入 3D 封装支持与可管理性、可测试性（DFx）方向；3.0 版（2025 年 8 月）把数据率档位提高到 48 GT/s 与 64 GT/s（联盟官方表述为 2.0 的 32 GT/s 的两倍）。各版本的具体档位、物理层参数与功能细节以 UCIe 联盟官方发布为准（待核实），本篇不转载二手速率表。
- **AMBA CHI（Arm）**：一致互连协议方向，具体版本与跨芯片扩展细节以 Arm 官方发布为准（待核实）。
- **C2C 建模公开研究**：Chiplet 间通信建模（如 C2C 网关架构与 CHI 跨裸片一致性扩展的研究）属于公开研究方向，存在性与方向有公开记录，具体结论须直读原文（待核实），本篇不转述其仿真数字作结论。
- **暂无单一论文可作为本篇的理论来源**：缓存一致性、NoC 拓扑与 NUMA 都是教科书级的基础理论与工程协作的结果，单篇论文不能覆盖；需要原理细节的读者应读体系结构教材的相关章节。

## 7. 当前实验结果

本节不写横向性能数字：跨裸片缓存命中延迟、D2D 带宽与 NUMA 访存延迟的数字高度依赖裸片划分、互连档位、LLC 分片策略与负载，脱离配置没有可比性。只写经核查的定性结论：

- 跨裸片之后，“缓存命中”不再是单一延迟：本地分片命中、远端分片命中、远端内存访问是三档不同的延迟，软件与调度器必须按档位优化。
- 一致性流量是 D2D 互连的隐性税：核数与共享数据越多，一致性流量占比越高；共享写密集的负载在跨裸片结构上的扩展效率低于读密集或分区良好的负载。
- 内存交织是双刃剑：它摊平带宽、消除了单通道热点，但也抹掉了本地性；NUMA 感知的页分配与交织是两种互相冲突的优化，实际系统常在两者之间取折中（例如节点内交织、节点间 NUMA 感知），具体策略以平台官方指南为准。
- 公开研究中，跨裸片一致性建模（如 C2C 网关工作）反复指出死锁避免与 NUMA 配置是建模必须回答的问题——这说明一致性与互联不是“接上线就行”，而是需要协同设计。

## 8. 技术瓶颈

- **互连税**：D2D 互连的带宽密度、延迟与每比特能耗始终劣于同一裸片内的 NoC；LLC 分片越分散、一致性流量越大，互连税越重。
- **一致性扩展瓶颈**：目录规模、监听过滤与一致性协议状态机随裸片数增长而复杂化；跨厂商裸片的一致性互操作（协议子集、时序假设是否一致）比同一厂商内部更难验证。
- **NUMA 感知鸿沟**：硬件暴露的 NUMA 拓扑与操作系统的页分配、调度策略若不一致，分层收益会被抵消；虚拟化、容器进一步加厚了这层抽象，拓扑信息可能在传递中失真。
- **内存控制器布局的两难**：控制器集中在 I/O 裸片上省成本但拉长访存路径；控制器分散到各计算裸片上缩短路径但乘上面积与功耗；没有通用最优解，只有按负载的取舍。
- **QoS 与干扰**：共享 NoC 与 D2D 链路上的流量干扰会让延迟敏感负载的尾延迟恶化；QoS 机制本身（限流、优先级、虚拟通道划分）又会吃掉一部分带宽与面积。
- **验证瓶颈**：多裸片一致性与 NoC 死锁的验证空间随裸片数与流量组合爆炸式增长，形式化验证与仿真覆盖都难以穷尽；封装后的整体测试（归 37 篇）是最后一道关，但不是万能的。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：单裸片内的缓存、NoC 与内存控制器是成熟应用，但跨裸片的一致性、分布式末级缓存与 NUMA 感知的协同设计仍在工程化——量产产品已有，跨厂商通用互操作与最优布局仍在摸索中。

## 10. 未来研究问题

- **已有研究在做**：更低延迟、更高带宽密度的 D2D 互连；目录式一致性的可扩展实现；控制器内遥测辅助的分层与 NUMA 感知调度。
- **已有研究在做**：光互连进入封装内是否能缓解 D2D 的带宽密度与能耗瓶颈；这与本域新型计算架构方向相邻，但属于互联问题而非计算问题。
- **本文推测**：缓存层次的下一道门槛可能不是“更大的 LLC”，而是“更聪明的分片”——即按访问模式动态决定缓存分片归属；检验标准是未来产品是否普遍采用可重构的分片或近内存计算结构。
- **本文推测**：NUMA 感知的胜负手可能从操作系统转向硬件——由互连与控制器直接向调度器提供细粒度的延迟与带宽遥测；检验标准是主流平台是否把这类遥测做成标准接口。
