# 确定性网络和超低延迟

## 1. 研究问题

普通以太网与 IP 网络是尽力而为的：平时很快，但拥塞时延迟会突然变大、包会丢。对浏览网页这没关系，对三类应用却是致命的：工业控制（机器人、PLC 闭环控制要求毫秒甚至亚毫秒级的可预测延迟）、车载网络（刹车、转向信号不能等）、专业音视频（多路流必须同步）。这些应用过去用专用现场总线（如 CAN、PROFIBUS）解决，但专用总线带宽小、成本高、与 IT 网络割裂。

确定性网络要回答的问题是：能不能在标准以太网与 IP 网络上，给关键流一个可承诺的上界——“延迟不超过 X、抖动不超过 Y、丢包率低于 Z”，同时让普通流量共享同一张网？注意：确定性不等于“最快”，而是“最坏情况也可预测”；一个承诺 2 毫秒必达的网络，比一个平时 50 微秒、偶尔 5 毫秒的网络更“确定”。

## 2. 基础理论

- **时间同步**：全网设备共享同一时钟是确定性调度的前提；IEEE 802.1AS（gPTP，基于 IEEE 1588 PTP 的 profile）提供亚微秒级同步的机制。
- **调度与整形**：时间感知整形（TAS，IEEE 802.1Qbv）、信用整形（CBS，IEEE 802.1Qav）、帧抢占（IEEE 802.1Qbu / 802.3br）等机制决定关键帧何时发送、普通帧如何让路。
- **冗余与复制消除**：帧复制与消除（FRER，IEEE 802.1CB）把关键帧沿多条路径复制发送、去重接收，以丢包换可靠性。
- **资源预留**：流预留协议（SRP，IEEE 802.1Qat 及其后继）与集中式配置（CNC/CUC 模型）负责在全网为关键流预留带宽与调度时隙。
- **DetNet 架构**：IETF DetNet 把确定性从二层桥接扩展到三层 IP/MPLS 路由，目标是多跳路径上的有界延迟、低丢包、低抖动与高可靠性。

## 3. 技术路线

- **TSN 路线（二层）**：IEEE 802.1 TSN 任务组（由原 AVB 任务组于 2012 年更名而来）的一族标准：时间同步（802.1AS）、调度（802.1Qbv/Qav/Qch）、冗余（802.1CB）、预留与配置（802.1Qat/Qcc）、帧抢占（802.1Qbu）。TSN 不是一个协议，而是一套工具箱，各行业用“画像”（profile）挑子集：工业自动化（IEC/IEEE 60802）、车载（IEEE 802.1DG）、移动前传（IEEE 802.1CM）、航空航天（IEEE 802.1DP）、音视频（IEEE 802.1BA）。
- **DetNet 路线（三层）**：IETF DetNet 工作组：RFC 8557（问题陈述，2019 年）、RFC 8655（架构，2019 年）、RFC 9023（IP over TSN，2021 年）、RFC 9055（安全考虑，2021 年）。DetNet 明确限定在“单一管理域或封闭管理域组”内，不解决全互联网的确定性。
- **集中式配置路线**：CNC（集中式网络配置）+ CUC（集中式用户配置）模型：控制器统一算调度表并下发；适合静态拓扑的工厂与车载网络，动态拓扑下的重算成本是难点。
- **分布式配置路线**：SRP 等分布式预留协议，设备自主协商；适合动态加入/退出的音视频场景，但全局最优性弱于集中式。
- **无线确定性路线**：5G URLLC、Wi-Fi 7 的确定性增强与 TSN/DetNet 的结合，目标是把有界延迟从有线延伸到无线最后一跳；无线信道的随机性使“硬上界”更难承诺，相关进展以 3GPP 与 IEEE 官方发布为准（待核实）。

## 4. 系统架构

一个典型的 TSN/DetNet 系统由以下部分组成：

- **Talker / Listener**：发送与接收关键流的端站（传感器、控制器、音视频设备）。
- **时间同步域**：gPTP 主时钟与全网同步机制，所有调度以此为基准。
- **桥/路由器**：支持 TSN 调度、整形、抢占与 FRER 的交换机，或支持 DetNet 转发的路由器。
- **配置面**：CNC（集中式）或 SRP（分布式），负责流注册、路径计算与调度表下发。
- **DetNet 边界**：DetNet 域与 TSN 子网之间的互通点，负责流标识转换与服务映射（RFC 9023）。

关键设计取舍：集中式配置全局最优但重算慢，分布式配置灵活但难保证全局无冲突；实际系统常按行业画像二选一。

## 5. 代表性实现与开源项目

- **Linux TSN 生态**：Linux 内核的 taprio、etf 等排队规则与 tc 工具支持 TAS 等调度机制，是研究与原型验证的常用底座；以下配置示例仅为概念演示，示例未实测，具体命令与内核版本有关，生产部署须以设备厂商文档为准。
- **OpenDaylight DetNet 插件（研究项目）**：社区提出的 DetNet 控制器插件方向，用于控制器与 DetNet 设备协同；成熟度与维护状态以项目官方发布为准（待核实）。
- **行业画像实现**：汽车以太网（车载 TSN）、工业以太网厂商的 TSN 交换机与端站产品已进入量产市场，具体型号与认证状态以厂商发布为准（待核实）。
- **尚无全互联网确定性系统**：按 DetNet 章程的限定，确定性服务不面向全互联网大组域；任何“全网确定性”的说法都超出了现有标准范围。

## 6. 关键论文与标准

- IEEE 802.1AS：时间同步（gPTP）。
- IEEE 802.1Qbv：时间感知整形（TAS）；IEEE 802.1Qav：信用整形（CBS）；IEEE 802.1CB：帧复制与消除（FRER）；IEEE 802.1Qbu：帧抢占。
- IEEE 802.1Qcc：TSN 配置模型（CNC/CUC）；IEC/IEEE 60802：工业自动化 TSN 画像；IEEE 802.1DG：车载 TSN 画像。
- IETF RFC 8557（DetNet 问题陈述）、RFC 8655（DetNet 架构）、RFC 9023（DetNet IP over TSN）、RFC 9055（DetNet 安全考虑）。
- 暂无统一的广域确定性标准：跨域确定性、跨运营商确定性尚无冻结标准。

## 7. 当前实验结果

本节不写脱离配置条件的延迟数字（拓扑、跳数、帧长、调度表都会改变结果）。只写经核查的定性结论：

- TSN 机制在实验室与行业试点中已证明：时间同步 + 调度 + 冗余的组合可以在共享以太网上给关键流有界延迟与低丢包。
- DetNet 的三层架构与安全分析已标准化，但大规模多跳 DetNet 部署的公开案例有限，广域确定性仍是研究问题。
- 无线确定性（5G URLLC、Wi-Fi 确定性）仍在标准化与工程推进中，硬上界承诺能力弱于有线 TSN。

## 8. 技术瓶颈

- **时钟同步的脆弱性**：时间攻击、主时钟故障会让全网调度表失效；同步安全（RFC 9055 讨论的风险之一）是确定性网络特有的安全面。
- **调度表计算复杂度**：多流、多跳的调度表是组合优化问题，规模一大就难算、难重算；动态流加入时的增量调度仍是研究问题。
- **跨域与互通**：TSN 子网之间、TSN 与 DetNet 之间、确定性域与尽力而为域之间的映射与隔离，缺乏统一的跨域标准。
- **配置与运维**：CNC/CUC 模型要求精确的拓扑与流描述，配置错误会直接破坏确定性承诺；运维工具链成熟度低于传统网络。
- **无线最后一跳**：无线信道的干扰与衰落是随机的，硬上界在无线段难以兑现；有线确定性 + 无线尽力而为的混合，端到端上界会被最弱一段决定。
- **成本**：支持 TSN 的交换机、端站与测试设备成本高于普通以太网，限制了在成本敏感场景的普及。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：TSN 标准族与行业画像已发布、行业产品已量产，但 DetNet 大规模部署、跨域确定性与无线确定性仍在推进中，整体不能算成熟应用。

## 10. 未来研究问题

- **已有研究在做**：大规模调度表的高效算法与增量重算；TSN/DetNet 跨域互通；时间同步的安全加固。
- **已有研究在做**：无线确定性（5G/6G 与 Wi-Fi 的确定性增强）与有线 TSN 的端到端组合。
- **本文推测**：确定性网络的下一个门槛是“可验证的承诺”——运营商能否向用户出具可审计的延迟上界 SLA，而非实验室数字；检验标准是是否出现带罚则的确定性 SLA 商用合同。
- **本文推测**：AI 可能进入调度面（学习式调度表优化），但 AI 调度的可验证性（能否证明上界仍成立）会成为新问题；检验标准是 AI 调度方案是否附带形式化上界证明。
