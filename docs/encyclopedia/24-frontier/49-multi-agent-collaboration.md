# 自主 Agent 与多 Agent 协作

本篇是 [AI Agent 前沿总览](06-frontier-ai-agents.md) 的分支文章，只讲自主 Agent 与多 Agent 协作的研究侧问题。总览已给出四条研究路线与五层系统架构，本篇展开协作本身：自主的程度如何分级、协作结构有哪些、通信带来什么新问题、以及为什么“单个安全”推不出“群体安全”。工具调用与工作流编排的实操见本站 18 域[Agent 与工作流自动化](../18-local-ai/03-agent-workflow.md)，本篇只链接、不复制。多智能体安全内容的完整讨论见[AI 可解释性、可靠性与安全性](52-ai-explainability.md)，本篇只讲协作结构侧的对应问题，不展开安全方法论。

## 1. 研究问题

自主 Agent 指能在没有人类逐步指令的情况下，接受目标、制定计划、调用工具、处理异常并推进到结果的系统；多 Agent 协作则指多个这样的系统分工、通信、互相审阅或竞争，以完成单个 Agent 难以完成的任务。研究问题是：协作带来的收益是否大于协作本身的成本与风险？以及，协作结构本身会不会引入单个 Agent 没有的新失效模式？

现有方法解决不了这个问题的三个原因。第一，**自主程度没有统一分级**：从“按固定流程执行”到“自己定目标、自己选工具、自己决定何时停”，中间有多个等级；不说明等级，“自主 Agent”的说法就没有可比性。第二，**协作收益难以归因**：多 Agent 系统表现好，可能是分工的功劳，也可能是其中某一个强模型、某一次幸运采样、或某个人工干预的功劳；现有评估很少做消融，无法把协作的净收益分离出来。第三，**通信是双刃剑**：智能体之间用自然语言沟通灵活，但自然语言的歧义、误读与操纵空间也随之进入系统；一个智能体的误解会被另一个智能体当作事实接力下去。

## 2. 基础理论

- **分布式人工智能与多智能体系统**：经典研究中的协作、协商、拍卖、共识等机制，为 LLM 时代的多智能体协作提供了概念词汇；但经典方法多假设智能体行为可形式化，而语言智能体的行为难以形式化，旧结论不能直接搬运。
- **分工与专业化**：亚当·斯密以来的分工理论指出，专业化提高效率，但也增加协调成本；多智能体协作同样面临“分工收益 vs 沟通与纠错成本”的权衡，且该权衡随任务复杂度变化。
- **共识与拜占庭容错**：分布式系统中的共识理论讨论在部分节点故障或作恶时如何达成一致；语言智能体场景下，“故障”可能是幻觉、“作恶”可能是被提示注入，传统共识方法需要重新设计。
- **涌现与非组合性**：总览已提出的核心论点——系统整体行为不等于个体行为之和；单个智能体通过安全测试，不保证群体协作也安全。本篇把这一论点具体化为协作结构中的失效模式，见第 8 节。

## 3. 技术路线

- **角色分工协作**：给不同智能体分配研究员、工程师、评审员等角色，各自产出、互相审阅。做法直观，评审环节理论上能拦截错误；实际中评审员可能盲从生产者、或用同样的错误前提做评审，导致“评审”只是把错误复述一遍。
- **编排器—执行器**：中心智能体拆任务、派活、汇总结果，执行智能体并行干活。适合可分解的任务；中心编排器是单点瓶颈与单点故障，且编排错误会同时污染所有执行分支。
- **辩论与多视角**：多个智能体对同一问题给出不同答案并互相辩论，最后汇总。理论上能暴露盲点；实际中辩论可能收敛到最自信而非最正确的答案，且辩论轮次增加成本与延迟。
- **层级与流水线**：智能体按层级组织，下层产出、上层审核与整合；或按流水线组织，前一环节的输出是后一环节的输入。结构清晰，但上游错误会沿流水线放大，且每一环节的“通过标准”都需要事先定义，否则环节只是走过场。
- **市场与协商机制**：智能体通过报价、竞标、协商分配任务与资源。适合资源竞争场景；但语言智能体的报价行为难以验证，容易出现策略性操纵，且机制设计本身是开放问题。
- **去中心化自组织**：无中心编排器，智能体通过共享状态或消息总线自发协调。灵活性高，但行为难以预测、难以审计，出问题后难以归因；目前多停留在仿真演示层面。

## 4. 系统架构

研究型多智能体系统的组成部分与总览一致，本篇补充协作特有的三点：

- **通信层**：消息格式（自然语言、结构化消息或混合）、通信拓扑（星型、链式、网状、层级）、消息可见性（谁能看到谁的消息）；通信拓扑决定了错误与污染的扩散路径，是协作系统设计中最应先定的一层。
- **任务图与状态层**：任务如何拆解、依赖关系如何表示、完成标准如何判定；没有显式任务图的多智能体系统，等于把“任务拆得对不对”这个最关键的判断交给了模型的即兴发挥。
- **监督与接管层**：人类在何时、以何种方式介入（审批关键行动、接管失败任务、叫停整个系统）；自主程度越高，接管设计越重要，而不是越不重要。

尚无代表性商用系统可以按“通用多智能体自主协作”来介绍：云上可用的多是框架、演示与受限场景产品，见总览。

## 5. 代表性实现与开源项目

- **AutoGen、CrewAI、LangGraph 等开源框架**：提供多智能体编排、角色定义与消息传递的基础设施；它们是搭系统的工具，不是系统本身正确的保证，用同一框架搭出的系统质量可以天差地别。
- **学术界的多智能体仿真**：如小镇仿真、协作游戏环境等研究载体，用于观察多智能体行为的涌现现象；仿真中的涌现结论向真实任务的迁移需谨慎，仿真环境的简化假设可能正是结论成立的前提。
- **评估基准**：SOP-Bench 等针对复杂操作流程的智能体评估工作，其公开结论之一是编排层敏感性——同一模型换一套编排成绩可差两位数百分点；本篇不采信任何基于单一编排的协作收益排名。

## 6. 关键论文与标准

- Hammond 等人《Multi-Agent Risks from Advanced AI》（2025）：多智能体风险的系统论述，安全属性不组合、群体可能产生个体所没有的危险能力等论点。
- ACM《AI Matters》第 11 卷第 3 期（2026 年 4 月刊）关于 agentic AI 评估、素养与治理的讨论：多数基准评估的是可测量的合成任务，而非真实部署中的成本、延迟、可靠性与失效模式。
- 暂无公开标准：多智能体协作的评估基准、安全测试方法、自主程度分级与责任划分均无公认标准。

## 7. 当前实验结果

本节只写定性结论与方法论问题，不写协作收益排名：

- 评估失效是公开承认的问题：基准成绩受编排层影响大，只看基准分数选框架或选协作结构会误导；消融实验（去掉某一路协作、看性能变化）是判断协作净收益的必要步骤，但现有公开研究中消融并不普遍。
- 协作收益的证据多来自特定任务类型：可分解、可并行、有明确评审标准的任务上，协作收益较易观察；开放、模糊、需要创造性判断的任务上，协作可能增加沟通成本而不带来净收益；任务类型不说明的“多智能体优于单智能体”说法没有意义。
- 安全失效模式已有公开归类：目标漂移、工具权限提升、记忆污染、规划与执行脱节、多步组合成的静默策略违规；这些失效在单轮对话评估里看不见，只在长程多步轨迹里出现，见[AI 可解释性、可靠性与安全性](52-ai-explainability.md)。
- 自主程度与可靠性的关系尚未建立：在受限场景中提高自主程度是可行的，但自主程度与任务成功率、成本、风险之间的定量关系因场景而异，未见通用曲线。

## 8. 技术瓶颈

- **评估瓶颈**：没有能同时度量正确性、成本、延迟、可靠性与失效模式的评估体系；协作的净收益无法与模型能力、编排质量、人工干预分离。
- **安全非组合性瓶颈**：群体可能合谋、可能通过拆解任务绕过防护、可能在实例之间相关地失齐；防御单个智能体的方法不能直接推广到群体。
- **通信瓶颈**：自然语言通信的歧义与操纵空间、消息量的成本爆炸、错误沿通信链的放大，都是协作特有的成本。
- **长程可靠性瓶颈**：任务越长、参与智能体越多，错误累积、上下文漂移、工具调用失败的概率越高。
- **责任与审计瓶颈**：决策轨迹分散在多个智能体之间，出问题后难以归因；审计工具与责任划分规则均不成熟。
- **成本瓶颈**：多智能体协作的消息、重试与评审开销可观；“协作收益大于协作成本”在很多场景下仍是未证实的前提。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：多智能体协作已有框架、基准与演示，但评估体系、安全组合性与长程可靠性三大问题均未解决，厂商自己的部署也多为受限场景，尚未进入可通用交付的工程阶段。

## 10. 未来研究问题

- **已有研究在做**：面向长程轨迹的安全评估框架、记忆污染的防御、规划与执行一致性的检查方法。
- **已有研究在做**：协作净收益的消融评估方法、通信拓扑与失效扩散的关系研究。
- **本文推测**：多智能体协作可能先从“受限场景的白名单协作”（固定角色、固定工具、固定通信渠道）落地，而不是从开放协作落地；检验标准是受限协作系统是否先于开放系统进入商用。
- **本文推测**：自主程度分级标准可能先于协作收益标准出现，因为安全与审计需求迫使人们先说清“系统在什么等级上自主、人类在何处接管”；检验标准是不同厂商能否用同一套分级语言描述各自系统。
