# 后冯·诺依曼架构

> 本篇是新型计算架构分支的范式总纲。它讲“为什么要离开冯·诺依曼架构、离开之后有哪些大方向”，各方向的具体器件、产品与实验细节归各三级主题篇：光子见 [光子计算](73-photonic-computing.md)，存算一体见 [存算一体与近存计算](75-compute-in-memory.md)，模拟见 [模拟计算](74-analog-computing.md)，类脑芯片产品见 [神经形态计算](02-neuromorphic-computing.md)。总览见 [新型计算架构：光子与存算一体](08-new-computing-arch.md)，本篇不重复总览内容。

## 1. 研究问题

冯·诺依曼架构的核心约定是：存储程序，处理器与存储器分离，程序按指令序列一步步取指、译码、执行、存回。这个约定在 1945 年前后成型（以 EDVAC 报告为代表），它最大的优点是通用——同一台机器换程序就能做完全不同的事。它的代价也写在结构里：计算要数据，数据在存储器里，处理器每算一步都要把数据搬过来、用完再搬回去。

这个代价在两个趋势下被放大。第一，算力增长长期快于访存带宽与延迟的改善，处理器经常不是在算，而是在等数据，这就是“存储墙”。第二，AI 工作负载把权重规模推到极大：一次推理要反复读取海量参数，搬运的延迟与能耗常常超过算术运算本身。于是研究问题就变成一句话：**能不能换一种组织计算的方式，让数据少搬、甚至不搬，同时不丢掉通用性？**

“后冯·诺依曼”不是一个具体的机器，而是一组回答这个问题的尝试的总称。判断它们成败的标准也必须先讲清：一个新范式要成立，不仅要在某个算子（例如矩阵乘法）上快，还要能表达控制流、条件分支、任意算法，能跑用户自己的程序，能被编译工具链支持，能以可接受的成本量产。只满足第一条的，叫加速器，不叫新架构。

## 2. 基础理论

- **冯·诺依曼瓶颈**：John Backus 在 1977 年图灵奖演讲中提出的批评——处理器与存储器之间的窄通道限制了系统吞吐；程序语言与体系结构都被这条通道的形状所束缚。来源：Backus《Can Programming Be Liberated from the von Neumann Style?》（1977）。
- **存储墙（memory wall）**：处理器速度与存储器延迟改善速度之间的差距随时间拉大；缓存层级、预取、乱序执行都是在冯·诺依曼框架内缓解它，而非消除它。
- **数据流（dataflow）**：指令不在程序计数器的驱动下顺序执行，而在操作数齐备时被触发执行；计算由数据依赖关系驱动，而非由控制序列驱动。来源：Dennis 等人的数据流模型研究（1970 年代起）。
- **归约与函数式执行模型**：把程序看作表达式求值，执行即归约；这类模型在理论上摆脱了可变存储与顺序状态，但工程化时仍需解决共享、并行调度与 I/O 问题。
- **存算融合的物理原理**：利用欧姆定律与基尔霍夫定律，在存储阵列中用电流求和直接完成乘积累加（见 [存算一体与近存计算](75-compute-in-memory.md)，本篇只点名、不展开器件细节）。
- **Amdahl 定律与并行边界**：任何架构的加速都受串行部分制约；新范式若只加速可并行部分而让串行与控制部分更慢，系统级收益会被吃掉。这是评估一切“后冯·诺依曼”宣称时必须先算的账。

## 3. 技术路线

后冯·诺依曼的路线可以按“动了架构的哪一部分”分成五条，每条动的东西不一样，代价也不一样：

- **路线一：数据不动，计算过去（存算一体与近存计算）**。把计算单元放进存储阵列或紧贴存储器，让权重留在原地。这是改动最小、离量产最近的一条，但它动的是“算在哪里”，不动“算什么、按什么顺序算”。细节归 [存算一体与近存计算](75-compute-in-memory.md)。
- **路线二：换执行模型（数据流与事件驱动）**。不再由程序计数器驱动指令流，而由数据就绪或事件到达驱动计算。类脑芯片的脉冲事件驱动属于这一路线的特例（产品侧见 [神经形态计算](02-neuromorphic-computing.md)）。它的难点是编程模型：程序员习惯了顺序思维，数据流程序的调试、确定性与死锁分析都更难。
- **路线三：换计算载体（光子、模拟、量子）**。用光、连续物理量或量子态代替数字电子信号做运算。载体换了，算得快的运算变了，但存储、非线性、控制与纠错往往要换回电子或另起炉灶。光子路线归 [光子计算](73-photonic-computing.md)，模拟路线归 [模拟计算](74-analog-computing.md)，量子路线归 [量子计算基础](01-quantum-computing.md)，本篇不重复三者的器件内容。
- **路线四：换并行组织（分布式与异构）**。不追求单台机器的范式革命，而是把计算组织成多节点、多类型处理器的协同系统。严格说这仍是冯·诺依曼节点的组合，但系统级看，数据局部性、调度与容错成了新的“一等公民”。细节归 [分布式计算架构](76-distributed-arch.md) 与 [异构计算与 CPU/GPU/NPU/TPU 协同](77-heterogeneous-computing.md)。
- **路线五：换硬件形态（可重构计算）**。硬件本身不再固定，逻辑结构随任务重构，介于通用处理器与专用芯片之间。这是“以结构换效率”的路线，代价是编译与重构开销。细节归 [可重构计算与 FPGA](78-reconfigurable-fpga.md)。

五条路线不是互斥的：真实系统常是组合，例如“数据流调度的存算加速器”“光子张量核 + 电子控制”。分类的意义在于定位瓶颈——每条路线解决一个瓶颈的同时，往往把另一个瓶颈放大。

## 4. 系统架构

一个典型的后冯·诺依曼系统（以“异构存算加速系统”为示意）由以下部分组成，缺一不可：

- **宿主与控制平面**：仍是冯·诺依曼通用处理器，负责操作系统、控制流、异常处理与任务调度。新范式至今没有替代这一层，它只是把“算得重的部分”外包出去。
- **非冯·诺依曼加速平面**：存算阵列、光子张量核、数据流引擎或可重构 fabric，负责某一类密集运算。
- **转换与搬运平面**：数模/模数转换、光电转换、片间互连与存储层级。讽刺但真实：许多新范式宣称“消灭搬运”，系统级却在转换平面上重新引入搬运与延迟。总览 [新型计算架构：光子与存算一体](08-new-computing-arch.md) 已把转换瓶颈列为共性瓶颈，本篇不再展开。
- **编译与映射层**：把高级程序切分到宿主与加速平面、把算子映射到非标准硬件、并在精度与噪声约束下保证结果正确。这是目前最薄弱的一层：硬件原型可以跑固定演示网络，编译器能不能跑用户自己的模型，是区分“演示”与“产品”的试金石。
- **评估层**：基准测试与仿真（见 [计算架构仿真与基准测试](79-arch-simulation-benchmarks.md)）。没有统一评估方法，不同范式的数字无法比较，这是本分支所有文章共同遵守的纪律：数字必须带来源与测试条件，否则不写。

这个分层说明一个关键判断：**可预见的未来是“冯·诺依曼宿主 + 非冯·诺依曼加速器”的混合系统，而非“后冯·诺依曼计算机”整体取代通用计算机。** 任何宣称“彻底取代 CPU/GPU”的说法，都需要先回答宿主层、控制流与编译层由谁来承担。

## 5. 代表性实现与开源项目

只列范式层面的代表性方向，不写未核实的性能倍数：

- **数据流处理器研究**：MIT 的数据流体系结构、后续的波形数据流与粗粒度可重构阵列（CGRA）研究，均属于“换执行模型”路线；CGRA 的工程细节归 [可重构计算与 FPGA](78-reconfigurable-fpga.md)。
- **存算一体原型**：SRAM、RRAM、PCM、MRAM 各类存算原型（器件对比归 [MRAM、ReRAM 与 PCM](18-mram-reram-pcm.md)，系统侧归 [存算一体与近存计算](75-compute-in-memory.md)）。
- **光子与模拟原型**：集成光子张量核、模拟存算阵列，均处于原型阶段（各归 [光子计算](73-photonic-computing.md)、[模拟计算](74-analog-computing.md)）。
- **尚无代表性商用系统**：按“通用可编程、按商用标准交付、能跑用户自有程序”的定义，今天不存在商用的后冯·诺依曼通用计算机；现有交付物都是特定场景的加速器或研究原型。

## 6. 关键论文与标准

- John Backus, 《Can Programming Be Liberated from the von Neumann Style?》, ACM 图灵奖演讲，1977 年——“冯·诺依曼瓶颈”一词的经典出处。
- J. B. Dennis 等，数据流模型相关论文（1970 年代起）——数据流执行模型的理论来源。
- 冯·诺依曼《First Draft of a Report on the EDVAC》（1945 年）——存储程序概念的原始文献；读它才能理解后冯·诺依曼到底在反什么（是“分离结构”，不是“存储程序”本身）。
- 暂无统一标准：后冯·诺依曼架构没有类似指令集标准或通用编程模型；各原型之间的结果不可直接比较（评估方法见 [计算架构仿真与基准测试](79-arch-simulation-benchmarks.md)）。

## 7. 当前实验结果

本节不写性能倍数：厂商与实验室宣传的“比 GPU 快多少倍、能效高多少倍”几乎都脱离了统一的测试条件（精度、模型、批量、是否含转换与存储开销），达不到“数字 + 来源 + 测试条件”三件套的标准，本篇一律不采信。只写经核查的定性结论：

- 存算、光子、模拟三条路线在“特定运算、特定规模、特定精度”上均有可复现的原型演示；但在通用性、精度、软件栈三项上均未达到通用计算的要求。
- 数据流与事件驱动模型在稀疏、流式负载上有理论优势，但编程模型与工具链成熟度落后于主流框架，限制了它走出实验室。
- 分布式与异构路线是例外：它们已经是工程现实（云、超算、手机 SoC 每天都在用），但它们解决的是系统级组织问题，不是单机范式问题——把它们算作“后冯·诺依曼”时要注明这个口径差异。

## 8. 技术瓶颈

- **通用性缺口**：新范式擅长矩阵乘法等规则密集运算，不擅长控制流、分支、指针追逐与任意算法；通用性是与主流架构之间最根本的差距。
- **编译与编程模型缺口**：没有成熟的编译器把通用程序自动切分、映射到非标准硬件并保证正确性；多数原型仍依赖手工映射与固定演示。
- **转换与互连瓶颈**：新计算平面与数字存储、宿主处理器之间的转换（DAC/ADC、光电转换）与互连，常常吃掉核心运算的收益。
- **精度、噪声与确定性**：模拟与光子路线的精度受噪声与器件差异制约；数据流与事件驱动路线的执行时序与确定性需要新的验证方法。
- **可制造性与成本**：新型器件的良率、代工兼容性与规模化集成仍在验证中；实验室原型与量产之间有距离。Chiplet 与先进封装细节归 [先进芯片与 Chiplet](05-advanced-chips-chiplet.md) 与 [Chiplet、先进封装与 3D IC](37-chiplet-packaging-3d.md)，本篇只链接、不展开。
- **评估缺失**：缺乏跨范式的统一基准与测试条件，导致宣传数字无法比较、无法证伪。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：后冯·诺依曼各路线均有原型演示，但通用性、编译工具链与规模化量产三项均未解决，尚无通用可编程的商用后冯·诺依曼计算机；其中分布式与异构组织已是工程现实，但它们属于系统级组合，不改变“单机范式仍是冯·诺依曼”的判断。

## 10. 未来研究问题

- **已有研究在做**：跨范式的统一编译与映射工具链——如何把通用程序自动切分到宿主与各类加速平面并保证精度与正确性。
- **已有研究在做**：新范式的基准测试方法——在统一测试条件下比较存算、光子、模拟、数据流路线（方法见 [计算架构仿真与基准测试](79-arch-simulation-benchmarks.md)）。
- **本文推测**：后冯·诺依曼最可能的落地形态是“宿主 + 多种专用加速平面”的混合系统，而不是单一新范式通吃；检验标准是是否出现能跑用户自有程序、可量产交付的混合系统产品。
- **本文推测**：理论边界问题——是否存在一类“冯·诺依曼结构下本质低效、而某新范式下本质高效”的问题类，并能被形式化刻画；目前只有个案（矩阵乘法、稀疏事件处理），没有一般性定理。
