# 可重构计算与 FPGA

> 本篇是新型计算架构分支中“换硬件形态”方向的三级展开，归属见 [后冯·诺依曼架构](72-post-von-neumann.md) 的路线五与 [新型计算架构：光子与存算一体](08-new-computing-arch.md) 总览的边界说明。它讲可重构计算本身（FPGA 与 CGRA），不讲某一款芯片的产品细节（归 [先进芯片与 Chiplet](05-advanced-chips-chiplet.md)），不讲异构系统中的通用协同问题（归 [异构计算与 CPU/GPU/NPU/TPU 协同](77-heterogeneous-computing.md)），Chiplet 与先进封装细节归 [Chiplet、先进封装与 3D IC](37-chiplet-packaging-3d.md)，只链接、不展开。

## 1. 研究问题

通用处理器灵活但能效低，专用芯片（ASIC）高效但出厂后改不了。可重构计算要回答的问题是：**能不能有一种硬件，出厂后仍可按任务重编程，既保留接近专用芯片的效率，又保留接近通用处理器的灵活性？**

FPGA 是这个问题的经典答案：芯片上的逻辑单元与互连在出厂后仍可由比特流重新配置，硬件结构本身成了“程序”。但这个答案自带代价：可重构的灵活性要用面积、功耗与编译时间来换——同样的逻辑，FPGA 实现通常比 ASIC 大、慢、耗电；把算法变成比特流的编译流程也比把算法变成机器码长得多、难得多。可重构计算的研究，就是不断收窄这个代价的过程。

## 2. 基础理论

- **查找表（LUT）**：FPGA 的基本逻辑单元；一个 n 输入 LUT 可以实现任意 n 输入布尔函数，逻辑功能由配置存储器的内容决定，而非由固定电路决定。这是“硬件可编程”的物理基础。
- **可编程互连**：逻辑单元之间通过可编程开关矩阵连接；互连的可编程性带来灵活性，也带来延迟与面积开销——FPGA 的性能瓶颈常常在互连而非逻辑单元。
- **时序收敛**：FPGA 设计必须满足建立时间与保持时间约束；布局布线的结果决定最高时钟频率，时序不收敛的设计即使逻辑正确也无法按目标频率运行。
- **高层次综合（HLS）**：把 C/C++ 等高级语言描述的行为自动综合成 RTL 电路；HLS 的目标是降低 FPGA 开发门槛，代价是生成的电路质量通常低于手写 RTL，且对代码风格敏感。
- **动态部分重构（DPR）**：在 FPGA 其余部分继续运行的同时，只重构其中一个区域；这是 FPGA 做“硬件多任务”与“硬件时分复用”的基础，但需要分区、隔离与比特流管理的专门支持。
- **粗粒度可重构阵列（CGRA）**：以算术单元（ALU、乘法器）而非位级 LUT 为基本单元的可重构阵列；粒度介于 FPGA 与 ASIC 之间，编译更简单、效率更高，但灵活性低于 FPGA。

## 3. 技术路线

- **细粒度 FPGA 路线（LUT 级）**：最灵活，可实现任意数字逻辑；代价是面积与功耗开销最大、编译时间最长。适合原型验证、通信、信号处理与定制加速。
- **粗粒度 CGRA 路线**：以字级运算单元为粒度，重构速度快、编译简单、能效比 FPGA 好；代价是只能表达规则的数据流与循环结构，不适合任意控制逻辑。近年 AI 加速器中常见 CGRA 思想。
- **SoC FPGA 路线（处理器 + FPGA fabric）**：把 ARM 等硬核处理器与 FPGA fabric 做到同一芯片（如 Xilinx Zynq、Intel SoC FPGA）；处理器跑控制与操作系统，fabric 跑定制加速，片内互连代替板级总线。这是今天 FPGA 系统的主流形态。
- **HLS 与领域专用语言路线**：用 HLS、Chisel、SpinalHDL 等工具降低硬件描述门槛；目标是让软件工程师也能做 FPGA 开发，但工具成熟度与生成电路质量仍是瓶颈。
- **云端 FPGA 路线（FPGA 即服务）**：云厂商把 FPGA 以虚拟化方式提供给用户，按需加载比特流；适合突发加速需求，但虚拟化、隔离与比特流安全仍是开放问题。
- **动态部分重构与硬件多任务路线**：用 DPR 实现 FPGA 的时分复用与多租户；研究上已证明可行，工程上仍受分区固定、重构时间与隔离机制的限制。

## 4. 系统架构

一个典型的 SoC FPGA 系统由以下部分组成：

- **处理系统（PS）**：硬核 CPU、内存控制器、外设接口，运行操作系统与控制软件。
- **可编程逻辑（PL）**：LUT、DSP 单元（硬核乘法累加）、块 RAM（BRAM）与可编程互连组成的 fabric；DSP 与 BRAM 是硬核资源，数量有限，是加速器设计的第一约束。
- **PS–PL 互连**：AXI 等片内总线连接处理器与 fabric；互连带宽决定加速器与处理器之间的数据搬运代价，是系统级瓶颈之一。
- **配置与重构通路**：比特流加载、部分重构控制器、配置存储器；重构时间（毫秒级）决定 DPR 能否用于实时任务切换——重构太慢的场景只能用静态配置。
- **开发工具链**：综合、布局布线、时序分析、仿真与调试；工具链质量直接决定 FPGA 开发效率，是 FPGA 生态与 ASIC 生态差距最大的地方之一。
- **运行时与驱动**：操作系统驱动、加速器 API、比特流管理；没有它们，FPGA 只是裸硬件，应用无法调用。

## 5. 代表性实现与开源项目

只列真实存在的项目与平台，不写未核实的性能数字：

- **AMD/Xilinx Vivado 与 Vitis**：FPGA 开发的主流工具链；Vivado 负责 RTL 综合与实现，Vitis 提供 HLS 与统一软件平台。
- **Intel Quartus Prime**：Intel FPGA 的开发工具链，与 Vivado 对应。
- **开源工具链（Yosys、nextpnr、Verilator）**：Yosys 做综合，nextpnr 做布局布线，Verilator 做仿真；开源工具链覆盖部分 FPGA 器件，是学术研究与开源硬件的重要基础，但器件覆盖与时序质量与厂商工具链仍有差距。
- **Chisel 与 SpinalHDL**：基于 Scala 的硬件构造语言，目标是提高硬件描述的可复用性与参数化能力。
- **Xilinx Zynq 与 Intel SoC FPGA 系列**：SoC FPGA 的代表性产品线，处理器 + fabric 的组合是嵌入式与边缘加速的主流形态。
- **云端 FPGA 实例**：AWS F1 等云端 FPGA 服务是“FPGA 即服务”的代表；具体规格与定价以云厂商官方发布为准。

## 6. 关键论文与标准

- 可重构计算的经典综述：FPGA 架构、HLS 与动态重构的系统性论述，见 2000 年前后 HLS 综述与后续 FPGA 架构综述文献。
- 动态部分重构综述：FPGA 布局规划与动态部分重构的分类研究（近年综述），说明 DPR 的工程约束（分区固定、重构时间、隔离）。
- 暂无统一标准：FPGA 比特流格式、HLS 语言子集、DPR 接口均无跨厂商统一标准；设计在厂商之间不可直接移植。

## 7. 当前实验结果

本节不写性能倍数：FPGA 加速比高度依赖算法、数据规模、时钟频率与实现质量，脱离测试条件的数字无法比较，本篇一律不采信。只写经核查的定性结论：

- FPGA 在原型验证、通信、信号处理、定制低延迟加速等场景已是工程现实；SoC FPGA 在嵌入式与边缘场景大规模出货。
- HLS 已可用，但生成电路质量与手写 RTL 仍有差距；复杂设计仍需 RTL 或 HLS+RTL 混合。
- 动态部分重构在研究上已证明可行（视觉流水线时分复用等原型），但工程化仍受分区、重构时间与隔离机制限制，未成为主流部署方式。
- CGRA 在 AI 加速器中已有产品化应用，但作为独立通用架构仍在演进中。

## 8. 技术瓶颈

- **面积与功耗开销**：可编程互连与配置存储器占用大量面积与功耗；同样逻辑的 FPGA 实现通常比 ASIC 大、慢、耗电，这是可重构的固有代价。
- **编译时间与时序收敛**：大设计的布局布线可耗时数小时，时序不收敛时需要反复迭代；编译时间是 FPGA 开发效率的主要瓶颈之一。
- **开发门槛**：硬件思维（并行、时序、资源约束）与软件思维差异大；HLS 降低了门槛但未消除它，FPGA 人才供给仍是瓶颈。
- **DPR 的工程约束**：重构区域大小在设计时固定、重构有时间开销、区域间隔离需要专门机制；硬件多任务的灵活性仍远低于软件多任务。
- **生态与标准缺失**：比特流、HLS 子集、DPR 接口均无跨厂商标准，设计锁定在厂商工具链内。
- **验证难度**：硬件验证（仿真、形式化、片上调试）比软件测试复杂得多；大规模 FPGA 系统的正确性验证仍是工程难题。
- **成本**：大容量 FPGA 单价高；量大时 ASIC 更便宜，量小时 FPGA 更划算——这个交叉点决定 FPGA 的适用场景边界。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：FPGA 作为原型验证与定制加速平台已大规模生产应用，但 HLS 质量、DPR 工程化、跨厂商标准与编译效率仍在演进中；CGRA 作为独立架构仍在从研究走向产品。

## 10. 未来研究问题

- **已有研究在做**：HLS 质量提升——让高级语言综合出的电路接近手写 RTL 的质量。
- **已有研究在做**：DPR 的布局规划与调度——用更灵活的分区与调度降低重构开销、提高 fabric 利用率。
- **已有研究在做**：FPGA 虚拟化与多租户隔离——让云端 FPGA 安全地共享给多个用户。
- **本文推测**：可重构计算最可能的演进方向是“粒度分层”——LUT 级 FPGA 做原型与长尾定制，CGRA 级阵列做规则加速，ASIC 做大批量；三者共存而非一者取代全部；检验标准是 CGRA 是否在 AI 加速器之外找到第二类大规模应用。
