# 并行算法与大规模矩阵计算

## 1. 研究问题

科学计算里的大规模矩阵问题长这样：解一个 n 元线性方程组、算一批特征值、做一次大规模矩阵乘法——当 n 达到几十万、矩阵本身放不进单台机器的内存时，问题就不再是“算法对不对”，而是“数据怎么分、通信怎么走、负载怎么匀”。并行算法要回答的问题是：在 p 个处理器上，如何把计算与数据分下去，让总时间随 p 增大而真正下降，而不是被通信与同步吃掉。

本篇只讲算法层：数据划分方式、矩阵乘法与分解的并行做法、迭代法与 FFT 的并行结构、以及从 ScaLAPACK 到 SLATE 的库演进。接口语法归本域 12 篇（MPI、OpenMP、CUDA、HIP、SYCL），集群怎么组织、作业怎么调度归[超算与高性能计算入门](03-hpc-supercomputing.md)，本篇不重复。

两个前提概念先讲清，否则后文的取舍无从谈起：**计算量**（如稠密矩阵乘法约 2n³ 次浮点运算，是数学量，不是实测速度）与**通信量**（处理器之间必须交换的数据量与消息次数）是并行算法的两本账；好算法的标准是两本账同时算得过来——计算分得匀、通信压得低。只谈一本账的“并行算法”都是耍流氓。

## 2. 基础理论

- **数据划分：1D 与 2D**：把矩阵按行（或列）分给一排处理器叫 1D 划分，实现简单，但某些步骤（如分解中的列操作）会让部分处理器闲置；把处理器排成二维网格、矩阵按二维分块分下去叫 2D 划分，负载更匀、通信模式更规则，是大规模稠密计算的主流选择。
- **二维块循环划分（2D block-cyclic）**：把矩阵先切成小块、再按“块行号、块列号对处理器网格取模”的方式循环分配；这样即使矩阵带状、三角等结构不均匀，每个处理器分到的块在全局也大致均匀，是 ScaLAPACK 的经典布局。块大小是调优参数：块太小则消息多、单块计算效率低（调不动 BLAS 3 级运算），块太大则负载不匀、流水线填不满。
- **通信成本模型**：一次消息的成本常建模为延迟 α（与消息大小无关的固定开销）加带宽项 β×消息字节数；算法设计的目标通常是同时压低消息次数（受 α 支配）与总字节数（受 β 支配），两者不可兼得时按硬件特性取舍。注意：这是理论模型，不是实测数字——真实互连的 α、β 须在目标系统上实测，本篇不给任何具体数值。
- **强扩展与弱扩展**：定义见总览第 2 节；并行算法的评价必须说明是哪一种：固定问题规模加处理器叫强扩展（看时间降多少），每处理器规模固定、总规模随处理器增长叫弱扩展（看时间稳不稳）。不注明扩展类型的加速比没有意义。
- **数值稳定性与并行化的张力**：并行化会改变运算顺序（如规约顺序、主元选取范围），浮点加法不满足结合律，运算顺序一变，结果的舍入误差也会变；主元选取、重排序等数值策略在并行时常常要让位于通信结构，这是“算法正确”与“算法并行”之间的真实 trade-off，不是实现 bug。
- **稠密与稀疏的分界**：稠密矩阵（大部分元素非零）与稀疏矩阵（大部分元素为零）的并行算法几乎是两个世界：稠密靠规则划分与 BLAS 3 级运算取胜，稀疏靠图划分（如按非零结构切分、减少割边）与预处理取胜；本篇以稠密为主，稀疏只在第 3 节末尾对照，不展开稀疏求解器的完整体系。

## 3. 技术路线

按问题类型分五条路线，每条一句话讲清做法与取舍：

- **并行矩阵乘法（C = C + AB）**：核心操作，计算量约 2n³。两大经典做法：SUMMA（可扩展通用矩阵乘法算法）——沿处理器行的列广播与沿列的行广播相结合，每步做分块外积更新，简单、易推广到非方阵与非方处理器网格，是实践中的主流；Cannon 算法——先把 A 的行块、B 的列块错位（skew），再每步只与近邻交换一块并做局部乘法，延迟成本更低，但要求处理器数为完全平方、矩阵分块对齐，推广性差。实践中 SUMMA 更常用，Cannon 更多出现在教材与特定拓扑上。
- **并行分解与直接求解（LU、Cholesky、QR）**：解线性方程组的主流直接法。做法是分块分解 + 尾矩阵更新（trailing update）的流水线：先分解当前列块（面板分解，panel factorization），再把结果广播、更新剩余子矩阵；瓶颈在面板分解的串行段与广播同步，缓解办法是“前瞻”（lookahead）——让部分处理器提前算下一步面板，与尾矩阵更新重叠。Cholesky（对称正定）省一半计算量、QR（最小二乘）数值更稳但计算量更大，选型首先看矩阵性质，其次看并行结构。
- **并行迭代法（Krylov 子空间法等）**：解大规模稀疏或矩阵规模过大、直接法内存装不下的问题。做法是每步做稀疏矩阵—向量乘（SpMV）加少量向量内积与规约；瓶颈从“算”变成了“同步”——每次内积都要一次全局规约，延迟随规模放大。缓解方向是通信避免（communication-avoiding）变体：把 s 步迭代的依赖重排、一次通信换多步计算，代价是数值稳定性与实现复杂度，见第 8 节。
- **并行 FFT 与谱方法**：一维 FFT 靠蝶形网络天然并行；多维 FFT 的并行做法通常是“每维轮流做一维 FFT、维间转置数据”（transpose）：每维 FFT 本地算、换维时全局交换数据，转置步的全局通信（常为全交换 all-to-all）是瓶颈，规模上去后转置成本主导总时间。
- **3D 与通信避免算法（前沿方向）**：经典 2D 算法把矩阵分在二维网格上；3D 算法把计算图本身再切一层（复制部分数据换通信量），用额外内存换更少的通信；通信避免算法则从下界出发重排计算顺序（如避免通信的 LU、QR），用数值与实现复杂度换通信量的数量级下降。这类算法是研究前沿，不是默认选项——只有当通信已确认为主导瓶颈时才值得付出代价。

## 4. 系统架构

并行矩阵计算的软件栈分四层，从底到顶：

1. **BLAS（基础线性代数子程序）**：单节点内的矩阵运算内核，分 1 级（向量运算）、2 级（矩阵—向量）、3 级（矩阵—矩阵）；3 级运算的数据复用最高，是性能的基石。各厂商提供高度优化的 BLAS（Intel oneMKL、NVIDIA cuBLAS、AMD rocBLAS 等），上层库一般不自己重写这层。
2. **LAPACK（线性代数包）**：单节点内的分解与求解（LU、Cholesky、QR、特征值），以分块算法组织计算、大量调用 BLAS 3 级运算；是串行与单节点并行的事实标准层。
3. **分布式层（PBLAS / BLACS / ScaLAPACK / SLATE）**：把 LAPACK 的做法搬到分布式内存上。BLACS 是 ScaLAPACK 时代的进程间通信层，PBLAS 是并行版 BLAS；SLATE 则改用现代 C++ 与任务图（见第 5 节），不再沿用 BLACS 的老结构。
4. **应用与求解器层**：天气预报、分子模拟、结构分析等应用调用分布式层，或调用更上层的稀疏求解器（如 PETSc、Trilinos——见第 5 节对照）；应用层决定矩阵从哪来（网格、粒子、观测），算法层决定矩阵怎么算。

数据在栈里的流动是：应用生成全局矩阵 → 按二维块循环划分分到各进程 → 各进程本地调用 BLAS/LAPACK 算子 → 进程间经 MPI 集合通信交换面板与更新块 → 结果按同样划分拼回或直接以分布式形式进入下一步（如特征向量、模拟场）。

## 5. 代表性实现与开源项目

只列真实存在的库，版本号以官方发布为准（待核实）：

- **ScaLAPACK（可扩展线性代数包）**：1995 年前后发布的分布式稠密线性代数库，基于 MPI + BLACS + PBLAS + 二维块循环划分，是二十多年来分布式稠密计算的行业标准；局限是诞生于加速器普及之前，难以直接利用 GPU，维护仍在继续但无大规模新架构演进。
- **SLATE（面向 exascale 的线性代数软件）**：美国田纳西大学创新计算实验室（ICL）主持、美国能源部 exascale 计算项目（ECP）支持的项目，目标是接替 ScaLAPACK；做法是现代 C++、分块（tile）数据布局、基于 OpenMP 任务图的调度，并经 BLAS++ / LAPACK++ 对接各厂商 CPU 与 GPU 的 BLAS/LAPACK；其 2025 年 5 月 28 日的版本见 ICL 官方页面（后续版本以官方发布为准，待核实）。
- **MAGMA（矩阵代数 GPU 与多核架构）**：同样出自 ICL 的混合 CPU–GPU 稠密线性代数库，做法是把计算密集部分放 GPU、控制与小规模部分留 CPU；与 SLATE 的区别是：MAGMA 面向单节点或小规模混合架构，SLATE 面向大规模分布式异构系统。
- **DPLASMA 与 Chameleon（任务图路线的对照）**：用分布式运行时构建任务依赖图、依赖满足即启动任务的库，是 SLATE 任务图思路的先行者；本篇列出只为说明“任务图”不是 SLATE 独创，SLATE 的区别在于把细粒度分块任务聚合成粗粒度块任务、控制任务图规模。
- **ELPA 与 Hydrogen（特征值求解的对照）**：ELPA 是面向千万亿次应用的分布式厄米特征值求解器（CPU 与 GPU 加速）；Hydrogen 是劳伦斯利弗莫尔国家实验室对已停止维护的 Elemental 库的活跃分支，补上了 GPU 加速的 3 级 BLAS。两者说明：特征值问题常有专用求解器，不必凡事调通用分解。
- **PETSc 与 Trilinos（稀疏与迭代法的对照）**：面向大规模稀疏问题与偏微分方程的知名工具集，提供 Krylov 迭代法、预处理子、非线性求解器；本篇不展开其 API，只说明分工：稠密问题找 ScaLAPACK/SLATE，稀疏与 PDE 问题找 PETSc/Trilinos，选错层等于选错算法世界。
- **HPL 与 HPCG（基准，不是库）**：HPL（解稠密线性方程组）是 TOP500 的排名基准，HPCG（共轭梯度）是更接近稀疏迭代应用的对照基准；两者都是“测量工具”，不是生产求解器——用 HPL 名次推断应用性能是总览第 8 节已指出的误读。

## 6. 关键论文与标准

- **ScaLAPACK**：Blackford 等，《ScaLAPACK Users' Guide》（SIAM，1997 年）——分布式稠密线性代数与二维块循环划分的奠基性文献；PBLAS 与 BLACS 的设计亦出自同一体系。
- **SUMMA**：van de Geijn 与 Watts，《SUMMA: Scalable Universal Matrix Multiplication Algorithm》（LAPACK 工作笔记 96 号，1995 年前后）——SUMMA 算法的原始描述；同系列 100 号工作笔记为 PBLAS 的相关设计。
- **Cannon 算法**：Cannon（1969 年）——二维网格上矩阵乘法的经典算法，教材与讲义（如康奈尔大学 CS 5220 稠密线性代数讲义）仍以它与 SUMMA 对照讲解。
- **通信避免算法**：Demmel 等关于通信避免 LU、QR 的系列工作（加州大学伯克利分校，2012 年前后，含《Communication Avoiding and Overlapping for Numerical Linear Algebra》）——从通信下界出发重排分解算法的代表性研究。
- **SLATE**：ICL 的 SLATE 项目论文与演进报告（《Evolution of the SLATE linear algebra library》，美国国家科学基金会存档）——SLATE 接替 ScaLAPACK 的设计目标、任务图结构与在 Summit、Frontier 系统上的实验背景；具体性能数字见该文与 ICL 官方页面，本篇不转载（缺统一测试条件时不写，见第 7 节）。
- **标准层面**：BLAS、LAPACK 为事实标准（de facto），无单一标准组织编号；MPI、OpenMP 的正式标准见本域 12 篇第 6 节。

## 7. 当前实验结果

按模板硬规则，本节不转载任何二手性能数字，理由有三：跨系统的加速比、效率数字高度依赖矩阵规模、划分参数、硬件与库版本，转载时测试条件必然残缺；SLATE 在 Summit、Frontier 上的实验见其演进论文原文，读者应直读原文的实验设置；TOP500 的 HPL 数字是系统级基准（见总览第 7 节），不是算法对比。

本节只写可核查的“存在性结论”：

- ScaLAPACK 的二维块循环 + SUMMA 系算法已在生产系统上验证数十年，是“能用且够用”的基线；任何新算法要进入生产，必须先在同等规模、同等测试条件下与这条基线对比。
- SLATE 已在 Summit（pre-exascale）与 Frontier（首个 exascale 系统）上开展双精度实验（见演进论文的实验设置），目标是在异构系统上达到与 ScaLAPACK 相当或更好的覆盖与可扩展性；“接替”是否完成，以 ICL 官方发布与应用迁移情况为准（待核实），本篇不宣布接替已完成。
- 读者自测的正确姿势：固定矩阵规模 n、处理器网格、块大小、库版本，分别报告强扩展与弱扩展曲线，并注明 BLAS 实现、MPI 实现与 GPU 型号；只报“加速比”不报这四项的实验不具备可复现性。

## 8. 技术瓶颈

- **通信墙**：处理器算力增长快于互连带宽增长，数据搬运正在成为主导成本；2D 算法的通信量随规模增长的规律决定了“堆核数”的收益递减点，3D 与通信避免算法正是为推迟这个点而生，但要付出内存与复杂度代价。
- **同步与负载不均**：面板分解的串行段、全局规约的同步点、非均匀矩阵结构导致的负载不均，都会让部分处理器等待；前瞻、任务图调度、动态负载均衡是缓解手段，不是根治办法。
- **数值与并行的张力**：主元选取、重排序、通信避免重排都会改变舍入误差的积累路径；并行算法的数值分析必须与串行版本分开做，不能默认“并行版继承串行版的稳定性结论”。
- **异构与可移植性**：CPU–GPU 混合系统上，同一算法要在不同加速器上都跑得快，需要分块大小、任务粒度、数据布局三处同时调优；SLATE 的 BLAS++/LAPACK++ 抽象解决的是“能跑”，“跑得快”仍需逐硬件调优（与 12 篇第 8 节的可移植性瓶颈同源）。
- **内存墙**：稠密矩阵的内存需求随 n² 增长，分布式存储只是把问题摊开，不是消除问题；检查点、重算（recompute）与压缩存储的取舍，在超大规模问题上会重新成为算法设计的一部分。
- **软件接替成本**：ScaLAPACK 到 SLATE 的迁移不只是换库名：数据布局、API（Fortran 风格到现代 C++）、构建与部署方式都变了，存量应用的迁移成本是 SLATE 推广的真实瓶颈，不是技术细节。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：经典并行算法本身（SUMMA、Cannon、分块 LU/Cholesky/QR、ScaLAPACK）是已成熟应用——有数十年生产验证；但本篇的整体判断面向“大规模矩阵计算的当前形态”，即面向异构 exascale 系统的分块任务图、通信避免与 GPU 感知实现（以 SLATE 接替 ScaLAPACK 为标志）仍在工程化与应用迁移过程中，尚未完成对 ScaLAPACK 的全面取代，故整体定为工程发展中而非成熟应用。

## 10. 未来研究问题

- **已有研究在做**：SLATE 对 ScaLAPACK 功能覆盖的补齐与应用迁移——检验标准是主流科学应用是否普遍从 ScaLAPACK 迁移到 SLATE（或同类库）且性能不退化。
- **已有研究在做**：通信避免算法的数值稳定性证明与工程落地——检验标准是通信避免 LU、QR 能否在不牺牲可接受精度的前提下进入生产库的默认路径。
- **已有研究在做**：混合精度算法——用低精度（如单精度、半精度）算大头、用高精度修正关键步，在保持最终精度的前提下换速度与能效；检验标准是误差分析与生产库的默认支持，而非单篇论文的演示。
- **本文推测**：并行矩阵计算的下一个分水岭可能不在“新分解算法”，而在“自动调优与自适应”——块大小、任务粒度、精度选择由运行时按硬件与问题规模自动决定；检验标准是生产库是否普遍内置此类自适应而不再依赖人工调参。
- **本文推测**：AI for Science 带来的新矩阵结构（如大规模注意力、图神经网络中的稀疏—稠密混合算子）可能催生不属于经典稠密/稀疏二分的新并行算法家族；检验标准是是否有经同行评议的新算法在真实 AI 科学负载上复现优势。
