# 基础模型与多模态模型

本篇是 [AI Agent 前沿总览](06-frontier-ai-agents.md) 的分支文章，只讲基础模型与多模态模型的研究侧问题：它们为什么成为 Agent 的“大脑”、多模态融合在架构上难在哪、以及能力边界如何评估。本地部署、量化与推理加速的实操归本站 18 域：本地部署见[本地模型部署](../18-local-ai/01-local-model-deployment.md)，量化见[量化与推理](../18-local-ai/02-quantization-inference.md)，本篇只链接、不复制操作步骤。模型压缩的前沿视角见本分支[模型压缩、量化、蒸馏与推理加速](51-model-compression.md)。

## 1. 研究问题

基础模型（foundation model）指在大规模数据上预训练、再通过微调或提示适配到多种下游任务的模型；多模态模型则进一步要求同一系统能处理文本、图像、语音、视频等多种模态，并能在模态之间建立对应关系。研究问题是：一个统一模型能否在不牺牲单模态性能的前提下获得跨模态理解？以及，跨模态理解到底指什么——是“能把图说成话”，还是“能用图中的信息做推理、做规划、做行动决策”？这两者的难度差了一个量级。

现有方法解决不了这个问题的三个原因。第一，**模态数据的分布与结构不同**：文本是离散符号序列，图像是连续空间信号，语音有时序与韵律，视频还叠加了时间因果；把它们压进同一个表示空间时，信息损失与对齐误差不可避免。第二，**对齐数据稀缺且带偏**：图文配对数据远不如纯文本丰富，且配对质量、文化覆盖、标注偏见都会传导到模型行为中。第三，**评估割裂**：单模态基准、多模态问答基准与真实任务表现之间缺乏可靠的对应关系，一个模型在图文问答上得分高，不等于它能看懂一张工程图、一段监控视频或一份带图表的报告。

## 2. 基础理论

- **自监督预训练**：用数据自身的结构作监督信号（如预测下一个词、遮蔽部分再恢复），使模型在没有人工标注的情况下学到通用表示；它是基础模型范式的起点，但预训练目标与下游任务目标之间的差距始终存在。
- **Transformer 与注意力机制**：Vaswani 等人《Attention Is All You Need》（2017）提出的架构，用自注意力建模序列内部的依赖关系；它是今天绝大多数基础模型的主干，但注意力计算随序列长度平方增长，是长上下文与高分辨率图像输入的主要成本来源。
- **缩放规律（scaling laws）**：Kaplan 等人（2020）与 Chinchilla 研究（Hoffmann 等人，2022）讨论了模型规模、数据量与算力之间的经验关系；它们是“规模化路线”的经验依据，但外推到新模态、新任务时需要谨慎，规律本身不保证能力泛化。
- **对比学习与对齐**：CLIP 一类方法用图文对比学习把图像与文本映射到共享空间；它的成功说明跨模态对齐可以学出来，但共享空间中的“接近”不等于语义上的“等价”，细粒度差异（如数量、空间关系、否定）仍是弱项。
- **指令微调与人类反馈对齐**：通过指令数据微调与基于人类反馈的强化学习，使模型输出更符合人类意图；对齐改善了可用性，但也引入了新的问题：对齐可能掩盖而非消除模型的知识缺陷与偏见，见[AI 可解释性、可靠性与安全性](52-ai-explainability.md)。

## 3. 技术路线

- **统一 Token 化路线**：把图像、语音等都切分成离散 token，与文本 token 一起送进同一个 Transformer。优点是架构统一、复用文本模型的推理能力；缺点是切分方式决定了信息损失，且不同模态的 token 语义密度差异极大，统一处理容易顾此失彼。
- **编码器拼接路线**：每种模态各用专门编码器（如视觉编码器、语音编码器），再通过投影层或交叉注意力把特征送进语言模型。优点是能复用各模态上最成熟的编码器；缺点是拼接处容易成为瓶颈，模型可能学会“看标题不看图”之类的捷径。
- **原生多模态预训练路线**：从一开始就用多模态数据联合预训练，而不是先训单模态再拼接。理论上最干净，但数据、算力与训练稳定性要求最高，且多模态数据的清洗与配比本身就是开放问题。
- **工具外挂路线**：语言模型本身不直接理解图像，而是调用外部视觉工具（如图像描述、目标检测、OCR）获取文本化结果再推理。优点是工程上最快、错误可定位；缺点是工具的误差会传导，且“模型是否真的理解图像”变成了“工具是否可靠”的问题，研究上不算多模态理解本身。

四条路线在实践中常混合：一个系统可能同时有原生多模态编码器与工具外挂。混合越多，归因越难——出错时很难说清是视觉、语言还是拼接层的问题。

## 4. 系统架构

一个典型的多模态基础模型系统包含：

- **模态编码器层**：视觉、语音等各模态的编码器，输出特征向量。
- **对齐与投影层**：把各模态特征映射到语言模型可接受的表示空间；这是多模态系统最脆弱的环节之一。
- **语言模型主干**：负责推理、生成与任务编排，是 Agent 的“大脑”部分。
- **解码与生成层**：除文本外，可能还需生成图像、语音或动作序列；生成模态越多，一致性约束越复杂。
- **评估与安全层**：针对跨模态幻觉（如描述图中不存在的物体）、模态间不一致与偏见传导的检查；目前多为事后抽查，缺乏系统方法。

尚无代表性商用系统可以按“已解决多模态理解”来介绍：各厂商的多模态产品在受控演示中表现良好，但在细粒度空间关系、长视频因果、跨模态一致性等任务上仍不稳定，具体表现以官方发布与独立评测为准（待核实）。

## 5. 代表性实现与开源项目

只列真实存在的项目类别与公开研究载体，不写性能排名：

- **CLIP 系列与开源复现（OpenCLIP 等）**：图文对比学习的代表实现，是理解跨模态对齐的入门参照。
- **开源多模态模型系列**：如 LLaVA 等学术界开源项目，展示了“视觉编码器 + 语言模型 + 指令微调”路线的可复现做法；其能力边界与训练数据细节以论文与仓库说明为准。
- **语音与视频理解研究项目**：语音识别、多说话人转写、视频问答等方向各有专门模型与基准；把它们拼进一个统一 Agent 仍是开放问题。
- **推理引擎与部署工具**：vLLM、llama.cpp 等是部署侧工具，实操见 18 域文章，本篇不展开。

## 7. 当前实验结果

本节不写模型排行榜数字，只写经公开研究反复确认的定性结论：

- 图文问答类任务上，主流多模态模型的表现已可用，但细粒度任务（如数清图中物体、判断左右与遮挡关系、识别否定表述对应的图像内容）仍是公开的弱项。
- 长视频理解仍处于早期：模型对视频中事件的时序与因果关系把握不稳，抽帧密度与上下文长度之间的权衡没有通用解。
- 跨模态幻觉是系统性问题：模型可能在文本中自信地描述图像里不存在的内容，且幻觉率随任务开放程度上升；现有缓解方法多为事后校验，治标多于治本。
- 小模型与大模型在多模态任务上的差距，比在纯文本任务上更明显；但具体差距因任务与评估条件而异，不写统一倍数。

## 8. 技术瓶颈

- **对齐瓶颈**：投影层的信息损失与模态捷径（只看文本不看图）难以根除。
- **数据瓶颈**：高质量、多样、带细粒度标注的多模态数据稀缺，且清洗标准不统一。
- **算力与上下文瓶颈**：高分辨率图像与长视频带来的 token 量爆炸，使推理成本与延迟急剧上升；压缩 token 又会丢信息。
- **评估瓶颈**：缺乏能同时度量感知准确性、推理正确性与跨模态一致性的评估体系。
- **安全瓶颈**：图像、语音中的对抗样本与隐藏指令（如图片里的文字指令）是文本安全方法覆盖不到的攻击面，见[AI 可解释性、可靠性与安全性](52-ai-explainability.md)。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：基础模型与多模态模型已有可用的工程产品与开源实现，能在受限场景交付价值，但跨模态细粒度理解、长视频因果与一致性安全三大问题未解决，尚不能按“已理解多模态世界”来交付通用系统。

## 10. 未来研究问题

- **已有研究在做**：更省 token 的视觉表示（在不丢细粒度信息的前提下压缩图像 token）、视频时序建模、跨模态幻觉检测。
- **已有研究在做**：多模态数据的质量度量与配比方法，以及“模型是否走了模态捷径”的诊断工具。
- **本文推测**：多模态研究的下一个分水岭可能不是“支持更多模态”，而是“在已有模态上证明细粒度一致性”——例如模型能否在同一任务中同时通过文本、图像与行动三种检验；检验标准是公开的、跨模态一致的测试集，而非各自独立的单模态基准。
