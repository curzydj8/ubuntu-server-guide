# 模型压缩、量化、蒸馏与推理加速（前沿视角）

本篇是 [AI Agent 前沿总览](06-frontier-ai-agents.md) 的分支文章，只讲模型压缩的前沿视角：新方法在研究什么、评估上有哪些陷阱、以及哪些问题尚未解决。量化与推理的落地操作、格式选择与部署步骤，见本站 18 域[量化与推理](../18-local-ai/02-quantization-inference.md)，本篇只链接、不复制；本地部署的整体流程见[本地模型部署](../18-local-ai/01-local-model-deployment.md)。小模型的设计思路见[小型语言模型与端侧模型](50-small-models-edge.md)，本篇聚焦压缩方法本身。

## 1. 研究问题

模型压缩要解决的问题是：如何在尽量不损失任务性能的前提下，减小模型体积、降低推理成本、缩短延迟，使大模型能在更便宜的硬件、更受限的设备上运行？研究问题进一步包括：压缩的损失来自哪里？不同任务对压缩的敏感度为何不同？以及，压缩后的模型在安全性、对齐与长程任务上的表现是否与压缩前一致？

现有方法解决不了这个问题的三个原因。第一，**压缩损失不均匀**：同一压缩方法在知识问答上损失很小，在代码、数学推理、长上下文任务上损失可能很大；只用困惑度（perplexity）评估压缩质量会掩盖任务间的差异。第二，**压缩与硬件耦合**：一种压缩格式的理论收益能否兑现，取决于推理引擎与硬件是否支持对应的算子；格式选对了、引擎不支持，收益为零。第三，**压缩改变模型行为**：量化、剪枝、蒸馏都可能改变模型的输出分布、对齐表现与失效模式；压缩后的模型需要重新做安全评估，不能默认继承压缩前的结论。

## 2. 基础理论

- **量化**：把权重与激活从高精度浮点（如 FP16/BF16）映射到低精度表示（如 INT8、INT4、FP8）；核心 trade-off 是表示精度与体积/速度之间的交换，关键技术是缩放因子、分组策略与校准数据的选择。
- **剪枝（pruning）**：删除不重要的权重、神经元、注意力头或整层；非结构化剪枝（删单个权重）压缩率高但硬件加速难，结构化剪枝（删整层/整通道）硬件友好但损失大，二者不可混为一谈。
- **知识蒸馏**：Hinton 等人（2015）提出，用教师模型的软标签训练学生模型；蒸馏的损失函数、温度参数与数据选择决定了学生学到的是教师的泛化结构还是表面答案。
- **低秩分解**：把大权重矩阵分解为两个小矩阵的乘积，用参数量换表达能力；适用于权重矩阵近似低秩的层，不适用于所有层。
- **推理加速理论**：投机解码（用小模型先猜、大模型验证）、KV 缓存管理、连续批处理等方法不改变模型权重，而是改变推理过程；它们的收益取决于任务的生成长度、批大小与硬件特性，没有通用加速比。

## 3. 技术路线

- **训练后量化（PTQ）**：不重训、只用少量校准数据确定量化参数后直接量化。代表方法：GPTQ（Frantar 等人，2023，arXiv:2210.17323）利用二阶（Hessian）信息逐层量化；AWQ（Lin 等人，2024，arXiv:2306.00978）按激活规模保护显著权重通道。优点是成本低、见效快；缺点是极低比特（如 2-bit）下质量下降明显，且校准数据的分布会影响结果。
- **量化感知训练（QAT）**：在训练或微调中模拟量化误差，使模型适应低精度表示。优点是低比特下质量更好；缺点是训练成本高，且需要原始训练流程的配合。
- **结构化剪枝与层删减**：删除整层或大块结构后用少量微调恢复性能；研究问题是“删哪层”的判定标准（影响度、冗余度）是否可靠，以及删减后模型在长程任务上的表现是否同步下降。
- **蒸馏与数据蒸馏**：教师生成数据或软标签训练学生；前沿问题包括：蒸馏数据的质量如何度量、蒸馏是否会放大教师的偏见、以及学生能否在教师未覆盖的任务上泛化。
- **混合压缩**：量化 + 剪枝 + 蒸馏组合使用；组合的顺序与配比影响最终质量，但组合空间大、缺乏系统性的搜索方法，目前多靠经验。
- **推理侧加速**：投机解码、KV 缓存压缩、注意力优化（如 FlashAttention 类方法）、算子融合等；前沿问题是这些方法在长上下文、多模态输入下的收益是否稳定，以及它们与量化、剪枝的交互效应。

## 4. 系统架构

一个压缩研究的工作流通常包含：

- **原模型与评估基线**：压缩前的模型在目标任务集上的表现，作为对照；任务集应覆盖知识、推理、代码、长上下文等多个维度，只用困惑度作基线是不够的。
- **压缩器**：执行量化、剪枝或蒸馏的模块，输出压缩后的模型与压缩配置（比特数、分组大小、剪枝比例、校准数据说明）。
- **推理引擎适配层**：把压缩格式映射到引擎支持的算子；不支持的格式需要回退或转格式，收益需重新评估。
- **多维评估器**：任务性能、安全对齐、长程任务、延迟、内存、功耗的联合评估；缺少任一维度，压缩结论都不完整。
- **回退与版本管理**：压缩后模型不达标时的回退规则（换格式、降压缩比、回原模型），以及压缩配置的版本记录；没有配置记录的压缩结果不可复现。

尚无代表性商用系统可以按“通用最优压缩方案”来介绍：最优方案随模型、任务、硬件、引擎而变，任何“某方法全面最优”的说法都应视为在特定测试条件下的结论。

## 5. 代表性实现与开源项目

- **GPTQ / AutoGPTQ**：训练后量化方法的代表实现，支持多比特配置；其效果取决于校准数据与分组策略，以论文与仓库说明为准。
- **AWQ / AutoAWQ**：激活感知量化方法的代表实现，在权重-only 量化场景下是常用对照；与 GPTQ 的优劣因任务与评估条件而异，不写统一排名。
- **llm-compressor、bitsandbytes 等工具**：提供多种压缩方法的集成实现；工具的存在不等于方法在你的任务上有效，选型前应在目标任务上实测。
- **推理引擎**：vLLM、TensorRT-LLM、llama.cpp 等对不同量化格式的支持程度不同；格式与引擎的匹配关系以各引擎官方发布为准（待核实）。
- **蒸馏框架**：各大模型厂商与开源社区均有蒸馏工具链；蒸馏数据的许可问题（教师模型输出的使用限制）需单独核对，不在本篇展开。

## 6. 关键论文与标准

- Hinton 等人《Distilling the Knowledge in a Neural Network》（2015，arXiv:1503.02531）。
- Frantar 等人《GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers》（2023，arXiv:2210.17323）。
- Lin 等人《AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration》（MLSys 2024，arXiv:2306.00978）。
- Frantar 与 Alistarh《SparseGPT: Massive Language Models Can Be Accurately Pruned in One-Shot》（ICML 2023，arXiv:2301.00774）。
- 暂无公开标准：压缩质量的统一评估标准（任务集、硬件口径、延迟与功耗度量）无公认标准，各方法的“加速比”“压缩比”说法口径不一。

## 7. 当前实验结果

本节数字均带来源与测试条件，不写厂商宣传的加速倍数：

- 第三方复现整理（Faster-LLM-Survey 对 Llama-2-7B 的量化复现，测试条件为该调查的校准数据与困惑度评估设置）显示：FP16 基线权重内存约 12.55 GB、困惑度约 5.85；GPTQ 4-bit 权重内存约 3.63 GB、困惑度约 6.08；AWQ 4-bit 权重内存约 3.68 GB、困惑度约 6.02；GPTQ 2-bit 在该设置下困惑度为 NaN、不可用。这些数字只说明在该模型的该测试条件下 4-bit 是较平衡的选择，不说明所有模型、所有任务都如此。
- IJCAI 2025 关于量化 trade-off 的研究（覆盖 1B–405B 指令模型、4 种量化方法、13 个数据集）定性结论是：量化模型通常优于更小的 FP16 基线，但指令遵循与幻觉检测任务上仍有困难；FP8 在该研究的任务集中表现较稳健；小模型在 4-bit 下的精度下降比大模型更严重。以上结论限于该研究的模型与任务范围。
- 剪枝与蒸馏的公开结论是：单方法的效果高度依赖任务与恢复微调；组合压缩的效果不是各方法效果的简单叠加，需要联合评估。
- 推理加速方法的公开结论是：投机解码等方法的收益随生成长度、批大小与硬件而变；在短生成、低批量的场景下收益可能不明显，任何统一加速比都应以测试条件为准（待核实）。

本节所有数字均为文献与第三方复现整理复述，不是本站实测；本地没有压缩实验环境，任何压缩复现均属示例未实测。

## 8. 技术瓶颈

- **评估瓶颈**：只用困惑度评估压缩会掩盖任务间差异；缺乏覆盖推理、代码、长上下文、安全的多维压缩评估标准。
- **极低比特瓶颈**：2-bit 及以下量化在多数公开复现中质量下降明显；极低比特的可用性仍是开放问题，不是已解决的工程选项。
- **硬件耦合瓶颈**：压缩格式的理论收益受引擎与硬件支持制约；格式、引擎、硬件三者的匹配矩阵缺乏公开的系统性整理。
- **行为改变瓶颈**：压缩可能改变对齐表现与失效模式；压缩后模型需要重新做安全评估，不能默认继承压缩前结论。
- **组合搜索瓶颈**：量化、剪枝、蒸馏的组合空间大，缺乏高效的联合搜索方法；目前的组合方案多靠经验试错。
- **长上下文瓶颈**：KV 缓存随上下文长度增长，压缩权重后 KV 缓存可能成为新的内存瓶颈；权重压缩与 KV 压缩需要联合考虑。

## 9. 成熟度判断

- **成熟度：工程发展中。** 判断依据一句话：4-bit 量化等方法已有可用的开源实现与部署实践，能在受限场景交付价值，但极低比特、组合压缩的最优搜索、压缩后安全重评估三大问题未解决，尚不能按“压缩无损”来交付。

## 10. 未来研究问题

- **已有研究在做**：极低比特量化的质量恢复方法、权重与 KV 联合压缩、压缩后安全评估的自动化。
- **已有研究在做**：压缩方法的任务敏感性分析——为什么同一方法在不同任务上损失差异巨大。
- **本文推测**：压缩研究可能先在“任务感知的自适应压缩”（按任务难度动态选精度）上取得实用进展，而非在“统一极低比特”上；检验标准是自适应方案能否在公开任务集上稳定地优于固定精度方案。
