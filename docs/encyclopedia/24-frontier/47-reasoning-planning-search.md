# 推理、规划与搜索

本篇是 [AI Agent 前沿总览](06-frontier-ai-agents.md) 的分支文章，只讲推理、规划与搜索的研究侧问题。总览把“规划与执行分离”列为多智能体系统的基本结构，本篇展开规划本身：模型如何把一个任务拆解、推演、搜索与纠错，以及这些方法在什么条件下会系统性失效。提示词怎么写、工具怎么调用、工作流怎么编排的实操，见本站 18 域[Agent 与工作流自动化](../18-local-ai/03-agent-workflow.md)，本篇只链接、不复制。

## 1. 研究问题

推理、规划与搜索要解决的问题是：给定一个目标与一组合法行动，系统能否找到一条从当前状态到达目标的行动序列，并在执行中根据反馈修正它？对大语言模型而言，这个问题有特殊的难度：模型生成的是 token 序列，不是经过验证的行动序列；它可以在语言上“看起来在推理”，却在逻辑上跳步、循环或自相矛盾。研究的核心因此不是“模型会不会说推理过程”，而是“推理过程是否可靠、可检查、可纠错”。

现有方法解决不了这个问题的三个原因。第一，**生成不等于验证**：自回归生成每步只保证局部流畅，不保证全局一致；一步错，后续步骤可能在错误前提上越走越远。第二，**搜索空间爆炸**：任务越长、分支越多，穷举不可能，启发式搜索又依赖启发函数的质量，而启发函数本身常由同一个不可靠的模型提供。第三，**反馈稀疏且滞后**：很多任务只有最终成败反馈，中间步骤对错难判定；模型难以从“最后失败了”反推出“哪一步错了”。

## 2. 基础理论

- **链式思考（Chain-of-Thought, CoT）**：Wei 等人（2022）提出，让模型在给出答案前先生成中间推理步骤；它改善了多步推理任务的表现，但中间步骤本身未经验证，错误会在链中传播。
- **搜索理论**：经典 AI 中的宽度优先、深度优先、A*、蒙特卡洛树搜索（MCTS）等方法，为“在状态空间中找路径”提供了系统的语言；把这些方法嫁接到语言模型上时，状态、行动与启发函数的定义都必须重新设计，不能直接照搬。
- **规划的形式化**：STRIPS、PDDL 等规划语言把“行动的前提与效果”形式化，使规划结果可验证；语言模型的自然语言规划缺乏这种形式化保证，这是“规划可验证性”研究分支的出发点。
- **自我一致性与验证**：通过多次采样取多数答案（self-consistency）、或用独立验证器检查推理步骤，来降低单次生成的偶然错误；验证器的可靠性本身又成为新的瓶颈。

## 3. 技术路线

- **链式思考与变体**：直接生成推理链；变体包括少样本示例、零样本触发词、结构化推理格式等。优点是简单、通用；缺点是推理链质量不稳定，且模型可能生成“看起来合理但逻辑断裂”的链。
- **推理与行动交错（ReAct）**：Yao 等人（2023）提出，在同一生成过程中交错“思考—行动—观察”，让外部观测纠正推理。优点是推理被观测锚定，减少纯空想；缺点是行动本身可能错，观测可能被误读，且长轨迹的上下文会漂移。
- **树搜索与多路径探索**：如 Tree-of-Thoughts（Yao 等人，2023），把推理组织成树，多个分支并行探索、用启发式打分剪枝。优点是单链错误可被其他分支弥补；缺点是计算成本随分支数上升，且打分函数常由同一模型提供，存在自我肯定的循环论证风险。
- **自我纠错与反思**：让模型检查自己的推理、找出错误并修正（如 Reflexion 一类方法）。优点是利用了模型的自我审视能力；缺点是模型常常“自信地坚持错误”或“把正确的改错”，纠错的净收益因任务而异，没有普适保证。
- **外部验证器与形式化规划**：把推理步骤交给外部工具验证（如代码执行、定理证明器、PDDL 求解器），只接受通过验证的步骤。优点是验证结果可信；缺点是可形式化的任务范围有限，开放任务难以形式化，且验证器本身的覆盖度决定了方法的上限。
- **学习式规划**：用强化学习直接优化“拆解与搜索策略”，而非只靠提示。优点是策略可随经验改进；缺点是训练成本高、奖励设计难，且学到的策略可能只在训练分布内有效。

## 4. 系统架构

一个研究型的推理—规划系统通常包含：

- **问题分解器**：把目标拆成子目标与子任务；分解错误是后续一切错误的源头。
- **推理生成器**：生成推理步骤或候选行动（常由大语言模型担任）。
- **搜索与调度器**：决定探索哪些分支、按什么顺序、花多少预算；包括剪枝与回溯规则。
- **执行与观测接口**：把行动送到工具或环境，取回观测；工具调用实操见 18 域文章。
- **验证器**：独立于生成器的检查环节（代码执行、规则检查、第二模型评审等）；没有验证器的长推理链不宜用于高风险任务。
- **记忆与回溯**：记录已探索路径与失败原因，避免重复探索同一死路；与[长期记忆与持续学习](48-long-term-memory.md)相关，但此处记忆的范围限于单次任务内。

尚无代表性商用系统可以按“通用可靠规划器”来介绍：现有系统多在特定任务类型上有效，跨任务类型的通用规划器仍是研究目标。

## 5. 代表性实现与开源项目

- **ReAct 范式与框架实现**：LangChain、LangGraph 等框架内置了思考—行动—观察循环的实现；它们是工程载体，不是推理正确性的保证。
- **Tree-of-Thoughts 与相关搜索实现**：学术界有公开代码实现，用于研究多路径推理；其效果高度依赖任务、模型与打分函数，不宜直接当作通用结论。
- **PDDL 求解器与形式化规划工具**：如 Fast Downward 等经典规划器，在可形式化任务上提供可验证的规划结果；它们是“验证”一侧的参照，不是语言模型规划的替代品。
- **代码执行验证**：把推理中的计算步骤交给代码解释器执行，是目前最易落地的一类验证器；但它只验证计算，不验证问题理解与分解是否正确。

## 6. 关键论文与标准

- Wei 等人《Chain-of-Thought Prompting Elicits Reasoning in Large Language Models》（NeurIPS 2022，arXiv:2201.11903）。
- Yao 等人《ReAct: Synergizing Reasoning and Acting in Language Models》（ICLR 2023，arXiv:2210.03629）。
- Yao 等人《Tree of Thoughts: Deliberate Problem Solving with Large Language Models》（NeurIPS 2023，arXiv:2305.10601）。
- Shinn 等人《Reflexion: Language Agents with Verbal Reinforcement Learning》（NeurIPS 2023，arXiv:2303.11366）。
- 暂无公开标准：推理正确性的统一评估方法、规划可验证性的分级标准均无公认标准。

## 7. 当前实验结果

本节数字均带来源与测试条件：

- ReAct（Yao 等人，2023）在 HotpotQA 与 Fever 等知识任务上，用 Wikipedia API 交互的 ReAct 方法克服了纯链式思考的幻觉与误差传播问题；在 ALFWorld 与 WebShop 两类交互决策基准上，ReAct 相对模仿学习与强化学习基线，绝对成功率分别高出约 34 个百分点与 10 个百分点，条件是仅用一两个上下文示例；这些数字来自论文的特定基准与基线设置，不能外推为“ReAct 在所有任务上都好这么多”。
- 同一论文的 HotpotQA 对照显示，ReAct 与自一致性链式思考结合时表现进一步提升，说明“行动锚定”与“多采样投票”可以互补；但该结论同样限于论文的测试设置。
- 树搜索类方法的公开结论是：在需要多步探索的任务上，多分支搜索优于单链推理，但计算成本与打分函数的可靠性是主要代价；成本与收益的比值因任务而异，未见统一数字。
- 自我纠错类方法的公开结论是混合的：模型在能获得外部反馈（如代码执行结果、环境观测）时纠错收益较明显，在只能靠“自己想想有没有错”时收益不稳定，甚至可能把正确结果改错。

本节所有结果均为文献复述，不是本站实测；本地没有 Agent 实验环境，任何复现均属示例未实测。

## 8. 技术瓶颈

- **验证瓶颈**：生成容易、验证难；没有可靠验证器时，推理链越长，可信度越低。
- **搜索成本瓶颈**：多分支搜索的计算成本随任务长度与分支数快速上升，实际部署中常被迫剪枝到近似单链。
- **启发函数瓶颈**：搜索的打分常由同一模型提供，模型偏见会自我强化，导致搜索“系统性地错过正确分支”。
- **分解瓶颈**：问题分解错误无法靠后续搜索弥补；分解器本身的可靠性研究不足。
- **反馈归因瓶颈**：最终失败时难以定位是哪一步错，纠错因此缺乏针对性。
- **形式化覆盖瓶颈**：可形式化验证的任务只占真实任务的一小部分，开放任务的验证方法仍是空白。

## 9. 成熟度判断

- **成熟度：实验研究中。** 判断依据一句话：链式思考、ReAct、树搜索等方法在特定基准上有可复现的改进，但推理的可验证性、搜索成本与纠错可靠性三大问题未解决，尚不能作为高风险长程任务的通用规划保证。

## 10. 未来研究问题

- **已有研究在做**：推理步骤的细粒度验证器、搜索打分与生成的解耦（避免自我肯定）、问题分解的可靠性评估。
- **已有研究在做**：把形式化验证扩展到更多任务类型，以及验证器覆盖不足时的回退策略。
- **本文推测**：推理研究可能先在“生成—验证分离”的架构上收敛（生成可以大胆，验证必须独立），而非在“让生成本身不出错”上收敛；检验标准是独立验证器能否在公开基准上稳定地拦截生成错误。
