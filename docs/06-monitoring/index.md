# 第 06 部分：系统监控、日志与性能调优

服务器上线只是起点。没有监控，你不知道它什么时候会坏；没有日志，坏了也不知道为什么坏；没有调优，硬件的钱花了却没有换来性能。这一部分要解决的正是这三个问题：看得见、查得到、跑得快。

## 本部分地图

| 章节 | 文件 | 一句话说明 |
| --- | --- | --- |
| 第 1 章 | 01-cli-tools.md | 用 htop、btop、iotop 等命令行工具做即时巡检与故障定位 |
| 第 2 章 | 02-prometheus-grafana.md | 用 Prometheus 加 Grafana 搭建带告警的企业级监控栈 |
| 第 3 章 | 03-logging-stack.md | 用 Loki 加 Vector 集中收集日志并规划保留与磁盘 |
| 第 4 章 | 04-kernel-tuning.md | 用 sysctl、Governor、zram 做有依据可回滚的内核调优 |

## 推荐阅读顺序

建议按 1、2、3、4 的顺序读。第 1 章是基本功，任何故障现场都会先用到；第 2 章把监控从看一眼升级为长期留存加自动告警；第 3 章补上日志这一维，和第 2 章的指标共用 Grafana 一个入口；第 4 章最后读，因为调优必须建立在前三章的观测数据之上，没有数据支撑的调优只是猜测。

!!! tip "先观测，后调优"
    如果你只能抽出一个小时，先读第 1 章并把工具装好。监控和日志属于长期资产，越早部署，故障时手里的数据越多。

## 前置知识

- 已完成前面部分的系统安装、用户与 SSH、网络基础配置。
- 熟悉 apt 包管理、systemd 服务管理与 journalctl 基本用法。
- 了解 CPU、内存、磁盘、网络四类资源的基本概念。
- 本部分所有操作默认在 Ubuntu Server 22.04 LTS 或 24.04 LTS 上执行，需要 sudo 权限。

## 学完你能做到什么

- 故障发生后 5 分钟内定位是 CPU、内存、磁盘还是网络瓶颈。
- 独立部署一套带邮件告警的监控系统并导入社区仪表盘。
- 把多台服务器的日志集中到一处检索，并控制磁盘占用上限。
- 看懂常见 sysctl 参数的默认值与影响，按场景调整且随时回滚。
