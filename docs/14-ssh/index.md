# 第 14 部分：SSH 专题：连接、密钥与隧道

SSH 是服务器的第一入口。无论服务器放在云厂商机房、公司机柜还是家里的小主机上，运维人员接触它的第一动作几乎都是在自己的电脑上打开终端、敲下一条 `ssh` 命令：登录、传文件、开隧道、排故障，全都从这条加密通道进去。第 02 部分已经把服务端「怎么守门」讲透了——密钥登录、改端口、禁用密码与 Root、双因素认证；但日常使用中同样高频的另一半问题——客户端怎么连、配置怎么写、指纹怎么核对、隧道怎么搭、断线怎么查——此前散落在各章里，没有一处系统讲清。本部分就是补上这一半：以使用者视角，从第一次连接讲到多机管理与故障排查，让你手里的 SSH 客户端从「能连上」升级为「连得稳、连得安全、连得省事」。

本部分与第 02 部分的分工很明确：第 02 部分站在服务器上，视角是管理员如何配置 `sshd`、收紧认证、防止暴力破解；本部分站在你的电脑前，视角是使用者如何组织连接、保管密钥、用好 Agent 与隧道。两部分有少量交叉（如密钥的生成），处理原则是：加固决策以第 02 部分为准，本部分只讲操作与原理，不重复发明规则；遇到「改服务端配置」的动作，本部分会直接链回第 02 部分对应章节。

## 每章一句话

- **01 SSH 原理与服务端安装**：先看懂一次 SSH 连接从 TCP 建连到加密会话的完整过程，再把服务端在 Ubuntu 上装好、验好，知道服务名、端口与生效配置从哪看。
- **02 连接与客户端配置**：把连接参数、指纹核对与 `~/.ssh/config` 一次讲透，从此用别名连机器，指纹变更先核实再处理，断线与假死有明确的自救动作。
- **03 密钥、Agent 与轮换**：密钥是身份不是文件——私钥只留本机、口令交给 ssh-agent 托管、轮换与吊销有固定流程，丢一把钥匙不牵连其他机器。
- **04 文件传输与远程执行**：scp 应急、sftp 交互、rsync 增量同步各归其位，再加远程执行命令的引号与退出码处理，构成日常批量操作的基本功。
- **05 隧道与跳板机**：三种端口转发覆盖「访问内网服务、暴露本地服务、全局代理」三类场景，ProxyJump 让跳板机之后的机器像直连一样使用。
- **06 故障排查与安全加固要点**：连不上时按网络、服务、认证、权限四层逐层缩小范围，用调试输出说话；最后收一遍客户端侧的安全与保活清单。

## 与已有内容的关系

本部分不是孤岛，与站内三处内容直接衔接，阅读时请按需跳转：

- **服务端加固**：[第 02 部分 · SSH 安全加固](../02-security/01-ssh-hardening.md) 讲的是服务端一侧的决策——改端口、禁用密码与 Root 登录、叠加双因素认证。本部分的第 01 章只把服务端「装好并确认在运行」，装完之后的第一件事就是去做那一章的加固；本部分第 06 章的「安全加固要点」也只收客户端侧要点，服务端规则不重复，以那一章为准。
- **密钥丢失恢复**：[第 08 部分 · 灾难恢复与系统迁移](../08-troubleshooting/05-disaster-recovery-migration.md) 给出了私钥丢失、把自己锁在门外时经云控制台等带外通道恢复访问的完整流程。本部分第 02、03 章讲的是「平时如何避免走到那一步」，真走到了，按那一章处理。
- **互动工具**：[工具页](../tools/index.md) 提供 SSH 相关的在线生成器，可按表单生成连接与防火墙放行所需的命令片段，填入自己的端口与地址后复制使用。生成结果仍要先看懂再执行，并注意工具页的提醒：启用 UFW 前先放行当前 SSH 端口，顺序反了会把自己锁在门外。

推荐的阅读顺序是 01 → 02 → 03 连续读完打基础，04、05 按需查用，06 作为案头排查手册随时翻。已经熟悉基础连接的读者可以直接从第 02 章的 `~/.ssh/config` 与第 05 章的隧道开始。

!!! note "版本与示例约定"
    本部分面向 Ubuntu 22.04 / 24.04 LTS，客户端命令以 OpenSSH 为准；26.04 待核验，文中不宣称已在该版本验证。示例地址一律使用文档保留段 192.0.2.x、198.51.100.x 与 2001:db8::，示例初始账号为 `ubuntu`、日常管理账号为 `opsadmin`，请替换为你自己的真实值后再执行。

读完本部分，你应能独立完成从装好 SSH 服务端、用别名与密钥稳定连接多台服务器、经跳板机与隧道访问内网服务，到连接出问题时分层定位并给出证据的完整闭环，且全程不靠猜、不留安全隐患。
