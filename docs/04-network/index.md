# 第 04 部分 网络服务与核心架构 · 导览

一台 Ubuntu Server 能开机、能登录，还不算真正上了网。名字怎么解析、网页怎么对外发布、异地机器怎么安全互通、时间为什么必须对齐、出了问题去哪里查日志，这五件事决定了服务器能不能稳定地为别人提供服务。本部分就围绕这条主线展开：先让名字找得到，再让服务发得出去，然后把通道加密，最后用时间和日志把系统管起来。

| 第 2 章 | [02-web-proxy.md](02-web-proxy.md) | 用 Nginx、Apache、Caddy 对外发布网站，学会虚拟主机、反向代理与自动 HTTPS。 |

## 推荐阅读顺序

建议按 01 到 04 的顺序读，不要跳。DNS 是后面所有服务的前置：反向代理要靠名字访问后端，VPN 客户端要靠名字找到服务端，日志排障时也要靠名字定位机器。Web 与反向代理排在第二位，因为它是对外服务的门面，理解了虚拟主机和代理，再看 VPN 的转发会更容易。VPN 排在第三位，它解决的是通道问题。时间与日志放在最后，不是因为不重要，而是因为前三章的服务一旦跑起来，你正好需要准确的时间戳和完整的日志来验证它们是否真的健康。

如果你的目标很明确，也可以按需直达：只想让内网机器互相用名字访问，先看第 1 章。只想把一个本地应用发布到公网并配好证书，直接看第 2 章。服务器在家里、没有公网地址，先看第 3 章的 Tailscale 一节，再回头补 SSH 与 DNS。服务器时间总是不准、日志查不到，先看第 4 章。

## 前置知识

开始本部分之前，你应当已经会用 SSH 密钥登录服务器，会用 `sudo` 执行管理命令，会用文本编辑器修改 `/etc` 下的配置文件，并理解 IP 地址、端口、TCP 与 UDP 的基本区别。如果还不熟悉防火墙，请先补完基础部分的 UFW 章节，因为本部分每开一个服务，都要同步考虑端口放行与来源限制。本部分所有示例均在 Ubuntu 22.04 LTS 与 Ubuntu 24.04 LTS 上验证，示例地址只使用文档保留段，示例域名只使用 example.com 与 example.org，请在实操时替换为你自己的真实地址与域名。

!!! tip "学习方法"
    每读完一章，先在测试机上完整跑一遍验证命令，确认输出与文中示例一致，再动生产机。网络配置改错最常见的后果是把自己锁在门外，改动前备份、改动后立刻验证，是本部分反复强调的习惯。

读完本部分，你应当能独立回答四个问题：一个名字是怎样被解析到一台机器的，一个请求是怎样经代理到达后端应用的，一台异地机器是怎样安全地加入内网的，以及一次故障发生后，你要去哪里、按什么时间顺序把证据找齐。
