# 09 网站搭建、域名与应用部署

服务器装好系统、加固好 SSH 之后，真正让它对外产生价值的一步是把网站和应用跑起来。本部分从域名解析讲起，依次走完面板路线、手工 LNMP/LAMP 路线、Docker 路线，最后用 HTTPS 自动化证书收尾。读完本部分，你应该能独立完成从买域名到网站上线全流程，并且在任何一环出问题时知道去哪里查。

## 每章一句话

- **01 域名解析**：先把解析链路和记录类型弄懂，后面所有「网站打不开」有一半能在这里定位。
- **02 宝塔面板**：适合想快速上线、且愿意花十分钟做完端口、入口、双因素和 SSL 加固的人。
- **03 LNMP/LAMP**：适合要长期维护、要把性能和安全细节握在自己手里的人，也是理解面板背后原理的最好教材。
- **04 Docker 应用**：适合应用本身有官方镜像的场景，一份 compose 文件就是全部部署说明。
- **05 HTTPS 证书**：无论前面走哪条路线都要做，Certbot 和 acme.sh 二选一，配好后基本不用再管。

## 三条建站路线对比

| 维度 | 宝塔面板路线 | 手工 LNMP/LAMP 路线 | Docker 路线 |
| --- | --- | --- | --- |
| 上手速度 | 最快，图形界面点选安装 | 最慢，每步都要敲命令 | 中等，会写 compose 后很快 |
| 学习收获 | 较少，细节被面板封装 | 最多，原理全部透明 | 中等，偏容器与编排知识 |
| 资源占用 | 面板常驻进程额外占内存 | 最省，只有业务进程 | 中等，多一层容器运行时 |
| 升级维护 | 面板内点升级，偶发兼容问题 | 自己控制版本与节奏 | 改镜像标签重新拉取即可 |
| 迁移备份 | 依赖面板备份功能 | 配置文件加数据目录，打包即走 | compose 加数据卷，打包即走 |
| 典型风险 | 面板端口暴露被爆破 | 配置写错导致站点不可用 | 数据卷误删导致数据丢失 |

## 选择建议

新手第一次建站、只跑一两个 WordPress 类站点，选宝塔路线，先把网站跑起来，再回头补原理。已经会看 Nginx 配置、打算长期运营或跑多个站点，选手工 LNMP/LAMP，后续排障最省心。应用有官方 Docker 镜像、或者你要在同一台机器上跑好几个互不干扰的服务，选 Docker 路线，并把宿主机上的 Nginx 只当反向代理用。三条路线不互斥，常见组合是宿主机手工 Nginx 做统一入口，后面同时挂着面板站点和 Docker 应用，但同一台机器上不要同时用宝塔的 Nginx 和系统 apt 的 Nginx 抢 80 端口，二选一即可。
