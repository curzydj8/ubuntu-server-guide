# 宝塔面板安装与安全加固

## 一、概述与使用场景

宝塔面板是一套在浏览器里管理服务器的图形化工具：装 Web 环境、建站点、管数据库、签证书、看监控，都可以在页面上点选完成，不必每件事都敲命令。它适合三类场景：第一次建站、想尽快把 WordPress 等程序跑起来；一台机器上站点不多、运维人手有限；需要给不懂命令行的同事开一个受限的管理入口。

不用面板的代价是学习曲线陡，手工 LNMP 每一步都要自己做，一旦写错配置排查时间很长。用面板的风险也很明确：面板本身就是一个高权限的 Web 入口，默认端口和默认路径在网上是公开的，如果装完不加固，扫描器几分钟内就会找上门尝试爆破。所以本章的态度是：装面板可以，但安装和加固必须一次做完，加固没做完之前不要在面板里建正式站点。

本章以纯净的 Ubuntu 22.04 或 24.04 为前提，已经装过 Nginx、Apache、MySQL、PHP 中任何一个的系统不要装面板，环境冲突会导致安装失败或服务互相覆盖，应改走本部分第 03 章的手工路线，或重装为纯净系统后再装面板。

!!! warning "核验日期与适用范围"
    本章安装命令最后核验日期：2026-10-21；宝塔官方安装方式如有变化，以官方安装页为准，执行前应回到官方安装页重新复制命令，不要照抄网上旧教程。Ubuntu 26.04 的官方支持结论见下一节：在官方支持列表明确列入之前，不要在 26.04 上直接套用本章命令。

## 二、环境准备与前置条件

- 操作系统：纯净的 Ubuntu Server 22.04 LTS 或 24.04 LTS，没有预装任何 Web 环境，可用下面命令自查，自查结果应为空或提示未找到。

    系统支持范围以官方页面为准（核验于 2026-10-21）：宝塔官方文档快速安装页只列出 CentOS、Ubuntu、Debian、AlmaLinux、RockyLinux 等发行版，没有逐一列明 Ubuntu 版本号；aaPanel 官方博客的安装前置条件写的是 Ubuntu 20.04 或 22.04。两处官方说明都没有明确列入 Ubuntu 26.04，因此 26.04 官方支持待确认，不要在 26.04 上直接套用本章命令，应等官方支持列表更新或先向官方确认。24.04 同样建议在执行前回官方安装页看当时的支持说明，不要默认所有版本都受支持。

```bash
lsb_release -a
which nginx apache2 mysql php
sudo ss -tlnp | grep -E ':(80|443|3306|8888) '
```

- 硬件建议：至少 1 核 CPU、1 GB 内存、10 GB 可用磁盘；要跑 MySQL 加多个站点，建议 2 核 4 GB 起步。
- 权限：使用 root 账号，或可使用 sudo 的账号，例如 ubuntu。安装全程需要管理员权限。
- 网络：服务器能访问互联网下载安装包；云厂商控制台的安全组和系统内 UFW 防火墙都要能放行后续用到的端口。
- 准备工作：先更新系统并安装下载工具，改任何系统状态前留好快照或备份。

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y wget curl
```

!!! warning "纯净系统是硬条件"
    宝塔官方明确要求在没有装过 Apache、Nginx、PHP、MySQL 的干净系统上安装。云厂商的某些镜像自带环境，选镜像时应选纯操作系统镜像，不要选带建站环境的应用镜像。

## 三、手把手操作步骤

### 3.1 区分国内版与国际版

| 项目 | 国内版宝塔 | 国际版 aaPanel |
| --- | --- | --- |
| 官网 | bt.cn | aapanel.com |
| 界面语言 | 简体中文 | 英文 |
| 账号要求 | 首次使用通常要求绑定宝塔账号 | 不强制绑定账号即可使用核心功能 |
| 下载源 | 国内节点，国内服务器下载快 | 海外节点，海外服务器下载快 |
| 功能定位 | 功能更新快，含国内常用插件与服务 | 与国内版同源，插件生态偏海外常用软件 |

两者是同一团队的两个发行渠道，核心建站能力基本一致。在国内云服务器上优先选国内版，在海外服务器上优先选国际版，主要考虑下载速度和账号体系，没有功能上的高下之分。下面分别给出两个版本的官方现行安装命令。

官方安装页（核验于 2026-10-21，命令以这些页面为准）：

- 国内版官方下载页：https://www.bt.cn/new/download.html （核验时该页正式版标注为 13.1.0）
- 国内版官方文档快速安装页：https://docs.bt.cn/getting-started/quick-installation-of-bt-panel/
- 国际版官方下载页：https://www.aapanel.com/new/download.html
- 国际版官方博客安装说明：https://www.aapanel.com/blog/how-to-install-aapanel-and-wordpress/

!!! note "最后核验日期"
    最后核验日期：2026-10-21；宝塔官方安装方式如有变化，以官方安装页为准。版本号、脚本名和脚本后面的参数都可能随官网改版变化，执行前应再去官方安装页确认一次并原样复制。

### 3.2 先下载审阅脚本，再执行安装

!!! warning "执行远程脚本前应先下载审阅"
    一键安装的本质是以管理员权限运行一段从网上下载的脚本。正确做法是先把脚本下载到本地，用文本编辑器或 less 通读一遍，确认下载地址是官网域名、脚本没有夹带陌生地址和可疑命令，再执行安装。直接把下载和执行写成一条管道命令虽然省事，但你完全不知道自己跑了什么，生产服务器禁止这样做。

国内版官方一键安装命令原文如下，来自宝塔官方下载页，核验于 2026-10-21：

```bash
if [ -f /usr/bin/curl ];then curl -sSO https://download.bt.cn/install/install_panel.sh;else wget -O install_panel.sh https://download.bt.cn/install/install_panel.sh;fi;bash install_panel.sh rU2tN9mZ
```

注意脚本名后面的参数：官方下载页写的是 `rU2tN9mZ`，官方文档快速安装页同一条命令写的是 `docscenter`。这是随复制来源不同的渠道参数，不是校验和，也不是必须改对的口令；从哪个官方页面复制，就原样保留哪个参数，不要把不同页面的写法混在一起。

本章推荐把官方命令拆开执行：先只下载、审阅并记录指纹，确认无误后才运行。国内版拆分写法如下，其中下载地址和执行参数与官方下载页一致：

```bash
cd /tmp
wget -O install_panel.sh https://download.bt.cn/install/install_panel.sh
less install_panel.sh
grep -nE 'curl|wget|https?://' install_panel.sh | head -n 100
sha256sum install_panel.sh | tee install_panel.sh.sha256.txt
sudo bash install_panel.sh rU2tN9mZ
```

审阅时重点看三件事：脚本里出现的下载域名是否只有 download.bt.cn 等宝塔官方域名；有没有陌生 IP、陌生域名和看不懂的编码混淆内容；有没有与装面板无关的命令。看不懂、解释不了的部分不要执行，先停下来查官方文档或换一台测试机验证。

!!! warning "官方未提供校验和，更要先审阅脚本"
    本次核查（2026-10-21）的宝塔官方下载页、官方文档快速安装页以及 aaPanel 官方安装页和官方博客，都没有提供安装脚本的 sha256 校验和或数字签名，所以没有官方校验值可以比对。上面 `sha256sum` 生成的只是你这次下载到的脚本指纹，只能用于记录和日后复核同一文件有没有变化，不能证明脚本可信，这正是必须先审阅脚本的原因。若官方将来提供校验文件，应按官方说明下载校验文件后用 `sha256sum -c 校验文件名` 核对（文件名以官方提供为准）；不要从第三方网站抄所谓的官方校验值来比对。

国际版 aaPanel 官方一键安装命令原文如下，来自 aaPanel 官方博客安装说明，核验于 2026-10-21：

```bash
URL=https://www.aapanel.com/script/install_panel_en.sh && if [ -f /usr/bin/curl ];then curl -ksSO "$URL" ;else wget --no-check-certificate -O install_panel_en.sh "$URL";fi;bash install_panel_en.sh
```

注意两点：第一，国际版官方原文执行时不带额外参数，不要给它套用国内版的参数。第二，官方原文里的 `-k` 和 `--no-check-certificate` 表示跳过 TLS 证书校验，会降低下载环节的可信度；拆分执行时下载这一步尽量改用正常校验证书的写法下载同一个官方地址，下载失败先排查网络和证书问题，不要习惯性加上跳过校验的参数。

国际版拆分写法如下：

```bash
cd /tmp
URL=https://www.aapanel.com/script/install_panel_en.sh
curl -sSO "$URL"
less install_panel_en.sh
sha256sum install_panel_en.sh | tee install_panel_en.sh.sha256.txt
sudo bash install_panel_en.sh
```

安装过程会依次检测系统、安装依赖、下载面板程序和基础组件，中途出现是否继续安装到指定目录的确认提示时输入 y 并回车。整个过程一般需要数分钟，网络较慢时更久，期间不要关闭终端。安装结束后终端会打印面板的外网访问地址、内网访问地址、用户名和随机密码，格式示意如下，实际字符以你机器输出为准。

### 3.3 首次登录并保存随机入口与账号密码

安装完成输出的信息包含三件必须当场保存的东西：带随机字符串的安全入口地址、随机用户名、随机密码。安全入口是指面板地址端口后面跟的一段随机路径，没有这段路径直接访问端口会返回错误页面，这是面板的第一道防线。

操作要求：第一时间把完整登录地址、用户名、密码存入你自己的密码管理器，不要只留在终端截图里，更不要发到聊天群里求助时把地址和密码一起发出去。保存后在浏览器打开登录地址完成首次登录。忘记密码或找不到入口时，不要反复猜密码触发锁定，应在服务器上用 `bt` 命令行工具查看默认信息或重置。

!!! warning "bt 编号随版本变化，先看帮助菜单再执行"
    `bt` 的数字编号和子命令随宝塔版本变化，旧教程里的编号在新版本上可能不存在或含义不同。执行任何 `bt 编号` 之前，先运行 `sudo bt` 看本机当前版本的帮助菜单，确认该编号存在且含义对得上，再执行，不要盲抄。按官方文档现行菜单（核验于 2026-10-21）：`14` 是查看面板默认信息，`5` 是修改面板密码，`6` 是修改面板用户名，`8` 是改面板端口，`28` 是修改面板安全入口，`34` 是更新面板。老版本常见的 `bt default` 在部分版本上可用，若本机提示不存在或无此选项，改用下面的 `bt 14`，不要反复试错命令。

```bash
sudo bt
sudo bt 14
```

上面命令会显示面板的默认信息，包括地址、入口、用户名等，改密码按菜单里对应的编号（现行文档为 `5`）操作。改面板相关文件前同样先备份，例如改端口配置前：

```bash
sudo cp /www/server/panel/data/port.pl /www/server/panel/data/port.pl.bak.20260101
```

### 3.4 安全加固一：改默认端口与安全入口

旧教程常说面板默认端口是 8888，但宝塔官方文档现已说明当前安装会生成随机端口，以安装完成后终端输出的面板地址为准。不论安装给你的是 8888 还是随机端口，都建议再改成你自己选的端口，不要沿用安装输出的端口长期使用。登录面板后进入面板设置页面，把面板端口改成一个 20000 到 50000 之间不规律的端口，例如 32417。改完面板会要求用新端口重新访问。同时在同一设置页修改安全入口，把安装时生成的随机路径换成你自己的一段无规律字符串，并把新入口地址重新存入密码管理器。改端口之前先确认新端口没有被其他程序占用：

```bash
sudo ss -tlnp | grep 32417
```

无输出表示该端口空闲，可以使用。

### 3.5 安全加固二：UFW 与云安全组放行

改完端口要同步放行两层防火墙，缺一层都会导致面板打不开。系统内 UFW 放行新面板端口，并关闭旧端口的放行规则（下面以旧端口 8888 为例，安装输出的端口不是 8888 时按实际端口替换）：

```bash
sudo ufw allow 32417/tcp comment "bt-panel"
sudo ufw delete allow 8888/tcp
sudo ufw status verbose
```

云厂商控制台的安全组里做同样的两步：入方向新增一条放行新面板端口的规则，来源地址优先只填你自己的办公出口 IP，实在需要全网访问时才填 0.0.0.0/0；再删除放行 8888 的旧规则。网站正常运行还需要放行 80 和 443，SSH 的 22 端口按你现有加固做法保留。

!!! tip "面板端口只对自己开放最稳妥"
    如果你的办公网络有固定公网 IP，面板端口在安全组里只放行这个 IP，其余来源全部拒绝，面板在公网上等于隐身，这是比改端口更有效的一步。经常出差没有固定 IP 时，可以配合只允许指定域名绑定访问等面板自带功能一起使用。

### 3.6 安全加固三：登录 MFA 与访问限制

在面板设置页面依次完成以下加固项，每做完一项退出重新登录验证一次，确认不会把自己锁在外面再做下一项：第一，修改默认随机用户名为你自己的无规律用户名，并把随机密码改成密码管理器生成的高强度密码。第二，开启登录的动态口令验证，也就是基于时间的一次性验证码 MFA，在面板的账号或安全相关设置中绑定验证器应用，绑定后保存好恢复方式。第三，开启面板的登录告警和失败锁定，连续输错密码时自动临时封禁来源。第四，如面板提供授权 IP 功能，把允许登录的来源限定为你的常用地址段。

### 3.7 安全加固四：给面板本身开 SSL

面板默认用 HTTP 明文传输，登录密码在链路上是裸奔的，必须开 SSL。在面板设置页面找到面板 SSL 选项开启，证书可使用面板内申请的免费证书，申请前需要先给面板绑定一个域名，并把该域名的解析指向本服务器，解析方法见本部分第 01 章。绑定域名并开启 SSL 后，用 https 加域名加新端口加安全入口的完整地址访问。证书续期方法见本部分第 05 章。

!!! note "自签证书警告的处理"
    临时使用自签证书时浏览器会报证书不受信任，这是预期现象，确认地址和端口无误后可继续访问。但长期使用应换成受信任的免费证书，避免养成见警告就点继续的习惯，真遇到中间人攻击时会失去警觉。

## 四、效果验证与测试

逐项验证，不要只看面板能打开就算完成：

```bash
sudo bt status
sudo ss -tlnp | grep 32417
sudo ufw status verbose
curl -Ik https://example.com:32417/
```

期望结果：bt status 显示面板服务运行中；ss 输出里只有新端口在监听，8888 不再出现；ufw 规则里有新面板端口的放行且没有 8888；用旧地址带 8888 端口访问面板应连接失败，用新地址带安全入口访问应出现登录页，输错入口路径应返回错误页而不是登录页；开启 MFA 后，输对密码还会要求输入动态验证码。最后在面板首页确认系统信息显示的 Ubuntu 版本与你的系统一致，时间和时区正确。

说明：`bt` 的子命令和数字编号随面板版本变化，上面用到的命令若在本机不存在或含义对不上，先运行 `sudo bt` 看当前版本的帮助菜单再找对应项，不要盲抄其他版本的编号（详见 3.3 节的警示）。

## 五、常见错误与排坑指南

**场景一：安装中途报错提示已有环境或安装失败退出。** 常见输出片段包含检测到已安装的软件名称和 abort 类字样。原因是系统不纯净，镜像自带了 Nginx 或 MySQL。修复方法是卸载冲突环境后重装，或直接重装纯净系统。先确认冲突来源：

```bash
dpkg -l | grep -E 'nginx|apache2|mysql-server|php'
sudo apt purge -y nginx apache2
sudo apt autoremove -y
```

卸载会影响已有站点数据，生产机不要这样处理，应改走手工路线。

**场景二：面板装好了但浏览器打不开，连接超时。** 十有八九是防火墙没放行：只改了系统 UFW 忘了云安全组，或反过来。逐层排查：

```bash
sudo ss -tlnp | grep 32417
sudo ufw status
curl -v http://127.0.0.1:32417/
```

本机能通说明面板本身正常，问题在云安全组或运营商拦截，去控制台补放行规则。

**场景三：改完端口或入口后自己也登录不上。** 原因是新地址没有记全，少了安全入口路径，或防火墙还停留在旧端口。用服务器终端兜底查看当前配置：

```bash
sudo cat /www/server/panel/data/port.pl
sudo bt 14
sudo ufw allow 32417/tcp
```

其中 `bt 14` 是官方现行菜单里查看面板默认信息的编号，执行前先用 `sudo bt` 确认本机菜单里该编号存在（老版本也可以试 `bt default`，不存在就不要反复试）。按输出拼出完整地址重新登录，登录后第一件事是把地址存入密码管理器。

**场景四：安装中途失败或装到一半退出，不知道怎么收尾。** 先收集日志，不要急着重跑安装脚本。安装开始前最好先开启终端会话记录，或把安装命令的完整输出保存到文件；已经失败的，把当前终端从头到尾的输出截图或复制保存下来，连同下载到的安装脚本和它的 sha256 指纹文件一起留存。面板已经装上一部分时，还可以这样收集现场信息：

```bash
lsb_release -a
uname -a
df -h
free -m
sudo bt
sudo bt 22
```

其中 `bt 22` 是官方现行菜单里显示面板错误日志的编号，同样先用 `sudo bt` 确认本机菜单里存在再执行；面板日志目录和安装日志的具体文件名随版本变化，以 `bt` 工具输出和官方文档当时说明为准，不要按旧教程猜路径乱删文件。求助或提工单时，把系统版本、失败步骤、终端完整输出的最后部分和错误日志一起给出，并先去掉其中的密码、入口路径等敏感信息。

失败后的安全恢复按这个顺序处理：第一选择是回滚到安装前做的云快照或系统备份，这是最干净的恢复方式；没有快照时，使用官方卸载脚本清理未完成的安装，脚本来自宝塔官方文档的安全卸载页（https://docs.bt.cn/getting-started/uninstall-panel/），同样先下载审阅再执行：

```bash
wget https://download.bt.cn/install/bt-uninstall.sh
less bt-uninstall.sh
sudo bash bt-uninstall.sh
```

按官方说明，运行时输入 1 只卸载面板，输入 2 会卸载面板并清理面板相关环境，可能影响网站和数据库数据，属于破坏性操作，选之前必须确认数据已经备份。最重要的一条：未完成的安装不要在生产机上反复重跑安装脚本，重跑会重新生成端口、入口和账号并叠加残留文件，越跑越乱；要重试，先在测试机复现，或回滚快照后在干净系统上一次装对。

## 六、生产环境最佳实践与安全建议

第一，面板不是装完就结束，面板和插件要跟随官方更新，重大更新前先做云快照，出问题可整机回滚。第二，面板账号只给需要的人，禁止多人共用一个账号，离职和交接时立即改密码并重置 MFA。第三，不要在面板里开启不需要的服务，例如用不到 FTP 就不要装 FTP 组件，少一个服务少一个攻击面。第四，站点和数据库的自动备份要在建站当天就配好，备份保留到异地或对象存储，只存本机等于没有备份。第五，定期看面板的安全日志和系统的登录日志，发现大量失败登录说明入口已经暴露，应立即更换端口、入口并收紧安全组来源。第六，重要生产业务在条件允许时仍推荐手工 LNMP 路线，面板更适合中小站点和过渡阶段，心里要清楚这条边界。第七，重装或大版本升级前，先回官方安装页复核当时的安装命令、脚本参数和支持系统列表，并把这次实际执行的安装脚本和它的 sha256 指纹记录一起归档，日后排障和审计时能对得上账。
