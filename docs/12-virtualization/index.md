# 第 12 部分：硬件、虚拟化与私有云

当 Ubuntu Server 从单机服务走向算力平台时，硬件能力决定上限：GPU 决定推理与训练吞吐，虚拟化决定资源隔离与利用率，直通与 SR-IOV 决定延迟与性能损耗。本部分从驱动层开始，逐层向上搭建一套可用于生产环境的虚拟化与私有云底座。

## 本部分地图

| 章节 | 主题 | 解决的问题 |
| --- | --- | --- |
| 第 1 章 | GPU 与 CUDA | 让系统正确识别显卡，让容器稳定调用 GPU 算力 |
| 第 2 章 | KVM/QEMU 宿主机 | 把一台物理服务器切分为多台隔离的虚拟机 |
| 第 3 章 | PCIe 直通与 SR-IOV | 让虚拟机近乎裸机地独占显卡、网卡与 NVMe |

学习路径建议按顺序阅读：第 1 章是 AI 与高性能计算的前置，第 2 章是私有云的通用底座，第 3 章是在底座之上追求极致性能的进阶能力，三者可以独立使用，也可以组合为 GPU 虚拟机与推理集群。

## 每章一句话

- **01 GPU 与 CUDA**：装对驱动、装对工具链、用对容器运行时，`nvidia-smi` 能在宿主机与容器内同时正常输出才算完成。
- **02 KVM/QEMU 宿主机**：用 libvirt 统一管理虚拟机生命周期，用桥接网络让虚拟机像独立服务器一样接入局域网。
- **03 PCIe 直通与 SR-IOV**：用 IOMMU 与 VFIO 把硬件设备完整交给虚拟机，性能接近裸机，但每一步都必须先想好回滚。

## 硬件前置检查清单

在开始任何一章之前，请逐项确认，任意一项不满足都应先处理再继续：

- [ ] 主板 BIOS/UEFI 已升级到厂商稳定版本，且能正常进入设置界面
- [ ] CPU 支持硬件虚拟化：Intel VT-x 或 AMD-V，且 BIOS 中已开启
- [ ] 计划直通时，BIOS 中已开启 VT-d 或 AMD-Vi 与 IOMMU 选项
- [ ] 内存容量满足宿主机保留需求：宿主机至少预留 4 GiB，单台虚拟机按业务另行规划
- [ ] 系统盘之外有独立数据盘或存储池规划，避免虚拟机镜像与系统日志互相挤占
- [ ] NVIDIA 显卡供电与散热到位：检查辅助供电线、机箱风道与满载温度预期
- [ ] 已确认 Secure Boot 当前状态，并准备好处理驱动模块签名的方式
- [ ] 已准备带外管理或本地显示器与键盘，直通显卡后远程图形可能不可用
- [ ] 已完成系统全量备份或快照，且确认备份可以恢复
- [ ] 网卡型号已查证是否支持 SR-IOV，不支持的型号不要强行启用虚拟功能

!!! tip "先检查再动手"
    本部分涉及内核参数、驱动模块与网络桥接，改动后多数需要重启。建议在维护窗口内操作，并保留一条可以登录宿主机的备用通道，例如带外管理口或本地控制台。

完成本部分后，你将拥有一台既能跑 GPU 容器、又能承载多台虚拟机、还能为关键虚拟机提供硬件直通能力的 Ubuntu 私有云宿主机。
