# 第 10 部分：游戏服务器部署与端口映射

把游戏服务端装好只是第一步，朋友连不进来、半夜崩服没人重启、在老家内网开服没有公网 IP——这三类问题才是自建游戏服真正的门槛。本部分按「先通路、再装服、再守护、最后穿透」的顺序，把一台 Ubuntu 云服务器或家用小主机变成 7×24 小时稳定在线的游戏服。

## 本部分地图

| 章节 | 解决的问题 | 核心产出 |
| --- | --- | --- |
| [01 端口开放：三重门](01-port-opening.md) | 服务端起来了但外网连不上 | 安全组、UFW、绑定地址三层全部打通并可验证 |
| [02 游戏服务端实战](02-game-server-setup.md) | 不知道怎么装、参数不会填 | SteamCMD、Minecraft Java 版、Palworld 三条完整开服路线 |
| [03 性能调优与守护](03-performance-daemon.md) | 崩服要手动救、内存爆了整机卡死 | systemd 自启自愈、SWAP 防 OOM、内核与资源上限 |
| [04 内网穿透与公网映射](04-nat-traversal.md) | 家里没有公网 IP，朋友进不来 | frp 主线方案加 NPS、Tailscale Funnel 选型对比 |

## 每章一句话

- **01 端口开放**：外网流量要连过云安全组、本机防火墙、应用绑定地址三道门，缺一道就全盘不通，排错必须逐层定位。
- **02 服务端实战**：先用 SteamCMD 建好统一的下载与更新底座，再按游戏分别走完 Minecraft 与 Palworld 的配置和首次启动。
- **03 性能与守护**：用 systemd 让游戏服开机自启、崩溃自愈，再用 SWAP、内核参数和资源上限兜住内存与网络的突发峰值。
- **04 内网穿透**：没有公网 IP 时，把一台有公网 IP 的 VPS 当中继，用 frp 把内网的游戏端口安全地映射出去。

## 开服前检查清单

开工前逐项打勾，缺一项先补齐再往下走：

- [ ] 服务器为 Ubuntu 22.04 LTS 或 24.04 LTS，已完成系统更新，且能用 SSH 登录。
- [ ] 已确认服务器的公网 IP；家用宽带场景已确认是否被运营商 CGNAT（详见第 04 章）。
- [ ] 内存满足目标游戏下限：Minecraft 小型服建议 4 GB 起，Palworld 建议 16 GB 起。
- [ ] 磁盘可用空间不少于 30 GB，世界存档和备份有地方放。
- [ ] 已想好服务器密码与管理员密码的强口令，并准备妥善保管、绝不写进公开文档。
- [ ] 已规划开放端口清单，只开游戏必需端口，不做全端口放行。
- [ ] 已安排存档备份策略：至少每日一份异地或异盘备份。

!!! tip "阅读顺序建议"
    第一次开服请按 01 → 02 → 03 顺序读完再动手；已有公网 IP 的云服务器可跳过第 04 章；家用内网开服则务必先读第 04 章确认穿透方案，再回头做第 01 章的本机部分。
