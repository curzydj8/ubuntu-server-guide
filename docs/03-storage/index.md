# 第 03 部分：磁盘、文件系统与存储

服务器的可靠性，一半在计算，一半在存储。系统盘满、文件系统损坏、备份不可用，往往是生产事故中最难挽回的一类。本部分从逻辑卷管理讲到现代文件系统、网络共享与备份体系，目标是让你在 Ubuntu Server 22.04 / 24.04 LTS 上，能独立完成扩容、组建冗余阵列、共享存储并建立可验证的备份。

## 本部分地图

| 章节 | 文件 | 一句话定位 |
|------|------|------------|
| 3.1 LVM 动态卷管理 | `01-lvm.md` | 用 PV / VG / LV 把物理磁盘抽象成可在线伸缩的逻辑卷，解决分区写死无法扩容的问题 |
| 3.2 ZFS 与 Btrfs | `02-zfs-btrfs.md` | 用自带校验、快照与 RAID 能力的文件系统保护数据完整性，对比两种方案的选型边界 |
| 3.3 挂载与存储共享 | `03-mount-sharing.md` | 讲清 fstab 每一列的含义，并落地 NFS、Samba、iSCSI 三种主流共享方式，含 Samba 深化：权限映射与多用户治理、凭据保护、配额、回收站与审计 |
| 3.4 磁盘健康与备份 | `04-backup.md` | 用 SMART 提前发现坏盘，用 rsync、restic、Borg 建立增量备份并做恢复演练 |

这四章不是孤立的：LVM 解决的是空间弹性，ZFS / Btrfs 解决的是数据正确性，挂载与共享解决的是数据如何被其他机器使用，备份解决的是数据丢失后如何回来。生产环境通常会组合使用，例如系统盘走 LVM，数据池走 ZFS，备份目标走 NFS 挂载。

## 推荐阅读顺序

建议按 3.1 → 3.2 → 3.3 → 3.4 的顺序阅读。先理解块设备、分区与逻辑卷的关系，再理解文件系统层面的快照与校验，随后学习如何把存储挂载并共享出去，最后补上健康监测与备份闭环。如果你已经熟悉 LVM，可以直接从 3.2 开始；但 3.3 中的 fstab 详解建议不要跳过，它是开机无法启动类故障的高发区。

## 前置知识

阅读本部分前，你应当已经会使用 `lsblk`、`df -h`、`mount` 查看当前磁盘布局，了解 `/dev/sdX`、`/dev/nvmeXnY` 的命名规则，熟悉 `sudo` 提权与 `systemctl` 服务管理，并完成第 01 部分的系统安装与第 02 部分的用户权限配置。所有涉及磁盘写操作的实验，强烈建议先在虚拟机或带快照的云主机上练习，确认命令无误后再上生产机。

!!! warning "操作前必读"
    本部分包含 `pvcreate`、`mkfs`、`lvreduce`、`zpool create` 等会直接改写磁盘元数据的命令。执行前务必用 `lsblk -f` 二次确认设备名，设备名写错一位就可能覆盖系统盘。任何时候都不要在未确认备份可用时做缩减与格式化操作。

学完本部分，你应该能独立判断一块盘该用 LVM 还是 ZFS、能写出一份不会导致无法开机的 `/etc/fstab`、能为文件服务器配置 NFS 与 Samba 共享，并能拿出一套可实际恢复的备份方案，而不是只有一堆从未验证过的备份文件。
