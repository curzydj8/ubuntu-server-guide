# 版本兼容与验证状态

本页是全站唯一的验证状态基准页：每个主题在各 Ubuntu LTS 版本上到底是「实机跑过」还是「只对过文档」，都以本页标注为准。正文中的命令如果与本页标注冲突，以本页为准，并欢迎到仓库提 Issue 指出。

## 验证状态图例

本站只使用以下三级状态，不使用任何模糊或夸大的兼容性说法：

| 状态 | 含义 |
| --- | --- |
| **已实测** | 核心流程已在真实机器上实际运行并确认效果。本站语境下，实测环境为站长自有的 Ubuntu 22.04 LTS / 24.04 LTS 机器（日常运维与服务部署环境）。超出核心流程的进阶参数、集群与高可用部分不在此列，仍按「文档核对」看待。 |
| **文档核对** | 命令、参数与配置文件写法已与 Ubuntu 官方文档及各项目官方文档逐项核对一致，但没有在实机上完整运行验证。照着做大概率可行，但首次在生产环境使用前请先在测试机演练。 |
| **待核验** | 尚未核对、尚未实测。可能是版本刚发布、实测环境暂不可用，或第三方尚未明确表态。在状态更新前，不要默认正文命令在该版本上可直接使用。 |

!!! warning "关于文件校验的一个提醒"
    SHA 一致只证明文件一致，不证明命令正确，验证状态以本页为准。下载的脚本、镜像或仓库文件即使哈希完全对得上，也只说明「文件没被改动」，不代表里面的命令在你的系统版本上一定正确、一定安全——执行前仍应审阅内容，并对照本页确认对应版本的验证状态。

## 26.04 升级规划

本站不会为了「支持新版本」而批量把正文中的 22.04 / 24.04 字样替换成 26.04，原因很实际：

- **命令表面相同，不代表行为相同**：新 LTS 往往伴随内核、systemd、OpenSSH、Netplan 等基础组件的大版本变化，同一条命令的默认值、配置文件路径或输出格式都可能改变。
- **驱动与第三方软件是重灾区**：NVIDIA 驱动与 CUDA、KVM/QEMU 的兼容性取决于内核与硬件组合；宝塔等第三方软件则取决于厂商是否发布了针对 26.04 的安装脚本与支持声明——在官方表态之前，本站只能标注「待确认官方支持」。
- **批量改写会掩盖未验证的事实**：文字上「适配」了、实际没跑过，是对读者最不负责任的做法。

后续推进方式：

1. 待 26.04.1 实测环境恢复可用后，按矩阵逐行核验：先核心流程（基础安装、SSH 与 UFW、Netplan、Docker、数据库），再进阶主题（集群、GPU、虚拟化、游戏服务器）。
2. 每核验完一行，立即更新本页对应单元格的状态，并在[更新日志](changelog.md)中留一条记录；未核验的行保持「待核验」不动。
3. 若核验发现命令或配置与 22.04 / 24.04 有差异，在正文对应章节用提示块单独标注版本差异，而不是直接覆盖旧版本写法。

!!! tip "欢迎反馈实测结果"
    如果你已经在 Ubuntu 26.04 LTS 上跑过本站的某个章节，无论成功还是踩坑，都欢迎到仓库 [Issues](https://github.com/curzydj8/ubuntu-server-guide/issues) 反馈：请注明系统版本（`lsb_release -a` 输出）、执行的章节与命令、实际结果或报错信息。经复核的读者实测同样可以推动矩阵状态升级，反馈时本站会注明来源与环境，不会把他人环境的结果冒充本站实测。
