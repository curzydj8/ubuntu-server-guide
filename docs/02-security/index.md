# 02 系统安全与权限管理 · 导览

一台 Ubuntu Server 装完系统、接上网络之后，最先要做的不是部署业务，而是把门锁好。本部分讲的就是这件事：谁能进门、进来之后能做多少事、门口有没有围墙、有人撬门时系统能不能自己报警并拦住人。四章按「从入口到内层」排列，做完就具备一套可上线生产的安全基线。

## 本部分地图

| 章节 | 文件 | 解决的问题 |
| --- | --- | --- |
| 第 1 章 | `01-ssh-hardening.md` | 远程入口怎么守：SSH 密钥登录、改端口、禁用 Root 与密码登录、双因素认证 |
| 第 2 章 | `02-users-sudo-pam.md` | 账号体系怎么管：用户与组、Sudo 授权边界、PAM 密码与登录规则 |
| 第 3 章 | `03-firewall.md` | 网络边界怎么围：UFW 快速封堵、nftables 与 iptables 精细规则与 NAT 转发 |
| 第 4 章 | `04-defense.md` | 主动防御怎么做：Fail2ban 自动封禁、AppArmor 进程隔离、AIDE 文件完整性检查 |

## 每章一句话

- **SSH 安全加固**：把 SSH 从「密码猜得中就能进」改造成「没有私钥进不来」，再叠加端口调整与双因素认证，让暴力破解失去意义。
- **用户与组、Sudo 与 PAM**：坚持一人一号、最小授权，用 Sudo 白名单控制谁能提权，用 PAM 在系统层面强制密码强度与登录限制。
- **防火墙管理**：默认拒绝入站、按需放行，用 UFW 管日常、用 nftables 管复杂规则，确保只有明确开放的端口暴露在外。
- **系统防御与入侵检测**：让服务器自己会反击和留痕，Fail2ban 封禁扫描源，AppArmor 困住被攻破的进程，AIDE 发现文件被篡改的痕迹。

## 推荐顺序与依赖关系

请按 01 → 02 → 03 → 04 的顺序学习和实操，不要跳章。原因很具体：01 章会关掉密码登录，如果 02 章的备用管理账号还没有建好，操作失误时就没有第二条退路；03 章的防火墙规则要放行 01 章改过的新 SSH 端口，顺序反了会直接断连；04 章的 Fail2ban 监控的是 01 章的 SSH 日志，AppArmor 与 AIDE 则建立在前几章账号与权限已经收紧的前提上。每章末尾的验证步骤通过之后，再进入下一章。

## 前置知识

开始之前，读者应已完成第 01 部分的安装与初始配置，并具备以下基础：会用终端执行命令并理解 `sudo` 的含义；会用 `nano` 或 `vim` 编辑 `/etc` 下的配置文件；理解 IP、端口、TCP 与 UDP 的基本概念；手边保留云厂商控制台等带外救援方式。密钥概念陌生的读者，先理解「公钥可以公开、私钥必须保密」这一条原则即可。

!!! warning "动手前先留退路"
    本部分的每一章都会修改登录与网络相关的关键配置。操作全程请保持至少一个已登录的 SSH 会话不要断开，每改完一项先开新终端验证能正常登录，再关闭旧会话。云服务器用户请提前确认控制台登录可用，这是把自己锁在门外时最后的自救通道。

## 学完本部分能达到的状态

服务器只允许密钥登录且 Root 无法远程登录，管理账号按人划分、提权有白名单、密码规则由系统强制，防火墙默认拒绝且只开放业务所需端口，暴力破解会被自动封禁，关键服务被 AppArmor 隔离，系统文件有完整性基线可比对。没有这四章打底，后面任何服务部署都是在敞着门营业。
