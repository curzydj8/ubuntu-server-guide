# 签名指南 — Linux Server Toolkit Release 签名（站长操作）

原则：发布密钥由站长自备自管；代理只配构建，永不经手密钥文件与口令；密钥与口令永不入 Git、永不走聊天。

## 1. 生成发布密钥（只需做一次，站长在自己机器上执行）

```sh
keytool -genkeypair -alias toolkit-release -keyalg RSA -keysize 2048 \
  -validity 10000 -keystore toolkit-release.keystore
```

- 别名、口令自定并离线备份（丢了就无法再以同一签名更新已装用户）。
- keystore 文件只存站长机器（建议再离线备份一份），不要放进工程仓库、不要发给代理。
- 注意：`-keystore` 给的路径必须是已存在的文件夹，keytool 不会自动建目录；示例里的 `C:\path\to\` 只是占位写法，实测会报“系统找不到指定的路径”，请换成真实存在的文件夹（如 `C:\Users\<你>\toolkit-release.keystore`）。

## 2. 构建签名版 release APK

在工程根目录，以 gradle properties 传入四项（不要写进仓库内的任何文件）：

```sh
./gradlew assembleRelease \
  -PreleaseStoreFile=/path/to/toolkit-release.keystore \
  -PreleaseStorePassword='<口令>' \
  -PreleaseKeyAlias=toolkit-release \
  -PreleaseKeyPassword='<口令>'
```

- 四项不齐时构建产出未签名 release APK（可用于冒烟，不可发布）。
- 产物：`app/build/outputs/apk/release/app-release.apk`；记录 `sha256sum`。

## 2b. 已有未签名包时的签名（本次 1.0.0 发布走法）

站长机器上有 Android Studio 时，不必在 Windows 上搭整套 Gradle 工程：代理交付未签名
release APK，站长用 SDK 自带的 apksigner 签名（口令交互输入，不进聊天、不入仓）：

```bat
REM 签名（keystore 与别名沿用第 1 节；apksigner 在 %LOCALAPPDATA%\Android\Sdk\build-tools\<版本>\ 下）
apksigner.bat sign --ks C:\path\to\toolkit-release.keystore --ks-key-alias toolkit-release ^
  --out toolkit-1.0.0-signed.apk app-release-unsigned.apk
```

- AGP 产出的未签名包已 zipalign，可直接签名。
- 签好后把签名包发回代理核对（第 3 节）再发布；keystore 文件与口令始终只留站长机器。

```sh
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

- 核对证书指纹与发布密钥一致；与 debug 签名（`androiddebugkey`）不同。
- 同签名才可覆盖安装升级；换签须卸载重装（数据重置，发布时提前告知）。
