# 第五阶段实施计划：SSH 与服务器管理

依据：《安卓 App 项目任务书》第九节第五阶段（主机配置、认证、主机密钥校验、终端和只读诊断，再逐步增加受控操作）与第三节之 2「服务器连接与管理」、第七节测试要求。

## 一、范围

**本阶段做：**
- 主机配置管理：地址、端口、用户名、认证方式；分组、标签、搜索、连接状态展示。
- 认证：密码认证 + 私钥认证（支持口令加密的私钥）；凭据只进 Keystore 保险库，数据库只存引用。
- 主机密钥校验：首次连接展示 SHA256 指纹由用户确认（TOFU）；后续连接自动比对，**指纹变化时警告并阻止连接**，不得静默信任。
- 终端会话：shell 通道、命令输出流式展示、连接超时/断线处理/用户取消。
- 只读诊断：一组预设只读命令（系统版本、运行时间、负载、内存、磁盘、失败服务、监听端口等）一键采集并结构化展示。
- 受控操作护栏：执行前展示目标主机 + 命令 + 风险等级；高风险命令二次确认；**网络失败绝不自动重发命令**（exec 不走重试策略）；禁止应用静默执行破坏性操作。
- 操作审计：连接与命令执行落审计表（时间、主机、命令、风险、退出码），**日志与审计不记录密码、私钥、令牌**。

**本阶段不做（后续增量）：** SFTP 文件传输、跳板机（ProxyJump）、端口转发、完整 ANSI/xterm 终端仿真（vim/top 等全屏程序不可用，终端只做文本流——明确边界）。

## 二、技术选型

| 项 | 选定 | 说明 |
|---|---|---|
| SSH 实现 | **com.hierynomus:sshj 0.41.2** | 持续维护的主流实现（旧坐标 net.schmizz 已冻结，勿用）；支持 ed25519/ecdsa/rsa、密码/密钥/keyboard-interactive、主机密钥验证 API |
| 加密提供者 | org.bouncycastle:bcprov-jdk18on 1.86 | Android 自带 BC 功能残缺，须注册完整 BC 才能用 ed25519 等算法（标准做法） |
| 日志门面 | slf4j-api + slf4j-simple（输出脱敏） | sshj 依赖 |
| 备选 | com.github.mwiede:jsch 2.28.8 | 仅当 sshj 真机冒烟失败时切换（JSch 维护分支） |

版本全部进 Version Catalog 锁定；经本机 Maven 镜像拉取，锁定前先做拉取冒烟。

## 三、架构与数据

- **新模块 `core:ssh`**：`SshTransport`（连接/认证/exec/shell 流）、`TofuHostKeyVerifier`、`Fingerprint`（OpenSSH 风格 SHA256 指纹）、`CommandRisk`（命令风险分级）、`SshSessionManager`（超时、取消、断线状态机）。与 UI、数据库解耦，可独立单测。
- **新模块 `feature:servers`**：主机列表（分组/标签/搜索/状态）、主机编辑、连接与指纹确认、终端页、只读诊断页、审计列表。
- **导航**：底部三栏为站长已定结构（首页/工具/设置），不新增底栏；服务器模块从「工具」页顶部入口进入（路由 `servers/...`）。
- **数据库 v2 → v3**：新增 `server_profiles`、`host_keys`、`op_audit` 三表，提供 Migration 2→3 与 schema 3.json，禁止清库升级。
- **凭据**：复用第一阶段 `KeystoreCredentialVault`（AES-256/GCM）；密码与私钥只存保险库，Room 只存 vault 引用 ID。

## 四、分波实施

- **W1 协议冒烟 + 核心层**：先做 sshj 真机冒烟（手机经 tailnet 连 muse-1，只验协议握手与认证通道，证库可用——全阶段最大风险前置）；再落地 core:ssh、DB v3 迁移与仓库层；单元测试：指纹计算、风险分级、脱敏、迁移。
- **W2 功能 UI**：主机 CRUD 与分组/标签/搜索；连接流程与指纹确认弹窗；终端（执行、流式输出、取消）；只读诊断面板；审计列表。
- **W3 真机验收**：手机 → muse-1 全流程实测（见验收标准），修复后出验收记录，版本定为 **0.6.0**。

## 五、测试与门禁

- `build.sh` 全量（assemble + 单测 + lint）必须全绿；本阶段新增单测目标 ≥ 25。
- 集成测试：优先在 VM 起用户态测试 sshd（高端口）供 JVM 冒烟 sshj 协议路径；可行性在 W1 验证，不可行则以真机实测替代并在验收记录中标注。
- 安全测试清单：指纹变更必拦截；数据库文件抽查无明文凭据；日志/审计脱敏断言；高风险命令必二次确认；exec 断线不重发（故障注入断言）。

## 六、风险清单

1. **sshj + BC 在 Android 13 / API 36 的兼容性**——W1 冒烟前置验证，备选 JSch 已就绪。
2. **VM → muse-1 的 SSH 仍在握手期被重置（未定位）**——不阻塞验收主路径（手机经 tailnet 直连服务器）；若需核对服务器端日志，需站长协助在服务器上执行命令。
3. **muse-1 的 zhangdawei 认证方式待验收时确认**——密码或私钥由站长在手机端输入，不经聊天传递。
4. **终端能力边界**——仅文本流，无 ANSI 光标控制；全屏程序不可用，验收时以普通命令为准。

## 七、验收标准（对任务书逐条）

- [ ] 主机配置可增删改查，分组/标签/搜索可用，连接状态正确展示

- [ ] 首次连接弹出指纹确认；确认后免重复打扰；指纹被人为变更时连接被阻止并告警
- [ ] 终端可执行命令并流式显示输出；超时、断线、取消均有正确状态与提示
- [ ] 只读诊断一键采集并展示系统信息（真机实测）
- [ ] 高风险命令执行前展示主机 + 命令 + 风险并二次确认；断线不自动重发
- [ ] 审计记录完整，抽查无明文凭据与敏感日志
- [ ] 数据库 2→3 迁移在真机升级安装后数据保留（收藏等既有数据不丢）
- [ ] 全量单测 + lint 全绿；验收记录落 docs/
