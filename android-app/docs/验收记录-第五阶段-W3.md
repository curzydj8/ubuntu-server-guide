- 档案地址改为 192.168.1.19 保存（密码留空＝不修改，保险库内已存凭据复用），发起连接后弹出 TOFU 指纹确认：ssh-ed25519，SHA256:MY+M5+SOUxfnH/pssQ1uZuE9pkEdCEgi3hAD/j1J3Mc。站长点「信任并连接」后连接成功，列表状态为已连接。

## 2. W3 期间发现并修复的 bug

| 现象 | 根因 | 修复版本 | 真机验证 |
|---|---|---|---|
| 点「服务器连接」闪退 | 保险库 ref 含 `/`（ssh-host-\<id\>/pw），违反 Keystore vault 命名正则；且 vault.get() 的 fileFor 在 catch 外抛异常 | 0.6.1（CredentialRefs 统一命名为 …-pw/…-key/…-kp；get/contains 不再抛） | 连接失败时优雅提示、进程存活 |
| 保存时「凭据写入保险库失败」 | KeystoreCredentialVault 写 filesDir/vault 前未建目录，File.writeText 不建父目录 | 0.6.2（fileFor 内 mkdirs） | 再次保存后 run-as 检查 files/ 下出现 vault 目录 |
| 点「打开终端」失败：打开终端失败：null | **ServersViewModel.openTerminal 在主线程调用阻塞网络 openShell**，Android 抛 NetworkOnMainThreadException（该异常 message 恒为 null）。同类隐患：诊断 exec 也在主线程 | 0.6.4（openShell 与诊断 exec 均包 withContext(dispatchers.io)）；0.6.3 先行落地失败信息类名+cause 链与 logcat 栈，才得以定位 | 终端、诊断均恢复（见下） |

- 0.6.3 诊断版另新增 shell 端到端集成测试（MINA 回显 shell，ShellReproTest）：JVM 上 openShell+echo 全通，证明客户端 shell 路径本身无误，故障在 Android 线程模型——该测试保留为回归用例。
