# 干净环境重建 — Linux Server Toolkit

从一台空白 Ubuntu 24.04 机器复现本工程构建的步骤（构建机差异是 0.5.x 签名漂移的教训：debug 签名已固定为工程自带 keystore，见下）。

## 1. 工具链

- JDK：Temurin 21（`javac` 需可用）。
- Android SDK：cmdline-tools + platforms android-35/36 + build-tools 35/36 + platform-tools；`ANDROID_HOME` 指向 SDK 根。
- Gradle 8.14.3、AGP 8.13.2、Kotlin 2.2.21、KSP 2.2.21-2.0.5（均由 Gradle Wrapper / Version Catalog 锁定，勿手动升级）。
- Node 不需要；Python 3 仅用于辅助脚本。

## 2. 网络与镜像（沙箱/代理环境必读）

- Java 默认 IPv6 映射套接字会被沙箱拦截：所有 JVM 须加 `-Djava.net.preferIPv4Stack=true`（`JAVA_TOOL_OPTIONS`）。
- 依赖走本地 L7 镜像（`gradle-home/init.gradle` 重写 dl.google.com、maven.google.com、repo.maven.apache.org、repo1.maven.org、plugins.gradle.org 到本地镜像端口），上游用 curl 拉取；不要把代理口令写进工程仓库。
- `GRADLE_USER_HOME` 指向机器专用的 gradle-home（含合并 CA 的 truststore）；直接跑 `gradlew` 而不用 `build.sh` 会丢这些配置。

## 3. 一键构建

```sh
./build.sh            # assembleDebug + testDebugUnitTest + lintDebug，全绿才算过
./build.sh ui-test    # connectedDebugAndroidTest（需真机；ColorOS 测试包须手动安装）
```

- 构建产物：`app/build/outputs/apk/debug/`、`app/build/outputs/apk/release/`。
- Release 默认开 R8 + 资源收缩（W4 定稿）；无 release 签名属性时产出未签名 release APK（见签名指南）。
- 守护进程占锁导致构建失败时：`./gradlew --stop` 清锁后重跑（W3 审计门禁实测）。

## 4. 签名与版本

- Debug 签名固定为工程自带 `keystore/debug.keystore`（口令为 Android 惯例公开值，仅调试用，绝非发布密钥）。
- Release 签名属性：`releaseStoreFile` / `releaseStorePassword` / `releaseKeyAlias` / `releaseKeyPassword`（gradle properties，密钥文件与口令由站长保管，永不入仓）。
- 版本号在 `app/build.gradle.kts` 的 `versionCode` / `versionName`；发布时主备两份 `app/latest.json` 须同升。
