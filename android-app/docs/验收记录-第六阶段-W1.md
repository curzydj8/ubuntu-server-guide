## W1 过程中发现并修复的两个问题

### 1. exec 超时文案误导（非假成功——此处更正前期推断）

- 边界测试新增 `exec timeout is reported as failure, not success`（MINA `BlockingCommand`，500ms 超时）。
- 前期推断“旧实现超时后返回 Success、exitCode 为 null”**实测不成立**：sshj 的 `join(timeout)` 超时时抛异常，旧代码的通用 catch 本就返回 Failure。真正的缺陷只是文案：异常被笼统写成“命令执行中断”，而非“超时”。
- 根因链（实测定位）：sshj 0.41.2 的 `Promise.retrieve` 产生 `TimeoutException`，但经 `ExceptionChainer.chain()` 转换后到达 catch 时类型已变、文案保留 `Timeout expired: 500 MILLISECONDS`。第一版修复仅按类型捕获，未命中；第二版改为类型 + 文案（`contains("Timeout expired")`）双重判定，直出“命令执行超时：…ms 内未完成”。
- 提交：`f5c1260`（初版）→ `f7725fa`（文案映射）→ `414c5de`（双重判定）。超时只杀命令不杀连接（`isConnected` 断言通过）、finally 照常关通道会话。

### 2. UI 测试 performScrollTo 在非滚动容器上必抛（3 败同根因）

- 首轮真机：4 条中 3 条失败，均为 `Semantic Node has no parent layout with a Scroll SemanticsAction`：工具列表是普通 Column，没有可滚动父布局。
- 修复：测试内新增容忍式 `scrollIfPossible()`（滚不动则继续，后续 `assertIsDisplayed` / `performClick` 如实判定）。提交 `f7725fa`。
- 首轮唯一通过：设置页版本与更新按钮。

## 真机安装限制（设备策略，记入已知限制）

- ColorOS 对 adb 安装测试包实施拦截：logcat 原话 `PackageInstaller: PC install attack detected!dev.linuxserver.toolkit.test` → `OPLUS_ADB_INSTALL_CANCEL`，`pm install` 与 `adb install` 均返回 `Failure [-99]`，且不弹确认框。主 App 无 instrumentation 属性，不受影响。
- 绕过方式：测试包推到手机 Download（`ToolkitUiTest.apk`），由站长在手机上手动安装（用户主动安装不触发该规则），装好后 `am instrument` 正常运行。
- 影响：后续 UI 测试包更新仍需站长手动重装一次；CI/自动化侧无法绕过此策略。
