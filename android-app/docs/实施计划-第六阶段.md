# 第六阶段实施计划：全面测试、性能优化、安全审计、Release 构建和发布准备

依据：《安卓 App 项目任务书》第九节第六阶段、第七节测试与质量门禁、第八节命令行构建与交付、第十节执行规则；承接第五阶段 W3 定版 0.6.5（单测 141/141、Lint 0 错误、真机验收通过）。

## 一、范围

**本阶段做：**

- 全面测试补齐：按任务书第七节逐项核对——单元、集成、UI、边界、安全、兼容性、回归七类，缺的补、弱的加，全部进 `build.sh` 门禁。
- 性能优化：先测基线再动手，动完复测，数据说话（启动耗时、APK 体积、首启导入耗时、终端输出与列表性能）。
- 安全审计：凭据、主机密钥、日志脱敏、危险命令、网络请求、依赖版本、仓库密钥残留，逐项出结论。
- Release 构建：release 配置（R8 取舍、AAB/APK）、正式签名方案、版本号规则。
- 发布准备：隐私政策、开源依赖与许可证清单、版本记录、功能矩阵与已知限制定稿、干净环境重建文档、发布检查清单。

**本阶段不做（需站长另定）：**

- 新功能（SFTP、ProxyJump、端口转发、ANSI 全屏终端仍属后续增量，不在本阶段顺带做）。
- 上架应用商店（发布渠道待站长确认，见第七节；默认按现有站内直分发准备，不默认走 Play）。
- 多机型兼容实测（无 KVM 故无模拟器，真机只有 OPPO PEQM00 Android 13 一台；超出此范围的兼容性结论标外部阻塞，不编造）。

## 二、现状基线（2026-10-24，0.6.5）

| 项 | 现状 | 缺口 |

| 边界测试 | 部分（风险分级、终端 200K 截断、超时/取消） | 逐工具核对补齐 |

## 三、分波实施

- **W1 全面测试补齐**：先出七类测试对账表（每类现状/缺口/补法），再补：仪器化 UI 测试（导航三栏、主机表单校验与错误态、终端与诊断关键操作、检查更新三态）；边界测试按工具与模块补齐；回归门禁：单测 + lint 保持全绿，UI 测试单独成项（`./build.sh ui-test`，需真机在线，离线标未验证）。
- **W2 性能优化**：测基线——冷启动耗时（adb 启动计时）、APK 体积（当前 debug 包约 16.7MB，release 另测）、首启 99 篇导入耗时、知识库列表滚动与搜索响应、终端大输出流式上限；再定优化项（只做有数据支撑的：如 R8、资源收缩、导入分批），逐项复测，不接受“感觉变快了”。
- **W3 安全审计**：凭据只进 Keystore（数据库/日志/审计抽查无明文）；TOFU 指纹变更必拦截（含真机复测一次）；日志与审计脱敏断言全覆盖；危险命令护栏复测；网络面：更新清单两地址均为 HTTPS、无明文凭据传输；依赖版本审计（Version Catalog 逐项核对已知漏洞，有则升级并回归）；仓库扫描：快照与本地仓无 keystore/口令/local.properties 残留（0.6.4 曾误带 local.properties，重点复查）。出审计记录，问题分级（阻断/建议）并修阻断项。
- **W4 Release 与发布准备**：release 构建配置定稿（R8 开关以 W2 实测为准，默认开、回归全绿才保留）；签名方案按站长确认执行（见第七节）；产出：release APK（+ SHA-256，AAB 仅当确认走 Play 时才出）；隐私政策（离线优先、无数据上传、凭据本地保管、更新清单仅拉取版本信息四条写实）；开源依赖与许可证清单（以 Version Catalog 为准逐项列）；版本记录与已知限制定稿；干净环境重建文档（devtools、镜像、build.sh 从零复现）；发布检查清单（逐项打勾，含回滚：清单回退与旧版覆盖安装）。

## 四、测试与门禁

- `build.sh` 全量（assemble + 单测 + lint）每波必须全绿；新增单测与 UI 测试目标：W1 结束时总数显著高于 141，具体数以对账表为准，不预设凑数目标。
- 仪器化测试在真机跑（OPPO PEQM00），跑前确认无线调试通道在线；通道不通标外部阻塞，不以 JVM 测试冒充。
- 每项测试记录真实执行命令、退出码、数量与失败原因；未执行的标未验证，禁止把未跑写成通过。

## 五、风险清单

1. **UI 测试需真机仪器化 APK 安装**——ColorOS 对全新安装有确认框，需站长在手机端点确认（沿用 0.5.x 以来做法）；通道脆弱，分片传输。
2. **兼容性结论受限**——只有一台真机，Android 版本与屏幕尺寸覆盖不足；结论如实标注，不外推。
3. **Release 签名密钥在站长手里**——代理无法也不应经手口令；签名仪式需他配合，时间不可控，W4 以此为前置。
4. **R8 开启可能破坏反射/序列化**——以回归全绿为准，不行就关掉并记录原因，不硬上。
5. **性能优化忌无数据动手**——无基线不优化，优化无复测不算完成。

## 六、验收标准（对任务书逐条）

- [ ] 七类测试对账表完整，缺口补齐，`build.sh` 全绿，UI 测试在真机跑通并有记录
- [ ] 性能基线与优化后复测数据成对出现，APK 体积与启动耗时有数可查
- [ ] 安全审计记录完整，阻断项清零，仓库扫描无密钥残留
- [ ] Release 构建可复现，签名方案按确认执行，产物 SHA-256 可验
- [ ] 隐私政策、许可证清单、版本记录、已知限制、干净环境重建文档、发布检查清单齐全
- [ ] 功能矩阵更新至最终版，每项状态有证据或明确标注未验证

## 七、待站长确认事项（计划确认时一并定，不影响 W1 开工）

1. **Release 签名流程**：A. 站长自备 release keystore，代理只配构建不碰口令，签名步骤由站长在自己机器上执行（代理出签名脚本与核对清单）；B. 其他方式（请明示）。未定前 W4 不动签名。
2. **发布渠道**：站内直分发（Workers 清单 + 直发 APK，沿用 0.5.0 以来模式）还是上架应用商店（若走商店，需补 AAB 与商店资料，工作量另计）。
3. **版本号规则**：第六阶段结束是否升 1.0（任务书未定 1.0 标准；建议以“本计划验收全过”为准，站长定）。
