## 优化决策：五项基线无性能问题，不做无数据改动

启动、滚动、搜索、导入、终端五项基线均健康：不做分批导入、不做列表专项优化、不动终端缓冲。唯一值得量化的优化项是 **R8 + 资源收缩**（同时是 W4 定 release 配置的实测依据），以临时 bench release 验证。

## R8 实验（成对数据）

- 实验方式：临时 `release { isMinifyEnabled = true; isShrinkResources = true; applicationIdSuffix = ".bench" }`，与主包共存上机，签 debug 密钥（仅测试），测完即 revert 构建配置并卸载 bench 包，主包全程未动。
- 包体积：R8 后 4,103,400 字节（未签名）/ 4,120,763 字节（签名后），相对未开混淆 release **−68%**，相对 debug **−76%**。
- 冷启动：R8 bench 包 441 / 399 / 418 ms（均值约 419 ms），相对同条件 bench debug 包 1240 ms **−66%**。
- 回归冒烟：R8 包内知识库首页正常渲染 99 篇 + 文章列表（Room 与 UI 在 R8 下工作，数据随同签名更新保留）。
- 结论：**建议 W4 采用 R8 + 资源收缩作为 release 默认配置**（最终定稿仍需 W4 全量回归绿灯）。
