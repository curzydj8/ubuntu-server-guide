    WEB-01：HTML 基础与语义化标签¶

    任务编号：WEB-01（网站建设与部署实战指南 · HTML 完整教程第 1 篇） 上一篇：WEB-00 现有项目审计与目录设计；下一篇（待开始）：WEB-02 HTML 表单、表格、媒体。 本篇只讲 HTML 的基础和语义化布局，不讲表单、表格、图片、视频（那是 WEB-02），不讲 CSS 和 JavaScript（那是 CSS-01、JS-01 之后的事）。

    1. 本章目标¶

    读完并动手做完本篇，你能：

    1. 说清楚 HTML 是什么、浏览器是怎么读它的；
    2. 从空文件开始，写出一个结构完整、语义正确的网页；
    3. 分清“为了好看才换行”和“为了表达结构才用标签”这两件事；
    4. 用 header、nav、main、section、article、aside、footer 搭出一个标准页面骨架，而不是全篇只用 div。

    2. 适用人群¶

    • 零基础、第一次写网页的人；
    • 会用宝塔、WordPress 建站，但没写过 HTML、想知道页面骨架是怎么回事的人；
    • 已经会写一点 HTML，但习惯全篇 div，想改成语义化写法的人。

    3. 适用系统和版本¶

    • 操作系统：Windows、macOS、Linux 都可以，本篇不依赖任何服务器系统。
    • HTML 版本：HTML5（即现在通用的 HTML 标准，没有“HTML6”这种日常版本，不用纠结）。
    • 浏览器：Chrome、Edge、Firefox、Safari 任选其一，能打开本地文件即可。
    • 编辑器：VS Code、Notepad++、记事本、gedit 都可以，VS Code 体验最好，但本篇不强制。

    4. 使用前提¶

    • 会新建文件夹、会用编辑器保存文件；
    • 知道什么是文件扩展名（.html），如果你的系统默认隐藏扩展名，先在文件管理器里打开“显示文件扩展名”，否则你保存的可能是 index.html.txt，浏览器打不开。

    5. 所需资源¶

    • 一台能打开浏览器的电脑，不需要服务器、不需要域名、不需要联网（本地文件就能看效果）；
    • 本篇第 10 节的完整代码，复制下来就能用；
    • 可选：Python 3（用来做第 14 节的本地服务验证，没有也不影响，只用浏览器打开本地文件也能验证）。

    6. 技术原理¶

    HTML 的全称是 HyperText Markup Language，超文本标记语言。它不是编程语言，没有“运行”这个概念，只有“标记”和“显示”两件事：

    1. 你用一对对标签把内容“标记”起来，告诉浏览器“这是一级标题”“这是一个段落”“这是一段导航”；
    2. 浏览器读到标签后，按自己的默认样式把内容显示出来。CSS 还没上场时，标题就是大一号粗一号的字，段落之间就是空一行，就这么简单。

    关键理解：

    • 标签是成对出现的：开始标签 <p>，结束标签 </p>，中间夹着内容。少数标签是自闭合的，比如换行 <br>、水平线 <hr>，在 HTML5 里写 <br> 就可以，不用写成 <br />。
    • 标签可以嵌套，但不能交叉：<p><strong>对的</strong></p> 是对的，<p><strong>错的</p></strong> 是错的，浏览器会自己“修”错的写法，但修出来的结果不一定是你想要的。
    • 浏览器对大小写不敏感，但约定俗成全部用小写，别写 <DIV>。
    • HTML 只管结构和语义，不管好看：颜色、间距、排版是 CSS 的活（CSS-01 再讲），本篇不要用 HTML 去调样式，比如不要用一堆 <br> 去撑间距，也不要用 <b>、<i> 只为了加粗斜体——加粗强调语义用 <strong>，斜体强调语义用 <em>，纯视觉加粗斜体以后交给 CSS。

    7. 架构说明¶

    一个标准 HTML5 页面的骨架是固定的，从外到内是三层：

    文档声明（告诉浏览器：这是 HTML5）
└── html（整个页面，lang="zh-CN" 说明页面语言是中文）
    ├── head（给浏览器和搜索引擎看的，不直接显示：编码、标题、描述）
    └── body（给用户看的，全部可见内容都在这里）
        ├── header（页眉：站名、口号）
        ├── nav（导航：到各个栏目的链接）
        ├── main（正文主体：一个页面只能有一个 main）
        │   ├── section（按主题分的一节）
        │   │   └── article（一篇独立完整的文章）
        │   └── aside（侧栏：相关链接、补充说明）
        └── footer（页脚：版权、联系、备案说明等）

    语义化就是：看到 header 就知道这是页眉，看到 nav 就知道这是导航，看到 article 就知道这是一篇可以单独拿出来的文章。搜索引擎、屏幕阅读器（给视障用户读网页的软件）都靠这些标签理解页面，全用 div 它们就只能看到“一堆盒子”，分不清哪是导航、哪是正文。

    8. 操作前检查¶

    开始之前，先确认三件事，缺一个都先补上：

    1. 编辑器能保存纯文本文件，且保存时编码选 UTF-8（VS Code 默认就是 UTF-8，不用改；记事本保存时要选“UTF-8”，不要选“ANSI”，否则中文会乱码）；
    2. 你有一个空文件夹可以放练习文件，比如桌面上的 my-first-site；
    3. 浏览器能打开本地文件（随便找一个 .html 文件双击能打开就行，没有也不要紧，做完第 10 节就有）。

    9. 逐步操作¶

    1. 在你的练习文件夹里新建一个文件，名字必须是 index.html（index 是约定俗成的首页文件名，服务器以后找首页也是先找它）。
    2. 把第 10 节的完整代码从头到尾复制进这个文件，不要只复制一半，也不要自己先改标签名。
    3. 保存，编码 UTF-8。
    4. 双击 index.html，用浏览器打开，看第 13 节描述的效果是否出现。
    5. 回到编辑器，把标题里的文字改成你自己的名字或站名，保存，刷新浏览器，看标题是不是跟着变了——变了就说明“改代码 → 保存 → 刷新”这个循环已经通了。
    6. 试着把一个 <section> 整个删掉，保存刷新，看页面是不是少了一节；再按 Ctrl+Z 恢复。这个练习是让你建立信心：删错了也能恢复，网页不是一碰就坏的东西。

    10. 完整代码¶

    下面是本篇的完整示例，从第一行到最后一行，没有省略号，复制下来就是一个能打开的页面。存放位置：练习文件夹里的 index.html，就是第 9 节第 1 步那个文件。

    <!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>我的第一个语义化网页</title>
</head>
<body>
  <header>
    <h1>我的学习笔记站</h1>
    <p>从 HTML 开始，一步一步建一个网站。</p>
  </header>
  <nav>
    <ul>
      <li><a href="#about">关于本站</a></li>
      <li><a href="#notes">学习笔记</a></li>
      <li><a href="#links">相关链接</a></li>
    </ul>
  </nav>
  <main>
    <section id="about">

    11. 完整配置文件¶

    本篇不需要服务器配置文件，也不需要 package.json、不需要构建工具。唯一的文件就是第 10 节的 index.html，存放在练习文件夹根目录。以后部署到服务器时（DEPLOY 阶段），这个文件会放在网站根目录（比如 Nginx 的网站目录）里，文件名还是 index.html，服务器收到“访问首页”的请求时，默认就会返回它。

    12. 每个关键标签和属性的解释¶

    标签 / 属性 作用 容易错的地方
    <!DOCTYPE html> 文档声明，必须是文件的第一行，告诉浏览器按 HTML5 解析 不是标签，没有结束标签；前面不能有空行和空格，否则个别浏览器会进兼容模式
    <html lang="zh-CN"> 整个页面的根，lang 说明页面语言是中文 漏写 lang 不会让页面打不开，但搜索引擎和屏幕阅读器会少一个判断依据
    <head> 放编码、标题等“给浏览器看”的信息，不直接显示 不要把可见内容（比如 h1）放进 head，放进去了浏览器会把它挪到 body，结构就乱了
    <meta charset="UTF-8"> 告诉浏览器用 UTF-8 解码，中文不乱码 必须是 head 里最靠前的内容之一，放在 title 后面也行，但别放到 body 里
    <meta name="viewport" content="width=device-width, initial-scale=1.0"> 告诉手机浏览器按设备宽度显示，不缩成桌面版再放大 漏写它，手机上打开会显得字很小，这是 CSS-06 响应式的前提，本篇先写上、以后再细讲
    <title> 浏览器标签页上显示的文字，也是搜索引擎结果里的标题 一个页面只能有一个 title，不要写成页面里的 h1，h1 是给用户看的正文标题
    <body> 全部可见内容都在这里 一个页面只能有一个 body
    <header> 页眉：站名、口号、页眉导航 一个页面可以有多个 header（比如每篇文章也可以有自己的 header），但本篇先只用一个整页页眉
    <nav> 导航区块：到站内各栏目的链接集合 不要把页面里所有链接都包进 nav，正文里的单个链接、页脚的链接不用包
    <main> 正文主体，一个页面只能有一个 不要把页眉、导航、页脚包进 main，也不要出现两个 main
    <section> 按主题分的一节，通常带一个标题（h2） 没有标题的 section 不如直接用 div；本篇每节都有 h2，是正确的用法
    <article> 一篇独立完整的内容，单独拿出来也能成立 一篇博客文章、一则新闻是一篇 article；一节里的普通段落不是
    <aside> 侧栏、补充内容：相关链接、广告、作者简介 aside 是“补充”，不是“不重要就可以删”，删了正文还能成立，才适合放 aside
    <footer> 页脚：版权、联系方式、备案说明等 和 header 一样，整页可以有一个，文章也可以有自己的 footer
    <h1>～<h6> 六级标题，数字越小越重要 一个页面只用一个 h1；不要跳级（h1 后面直接 h3）；不要为了字大用 h1，字大是 CSS 的事
    <p> 一个段落 不要在 p 里面再套 div、section、article，p 里面只能放文本和行内标签
    <strong> / <em> 强调：strong 是重要、加粗语气；em 是重读、斜体语气 纯视觉加粗用 CSS，不要用 <b>；纯视觉斜体用 CSS，不要用 <i>
    <ul> / <li> 无序列表：导航、相关链接这种“没有先后顺序”的一组项目 ul 里面只能直接放 li，不能直接放 a 或 p，链接要放在 li 里面
    <a href="..."> 超链接，href 是目标地址 站内跳转用 #about 这种锚点（对应 id="about" 的元素），外站用完整 https:// 地址；漏写 href 的 a 不是链接

    15. 常见错误¶

    错误 现象 改法
    文件存成 .txt 浏览器显示源代码 改扩展名为 .html，并在文件管理器里打开“显示文件扩展名”
    中文乱码 中文变成问号或方块 检查两点：文件保存时编码是 UTF-8；head 里有 <meta charset="UTF-8">
    标签交叉嵌套 页面结构错乱，某段文字跑到不该去的地方 改成正确嵌套：先开的后关，<p><strong>…</strong></p>
    一个页面多个 h1 搜索引擎分不清页面主题 只留一个 h1，其他标题降级为 h2、h3
    全篇只用 div 页面能看，但搜索引擎和屏幕阅读器分不清结构 按第 7 节的骨架，把页眉、导航、正文、侧栏、页脚换成对应的语义标签
    用 <br> 凑段落、凑间距 段落之间空行不均匀，改起来麻烦 一段话一个 p，间距以后用 CSS 调，本篇不要用 <br> 凑
    ul 里直接放 a 浏览器能显示，但结构不规范，校验会报错 ul 里只放 li，a 放进 li 里
    漏写 <!DOCTYPE html> 页面进入兼容模式，样式表现不一致 补到文件第一行，前面不要有空行

    16. 故障排查¶

    • 打开是空白：先看文件是不是空的、是不是保存错了文件夹；再看是不是把内容写进了 head 而不是 body。
    • 中文乱码：按第 15 节查编码和 meta charset，两个都要对，只对一个还是会乱。
    • 导航点不动：检查 href="#about" 里的 #about 和对应 <section id="about"> 里的 id 是不是一模一样，差一个字母就跳不过去。
    • 标题层级乱了：在编辑器里搜索 h1，数一下是不是只有一个；再从上往下看 h1 → h2 → h3 是不是依次出现。
    • 改了代码刷新没变：确认保存了（编辑器标题栏没有小圆点），再按 Ctrl+F5 强制刷新，排除浏览器缓存。

    17. 安全注意事项¶

    • 本篇的页面是纯静态本地文件，没有表单、没有后端、没有用户输入，所以没有注入、没有登录安全问题，不要把本篇的简单写法直接套到以后有表单、有数据库的页面上。
    • 不要从不明来源复制 HTML 代码直接粘贴到你的页面里：复制来的代码里可能藏着外链图片、脚本或跳转链接，先看懂再贴。
    • 外链（比如本篇的 MDN 链接）要确认是 https:// 开头的正规地址，不要链到自己不认识的短链接。
    • 以后在页面里展示用户输入的内容时，必须做转义（把 <、> 转成实体字符），否则用户输入的标签会被浏览器当成真标签执行——这是 XSS 的入门概念，JS-02 和 BE 阶段会细讲，本篇先记住结论。

    18. 回滚和恢复¶

    本篇没有服务器、没有数据库、没有配置改动，回滚就是：

    • 改错了：编辑器里 Ctrl+Z 撤销，或把第 10 节的完整代码重新复制覆盖一次；
    • 文件删错了：重新新建 index.html，把第 10 节代码再贴一遍；
    • 没有任何线上内容会被影响，因为本篇文件只在你的练习文件夹里，还没有部署到 crozz.me。
