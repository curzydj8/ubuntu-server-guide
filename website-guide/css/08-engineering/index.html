    CSS-08：CSS 工程化¶

    任务编号：CSS-08（网站建设与部署实战指南 · CSS 完整教程第 8 篇） 上一篇：CSS-07 动画与高级效果；下一篇：CSS-09 Bootstrap。 本篇只讲 CSS 工程化：文件怎么组织、全局样式和组件样式怎么分工、样式怎么隔离、Sass、Less、PostCSS 是干什么的、命名规范怎么写、样式怎么维护和优化。不讲具体某个 CSS 框架的组件用法（那是 CSS-09 起的框架篇），不讲 Flex 和 Grid 的基础（那是 CSS-04、CSS-05），不讲动画细节（那是 CSS-07）。

    1. 本章目标¶

    读完并动手做完本篇，你能：

    1. 给一个多页面的小网站定一套 CSS 文件组织方式，说清楚每个文件放什么、入口文件怎么汇总；
    2. 分清全局样式和组件样式的分工：哪些放全局、哪些只属于某个组件；
    3. 用 BEM 命名写出一个不会和别人撞名的组件，读懂 Block__Element--Modifier 的每一部分；
    4. 说清楚 CSS Modules、Sass、Less、PostCSS 各解决什么问题，各在什么场景用；
    5. 写出带变量、嵌套、混合的 SCSS，并说清楚它为什么必须先编译成 CSS 才能给浏览器用；
    6. 发现并删掉没用的 CSS，知道关键 CSS 是什么，不再全站写超长选择器和滥用 !important。

    2. 适用人群¶

    • 已完成 CSS-01 至 CSS-03，能写选择器、单位、颜色、盒模型、定位的人；
    • 样式文件已经超过一两百行，改一处怕影响别处，或者多人一起写样式总互相撞名的人；
    • 听说过 Sass、BEM、CSS Modules，但不知道它们到底是干什么、该不该用的人；
    • 还没有接触过构建工具的人——本篇讲概念和手工做法，构建工具的完整配置在 JS-04 前端工程化阶段再讲。

    3. 适用系统和版本¶

    • 与 CSS-01 至 CSS-03 相同：Windows、macOS、Linux 均可，任意现代浏览器，任意纯文本编辑器。
    • CSS 版本：CSS3 及之后的标准；本篇讲的原生 CSS 部分（BEM 命名、文件组织）不需要任何工具就能用。
    • Sass / SCSS 版本：本篇示例按现代 Sass 的 SCSS 语法写，@use 是当前推荐的模块写法，@import 是旧写法，只讲概念，不要求你现在就装 Sass；浏览器不直接认 SCSS，这一点在第 10 节、第 14 节会反复提醒。
    • Less、PostCSS：本篇只讲概念，不要求安装，不要求配置。

    4. 使用前提¶

    • 已完成 CSS-01（选择器、优先级、继承），知道类选择器、ID 选择器、伪类是什么；
    • 已完成 CSS-02（单位、颜色、字体、背景、边框），能看懂示例里的颜色、字号、边框写法；
    • 已完成 CSS-03（盒模型、定位），知道 box-sizing、margin、padding 是什么；
    • 知道怎么保存 UTF-8 编码的 .html 文件，知道浏览器刷新、查看源代码怎么操作。

    5. 所需资源¶

    • 一台能打开浏览器的电脑，一个练习文件夹（沿用 CSS-01 至 CSS-03 的练习文件夹即可）；
    • 本篇第 10 节的完整代码（一个 BEM 组件示例页和一段 SCSS 示例）；
    • 可选：浏览器的开发者工具（按 F12），用来做第 14 节的检查，没有也不影响前三项验证；
    • 不需要安装 Sass、Less、PostCSS 才能完成本篇——SCSS 示例在本篇只是语法示例，未在本机编译，见第 14 节的如实说明。

    6. 技术原理¶

    为什么小项目不用工程化，大项目非用不可¶

    一个页面、几十行 CSS 时，把所有样式写在一个文件里完全没问题，找起来也快。页面一多、组件一多、参与的人一多，三个问题就会同时出现：

    1. 互相影响：全局样式没有边界，给一个按钮写的样式，不小心影响了另一个按钮，因为选择器撞名了，或者优先级盖过去了；
    2. 不敢改：不知道某条规则还有没有地方在用，删了怕别处坏掉，留着又越积越多；
    3. 不好找：一个文件几千行，改一个卡片样式要先翻半天，不知道它到底写在哪。

    工程化不是“把简单问题搞复杂”，而是给样式定三条规矩：文件怎么分、名字怎么写、工具帮你干什么。文件组织解决“不好找”，命名规范和隔离手段解决“互相影响”，删除无用样式和关键 CSS 解决“越积越多、首屏变慢”。

    文件组织的核心：按“谁用”分，不按“属性”分¶

    不要按属性分文件（比如一个文件只放颜色、一个文件只放字号），那样改一个组件要同时改好几个文件。按“谁用”分才是工程化的分法：

    • 按页面分：首页一个文件、文章页一个文件，适合页面之间差异很大的站；
    • 按组件分：卡片一个文件、导航一个文件、按钮一个文件，适合组件复用多的站，是现在最常用的分法；
    • 按功能分：变量一个文件、工具类一个文件、全局基础样式一个文件，这些是跨页面、跨组件共用的部分。

    实际项目里三种分法会混着用：功能层放共用的东西，组件层放各组件自己的东西，页面层只放某个页面特有的东西。第 7 节会给出一套可以直接照抄的目录结构。

    全局样式和组件样式的分工¶

    • 全局样式：全站都一样的底子，比如 box-sizing 统一、body 的默认字号和颜色、链接的默认样式、标题的默认字号层级。它只定“默认值”，不定某个具体组件长什么样；
    • reset / normalize：全局样式里最常见的两种底子。reset 是把浏览器默认样式清零（比如去掉所有内外边距），从零开始写；normalize 是把不同浏览器的默认样式统一成一致，而不是清零。两者目标都是“不同浏览器看起来一样”，手段不同，新项目用 normalize 的思路更常见，因为它保留了有用的默认行为（比如标题还是比正文大）；
    • 全局变量：全站共用的数值，比如主色、辅色、圆角、间距档位。原生 CSS 用自定义属性（CSS Variables，CSS-07 会讲），Sass 用 $ 变量，本篇第 12 节会把两者放在一起讲清楚；
    • 组件样式：只属于某个组件的样式，比如卡片的边框、按钮的颜色。组件样式不应该去改全局元素（不要在卡片文件里写 h2 { color: red; }，那样全站的 h2 都会变红），只应该写这个组件自己的类名。

    一句话记分工：全局定底子，组件定自己，页面定特例。越往下越具体，越具体的样式越不应该影响别人。

    样式隔离：为什么全局样式容易互相影响¶

    CSS 默认就是全局的：只要选择器匹配，样式就生效，不管这条规则写在哪个文件里。所以两个组件都写了一个 .title，后加载的那个就会盖掉先加载的那个，或者两者混在一起，谁也说不清最后生效的是谁。隔离就是给样式加边界，让它只对当前组件生效，隔离手段有三种，适用场景不同：

    • 命名规范（BEM）：靠名字本身防冲突，名字里带上组件名，别人就不会和你撞名。不需要工具，任何项目都能用，是成本最低的隔离；
    • CSS Modules：靠工具在构建时给类名自动加哈希后缀，.title 编译后变成 .title_a1b2c3，不同组件的同名类编译后就不是同一个名了。需要构建工具配合，适合组件化项目；
    • 组件化本身：框架的组件（Vue、React 的单文件组件）把 HTML、CSS、JS 放在一个文件里，CSS 只对这个组件的模板生效。这是框架层面的隔离，CSS-08 只讲思路，具体框架配置在 FE 阶段再讲。

    三种手段不是互斥的：小项目用 BEM 就够了，中型项目用 BEM 加 Modules，大型组件化项目用框架组件加 Modules，选哪个看项目规模，不要一上来就全用。

    预处理器和后处理器：一句话分清¶

    • 预处理器（Sass、Less）：让你用“更高级的写法”写样式（变量、嵌套、混合、函数），然后编译成浏览器能认的普通 CSS。浏览器不认 Sass、Less，只认 CSS，所以预处理器永远多一步编译；
    • 后处理器（PostCSS）：先写普通 CSS（或接近普通的 CSS），再用插件加工一遍，比如自动加浏览器前缀、把未来语法转成现在浏览器能认的语法。它不改变你写样式的方式，只在输出时加工。

    预处理器解决“写起来麻烦”，后处理器解决“兼容性麻烦”，两者可以一起用，也可以只用其一。

    维护和性能：样式越写越多的两个刹车¶

    • 选择器不要写太长：body main section article div p span 这种超长选择器，优先级高、难覆盖、浏览器匹配也慢，而且一改 HTML 结构就全断。能用一个类名选中的，就不要写五层后代；
    • 不要滥用 !important：CSS-01 已经讲过，!important 会盖过一切正常声明，用多了以后想改都改不动。工程化项目里 !important 应该只出现在极少数“必须赢”的工具类里，并且要写注释说明为什么必须赢；
    • 不要全站写 * 通配：* { margin: 0; } 这种写法会选中所有元素，包括你没想到的元素，而且浏览器要对每个元素都算一遍。全局清零只在 reset 文件里做一次，而且要写得有针对性，不要在组件文件里再写 *；
    • 未使用的 CSS：页面越改越多，删了 HTML 却忘了删 CSS，样式文件里就会留下“死代码”。浏览器开发者工具的 Coverage 面板可以录一次页面访问，标出哪些 CSS 规则一次都没用到，删之前先确认它真的没在其他页面用；
    • 关键 CSS：首屏（用户第一眼看到的那部分）用到的样式，优先加载、优先渲染；首屏之外的样式可以晚一点加载。这样首屏不用等整个样式文件下载完就能显示，感觉上就快了。关键 CSS 的提取和内联属于构建细节，本篇只讲概念，不展开构建配置。

    7. 架构说明¶

    本篇推荐的一套目录结构，可以直接照抄到练习项目里，文件数不多，但分工已经齐全：

    my-site/
├── index.html              # 首页，引用 styles/main.css
├── styles/
│   ├── main.css            # 入口文件：只负责汇总，不写具体组件样式
│   ├── base.css            # 全局基础：box-sizing、body 默认字号颜色、链接默认样式
│   ├── variables.css       # 全局变量：主色、辅色、圆角、间距（原生 CSS 自定义属性写法）
│   ├── utilities.css       # 工具类：只做一件事的小类，比如文字居中、隐藏
│   └── components/
│       ├── card.css        # 卡片组件：只写 .card 开头的类
│       ├── nav.css         # 导航组件：只写 .nav 开头的类
│       └── button.css      # 按钮组件：只写 .btn 开头的类
└── scss/
    └── card.scss           # SCSS 示例文件（第 10 节第二段），编译后才变成 CSS

    入口文件 main.css 的汇总思路有两种，学习阶段和正式项目要分清：

    • 学习阶段可以用 @import：在 main.css 里写 @import "base.css";、@import "components/card.css"; 这样一行一行引入，浏览器会按顺序下载每个文件，思路最直观；
    • 正式项目用构建工具合并：@import 每引入一个文件，浏览器就要多发一次请求，文件一多首屏就变慢。正式项目的做法是在构建时把多个文件合并成一个 main.css 再上线，浏览器只下载一次。本篇不展开构建配置，只把这个性能提醒说清楚：学习时用 @import 没问题，上线前要合并。

    SCSS 文件的存放位置也要说清楚：scss/ 里的 .scss 文件是“源文件”，浏览器不直接用它；编译后的 .css 文件才是“产物”，放在 styles/ 里给 HTML 引用。源文件和产物不要混在一个文件夹里，否则以后分不清哪个是能改的、哪个是生成的。

    12. 每个关键概念的解释¶

    BEM 命名规范¶

    BEM 是 Block（块）、Element（元素）、Modifier（修饰符）三个词的首字母，写法是 Block__Element--Modifier，双下划线分隔块和元素，双横线分隔元素和修饰符：

    部分 写法 示例 读法
    Block（块） card .card 一个独立的组件，卡片本身
    Element（元素） card__title .card__title 属于这个块的一部分，卡片的标题，离开卡片就没有意义
    Modifier（修饰符） card--featured、card__button--primary .card--featured 块或元素的某个变体，特色卡片、主要按钮，修饰符总是和原来的类一起用，不能单独用

    为什么 BEM 能防冲突：名字里带上了块名，两个组件都叫 title 时，一个叫 card__title，一个叫 nav__title，根本不是同一个类，就不会互相盖掉。读 BEM 名字时，从左往右读就是“哪个组件的哪个部分、是什么变体”，不用翻到样式文件里才知道它属于谁。

    BEM 的注意事项：元素不要套太多层，card__body__text__link 这种四层名字说明组件拆得不够细，应该把内层再拆成一个独立的块；修饰符不要单独用，<article class="card--featured"> 而不写 card，那它就没有卡片的基础样式，只有特色那一部分，效果是不完整的。

    Sass / SCSS¶

    Sass 是一种 CSS 预处理器，SCSS 是 Sass 的一种语法（另一种是缩进语法，本篇只讲 SCSS，因为它和普通 CSS 长得最像，学起来最顺）。SCSS 的核心是“写的时候方便，编译后还是普通 CSS”：

    概念 写法 作用 容易错的地方
    变量 $card-border: #1a5276;，用的时候写 $card-border 一个值多处用，改一处全站都变，比如主色、圆角、间距 变量名以 $ 开头，和 CSS 自定义属性（-- 开头）不是一回事，不要混用
    嵌套 .card { &__title { } }，& 代表父选择器 把属于同一个组件的规则写在一起，不用来回写块名 嵌套太深（超过三四层）会生成超长选择器，优先级高、难覆盖，和第 6 节讲的“不要写超长选择器”是同一个问题
    混合（Mixin） @mixin card-shadow { } 定义，@include card-shadow; 使用 一段可复用的样式，定义一次，多处引入，还可以带参数 混合是“复制粘贴”，每次 @include 都会把样式复制一份，用多了编译后的 CSS 会变大，不适合放超大段样式
    继承（Extend） %card-base { } 定义占位选择器，@extend %card-base; 使用 多个选择器共用同一组声明，编译后会把选择器合并，而不是复制样式 @extend 会改变选择器的组合方式，用多了编译结果难预测，新手建议先用混合，熟练了再用继承
    模块引入 旧写法 @import "variables";，新写法 @use "variables" as vars;，用的时候写 vars.$card-border 把变量、混合分文件放，别的 SCSS 文件可以引用 @import 是旧写法，全局共享、容易撞名，现代 Sass 推荐 @use，因为它带命名空间，不会撞名；本篇示例为了自包含没有用 @use 分文件，正式项目分文件时要用 @use

    SCSS 和普通 CSS 的关系要记牢：SCSS 是源文件，CSS 是产物，浏览器只认产物。没有装 Sass 工具时，SCSS 文件就是一份“还没编译的草稿”，不能直接给浏览器用，也不能用 <link> 引用它。

    Less：与 Sass 的异同¶

    Less 和 Sass 是同类工具，都是 CSS 预处理器，概念上几乎一一对应，语法上符号不同：

    概念 Sass / SCSS Less 说明
    变量 $card-border @card-border 符号不同，作用相同，都是“一个值多处用”
    混合 @mixin / @include 把一个类当成混合用，比如 .card-shadow() { } 定义，.card-shadow(); 使用 Less 的混合写法更像“调用一个类”，Sass 的混合写法更像“调用一个函数”，概念一样
    嵌套 .card { &__title { } } 同样支持嵌套，写法基本一致 嵌套太深的问题两者都有
    编译 必须编译成 CSS 同样必须编译成 CSS 浏览器两者都不直接认

    选哪个看团队和项目：新项目用 Sass 更常见，文档和生态也更全；老项目如果已经在用 Less，不用为了换而换，概念通了换个符号就能上手。本篇不展开 Less 的全部语法，知道上面这张对照表就够了。

    PostCSS 与 Autoprefixer¶

    概念 作用 容易错的地方
    PostCSS 一个用插件加工 CSS 的工具，本身不规定你怎么写样式，只负责在输出时按插件加工 PostCSS 不是预处理器，不提供变量、嵌套这些写法（除非装了相应插件），不要把它和 Sass 混为一谈
    Autoprefixer PostCSS 最常用的插件，自动给需要加前缀的属性补前缀，比如给 display: grid 在需要的浏览器上补旧写法 Autoprefixer 按“目标浏览器列表”决定补哪些前缀，目标浏览器列表要写清楚（比如“最近两个版本的主流浏览器”），不写它就不知道该补什么；现代浏览器很多属性已经不需要前缀了，不要手动全量加前缀
    未来语法转译 PostCSS 插件可以把“未来 CSS 语法”转成“现在浏览器能认的语法”，比如嵌套、自定义属性在某些场景下的转译 转译后的 CSS 和源文件长得不一样，调试时要看编译后的文件，不要只看源文件猜

    样式隔离手段对照¶

    手段 原理 适合场景 成本
    BEM 命名 名字里带块名，靠名字防冲突 任何项目，尤其是小项目、无构建工具的项目 最低，不需要工具
    CSS Modules 构建时给类名自动加哈希后缀，同名类编译后不是同一个名 组件化项目，有构建工具，组件复用多 中等，需要构建工具配合
    框架组件隔离 组件的 CSS 只对这个组件的模板生效 Vue、React 等框架项目 较高，需要框架和构建工具

    维护和性能要点对照¶

    要点 做法 反例
    选择器长度 能用一个类名选中的，就不要写五层后代 body main section article div p span
    !important 只在极少数必须赢的工具类里用，并且写注释说明为什么 到处写 !important，最后改不动
    * 通配 只在 reset 文件里有针对性地用一次，不要在组件文件里再写 每个组件文件开头都写 * { margin: 0; }
    未使用的 CSS 用浏览器 Coverage 面板录一次访问，标出没用到的规则，确认没在其他页面用再删 删 HTML 时不删 CSS，死代码越积越多
    关键 CSS 首屏用到的样式优先加载，首屏之外的样式晚一点加载 首屏要等整个几百 KB 的样式文件下载完才显示

    13. 执行结果示例¶

    双击打开 engineering.html 后，你应该看到：

    • 标题“CSS 工程化示例”和一行说明“下面是两个卡片组件，类名全部按 BEM 规范写”；
    • 普通卡片：深蓝色边框、12px 圆角、白色背景，标题是深蓝色 20px，下面有一段正文，两个按钮，一个是深蓝底白字的主要按钮，一个是白底绿字绿边的次要按钮；
    • 特色卡片：边框变红，背景变浅橙，其他结构和普通卡片一样，只多了一个 card--featured 类；
    • 把特色卡片的 card--featured 删掉，保存刷新，它就变回普通卡片；把主要按钮的 card__button--primary 改成 card__button--secondary，保存刷新，按钮就变绿边白底绿字。

    card.scss 打开后，你应该看到的是 SCSS 源码（变量、嵌套、混合、继承都在），而不是渲染后的页面——因为 SCSS 本身不是页面，它要编译后才能变成页面用的 CSS，这一点和 HTML 文件完全不同。

    14. 成功验证¶

    按顺序做，全部通过才算本篇完成（其中 SCSS 一项如实说明，见第 4 项）：

    1. 文件验证：engineering.html 在练习文件夹里，双击能打开，不是 .txt；card.scss 在练习文件夹的 scss/ 子文件夹里（或练习文件夹根目录，位置以第 11 节为准），能用编辑器打开；
    2. BEM 验证：普通卡片和特色卡片结构相同，只差一个 card--featured 类；删掉特色卡片的 card--featured，保存刷新，它变回普通卡片；
    3. 按钮验证：把主要按钮的 card__button--primary 改成 card__button--secondary，保存刷新，按钮颜色变了，改回去又变回来；
    4. SCSS 验证（如实说明）：本机没有安装 Sass 工具，所以 SCSS 示例没有在本机编译通过，也没有生成编译后的 CSS 文件——这一点必须如实说，不能谎称编译通过。本项的验证只做到“SCSS 文件存在、语法完整、大括号平衡”（见第 5 节汇报里的实测数字），编译步骤留到装了 Sass 工具后再做；
    5. 命名验证：页面里没有出现裸的 .title、.button 这种不带块名的类，所有组件类都以 card 开头，改一个卡片的类名不会影响另一个卡片；
    6. 可选的 Coverage 验证：按 F12 打开开发者工具，找到 Coverage 面板，录一次页面访问，看 engineering.html 里的样式规则是不是都被用到了——本篇示例小，所有规则都应该被用到，如果有没用到的，说明示例里多写了规则，要删掉。

    15. 常见错误¶

    错误 现象 改法
    BEM 名字写错一个字母 那块样式不生效，其他部分都正常 对照 HTML 里的类名和 CSS 里的选择器，一个字母一个字母对，和 CSS-01 的选择器排查方法一样
    修饰符单独用，不写基础类 只有变体部分生效，基础样式没了，比如只有红边框、没有圆角和内边距 修饰符总是和基础类一起用，比如 class="card card--featured"，不能只写 card--featured
    元素名字套太多层 card__body__text__link 这种四层名字，读不懂、改不动 把内层拆成独立的块，或者用更短的元素名，BEM 元素一般不超过两层
    在组件文件里写全局元素选择器 卡片文件里写 h2 { color: red; }，全站的 h2 都变红 组件文件里只写这个组件自己的类，不要写裸的元素选择器
    SCSS 直接用 <link> 引用 浏览器读不懂，样式全没生效 SCSS 先编译成 CSS，再让 HTML 引用编译后的 CSS 文件
    @import 滥用导致请求多 页面加载变慢，样式文件一个接一个下载 学习阶段用 @import 可以，正式项目用构建工具合并成一个文件再上线
    嵌套太深 编译后的选择器超长，优先级高、难覆盖 嵌套控制在三四层以内，超过了就拆成独立的类
    混合里放超大段样式 每次 @include 都复制一份，编译后的 CSS 越来越大 混合只放小段可复用样式，大段共用样式用继承或抽成独立的类
    到处写 !important 一开始好使，越改越乱，最后到处都要加 删掉 !important，用提高选择器权重或调整顺序解决冲突，见 CSS-01
    全站写 * 通配 没想到的元素也被改了，浏览器每个元素都要算一遍 只在 reset 文件里有针对性地用一次，组件文件里不要再写 *
    删 HTML 不删 CSS 样式文件里留下死代码，越积越多 删 HTML 时顺手删对应的 CSS，定期用 Coverage 面板查一次

    16. 故障排查¶

    • 样式完全没生效：先看 HTML 里引用的 CSS 文件路径对不对，再看类名是不是写错了，再看是不是把 SCSS 文件直接引用了（SCSS 不能直接引用，要先编译）；
    • 只生效了一部分：先看 BEM 名字是不是少写了基础类（只写了修饰符），再看是不是被更高优先级的规则盖住了（CSS-01 的优先级算法），再看是不是嵌套太深导致选择器和 HTML 结构对不上；
    • 改了 SCSS 刷新没变：确认是不是只改了 SCSS 源文件、没有重新编译——只改源文件不编译，浏览器用的还是旧的 CSS，刷新多少次也不会变；
    • 两个组件互相影响：先看类名是不是撞了（都叫 .title、.button），再看是不是在组件文件里写了全局元素选择器，改成带块名的 BEM 类就能隔开；
    • 页面加载变慢：先看是不是 @import 引入了太多文件，再看是不是样式文件里有大量没用到的规则，用 Coverage 面板查一次，删掉确认没用的；
    • 改了 CSS 刷新没变：确认保存了，再按 Ctrl+F5 强制刷新，排除浏览器缓存；外部样式表尤其容易被缓存，改完看不到变化先强制刷新一次。

    17. 安全注意事项¶

    • CSS 本身不能直接偷数据、不能运行脚本，但从不可信来源引入的外部样式表仍然有风险，CSS-01 第 17 节讲过，正式网站只引用自己站内或可信 CDN 的样式表，不要贴来路不明的 <link>；
    • SCSS、Less 的编译工具要从官方渠道安装，不要从不明链接下载所谓的“一键编译工具”，编译工具一旦被换成恶意版本，生成的 CSS 里就可能被塞进你看不见的内容；
    • 不要把真实用户的隐私信息、密钥、令牌写进示例样式或变量文件里，颜色值、字号这些占位数据就够了；
    • !important 和超大 z-index 不是安全问题，是维护和无障碍问题：用超大 z-index 盖住用户必须能点的按钮（比如关闭、取消），用户就操作不了了，CSS-03 讲过这个原则。

    18. 回滚和恢复¶

    本篇和 CSS-01 至 CSS-03、WEB 系列一样，没有服务器、没有数据库、没有配置改动，回滚就是：

    • 改错了：编辑器里 Ctrl+Z 撤销，或把第 10 节的完整代码重新复制覆盖一次；
    • BEM 名字改乱了：把类名改回第 10 节示例里的名字，样式就回来了；
    • SCSS 改错了：SCSS 只是源文件，删掉重写都不会影响已经打开的 HTML 页面，因为 HTML 用的是已经写好的普通 CSS，不是 SCSS 编译的产物；
    • 文件删错了：重新新建 engineering.html 和 card.scss，把第 10 节代码再贴一遍；
    • 没有任何线上内容会被影响，因为本篇文件只在你的练习文件夹里，还没有部署到 crozz.me。
